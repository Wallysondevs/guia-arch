Arch pwd e cd

O terminal está sempre "dentro" de alguma pasta. O pwd diz qual é, e o cd leva você para outra. Com esses dois comandos você anda pelo sistema inteiro sem mouse, e no Arch eles são ainda mais importantes, porque o prompt mostra só um pedaço do caminho.

Você vai aprender
  • Ler o prompt do Arch ([ana@notebook Documentos]$) e saber o que ele não mostra.
  • Descobrir em que pasta você está com pwd e pwd -P.
  • Todas as formas do cd: caminho absoluto e relativo, .., ~, -, sem argumento e nomes com espaço.
  • Guardar e voltar para pastas com pushd e popd.
  • Entender os erros "Arquivo ou diretório inexistente", "Não é um diretório", "Permissão negada" e "número excessivo de argumentos".

Todos os exemplos foram feitos numa instalação real do Arch, com a usuária ana na máquina notebook. No seu computador, o prompt terá o seu usuário e o nome da sua máquina.

Antes de tudo: a pasta atual

Pense no terminal como uma pessoa andando por um prédio de arquivos. Ela está sempre em uma sala (uma pasta). Quando você digita ls, ela olha em volta e diz o que tem naquela sala. Quando você abre um arquivo pelo nome, ela procura naquela sala. Essa sala é a pasta atual, também chamada de diretório de trabalho (working directory). "Diretório" é o nome técnico de pasta.

Quando você abre o terminal, ele começa na sua pasta pessoal: /home/ana para a Ana. A pasta pessoal tem um apelido curto: ~ (til).

O prompt do Arch mostra só o nome da pasta

O texto antes do cursor é o prompt. No Arch ele vem definido no arquivo ~/.bashrc como PS1='[\u@\h \W]\$ ':

$ pwd
/home/ana
PedaçoVem deSignificado
[ … ]texto fixoOs colchetes são só enfeite: é o estilo do Arch.
ana\u (user)Quem está usando o terminal.
@notebook\h (host)O nome da máquina. "@" se lê "em".
~\W (working directory)O nome da pasta atual, só o último pedaço do caminho.
$\$Você é um usuário comum. Vira # quando você é o root.

O detalhe importante é o \W maiúsculo: ele mostra só o nome da pasta, não o caminho todo. Dentro de /home/ana/Documentos/projetos, o prompt mostra apenas [ana@notebook projetos]$. Se existir outra pasta chamada projetos em outro lugar, o prompt fica igualzinho. Por isso, no Arch, o pwd é o jeito de ter certeza de onde você está.

Vindo do Debian ou do Ubuntu?

Lá o prompt é ana@notebook:~/Documentos/projetos$, com o caminho inteiro (\w minúsculo). No Arch é [ana@notebook projetos]$. Os comandos são os mesmos; só o prompt é mais curto. Você pode mudar isso no ~/.bashrc (veja Bash/Prompt customization na Arch Wiki).

pwd: onde estou?

pwd vem de print working directory, "mostre o diretório de trabalho". Ele escreve o caminho absoluto da pasta atual, ou seja, o caminho completo, a partir da raiz /.

pwd
Mostra o caminho completo da pasta em que o terminal está. Não precisa de nada depois.
$ pwd
/home/ana                    « a raiz /, a pasta home, a pasta ana
$ echo $?
0                            « código de saída 0: deu certo

O echo $? mostra o código de saída do comando anterior: 0 quer dizer sucesso, e qualquer outro número quer dizer erro. Você vai usá-lo nesta aula para conferir o que o cd fez, já que ele não escreve nada quando dá certo.

pwd -P: o lugar de verdade

Algumas "pastas" são, na verdade, atalhos para outras (o nome técnico é link simbólico; veja Links (ln)). Quando você entra por um atalho, o pwd mostra o atalho. Com -P (de physical, "físico") ele mostra o destino real.

No Arch, /bin é um atalho para /usr/bin, a pasta onde ficam os programas:

$ cd /bin
$ pwd
/bin                         « o caminho por onde você entrou
$ pwd -P
/usr/bin                     « onde você realmente está

O ls -ld (que você vai conhecer na aula ls) mostra esses atalhos. A seta -> aponta para o destino:

$ ls -ld /bin /sbin /lib /lib64 /usr/sbin
lrwxrwxrwx 1 root root 7 12 out  2025 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 12 out  2025 /lib -> usr/lib
lrwxrwxrwx 1 root root 7 12 out  2025 /lib64 -> usr/lib
lrwxrwxrwx 1 root root 7 12 out  2025 /sbin -> usr/bin       « no Arch, até o /sbin aponta para /usr/bin
lrwxrwxrwx 1 root root 3 12 out  2025 /usr/sbin -> bin

Repare na última linha: no Arch, /sbin e /usr/sbin também levam a /usr/bin. Todos os programas moram numa pasta só. Em outras distribuições, /sbin costuma ser uma pasta separada. A aula Estrutura de Diretórios explica para que serve cada pasta da raiz.

cd: mudar de pasta

cd vem de change directory, "mudar de diretório". Ele leva o terminal para outra pasta.

cd
O comando que troca a pasta atual.
Documentos
O destino. Pode ser um caminho relativo (a partir de onde você está) ou absoluto (começando com /).
$ cd Documentos
$ pwd
/home/ana/Documentos
$ ls
acesso.log  alunos.csv  notas.txt  projetos  relatorio.odt

Três coisas para reparar:

  1. O cd não mostrou nada. No Linux, silêncio quer dizer sucesso.
  2. O que mudou foi o prompt: de [ana@notebook ~]$ para [ana@notebook Documentos]$.
  3. Agora o ls lista a pasta nova, e não mais a pasta pessoal.

Por curiosidade: o cd e o pwd não são programas guardados em /usr/bin; eles fazem parte do próprio Bash. Faz sentido: só o próprio shell pode mudar a pasta em que ele mesmo está.

$ type cd pwd
cd é um comando interno do shell
pwd é um comando interno do shell

Caminho relativo e caminho absoluto

Há duas formas de dizer para onde ir. A aula Caminhos aprofunda o assunto; aqui vai o essencial para o cd.

TipoComeça comParte deExemplo
Absoluto/A raiz do sistema. Funciona de qualquer lugar.cd /etc/pacman.d
Relativoqualquer outra coisaA pasta atual. Depende de onde você está.cd projetos

Um caminho relativo pode ter vários níveis, separados por /:

$ cd Documentos/projetos/site
$ pwd
/home/ana/Documentos/projetos/site

E um caminho absoluto leva para qualquer lugar, não importa onde você esteja. Aqui a Ana vai para a pasta de configuração dos espelhos do pacman (assunto da aula Espelhos):

$ cd /etc/pacman.d
$ pwd
/etc/pacman.d
$ ls
gnupg  mirrorlist

Dois nomes especiais: . e ..

Toda pasta tem duas entradas escondidas: . (um ponto) é a própria pasta, e .. (dois pontos) é a pasta de cima, a "pasta-mãe".

cd
Mudar de pasta…
..
…para a pasta de cima.
$ cd ..
$ pwd
/etc

Os dois pontos se combinam com outros nomes. ../.. sobe dois níveis; ../Downloads sobe um e entra em Downloads:

$ cd Documentos/projetos
$ cd ../..
$ pwd
/home/ana
$ cd Documentos/projetos/site
$ cd ../../../Downloads              « sobe três níveis e entra em Downloads
$ pwd
/home/ana/Downloads

Já cd . não sai do lugar: "vá para a pasta onde você já está". O ponto é mais útil em outros comandos, como ./script.sh ("o script desta pasta").

Atalhos do cd

Para casa: cd, cd ~ e cd "$HOME"

O cd sem nada depois leva para a sua pasta pessoal. É o "botão de voltar para casa": se você se perder, digite cd e Enter.

$ cd
$ pwd
/home/ana

O ~ também quer dizer "minha pasta pessoal", e pode ser o começo de um caminho maior:

$ cd ~/Downloads
$ pwd
/home/ana/Downloads

Quem troca o ~ por /home/ana é o Bash, antes de chamar o cd. Ele faz o mesmo com ~ana (a pasta pessoal da usuária ana) e com a variável $HOME:

$ echo $HOME
/home/ana
$ cd ~ana
$ pwd
/home/ana

Para a pasta anterior: cd -

O cd - (hífen) volta para a pasta em que você estava antes, como o botão "voltar" do navegador. Diferente do cd comum, ele mostra para onde foi:

$ cd /etc/pacman.d
$ cd ..
$ pwd
/etc
$ cd -
/etc/pacman.d                « voltou e avisou
$ cd -
/etc                         « dois cd - seguidos alternam entre as duas pastas
$ echo $OLDPWD
/etc/pacman.d

A pasta anterior fica guardada na variável OLDPWD (old PWD, "o PWD antigo"). O cd - é o mesmo que cd "$OLDPWD".

Para a raiz: cd /

$ cd /
$ pwd
/
$ ls
bin   dev  home  lib64       mnt  proc  run   srv  tmp  var
boot  etc  lib   lost+found  opt  root  sbin  sys  usr

Na raiz o prompt vira [ana@notebook /]$, porque o nome da pasta é a própria barra.

Missão 1: vá até /etc/pacman.d e confira com pwd. Depois volte para a sua pasta pessoal e, por fim, retorne a /etc/pacman.d usando cd -. Repare como o prompt muda a cada passo.

Missão 2: você está em /usr/share. Com um único cd, entre em site, que fica dentro de projetos, que fica dentro de Documentos, na sua pasta pessoal. Dica: comece o caminho com ~.

Nomes com espaço

A pasta "Área de trabalho" tem dois espaços no nome. Para o Bash, o espaço separa as partes de um comando. Então cd Área de trabalho vira um cd com três destinos: "Área", "de" e "trabalho". O cd aceita um só, e reclama:

$ cd Área de trabalho
bash: cd: número excessivo de argumentos
$ echo $?
2

Há três jeitos de dizer ao Bash que o espaço faz parte do nome. Todos funcionam igual:

$ cd "Área de trabalho"
$ pwd
/home/ana/Área de trabalho
$ cd ..
$ cd Área\ de\ trabalho
$ pwd
/home/ana/Área de trabalho
FormaComo funcionaQuando usar
cd "Área de trabalho"Aspas duplas juntam tudo num nome sóO jeito mais fácil de ler
cd 'Área de trabalho'Aspas simples fazem o mesmo, e desligam também $ e ~Nomes com $ ou !
cd Área\ de\ trabalhoA barra invertida "protege" o espaço seguinteÉ o que o Tab escreve para você
cd Ár + TabO Bash completa o nome sozinhoSempre: evita erros de digitação
Use o Tab

Digite o começo do nome e aperte Tab: o Bash completa o resto, já com as barras invertidas e a / do fim. Se houver mais de uma opção, aperte Tab duas vezes para ver a lista. Além de economizar digitação, o Tab é um teste: se ele não completa, o nome não existe ali.

As aspas não podem cobrir o til

cd "~/Área de trabalho" não funciona: entre aspas, o ~ é só um til, e o Bash procura uma pasta chamada literalmente ~. Deixe o til de fora das aspas: cd ~/"Área de trabalho". A aula de aspas do Guia Bash explica o porquê.

Missão 3: entre na pasta Área de trabalho. Tente primeiro sem aspas e leia o erro. Depois use aspas, ou digite cd Ár e aperte Tab.

pushd e popd: uma pilha de pastas

O cd - lembra só uma pasta. Quando você precisa visitar algumas pastas e depois voltar exatamente para onde estava, use uma pilha: uma lista em que o último que entra é o primeiro que sai, como uma pilha de pratos.

pushd
De push directory, "empurrar diretório": guarda a pasta atual no topo da pilha e vai para outra.
/etc
O destino.
$ pushd /etc
/etc ~/Documentos                « a pilha: a pasta atual vem primeiro
$ pushd /var/log
/var/log /etc ~/Documentos
$ dirs -v
 0  /var/log                     « 0 = onde você está agora
 1  /etc
 2  ~/Documentos
$ popd
/etc ~/Documentos                « tirou /var/log e voltou para /etc
$ popd
~/Documentos
$ pwd
/home/ana/Documentos
popd
De pop directory, "tirar diretório": tira a pasta do topo da pilha e volta para a próxima.
dirs -v
Mostra a pilha sem mudar de pasta; o -v (de verbose) põe uma pasta por linha, numerada.

Quando a pilha acaba, o popd avisa e devolve o código 1:

$ popd
bash: popd: pilha de diretórios está vazia
$ echo $?
1

Missão 4: você está em ~/Documentos. Com pushd, visite /etc e depois /var/log. Veja a pilha com dirs -v e volte para Documentos só com popd.

Quando não funciona

"Arquivo ou diretório inexistente" 
$ cd documentos
bash: cd: documentos: Arquivo ou diretório inexistente
$ echo $?
1

O que aconteceu: não existe pasta com esse nome a partir de onde você está. Aqui o problema é a maiúscula: o Linux diferencia documentos de Documentos. Também pode ser erro de digitação ou você estar na pasta errada.

Como confirmar: rode pwd (estou onde penso?) e ls (o nome é esse mesmo?).

Como resolver: digite o começo do nome e use Tab para completar.

"Não é um diretório" 
$ cd frutas.txt
bash: cd: frutas.txt: Não é um diretório
$ cd .bashrc
bash: cd: .bashrc: Não é um diretório

O que aconteceu: o nome existe, mas é um arquivo, e o cd só entra em pastas.

Como confirmar: ls -l frutas.txt: se a linha começa com -, é arquivo; com d, é pasta (veja ls).

Como resolver: para ver o conteúdo de um arquivo, use cat ou less (veja cat, less, head, tail).

"Permissão negada" 
$ cd /root
bash: cd: /root: Permissão negada
$ echo $?
1
$ ls -ld /root
drwxr-x--- 3 root root 4096 16 out 13:05 /root

O que aconteceu: a pasta existe, mas você não tem permissão para entrar. /root é a pasta pessoal do administrador, e o drwxr-x--- diz que só o dono (root) e o grupo root podem entrar; a ana não é nenhum dos dois. As pastas pessoais em /home também são fechadas no Arch: o useradd -m as cria com modo 700 (drwx------), só o dono entra.

Como resolver: pense se você precisa mesmo entrar ali. Se precisar, abra um shell de root com sudo -i e saia com exit quando terminar (veja sudo, root e Usuários). As letras rwx são explicadas em Entendendo Permissões.

"número excessivo de argumentos" 
$ cd /etc /tmp
bash: cd: número excessivo de argumentos

O que aconteceu: o cd aceita um destino só, e recebeu dois. É o mesmo erro do cd Área de trabalho sem aspas.

Como resolver: passe um destino só; nomes com espaço vão entre aspas.

"pilha de diretórios está vazia" / "nenhum outro diretório" 
$ popd
bash: popd: pilha de diretórios está vazia
$ pushd
bash: pushd: nenhum outro diretório

O que aconteceu: o popd não tem para onde voltar, porque nada foi guardado com pushd. O pushd sem destino troca as duas pastas do topo da pilha, e aqui só havia uma.

Como resolver: use dirs -v para ver a pilha antes. Para simplesmente voltar, cd -.

Missão 5: provoque de propósito os erros acima: cd nada, cd /root e cd frutas.txt. Leia cada mensagem e confira o código com echo $?. Termine dentro de /var/log.

Exercícios

1. Voltar para casa

Qual comando, com duas letras, leva você para a sua pasta pessoal de qualquer lugar?

2. Pasta anterior

Complete para voltar à pasta em que você estava antes:

cd

3. Nome com espaço

Complete para entrar na pasta Área de trabalho:

cd

4. O prompt mostra [ana@notebook projetos]$. O que você sabe com certeza?

5. Você deu cd /sbin. O que pwd -P mostra no Arch?

6. Você está em /home/ana/Documentos/projetos. Para onde leva cd ../../Downloads?

Resumo

  • O prompt do Arch ([ana@notebook Documentos]$) mostra só o nome da pasta; o pwd mostra o caminho completo.
  • pwd -P ignora atalhos: no Arch, /bin e /sbin levam a /usr/bin.
  • cd muda de pasta e não mostra nada quando dá certo; o prompt muda e o código de saída é 0.
  • cd sozinho vai para casa, cd .. sobe, cd - volta (e mostra para onde).
  • Nomes com espaço precisam de aspas, de \ ou do Tab.
  • pushd/popd guardam pastas numa pilha; dirs -v mostra a pilha.
  • Os erros dizem exatamente o problema: inexistente, "não é um diretório", permissão ou argumentos demais.

Na Arch Wiki: o cd e o pwd fazem parte do Bash, descrito em Bash; lá estão a seção Use directory stack to navigate (a pilha do pushd/popd), a do Tab completion e a do "cd automático" (Auto "cd" when entering just a path). Para mudar o prompt [\u@\h \W]\$, veja Bash/Prompt customization. A visão geral dos comandos básicos está em Core utilities (em português: Core utilities (Português)).
