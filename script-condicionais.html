Arch Condicionais

Até agora seus scripts faziam sempre a mesma coisa, linha após linha. Com condicionais, o script passa a tomar decisões: "se o pacote está instalado, mostre a versão; senão, avise". "Se o pacman está travado, pare". Esta aula mostra o if e seus parceiros, parte por parte, com perguntas que você faz ao seu Arch todo dia.

Você vai aprender
  • Por que o if do Bash testa comandos (como pacman -Qi), e não "verdadeiro ou falso".
  • Como usar [ ], [[ ]] e (( )) para testar arquivos, textos e números.
  • Quando trocar o if por &&, || ou case.
  • Ler códigos de saída com vários significados, como os do checkupdates (0, 1 e 2).
  • Os erros mais comuns: "faltando `]'", "esperava operador unário" e "esperava número inteiro".

Antes, leia Primeiro Script e Variáveis e Argumentos. Os exemplos rodam na máquina notebook, com a usuária ana; as saídas vêm de um Arch Linux real.

A ideia: todo comando diz se deu certo

Você já viu que todo comando devolve um código de saída: 0 quando deu certo e outro número quando deu errado. O if do Bash usa exatamente isso. Ele roda um comando e olha o código:

  • Código 0 → o if considera verdadeiro e executa o bloco do then.
  • Qualquer outro código → falso: pula para o else, se existir.

O pacman -Qi (query info) é um ótimo exemplo: ele responde com 0 se o pacote está instalado e com 1 se não está.

$ pacman -Qi htop > /dev/null
$ echo $?
0                                                   « instalado = verdadeiro
$ pacman -Qi firefox > /dev/null
erro: o pacote "firefox" não foi encontrado
$ echo $?
1                                                   « não instalado = falso

O > /dev/null joga fora a ficha do pacote (só queremos o código). Mas a mensagem de erro ainda apareceu: ela sai por outro canal, a saída de erros. Para calar as duas, acrescente 2>&1 (veja Redirecionamento):

$ pacman -Qi firefox > /dev/null 2>&1
$ echo $?
1                                                   « nenhuma mensagem, só o código
Ao contrário de outras linguagens

Em Python ou JavaScript, 0 significa "falso". No shell é o oposto: 0 significa sucesso. Pense em "zero problemas".

A estrutura do if

if COMANDO; then
  comandos se COMANDO deu certo
fi
if
"Se". Começa a decisão.
pacman -Qi htop > /dev/null 2>&1
O comando testado, sem mostrar nada na tela. Só o código importa.
; then
"Então". O ; separa o comando do then quando estão na mesma linha.
echo "o htop está instalado"
O que fazer quando o comando deu certo.
; fi
Fim do if. fi é if ao contrário.
$ if pacman -Qi htop > /dev/null 2>&1; then echo "o htop está instalado"; fi
o htop está instalado
$ if pacman -Qi firefox > /dev/null 2>&1; then echo "o firefox está instalado"; fi
$ echo $?
0

Na segunda vez, nada apareceu: o pacman devolveu 1, e o if pulou o echo. Repare que o echo $? mostra 0: um if sem else que não executou nada termina com sucesso.

Em scripts, escrevemos em várias linhas, com o bloco indentado (recuado com espaços), e acrescentamos o else ("senão"), que roda quando o comando falha:

#!/usr/bin/env bash
pacote="$1"

if pacman -Qi "$pacote" > /dev/null 2>&1; then
  echo "O $pacote está instalado."
else
  echo "O $pacote NÃO está instalado."
fi
$ ./instalado.sh htop
O htop está instalado.
$ ./instalado.sh firefox
O firefox NÃO está instalado.

O mesmo vale para o systemctl: systemctl is-active --quiet nginx não mostra nada (--quiet) e devolve 0 se o serviço está rodando. Então if systemctl is-active --quiet nginx; then … lê-se "se o nginx está ativo, então…" (veja systemctl e Serviços).

Testar condições: o comando [ ]

E quando você quer perguntar "este arquivo existe?" ou "este número é maior que 30?". Para isso existe o comando test, que tem um apelido: [. Isso mesmo: o colchete é um comando, e também responde só com o código de saída.

$ type [
[ é um comando interno do shell
$ test -f /etc/pacman.conf
$ echo $?
0                                                   « o pacman.conf existe e é um arquivo
$ [ -e /var/lib/pacman/db.lck ]
$ echo $?
1                                                   « não há trava do pacman: ótimo
[
O comando de teste (o mesmo que test).
-e
O tipo de teste: "existe" (exists).
/var/lib/pacman/db.lck
O que está sendo testado. Com variáveis, sempre entre aspas: "$arquivo".
]
Fecha o teste. É obrigatório e precisa de espaço antes.
Espaços são obrigatórios

Como [ é um comando, ele precisa de espaço depois, e o ] é o último argumento, com espaço antes. [-f arq] e [ -f arq] dão erro. O certo é [ -f arq ].

Um teste numérico clássico: "estou rodando como root?". A variável $EUID guarda o número do usuário efetivo; o root é sempre 0:

$ echo $EUID
1000
$ [ "$EUID" -eq 0 ] && echo "sou root" || echo "sou um usuário comum"
sou um usuário comum
Para números, -gt; nunca > dentro de [ ]

Dentro de [ ], o > é um redirecionamento. Veja o estrago:

$ if [ 3 > 5 ]; then echo "3 é maior que 5?!"; fi
3 é maior que 5?!                                   « resposta errada…
$ ls 5
5                                                   « …e ainda criou um arquivo chamado "5"

O > 5 mandou a saída do teste para um arquivo "5", e o teste que sobrou ([ 3 ]) é sempre verdadeiro. Use [ 3 -gt 5 ] ou (( 3 > 5 )).

Várias saídas: elif e else

elif é a junção de else if, "senão, se". O Bash testa de cima para baixo e executa só o primeiro bloco verdadeiro. Um script que aconselha você sobre a atualização, conforme a quantidade de pacotes pendentes:

#!/usr/bin/env bash
qtd="$1"

if [ "$qtd" -eq 0 ]; then
  echo "Sistema em dia."
elif [ "$qtd" -lt 30 ]; then
  echo "$qtd atualizações: pode rodar o pacman -Syu."
else
  echo "$qtd atualizações: leia as notícias do archlinux.org antes."
fi
$ ./atualizacoes.sh 0
Sistema em dia.
$ ./atualizacoes.sh 12
12 atualizações: pode rodar o pacman -Syu.        « 12 não é 0, mas é < 30
$ ./atualizacoes.sh 30
30 atualizações: leia as notícias do archlinux.org antes.

Por que ler as notícias? Porque, de vez em quando, uma atualização grande do Arch pede uma ação manual, anunciada em archlinux.org/news (veja Atualizar o Sistema).

Formas diferentes de testar

O Bash tem vários jeitos de escrever um teste. Todos funcionam; cada um tem seu ponto forte.

[[ ]]: o teste moderno do Bash

O colchete duplo é uma palavra-chave do Bash (não um comando). Ele aceita variáveis sem aspas, && e || por dentro e comparação com curingas:

$ kernel=$(uname -r)
$ if [[ $kernel == *lts ]]; then echo "kernel LTS"; else echo "kernel padrão: $kernel"; fi
kernel padrão: 7.2.10-arch1-1
$ if [[ -f /etc/pacman.conf && -r /etc/pacman.conf ]]; then echo "posso ler o pacman.conf"; fi
posso ler o pacman.conf

O *lts é um curinga: "qualquer coisa terminada em lts". Quem iniciou com o kernel linux-lts veria "kernel LTS" (veja Kernels). Com =~, o [[ ]] compara com uma expressão regular: [[ $qtd =~ ^[0-9]+$ ]] pergunta "só tem dígitos?".

(( )): contas e comparações de números

Dentro de (( )), os sinais > < == funcionam como na matemática, sem $ nas variáveis:

$ aur=$(pacman -Qqm | wc -l)
$ if (( aur > 0 )); then echo "Você tem $aur pacotes do AUR"; fi
Você tem 4 pacotes do AUR

&& e ||: o if de uma linha

Para decisões curtas, você nem precisa do if:

pacman -Q yay-bin > /dev/null
Primeiro comando: o yay-bin está instalado?
&& echo "yay instalado"
"E então": só roda se o anterior deu certo.
|| echo "sem yay"
"Ou então": só roda se o anterior deu errado.
$ pacman -Q yay-bin > /dev/null && echo "yay instalado" || echo "sem yay"
yay instalado
$ [ -d ~/backups ] || mkdir ~/backups                « cria só se não existir
$ mkdir ~/backups && echo "pasta criada" || echo "falhou"
mkdir: não foi possível criar o diretório “/home/ana/backups”: Arquivo existe
falhou

Por fim, rode mkdir ~/backups && echo ok || echo "já existe" e veja qual mensagem aparece. (O simulador também entende um if … ; then … ; fi numa linha só: tente if pacman -Qi htop > /dev/null 2>&1; then echo sim; fi.)

Escolher entre muitas opções: case

Quando uma variável pode ter vários valores, uma fila de elif fica longa. O case ("caso") compara o valor com uma lista de padrões. Um exemplo: traduzir a resposta do systemctl is-active, que é uma palavra em inglês (active, inactive, failed…):

#!/usr/bin/env bash
servico="${1:-sshd}"
estado=$(systemctl is-active "$servico")

case "$estado" in
  active)
    echo "$servico: rodando"
    ;;
  inactive)
    echo "$servico: parado"
    ;;
  failed)
    echo "$servico: FALHOU (veja: journalctl -u $servico)"
    ;;
  *)
    echo "$servico: estado '$estado'"
    ;;
esac
case "$estado" in
"No caso do valor de $estado…"
active)
Um padrão. O ) fecha o padrão. Vários padrões se juntam com | ("ou"): activating|reloading).
;;
Fim deste caso. O case para aqui.
*)
Qualquer outra coisa (o "senão" do case). Fica sempre por último.
esac
Fim do case (case ao contrário).
$ ./estado.sh
sshd: rodando                                       « sem argumento: o padrão sshd
$ ./estado.sh nginx
nginx: parado

Os padrões aceitam curingas: *.pkg.tar.zst) pega pacotes, [sS]|[sS]im) pega "s", "S", "sim" e "Sim".

Quando o código tem vários significados: o checkupdates

Nem todo comando usa só "0 = deu certo, resto = deu errado". O checkupdates, do pacote pacman-contrib, consulta os espelhos sem mexer no banco de dados do pacman (por isso é seguro, ao contrário de um pacman -Sy solto) e usa três códigos:

CódigoSignificado no checkupdates
0Há atualizações (a lista sai na tela, uma por linha).
1Erro: não conseguiu consultar (sem internet, espelho fora do ar…).
2Nenhuma atualização: o sistema está em dia. Não mostra nada.
$ checkupdates
$ echo $?
2                                                   « silêncio + 2 = está tudo em dia

Se você testasse com um simples if checkupdates, o "em dia" (2) cairia no mesmo lugar que o "erro" (1). Com case, cada código ganha a sua resposta:

#!/usr/bin/env bash
lista=$(checkupdates)
codigo=$?

case $codigo in
  0) echo "Há $(wc -l <<< "$lista") atualização(ões):"
     echo "$lista" ;;
  2) echo "Nada para atualizar." ;;
  *) echo "Não consegui verificar (código $codigo)." >&2
     exit 1 ;;
esac
lista=$(checkupdates)
Guarda a lista. Depois de uma atribuição com $( ), o $? é o código do comando de dentro.
codigo=$?
Guarda o código já, na linha seguinte: qualquer outro comando trocaria o $?.
wc -l <<< "$lista"
Conta as linhas do texto da variável (o <<< entrega o texto ao wc).
>&2
Manda a mensagem para a saída de erros, como fazem os comandos de verdade.
$ ./verifica-updates.sh
Nada para atualizar.
$ CHECKUPDATES_DB=/proc/nao-existe ./verifica-updates.sh
mkdir: não foi possível criar o diretório “/proc/nao-existe”: Arquivo ou diretório inexistente
==> ERROR: Cannot fetch updates
Não consegui verificar (código 1).

Na segunda execução, provocamos o erro de propósito, dando ao checkupdates uma pasta impossível para o banco temporário. Sem internet, a linha ==> ERROR: Cannot fetch updates (em inglês, como todo o pacman-contrib) e o código 1 são os mesmos. Quando há atualizações, cada linha da lista tem a forma pacote versão-instalada -> versão-nova, como no pacman -Qu.

O checkupdates não funciona no terminal simulado (ele precisa da internet); experimente na sua máquina, depois de sudo pacman -S pacman-contrib.

Exemplo completo: é uma boa hora para atualizar?

Este script junta o que você aprendeu. Antes de você rodar o sudo pacman -Syu, ele confere quatro coisas, e cada problema devolve um código diferente:

#!/usr/bin/env bash
# antes-de-atualizar — confere se é uma boa hora para o pacman -Syu

if [ "$EUID" -eq 0 ]; then
  echo "Rode como usuário comum, não como root." >&2
  exit 1
fi

if [ -e /var/lib/pacman/db.lck ]; then
  echo "Erro: o pacman está travado (/var/lib/pacman/db.lck)." >&2
  exit 2
fi

livre=$(df --output=avail -m / | tail -1)
if (( livre < 2048 )); then
  echo "Erro: só $livre MiB livres na raiz; libere espaço antes." >&2
  exit 3
fi

if ! command -v checkupdates > /dev/null; then
  echo "Erro: instale o pacman-contrib (sudo pacman -S pacman-contrib)." >&2
  exit 4
fi

lista=$(checkupdates)
case $? in
  0) echo "Há $(wc -l <<< "$lista") atualização(ões). Pode rodar: sudo pacman -Syu" ;;
  2) echo "Nada para atualizar." ;;
  *) echo "Erro: não consegui consultar os espelhos." >&2
     exit 5 ;;
esac
  • [ "$EUID" -eq 0 ]: o root tem EUID 0. Rodar tudo como root é um mau hábito; o script recusa.
  • [ -e /var/lib/pacman/db.lck ]: outro pacman está rodando, ou um travamento antigo ficou para trás (veja pacman).
  • df --output=avail -m / mostra só o espaço livre, em MiB, com um cabeçalho (Disp.) que o tail -1 descarta. (( livre < 2048 )) pede pelo menos 2 GiB.
  • ! command -v checkupdates: o ! inverte. "Se o checkupdates não existe…".
  • Cada exit tem um número diferente, para quem chamou o script saber o que houve.
$ df --output=avail -m /
Disp.
18717
$ antes-de-atualizar
Nada para atualizar.
$ echo $?
0

Quando não funciona

"faltando `]'" 
$ if [ -f /etc/pacman.conf]; then echo ok; fi
bash: [: faltando `]'

O que aconteceu: faltou o espaço antes do ]. O [ recebeu /etc/pacman.conf] como uma palavra só e não achou o ] de fechamento.

Como resolver: espaço dos dois lados: [ -f /etc/pacman.conf ].

"[a: comando não encontrado" 
$ if ["a" = "a"]; then echo ok; fi
bash: [a: comando não encontrado

O que aconteceu: sem espaço depois do [, o Bash procurou um comando chamado [a.

Como resolver: [ "a" = "a" ].

"esperava operador unário" 
$ nome=""
$ if [ $nome = "ana" ]; then echo oi; fi
bash: [: =: esperava operador unário

O que aconteceu: a variável estava vazia e sem aspas. O teste virou [ = "ana" ], que não faz sentido.

Como resolver: sempre coloque variáveis entre aspas dentro de [ ]: [ "$nome" = "ana" ]. Ou use [[ ]], que não tem esse problema.

"esperava número inteiro" 
$ ./atualizacoes.sh doze
./atualizacoes.sh: linha 4: [: doze: esperava número inteiro
./atualizacoes.sh: linha 6: [: doze: esperava número inteiro
doze atualizações: leia as notícias do archlinux.org antes.

O que aconteceu: -eq e -lt só comparam números inteiros. Com "doze", os dois testes deram erro (código 2, que conta como falso), e o script caiu no else. Repare que ele não parou: deu uma resposta errada.

Como resolver: valide a entrada antes. Por exemplo: [[ $qtd =~ ^[0-9]+$ ]] || { echo "Digite um número" >&2; exit 1; }.

"erro de sintaxe próximo ao token inesperado `fi'" 
$ if [ "ana" = "ana" ] then echo oi; fi
bash: erro de sintaxe próximo ao token inesperado `fi'

O que aconteceu: faltou o ; antes do then. Na mesma linha, o Bash precisa dele para saber onde o teste termina.

Como resolver: if [ … ]; then …; fi. Em várias linhas, o then pode ir na linha de baixo, sem ;.

O if pacman -Qi … funciona, mas suja a tela com "erro: o pacote … não foi encontrado"

O que aconteceu: você calou só a saída normal (> /dev/null); a mensagem de erro vai pela saída de erros.

Como resolver: > /dev/null 2>&1 (ou &> /dev/null, a forma curta do Bash).

systemctl is-active deu "verdadeiro" com um serviço parado 
$ systemctl is-active sshd nginx
active
inactive
$ echo $?
0

O que aconteceu: com vários serviços, o is-active devolve 0 se pelo menos um estiver ativo. E um nome que não existe (systemctl is-active xyz) responde inactive (código 4, "unidade desconhecida"), como se fosse um serviço parado.

Como resolver: teste um serviço por vez (num laço, veja Laços), e confira o nome com systemctl status antes.

O terminal mostra > e não responde 
$ if [ -f /etc/pacman.conf ]; then echo ok
>

O que aconteceu: o if não foi fechado com fi. O > é o Bash pedindo o resto do comando.

Como resolver: digite fi e Enter, ou cancele com Ctrl+C.

Exercícios

1. A pasta existe?

Complete para escrever "achei" se ~/aur for uma pasta:

if [ ~/aur ]; then echo "achei"; fi

2. Pacote instalado?

Complete o comando que responde só com o código (0 = instalado):

if pacman htop > /dev/null 2>&1; then echo "tem htop"; fi

3. Fechando o if

Complete a palavra que encerra o bloco:

if [ -z "$1" ]; then echo "faltou o pacote";

4. Criar só se faltar

Complete para criar a pasta logs apenas se ela não existir:

[ -d logs ] mkdir logs

5. O checkupdates não mostrou nada e echo $? deu 2. O que isso quer dizer?

6. Por que [ 3 > 5 ] é perigoso?

Resumo

  • O if roda um comando: código 0 é verdadeiro, qualquer outro é falso. pacman -Qi e systemctl is-active --quiet são perguntas prontas.
  • [ ] é um comando: precisa de espaços e de variáveis entre aspas.
  • Arquivos: -e -f -d -s -x -L; textos: = != -z -n; números: -eq -ne -lt -le -gt -ge.
  • [[ ]] é o teste mais seguro no Bash; (( )) é o melhor para números.
  • && e || fazem decisões de uma linha; case organiza muitas opções, inclusive códigos como os do checkupdates (0, 1, 2).

Para ir mais fundo: no Guia Bash, veja if, testes, case, códigos de saída e operadores.
