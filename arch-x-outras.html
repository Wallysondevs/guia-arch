Arch × Debian × Fedora

Toda distribuição Linux usa o mesmo kernel e quase os mesmos programas. O que muda é a receita: quando as versões novas chegam, como os pacotes são feitos, o que vem ligado de fábrica e quem decide. Esta aula compara o Arch com as três distribuições que você mais vai encontrar, para você saber traduzir um tutorial de uma para outra e escolher com consciência.

Você vai aprender
  • As diferenças de ciclo, pacotes, instalador e padrões entre Arch, Debian, Fedora e Ubuntu.
  • Traduzir comandos de pacotes entre pacman, apt e dnf.
  • O que acontece "depois do install" em cada uma (serviços, firewall, MAC).
  • O que Manjaro, EndeavourOS e CachyOS mudam em relação ao Arch.

Como o Arch se descreve

O próprio sistema conta quem ele é no arquivo /etc/os-release, que existe em todas as distribuições com systemd:

$ cat /etc/os-release
NAME="Arch Linux"
PRETTY_NAME="Arch Linux"
ID=arch                                     « o "código" da distribuição (debian, fedora, ubuntu…)
BUILD_ID=rolling                            « não há número de versão: é rolling release
ANSI_COLOR="38;2;23;147;209"
HOME_URL="https://archlinux.org/"
DOCUMENTATION_URL="https://wiki.archlinux.org/"
SUPPORT_URL="https://bbs.archlinux.org/"
BUG_REPORT_URL="https://gitlab.archlinux.org/groups/archlinux/-/issues"
PRIVACY_POLICY_URL="https://terms.archlinux.org/docs/privacy-policy/"
LOGO=archlinux-logo

Repare na falta de VERSION_ID: no Debian você veria VERSION_ID="13"; no Ubuntu, algo como VERSION_ID="26.04". O Arch não tem versões, só o estado de hoje. Scripts usam o ID= para saber em que distribuição estão.

Missão: descubra qual é o ID desta distribuição lendo o arquivo que a descreve.

A diferença que mais morde quem vem do Debian/Ubuntu

No Arch, pacman -S nginx instala e não liga. Você viu isso na prática em Servidor Web: o nginx fica inactive (dead), disabled; preset: disabled até o systemctl enable --now. Tutoriais de Ubuntu pulam esse passo porque lá o serviço já sobe na instalação. Na VM do guia, só 8 unidades estão habilitadas, quase todas por decisão explícita na instalação:

$ systemctl list-unit-files --state=enabled --no-legend
getty@.service                     enabled enabled
NetworkManager-dispatcher.service  enabled disabled
NetworkManager-wait-online.service enabled disabled
NetworkManager.service             enabled disabled
sshd.service                       enabled disabled
systemd-userdbd.socket             enabled enabled
remote-fs.target                   enabled enabled
snapper-timeline.timer             enabled disabled

A terceira coluna é o preset, a política da distribuição: no Arch quase tudo é disabled, e quem ligou foi o administrador (a segunda coluna).

Pacotes: poucos, e só os que você pediu

$ pacman -Q | wc -l
408                                         « pacotes instalados ao todo
$ pacman -Qe | wc -l
45                                          « instalados explicitamente (o resto são dependências)
$ pacman-conf --repo-list
core
extra
$ pacman -Sl core | wc -l
299
$ pacman -Sl extra | wc -l
15031

São 408 pacotes nesta VM sem interface gráfica, com tudo o que as aulas usam. Os repositórios oficiais ativos são só dois: core (o básico) e extra (todo o resto, cerca de 15 mil pacotes). O multilib (programas de 32 bits, como o Steam) existe mas vem desligado no /etc/pacman.conf. Uma instalação mínima do Debian já passa de 300 pacotes; uma do Ubuntu Desktop passa de 1.500.

A armadilha da tradução literal

apt update é seguro sozinho, mas o equivalente no Arch, pacman -Sy, não é: atualizar a lista e depois instalar um pacote sem atualizar o resto (pacman -Sy pacote) cria uma atualização parcial, que o Arch não suporta. No Arch, o -y anda sempre com o -u: pacman -Syu. Veja Atualizar o Sistema.

Derivadas do Arch: o que muda

Várias distribuições usam o Arch como base e mudam algumas peças. Elas usam pacman e quase todo este guia vale para elas, mas os fóruns do Arch não dão suporte a derivadas: lá, pergunte só sobre o Arch.

Conclusão prática: o EndeavourOS é "Arch com instalador"; o CachyOS é "Arch com otimizações"; o Manjaro é uma distribuição à parte que usa o pacman. Saber o Arch puro (o que este guia ensina) torna fácil usar qualquer uma delas.

Quando não funciona

"Segui um tutorial de Ubuntu e o serviço não responde"

O que aconteceu: o tutorial supõe que a instalação liga o serviço.

Como confirmar: systemctl status SERVIÇO mostra inactive (dead) e disabled.

Como resolver: sudo systemctl enable --now SERVIÇO.

"erro: o pacote "build-essential" não foi encontrado"

O que aconteceu: o nome do pacote é de outra distribuição.

Como resolver: procure o equivalente (pacman -Ss, pacman -F arquivo) ou use a tabela "Outros nomes que mudam". Aqui: base-devel.

"sudo: ana não está no arquivo sudoers" depois de "adicionar ao grupo sudo"

O que aconteceu: no Arch o grupo é wheel, e o sudo nem vem instalado na base.

Como resolver: veja sudo, root e Usuários.

Resumo

  • Arch: rolling, mínimo, serviços desligados até você ligar, sem firewall nem MAC ativos.
  • Debian: estável e conservador; Fedora: novo e seguro de fábrica; Ubuntu: popular, com Snap.
  • pacman -Syu / -S / -Rns / -Ss / -Qo ≈ apt upgrade / install / purge / search ≈ dnf upgrade / install / remove / search.
  • Nomes mudam: wheel, http, base-devel, .pacnew, mkinitcpio.
  • Manjaro tem repositórios próprios; EndeavourOS e CachyOS usam os do Arch (o CachyOS soma os seus otimizados).
