Arch Caminhos

Um caminho é o endereço de um arquivo ou de uma pasta na árvore que começa em /. Todo comando que mexe em arquivos recebe caminhos: ls, cd, cp, nano, até o pacman -Qo. Saber escrevê-los é a diferença entre "funcionou" e "Arquivo ou diretório inexistente".

Você vai aprender
  • A diferença entre caminho absoluto e relativo, e o que é a pasta atual.
  • Por que, no Arch, o pwd é mais importante que o prompt.
  • Os atalhos ~, ~ana, ., .. e -.
  • Como escrever nomes com espaço, como "Área de trabalho".
  • Como o Tab escreve caminhos por você.

Esta aula usa a árvore que você conheceu em Estrutura de Diretórios. Uma parte da pasta pessoal da Ana, desenhada pelo tree (o -F marca as pastas com / e os executáveis com *; o -I esconde as pastas que não interessam aqui):

A ideia: endereço completo ou "a partir daqui"

Pense num endereço de entrega. Você pode dizer o endereço completo ("Rua das Flores, 10, Recife") ou dar uma direção a partir de onde a pessoa está ("a segunda casa à direita"). No terminal é igual:

TipoComeça comExemploFunciona de qualquer pasta?
Absoluto//home/ana/Documentos/notas.txtSim
RelativoQualquer outra coisaDocumentos/notas.txtNão: depende de onde você está

A pasta atual

O "onde você está" se chama pasta atual (ou diretório de trabalho, working directory). Todo terminal está sempre "dentro" de alguma pasta; ao abrir, é a sua pasta pessoal. O pwd (de print working directory) mostra qual é, com o caminho absoluto:

$ pwd
/home/ana
O prompt do Arch só mostra o último nome

O prompt padrão do Arch (PS1='[\u@\h \W]\$ ') mostra só o nome da pasta atual, não o caminho. Estando em /home/ana/Documentos/projetos/site, você vê [ana@notebook site]$; estando em /srv/http, [ana@notebook http]$. Se houver duas pastas site em lugares diferentes, o prompt fica igual. Na dúvida, rode pwd. (A pasta pessoal aparece como ~; veja O Terminal no Arch.)

$ pwd
/home/ana/Documentos/projetos/site

Caminho absoluto

Um caminho absoluto começa na raiz / e desce pasta por pasta até o alvo. Cada / separa uma pasta da próxima.

/
A raiz: o começo de tudo.
home/
Dentro da raiz, a pasta home.
ana/
Dentro de home, a pasta da Ana.
Documentos/notas.txt
Dentro dela, a pasta Documentos e o arquivo.

Como ele não depende da pasta atual, funciona de qualquer lugar. Aqui a Ana está em /etc/pacman.d e mesmo assim acha o arquivo. O wc -l conta as linhas (de word count, lines):

$ wc -l /home/ana/Documentos/notas.txt
4 /home/ana/Documentos/notas.txt

Os caminhos que você vê nas aulas de administração são quase todos absolutos: /etc/pacman.conf, /var/log/pacman.log, /boot/grub/grub.cfg. Assim eles valem não importa onde você esteja.

Missão: você está em /etc/pacman.d. Sem sair daí, conte as linhas do arquivo notas.txt da pasta Documentos da Ana usando um caminho absoluto.

Caminho relativo

Um caminho relativo não começa com /. O sistema junta a pasta atual com o que você escreveu. Estando em /home/ana, o caminho Documentos/notas.txt vira /home/ana/Documentos/notas.txt:

$ wc -l Documentos/notas.txt
4 Documentos/notas.txt

O mesmo caminho relativo, digitado em outra pasta, aponta para outro lugar e falha:

$ wc -l Documentos/notas.txt
wc: Documentos/notas.txt: Arquivo ou diretório inexistente      « procurou /etc/pacman.d/Documentos/notas.txt
Quando usar cada um

Relativo é mais curto e prático quando você está perto do arquivo. Absoluto é mais seguro em scripts, em serviços do systemd e em tarefas agendadas, porque não depende de onde o comando foi chamado.

Missão: este script entra em /tmp e depois tenta contar as linhas das notas da Ana com um caminho relativo, que lá não existe. Corrija o caminho para que funcione de qualquer pasta e clique em Rodar; a última linha deve ser 4.

#!/usr/bin/env bash
cd /tmp
echo "Linhas das notas:"
wc -l < Documentos/notas.txt

#!/usr/bin/env bash
cd /tmp
echo "Linhas das notas:"
wc -l < ~/Documentos/notas.txt

O til: ~ e ~usuário

Quem troca o ~ pelo caminho é o shell, antes de o comando rodar. O echo mostra o resultado da troca:

$ echo ~
/home/ana
$ echo ~ana
/home/ana
$ echo ~root
/root                                « a casa do root não fica em /home
$ ls ~root
ls: não foi possível abrir o diretório '/root': Permissão negada
$ echo ~naoexiste
~naoexiste                           « usuário inexistente: o til fica como está

Repare que o ls ~root mostrou o erro com /root: o ls nem viu o til, recebeu o caminho já trocado.

O ponto: . e ..

Toda pasta tem duas entradas escondidas: . (ela mesma) e .. (a mãe). Elas aparecem no ls -a. O . é usado principalmente para rodar um programa da pasta atual (./backup.sh), porque o shell não procura programas na pasta atual por conta própria.

Subindo com ..

Cada .. sobe um nível. Dá para encadear:

cd
Muda de pasta (de change directory; veja pwd e cd).
../..
Sobe dois níveis: da pasta atual para a mãe, e da mãe para a avó.
$ cd Documentos/projetos
$ pwd
/home/ana/Documentos/projetos
$ cd ../..
$ pwd
/home/ana

Na raiz não há para onde subir: cd .. em / continua em /, sem erro.

$ cd ..
$ pwd
/

Missão: você está em ~/Documentos/projetos/site (o prompt mostra só site). Suba até ~/Documentos usando um caminho relativo, com ... Confira com pwd.

Voltando com -

O cd - volta para a pasta em que você estava antes, e mostra para onde foi. É ótimo para alternar entre duas pastas, como a sua e a de configuração:

$ cd /etc/pacman.d
$ cd -
/home/ana
$ cd -
/etc/pacman.d

A pasta anterior fica guardada na variável $OLDPWD.

Missão: você acabou de sair de /etc/pacman.d e voltou para a sua pasta. Volte para lá sem digitar o caminho.

Combinando

Os atalhos podem aparecer no meio do caminho. Estando em ~/Documentos/projetos/site, estes dois caminhos apontam para o mesmo arquivo:

$ ls ~/frutas.txt ../../../frutas.txt
../../../frutas.txt  /home/ana/frutas.txt

O ls mostra os dois nomes como recebeu: um já com o ~ trocado, o outro relativo. Para ver o caminho absoluto "limpo" de qualquer caminho, use realpath:

$ realpath Documentos/../Imagens/./ferias.jpg
/home/ana/Imagens/ferias.jpg

Nomes com espaço

O espaço separa as partes de um comando. Por isso um nome como "Área de trabalho" vira três argumentos se for digitado sem cuidado:

$ cd Área de trabalho
bash: cd: número excessivo de argumentos

Há duas formas de dizer ao shell que é um nome só:

FormaExemploObservação
Aspascd 'Área de trabalho'A mais legível; simples ou duplas
Barra invertidacd Área\ de\ trabalhoÉ o que o Tab escreve para você
$ cd 'Área de trabalho'
$ pwd
/home/ana/Área de trabalho

O prompt, nesse momento, fica [ana@notebook Área de trabalho]$. A explicação completa das aspas está em Sintaxe dos Comandos.

Missão: entre na pasta Área de trabalho. Tente primeiro sem aspas para ver o erro, depois do jeito certo.

Maiúsculas importam

Para o Linux, Documentos e documentos são nomes diferentes:

$ ls documentos
ls: não foi possível acessar 'documentos': Arquivo ou diretório inexistente

As pastas pessoais em português (Documentos, Imagens, Música…) começam com maiúscula e têm acentos. As pastas do sistema (/etc, /usr, /var) são todas minúsculas.

Deixe o Tab escrever

Digite o começo de um nome e aperte Tab. Se só houver uma possibilidade, o shell completa sozinho. Se houver várias, aperte Tab duas vezes para ver a lista. O Tab evita erros de digitação e já põe as barras invertidas nos nomes com espaço.

$ cd Do        « aqui você aperta Tab duas vezes
Documentos/  Downloads/
$ cd Doc       « mais uma letra e Tab: vira "cd Documentos/"

(O Tab é uma tecla, não uma saída de comando; a lista acima mostra o que aparece na máquina do guia, cujos nomes que começam com Do são Documentos e Downloads.)

No Arch, o Tab "esperto" é um pacote à parte

Sem nada instalado, o Tab do Bash completa nomes de comandos e de arquivos. O pacote bash-completion o ensina a completar também opções e argumentos: pacman -S fireTab vira firefox, systemctl status ngiTab vira nginx.service. Ele não vem no base; na máquina do guia foi instalado junto com os pacotes das aulas, e o /etc/bash.bashrc do Arch o carrega sozinho quando existe:

$ pacman -Q bash-completion
bash-completion 2.18.0-1
$ grep -n bash_completion /etc/bash.bashrc
23:if [[ -r /usr/share/bash-completion/bash_completion ]]; then
24:  . /usr/share/bash-completion/bash_completion

Para ter o mesmo: sudo pacman -S bash-completion e abra um terminal novo.

Quando não funciona

"Arquivo ou diretório inexistente" com um caminho que existe

O que aconteceu: quase sempre é um caminho relativo digitado na pasta errada (lembre: o prompt do Arch só mostra o último nome), ou uma maiúscula trocada.

Como resolver: rode pwd para ver onde você está e ls para ver os nomes exatos. Na dúvida, use o caminho absoluto, o ~ ou o Tab.

"número excessivo de argumentos" no cd 
$ cd Área de trabalho
bash: cd: número excessivo de argumentos

O que aconteceu: o nome tem espaço e o shell o dividiu em três.

Como resolver: use aspas: cd "Área de trabalho".

"Não é um diretório" 
$ cd Documentos/notas.txt
bash: cd: Documentos/notas.txt: Não é um diretório

O que aconteceu: o cd só entra em pastas, e notas.txt é um arquivo.

Como resolver: para ler o arquivo, use cat ou less (veja cat, less, head, tail); para entrar na pasta dele, cd Documentos.

O ~ não funcionou dentro de aspas 
$ ls "~/Documentos"
ls: não foi possível acessar '~/Documentos': Arquivo ou diretório inexistente

O que aconteceu: dentro de aspas o ~ perde o significado especial e vira um til comum.

Como resolver: deixe o til fora das aspas, ls ~/"Documentos", ou use a variável "$HOME/Documentos", que funciona dentro de aspas duplas.

"Permissão negada" ao seguir um caminho 
$ ls ~root
ls: não foi possível abrir o diretório '/root': Permissão negada

O que aconteceu: o caminho está certo, mas a pasta é fechada para você.

Como resolver: se precisar mesmo, sudo ls /root (veja sudo, root e Usuários).

Resumo

  • Absoluto começa com / e funciona de qualquer lugar; relativo parte da pasta atual.
  • O prompt do Arch só mostra o nome da pasta; o caminho completo vem do pwd.
  • ~ é sua pasta pessoal (~root é /root), . é a atual, .. é a de cima e cd - volta para a anterior.
  • Nomes com espaço vão entre aspas ou com \; o ~ não funciona dentro de aspas (use $HOME).
  • Maiúsculas importam. Use o Tab; com o pacote bash-completion, ele completa até pacotes e serviços.
