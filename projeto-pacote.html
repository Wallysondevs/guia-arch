Projeto: Empacotar um Programa Seu

Neste laboratório você pega um programa de verdade, o tarefas (uma lista de afazeres no terminal, escrita em Bash), e faz todo o caminho que um empacotador do Arch faz: preparar um lançamento, escrever o PKGBUILD, compilar, testar, corrigir o que o namcap e os testes apontarem, instalar, pôr num repositório seu e, por fim, ver como seria publicá-lo no AUR. Tudo foi feito na VM do guia; os erros que aparecem no caminho são reais.

O que você vai praticar
  • Preparar um programa para ser empacotado (--help, --version, licença, lançamento .tar.gz).
  • Escrever um PKGBUILD com check() e package() (veja Escrever um PKGBUILD).
  • Corrigir avisos do namcap e um teste que falha de verdade.
  • Instalar com pacman -U e servir num repositório local.
  • O caminho (ilustrativo) para publicar no AUR.
Antes de começar

Você precisa de base-devel, pacman-contrib (para o updpkgsums) e namcap: sudo pacman -S --needed base-devel pacman-contrib namcap. Na VM, o trabalho foi feito em /tmp/a5/projeto; no seu PC, use algo como ~/projetos.

Etapa 1: o programa

O tarefas é o projeto final do Guia Bash, com duas mudanças para virar pacote: aceita --help e --version (o costume dos programas de terminal) e declara a licença MIT.

  1. A pasta do projeto tem o programa, o completar do Bash (para a tecla Tab sugerir os comandos), a licença e um README: 
    $ ls -l
total 16
-rw-r--r-- 1 ana ana 1060 16 out 13:32 LICENSE
-rw-r--r-- 1 ana ana  115 16 out 13:32 README
-rwxr-xr-x 1 ana ana 3224 16 out 13:32 tarefas
-rw-r--r-- 1 ana ana  481 16 out 13:32 tarefas.bash
  2. O programa, completo: 
    #!/usr/bin/env bash
# tarefas — uma lista de tarefas guardada num arquivo de texto.
# Licença: MIT. Requer bash 4.0+.
set -euo pipefail

readonly VERSAO=1.0
readonly PROG=${0##*/}
arquivo=${TAREFAS_ARQUIVO:-${XDG_DATA_HOME:-$HOME/.local/share}/tarefas/tarefas.txt}

uso() {
  cat <<FIM
Uso: $PROG [-f ARQUIVO] COMANDO [ARGUMENTOS]

Comandos:
  add TEXTO...   acrescenta uma tarefa
  list [-a]      mostra as tarefas pendentes (-a: todas)
  done N         marca a tarefa N como feita
  rm N           apaga a tarefa N

Opções:
  -f ARQUIVO     usa outro arquivo (padrão: $arquivo)
  -h, --help     mostra esta ajuda
  -V, --version  mostra a versão

Códigos de saída: 0 = ok, 1 = erro, 2 = uso errado.
FIM
}

erro()       { printf '%s: %s\n' "$PROG" "$*" >&2; }
falhar()     { erro "$*"; exit 1; }
uso_errado() { erro "$*"; echo "Tente '$PROG --help'." >&2; exit 2; }

# confere que $1 é o número de uma tarefa que existe
validar_numero() {
  local n=$1 total
  [[ $n =~ ^[1-9][0-9]*$ ]] || uso_errado "número de tarefa inválido: '$n'"
  total=$(wc -l < "$arquivo")
  (( n <= total )) || falhar "não existe a tarefa $n (a lista tem $total)"
}

cmd_add() {
  (( $# > 0 )) || uso_errado "add: falta o texto da tarefa"
  printf '[ ] %s\n' "$*" >> "$arquivo"
  echo "Tarefa $(wc -l < "$arquivo") adicionada: $*"
}

cmd_list() {
  local todas=0 opt OPTIND=1
  while getopts ':a' opt; do
    case $opt in
      a) todas=1 ;;
      *) uso_errado "list: opção inválida: -$OPTARG" ;;
    esac
  done
  local n=0 pendentes=0 linha
  while IFS= read -r linha; do
    n=$(( n + 1 ))
    if [[ $linha == '[ ] '* ]]; then
      pendentes=$(( pendentes + 1 ))
      printf '%3d  [ ] %s\n' "$n" "${linha#'[ ] '}"
    elif (( todas )); then
      printf '%3d  %s\n' "$n" "$linha"
    fi
  done < "$arquivo"
  if (( pendentes == 0 && ! todas )); then
    echo "Nenhuma tarefa pendente."
  fi
}

cmd_done() {
  (( $# == 1 )) || uso_errado "done: informe um número (ex.: $PROG done 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  [[ $linha == '[ ] '* ]] || falhar "a tarefa $1 já estava feita"
  sed -i "${1}s/^\[ \]/[x]/" "$arquivo"
  echo "Feito: ${linha#'[ ] '}"
}

cmd_rm() {
  (( $# == 1 )) || uso_errado "rm: informe um número (ex.: $PROG rm 2)"
  validar_numero "$1"
  local linha
  linha=$(sed -n "${1}p" "$arquivo")
  sed -i "${1}d" "$arquivo"
  echo "Apagada: ${linha:4}"
}

main() {
  case ${1-} in
    --help)    uso; exit 0 ;;
    --version) echo "$PROG $VERSAO"; exit 0 ;;
  esac

  local opt
  while getopts ':f:hV' opt; do
    case $opt in
      f)  arquivo=$OPTARG ;;
      h)  uso; exit 0 ;;
      V)  echo "$PROG $VERSAO"; exit 0 ;;
      :)  uso_errado "a opção -$OPTARG precisa de um valor" ;;
      \?) uso_errado "opção inválida: -$OPTARG" ;;
    esac
  done
  shift $(( OPTIND - 1 ))
  (( $# > 0 )) || { uso >&2; exit 2; }

  mkdir -p -- "$(dirname -- "$arquivo")"
  touch -- "$arquivo"

  local comando=$1
  shift
  case $comando in
    add)       cmd_add "$@" ;;
    list|ls)   cmd_list "$@" ;;
    done)      cmd_done "$@" ;;
    rm)        cmd_rm "$@" ;;
    help)      uso ;;
    *)         uso_errado "comando desconhecido: '$comando'" ;;
  esac
}

main "$@"

    O que importa para o empacotamento: o arquivo começa com #!/usr/bin/env bash (roda de qualquer pasta), guarda os dados em ~/.local/share/tarefas/ (nunca dentro de /usr, que é do pacman), tem uma variável TAREFAS_ARQUIVO para trocar o arquivo (vai ser útil nos testes) e devolve códigos de saída diferentes para erro (1) e uso errado (2).

  3. Teste à mão, antes de empacotar qualquer coisa. Para não sujar a sua lista de verdade, use um arquivo de teste com a variável: 
    $ ./tarefas --help

Opções:

Etapa 2: o lançamento

Um pacote não empacota "a pasta onde estou trabalhando": empacota uma versão lançada, um arquivo fixo que todo mundo pode baixar e conferir pela soma. No GitHub, isso é o .tar.gz de uma release. Aqui, fazemos o nosso:

  1. Crie o arquivo do lançamento com a pasta no nome tarefas-1.0 (o costume: nome-versão), dentro da pasta onde ficará a receita: 
    $ cp -r tarefas tarefas-1.0
$ tar -czvf pacote-tarefas/tarefas-1.0.tar.gz tarefas-1.0

Etapa 3: o PKGBUILD

  1. Escreva a receita na pasta pacote-tarefas, com as somas vazias (esta é a primeira versão, que vai precisar de duas correções): 
    # Maintainer: Ana <ana@notebook>
pkgname=tarefas
pkgver=1.0
pkgrel=1
pkgdesc="Lista de tarefas no terminal, guardada num arquivo de texto"
arch=('any')
url="https://example.com/tarefas"
license=('MIT')
depends=('bash' 'coreutils' 'sed')
source=("$pkgname-$pkgver.tar.gz")
sha256sums=()

check() {
  cd "$pkgname-$pkgver"
  export TAREFAS_ARQUIVO="$srcdir/teste.txt"
  ./tarefas --version
  ./tarefas add "Testar o pacote"
  ./tarefas done 1
}

package() {
  cd "$pkgname-$pkgver"
  install -Dm755 tarefas "$pkgdir/usr/bin/tarefas"
  install -Dm644 tarefas.bash "$pkgdir/usr/share/bash-completion/completions/tarefas"
  install -Dm644 README "$pkgdir/usr/share/doc/$pkgname/README"
  install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
}

    Dois tipos de aviso:

    • "Description should not contain the package name": a descrição diz "Lista de tarefas…", e o nome já aparece ao lado dela em toda listagem. Procede: vamos reescrever.
    • "Dependency included, but may not be needed": o namcap só "enxerga" bibliotecas e o interpretador de scripts; ele não vê que o script chama sed e wc pelo nome. Aqui é falso alarme: o programa usa os dois, então eles ficam.

Etapa 5: instalar

  1. Instale com pacman -U. Na VM, o pacman mostrou o resumo e a resposta foi "n": 
    #> pacman -U /tmp/a5/projeto/pacote-tarefas/tarefas-1.0-1-any.pkg.tar.zst
carregando pacotes...
resolvendo dependências...
procurando pacotes conflitantes...

Pacotes (1) tarefas-1.0-1

Tamanho total instalado:  0,00 MiB

:: Continuar a instalação? [S/n]

    No seu PC: sudo pacman -U tarefas-1.0-1-any.pkg.tar.zst e S.

  2. Confira como qualquer pacote (ilustrativo, na VM não foi instalado): tarefas --version de qualquer pasta, pacman -Qi tarefas, pacman -Qo /usr/bin/tarefas, e tarefas d + Tab completando para done (abra um terminal novo para o completar carregar). Para remover: sudo pacman -R tarefas; a sua lista em ~/.local/share/tarefas fica, porque não é do pacote.

Etapa 7: publicar no AUR (ilustrativo)

Nada desta etapa foi feito de verdade

O tarefas é um exemplo de aula: publicá-lo poluiria o AUR, que é de todos. Os comandos abaixo mostram o caminho real, para quando você tiver um programa útil para outras pessoas. Leia antes as regras de envio: o pacote não pode já existir (nem nos repositórios oficiais), precisa ser útil para mais gente e não pode conter binários compilados por você.

  1. Publique o código num lugar público (GitHub, Codeberg, GitLab) e crie a release v1.0. O AUR só guarda a receita; o source precisa apontar para um endereço que qualquer um baixe. A linha muda para algo como: 
    url="https://github.com/ana/tarefas"
source=("$pkgname-$pkgver.tar.gz::$url/archive/refs/tags/v$pkgver.tar.gz")

    O nome::endereço diz ao makepkg com que nome salvar o download. Depois disso, updpkgsums (a soma muda, porque o arquivo agora é o do GitHub), makepkg, namcap e .SRCINFO de novo.

  2. Crie a conta em aur.archlinux.org ("Register") e uma chave SSH só para o AUR: 
    ssh-keygen -t ed25519 -f ~/.ssh/aur -C "ana@aur"
cat ~/.ssh/aur.pub          # cole esta linha em "My Account" → "SSH Public Key"

    E diga ao SSH para usar essa chave com o AUR:

    Host aur.archlinux.org
  IdentityFile ~/.ssh/aur
  User aur
  3. Clone o repositório (vazio) do nome escolhido. No AUR, o pacote é criado no primeiro push: 
    git -c init.defaultBranch=master clone ssh://aur@aur.archlinux.org/tarefas.git aur-tarefas
cd aur-tarefas
cp ../pacote-tarefas/PKGBUILD ../pacote-tarefas/.SRCINFO .
git add PKGBUILD .SRCINFO
git commit -m "Versão inicial: tarefas 1.0-1"
git push

    Só entram a receita, o .SRCINFO e arquivos pequenos de que a receita precisa (patches, um .install). Nada de .tar.gz, .pkg.tar.zst, src/ ou pkg/: crie um .gitignore como o do yay-bin. O branch tem que ser master, e o servidor recusa o push se o .SRCINFO estiver faltando.

  4. Cuide do pacote. A cada versão nova do programa: pkgver=1.1, pkgrel=1, updpkgsums, makepkg (de preferência num chroot limpo, veja AUR com Segurança), namcap, makepkg --printsrcinfo > .SRCINFO, git commit e git push. Responda os comentários; se não puder mais manter, use "Disown Package" para deixá-lo órfão em vez de abandoná-lo.

Desafios

1. Versão 1.1

Você corrigiu um bug no tarefas e lançou a 1.1. Como ficam as duas variáveis?

pkgver= pkgrel=

2. Só a receita

Você esqueceu de instalar o README e corrigiu só o package(). Qual o novo pkgrel (era 1)?

pkgrel=

3. Por que o check() passou na primeira vez e falhou na terceira?

4. Para publicar no AUR, o que vai no repositório git do pacote?

Para ir além: acrescente uma página de manual (tarefas.1) instalada em /usr/share/man/man1/ (o makepkg a comprime sozinho, a fase "Comprimindo páginas de man"); escreva um hook que avise quando o tarefas for atualizado; compile num chroot limpo com extra-x86_64-build.

Resumo

  • Prepare o programa: --help, --version, dados fora de /usr, licença, lançamento nome-versão.tar.gz.
  • PKGBUILD com check() que não depende de sobras de rodadas anteriores.
  • namcap: corrija o que procede, entenda os falsos alarmes.
  • .SRCINFO sempre atualizado; pacman -U para testar; repo-add para distribuir em casa.
