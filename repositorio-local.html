Seu Próprio Repositório

Um repositório do pacman não tem mágica: é uma pasta com pacotes e um arquivo de índice que diz o que tem lá. Com o comando repo-add você transforma qualquer pasta de .pkg.tar.zst num repositório; com três linhas no pacman.conf, o pacman passa a instalar e atualizar seus pacotes como se fossem do Arch, em quantos computadores você quiser.

Você vai aprender
  • Como um repositório é organizado (o .db e os pacotes).
  • Criar e atualizar o índice com repo-add e repo-remove.
  • A seção [meurepo] do pacman.conf, e testá-la sem mexer no sistema.
  • Servir o repositório pela rede (HTTP) e assiná-lo com GPG.
  • Para que isso serve: vários PCs, cache dos pacotes do AUR, seus próprios programas.

Como é um repositório por dentro

Quando você roda pacman -Sy, o pacman baixa de cada espelho um arquivo por repositório, o NOME.db, e guarda em /var/lib/pacman/sync:

$ ls -l /var/lib/pacman/sync
total 60516
-rw-r--r-- 1 root root   130987 16 out 09:43 core.db          « índice do core (130 KB)
-rw-r--r-- 1 root root  1527139 16 out 09:43 core.files       « lista de arquivos (para pacman -F)
drwx------ 2 alpm alpm     4096 16 out 12:53 download-la4D31
-rw-r--r-- 1 root root  8888740 16 out 11:13 extra.db
-rw-r--r-- 1 root root 51411977 16 out 11:13 extra.files

O .db é um arquivo compactado com uma pasta por pacote, cada uma com os dados (nome, versão, dependências, soma). Os pacotes em si ficam no espelho, na mesma pasta do .db, e só são baixados quando você instala. O endereço vem do pacman.conf:

$ grep -n -A1 "^\[core\]" /etc/pacman.conf
78:[core]
79-Include = /etc/pacman.d/mirrorlist
$ grep -m1 "^Server" /etc/pacman.d/mirrorlist
Server = https://mirror.ufscar.br/archlinux/$repo/os/$arch

O $repo vira o nome entre colchetes (core) e o $arch, x86_64. Ou seja: para ter um repositório, basta uma pasta com os pacotes e um NOME.db, e um [NOME] no pacman.conf apontando para ela.

1. Juntar os pacotes

Vamos usar os dois pacotes feitos nas aulas anteriores: o ola (de Escrever um PKGBUILD) e o tarefas (do projeto). Na VM, a pasta de testes é /tmp/a5; no seu PC, algo como ~/repo.

$ mkdir -p /tmp/a5/repo
$ cp /tmp/a5/ola/ola-1.0-1-any.pkg.tar.zst /tmp/a5/projeto/pacote-tarefas/tarefas-1.0-1-any.pkg.tar.zst /tmp/a5/repo/
$ cd /tmp/a5/repo
$ ls
ola-1.0-1-any.pkg.tar.zst  tarefas-1.0-1-any.pkg.tar.zst
Mande o makepkg entregar os pacotes direto lá

Com PKGDEST=~/repo no seu ~/.config/pacman/makepkg.conf (veja makepkg), todo pacote que você compilar, do AUR ou seu, vai parar nessa pasta.

3. Dizer ao pacman: a seção [meurepo]

No /etc/pacman.conf, depois das seções do Arch, acrescente (exemplo, com a pasta em /home/ana/repo):

[meurepo]
SigLevel = Optional TrustAll
Server = file:///home/ana/repo
LinhaSignificado
[meurepo]O nome. Tem que bater com o meurepo.db da pasta.
SigLevel = Optional TrustAllAssinaturas: confere se existirem (Optional), e aceita qualquer chave conhecida (TrustAll). Para um repositório só seu, na sua máquina, é o comum. Com assinatura (abaixo), use Required.
Server = file:///…Onde está a pasta: file:// + caminho absoluto (por isso três barras). Pela rede: http://… ou https://….

A ordem das seções importa: se dois repositórios têm um pacote com o mesmo nome, ganha o que vem primeiro. No final, os do Arch têm prioridade; antes do [core], os seus "passam na frente" (útil para substituir um pacote oficial por uma versão sua, mas perigoso).

Testar sem mexer no sistema

Dá para conferir o repositório antes de mexer no /etc/pacman.conf de verdade. O pacman aceita outro arquivo de configuração (--config) e outra pasta de dados (--dbpath); assim nada do sistema é tocado. Foi assim que testamos na VM, com este arquivo:

# /tmp/a5/pacman-meurepo.conf — um pacman.conf só para testar o repositório
[options]
Architecture = auto

[meurepo]
SigLevel = Optional TrustAll
Server = file:///tmp/a5/repo
#> mkdir -p /tmp/a5/db
#> pacman --config /tmp/a5/pacman-meurepo.conf --dbpath /tmp/a5/db -Sy
:: Sincronizando a base de dados de pacotes...

Depois de pôr a seção no /etc/pacman.conf de verdade, o uso é o de sempre (ilustrativo; na VM não instalamos): sudo pacman -Syu (atualiza os índices e o sistema) e depois sudo pacman -S tarefas. Lembre da regra da aula Atualizar o Sistema: nada de -Sy sem o u.

Atualizar o repositório

Compilou uma versão nova? Copie o pacote para a pasta e rode o repo-add de novo, só com ele: a entrada antiga é trocada. Com -R, o repo-add também apaga o arquivo da versão antiga. Para tirar um pacote do índice, repo-remove com o nome (sem versão). Numa cópia do repositório:

$ repo-remove meurepo.db.tar.gz ola
==> Extraindo meurepo.db.tar.gz para um local temporário...
==> Extraindo meurepo.files.tar.gz para um local temporário...
==> Procurando o pacote 'ola'...
  -> Removendo entrada existente 'ola-1.0-1'...
==> Criando arquivo atualizado da base de dados 'meurepo.db.tar.gz'
$ tar -tzf meurepo.db.tar.gz
tarefas-1.0-1/
tarefas-1.0-1/desc
$ repo-add -n meurepo.db.tar.gz *.pkg.tar.zst
==> Extraindo meurepo.db.tar.gz para um local temporário...
==> Extraindo meurepo.files.tar.gz para um local temporário...
==> Adicionando o pacote 'ola-1.0-1-any.pkg.tar.zst'
  -> Computando somas de verificação...
  -> Criando a entrada de base de dados 'desc'...
  -> Criando a entrada de base de dados 'files'...
==> Adicionando o pacote 'tarefas-1.0-1-any.pkg.tar.zst'
==> ATENÇÃO: Uma entrada para 'tarefas-1.0-1' já existe      « o -n pula o que já está lá
==> Criando arquivo atualizado da base de dados 'meurepo.db.tar.gz'
ComandoO que faz

Servir pela rede

Para outros computadores usarem o repositório, sirva a pasta por HTTP. O jeito mais rápido, para um teste, é o servidor embutido do Python (rode na pasta do repositório):

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...

Em outro terminal (ou em outro PC, trocando 127.0.0.1 pelo IP desta máquina), um pacman.conf de teste com Server = http://127.0.0.1:8080 sincroniza pela rede:

#> pacman --config /tmp/a5/pacman-http.conf --dbpath /tmp/a5/db -Syy
:: Sincronizando a base de dados de pacotes...
 meurepo               618,0   B   604 KiB/s 00:00 [######################] 100%

E o servidor registra os pedidos:

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...
127.0.0.1 - - [16/Oct/2026 13:34:40] "GET /meurepo.db HTTP/1.1" 200 -
127.0.0.1 - - [16/Oct/2026 13:34:40] code 404, message File not found
127.0.0.1 - - [16/Oct/2026 13:34:40] "GET /meurepo.db.sig HTTP/1.1" 404 -

O pacman pediu o meurepo.db (200 = achou) e também o meurepo.db.sig (404 = não existe): com SigLevel = Optional, ele tenta a assinatura e segue sem ela. Ctrl+C para o servidor.

Para um servidor permanente, use o nginx (veja Servidor Web (nginx)). Um bloco mínimo (ilustrativo):

server {
    listen 8080;
    location /meurepo/ {
        alias /srv/meurepo/;      # a pasta com o .db e os pacotes
        autoindex on;             # lista os arquivos no navegador (opcional)
    }
}

E nos clientes: Server = http://IP-DO-SERVIDOR:8080/meurepo. Se o firewall estiver ligado, libere a porta (veja Firewall).

Assinar o repositório

Na rede, assine o índice e os pacotes com uma chave GPG sua. Assim os outros PCs só aceitam o que foi feito por você. Na VM, com uma chave de teste criada numa pasta temporária (a variável GNUPGHOME diz ao gpg qual chaveiro usar, para não misturar com o seu):

$ export GNUPGHOME=/tmp/a5/gnupg
$ gpg --list-secret-keys --keyid-format long

      A2AD0CFD89637E4B308F91F2E82E69CA4BA7D94E
uid               [   plena  ] Ana (repositório) <ana@notebook>

$ for p in *.pkg.tar.zst; do gpg --detach-sign "$p"; done

Nos clientes, a seção passa a exigir assinatura (SigLevel = Required), e o pacman precisa conhecer e confiar na sua chave. Sem isso, a sincronização falha. Saída real, com um pacman.conf de teste igual ao de cima, mas com Required, numa pasta de dados nova, respondendo n:

#> pacman --config /tmp/a5/p-sig.conf --dbpath /tmp/a5/db3 -Sy
:: Sincronizando a base de dados de pacotes...
 meurepo               618,0   B   604 KiB/s 00:00 [######################] 100%
erro: meurepo: a chave "A2AD0CFD89637E4B308F91F2E82E69CA4BA7D94E" é desconhecida
:: Importar a chave PGP A2AD0CFD89637E4B308F91F2E82E69CA4BA7D94E? [S/n] n
erro: falha ao sincronizar todas as bases de dados (base de dados inválida ou corrompida (assinatura PGP))

O jeito certo de confiar na chave, em cada cliente (ilustrativo; na VM não mexemos no chaveiro do pacman), é exportá-la do seu PC e importá-la no chaveiro do pacman (veja Chaves e Assinaturas):

gpg --export --armor A2AD0CFD89637E4B308F91F2E82E69CA4BA7D94E > meurepo.asc   # no PC que assina
sudo pacman-key --add meurepo.asc                                              # em cada cliente
sudo pacman-key --lsign-key A2AD0CFD89637E4B308F91F2E82E69CA4BA7D94E           # "eu confio nesta chave"
# e no pacman.conf do cliente:
# [meurepo]
# SigLevel = Required
# Server = http://192.168.0.10:8080/meurepo

Quando não funciona

"falha ao obter o arquivo "meurepo.db" … Could not open file" 
#> pacman --config /tmp/a5/p-erro.conf --dbpath /tmp/a5/db2 -Syy
:: Sincronizando a base de dados de pacotes...
 meurepo.db falhou em ser baixadoerro: falha ao obter o arquivo "meurepo.db" de disco : Could not open file /tmp/a5/naoexiste/meurepo.db
erro: falha ao sincronizar todas as bases de dados (erro na biblioteca de download)
#> echo $?
1

(Assim mesmo: o pacman cola o aviso do download e o erro na mesma linha. O p-erro.conf é o arquivo de teste com Server = file:///tmp/a5/naoexiste.)

O que aconteceu: o caminho do Server está errado, ou o nome entre colchetes não bate com o arquivo ([meurepo] procura meurepo.db).

Como resolver: confira com ls o caminho exato e o nome do .db. Lembre das três barras: file:///.

"a chave … é desconhecida"

O que aconteceu: o repositório é assinado e o chaveiro do pacman não conhece a chave.

Como resolver: pacman-key --add + pacman-key --lsign-key, como acima. Não responda S à pergunta de importar sem saber de quem é a chave.

"OSError: [Errno 98] Address already in use" 
$ python -m http.server 8080
Traceback (most recent call last):
…
OSError: [Errno 98] Address already in use

O que aconteceu: outro programa (talvez outro http.server esquecido) já usa a porta 8080.

Como resolver: feche o outro, ou use outra porta (python -m http.server 8081). Para ver quem usa a porta: ss -ltnp | grep 8080.

O pacote novo não aparece nos clientes

O que aconteceu: você copiou o pacote mas não rodou o repo-add, ou o cliente não sincronizou.

Como resolver: no servidor, repo-add; no cliente, sudo pacman -Syu. Para forçar o download do índice mesmo que pareça igual: -Syyu.

Resumo

  • Repositório = pasta com pacotes + NOME.db (feito pelo repo-add).
  • No pacman.conf: [NOME], SigLevel e Server; a ordem das seções define a prioridade.
  • Teste com --config e --dbpath antes de mexer no sistema.
  • Pela rede: python -m http.server para testar, nginx para ficar.
  • Na rede, assine (gpg --detach-sign, repo-add --sign) e use SigLevel = Required.
