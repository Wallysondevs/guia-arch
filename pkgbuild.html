Escrever um PKGBUILD

Até aqui você leu receitas dos outros. Agora vai escrever a sua. Um PKGBUILD é um script Bash com algumas variáveis (o que é o pacote) e algumas funções (como montá-lo). Com ele, qualquer programa (até um script seu de dez linhas) vira um pacote que o pacman instala, lista, atualiza e remove direitinho, sem arquivos esquecidos pelo sistema.

Você vai aprender
  • As variáveis de um PKGBUILD: pkgname pkgver pkgrel pkgdesc arch url license depends makedepends source sha256sums.
  • As funções prepare, build, check e package, e as pastas $srcdir e $pkgdir.
  • Gerar as somas com updpkgsums e o .SRCINFO com makepkg --printsrcinfo.
  • Conferir com namcap e testar a instalação com pacman -U.

Por que empacotar, se dá para copiar?

Você poderia copiar um script para /usr/local/bin e pronto. O problema aparece depois: em outra máquina você não lembra o que copiou; para remover, não sabe quais arquivos eram dele; e o pacman, que cuida de todo o resto do sistema, não sabe que aquilo existe. Um pacote resolve tudo isso:

Copiar à mãoPacote
Saber o que está instaladoSó lembrandopacman -Q ola, pacman -Ql ola
De quem é um arquivo?pacman -Qo /usr/bin/ola
RemoverCaçar os arquivossudo pacman -R ola
DependênciasVocê instala e esquece por quêDeclaradas e instaladas junto
Instalar em outro PCRepetir tudosudo pacman -U ola-1.0-1-any.pkg.tar.zst

O programa: ola

Vamos empacotar um script pequeno, ola, que cumprimenta alguém. O arquivo se chama ola.in porque ainda não está pronto: a versão está escrita como @VERSAO@ e o PKGBUILD vai trocar pelo número certo (o .in é uma convenção para "arquivo de entrada, a ser processado").

#!/usr/bin/env bash
# ola — diz olá no terminal (exemplo do Guia Arch)
versao=@VERSAO@

case ${1-} in
  -h|--help)
    echo "Uso: ola [NOME]"
    echo "Diz olá para NOME (sem NOME, para você)."
    exit 0 ;;
  -V|--version)
    echo "ola $versao"
    exit 0 ;;
esac

echo "Olá, ${1:-$USER}!"

Na mesma pasta fica um arquivo LICENSE com o texto da licença MIT (todo pacote deve instalar a licença do programa). A pasta de trabalho deste exemplo, na VM, é /tmp/a5/ola; use a que quiser, por exemplo ~/pacotes/ola.

O PKGBUILD completo

# Maintainer: Ana <ana@notebook>
pkgname=ola
pkgver=1.0
pkgrel=1
pkgdesc="Diz olá no terminal (exemplo do Guia Arch)"
arch=('any')
url="https://example.com/ola"
license=('MIT')
depends=('bash')
source=('ola.in' 'LICENSE')
sha256sums=('471492c49ecd1c40ec7cdc72a76dba60e315476bbb6d2fb88f8f3e3f1ba757da'
            '9c0aba2dd3610a99dbd3f3d14411293990385021d09ab087777faa0f68f41bb5')

prepare() {
  sed "s/@VERSAO@/$pkgver/" ola.in > ola
}

check() {
  bash -n ola
  test "$(bash ola Teste)" = "Olá, Teste!"
}

package() {
  install -Dm755 ola "$pkgdir/usr/bin/ola"
  install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
}

Vamos por partes.

As variáveis

VariávelNeste exemploPara que serve
pkgnameolaNome do pacote: minúsculas, números e @ . _ + -; não pode começar com - ou .
pkgver1.0Versão do programa (a do autor). Sem hífen.
pkgrel1Versão da receita. Volta a 1 quando o pkgver muda; sobe (2, 3…) quando só a receita mudou.
pkgdesc"Diz olá…"Descrição curta, uma linha. Não repita o nome do pacote nela (o namcap reclama).
arch('any')any para scripts e dados; ('x86_64') para programas compilados.
url…Site do programa.
license('MIT')Licença, com o nome padrão SPDX (MIT, GPL-3.0-or-later, Apache-2.0…).
depends('bash')O que precisa estar instalado para o programa rodar.
makedepends(não tem)O que só é preciso para compilar (ex.: ('cargo') no paru, ('go') no yay). Não precisa listar o que vem no base-devel.
optdepends(não tem)Opcionais, no formato 'pacote: para que serve'.
source('ola.in' 'LICENSE')Os arquivos de entrada. Nomes simples = arquivos ao lado do PKGBUILD; endereços https://… são baixados; git+https://… clona.
sha256sumsDuas somasUma por item de source, na mesma ordem.

Outras que você vai encontrar em receitas maiores: provides e conflicts (como no yay-bin, que "fornece" yay), backup (arquivos de configuração que o pacman preserva e transforma em .pacnew, veja .pacnew e .pacsave), install (o script .install), validpgpkeys (veja makepkg) e epoch (força uma versão a ser considerada mais nova, quando o autor muda o esquema de numeração).

As funções e as pastas

O makepkg chama as funções nesta ordem, cada uma dentro da pasta $srcdir (a src/, onde os arquivos de source foram colocados):

FunçãoPara quêNo ola
prepare()Ajustar o código antes de compilar: aplicar patches, trocar textosTroca @VERSAO@ por 1.0 e grava o resultado em ola
build()Compilar (./configure, make, cargo build…)Não tem: um script não se compila
check()Rodar os testes. Se falhar, o pacote não é criadoConfere a sintaxe (bash -n) e a saída
package()Obrigatória. Copiar os arquivos para $pkgdir, que imita a raiz / do sistemaInstala em $pkgdir/usr/bin/ola e a licença

Para um programa que se compila, o build() é onde o trabalho acontece. Um exemplo real, da receita do ncurses5-compat-libs no AUR (encurtado):

build() {
  cd "${srcdir}/${_pkgname}-${pkgver}"
  ./configure "${configure_options[@]}" --enable-widec
  make
}

package() {
  cd "${srcdir}/${_pkgname}-${pkgver}"
  make DESTDIR="$pkgdir" install.libs        # "instale, mas dentro de $pkgdir"
  install -Dm644 COPYING "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
}
install
Copia um arquivo já com a permissão certa (o comando install do coreutils, não o pacman).
-D
Cria as pastas do caminho de destino que não existirem.
-m755
Permissão do arquivo: 755 para programas (todos executam), 644 para dados e textos.
"$pkgdir/usr/bin/ola"
O destino dentro do pacote. Esquecer o $pkgdir é o erro clássico: o comando tentaria escrever no /usr/bin de verdade (e falharia, porque você não é root).
Onde os arquivos devem ir

Pacotes instalam em /usr (/usr/bin, /usr/share/…, /usr/lib), e configuração em /etc. Nunca em /usr/local (é seu, para coisas fora do pacman), /home, /opt sem motivo, ou /bin e /sbin (no Arch são atalhos para /usr/bin).

Um PKGBUILD é só Bash

O makepkg "carrega" o PKGBUILD com o Bash. Teste: o script abaixo tem as mesmas variáveis e monta o nome do arquivo que o makepkg vai criar.

Missão: você corrigiu só a receita, sem mudar o programa. Mude o que for preciso para o pacote novo se chamar ola-1.0-2-any.pkg.tar.zst e clique em Rodar.

#!/usr/bin/env bash
# as variáveis de um PKGBUILD são variáveis comuns do Bash
pkgname=ola
pkgver=1.0
pkgrel=1
arch=('any')

echo "Pacote: $pkgname-$pkgver-$pkgrel-${arch[0]}.pkg.tar.zst"

#!/usr/bin/env bash
# as variáveis de um PKGBUILD são variáveis comuns do Bash
pkgname=ola
pkgver=1.0
pkgrel=2
arch=('any')

echo "Pacote: $pkgname-$pkgver-$pkgrel-${arch[0]}.pkg.tar.zst"

Conferir: namcap

O namcap confere a receita e o pacote. Para o ola, nenhuma reclamação (silêncio = tudo certo):

$ namcap PKGBUILD
$ namcap ola-1.0-1-any.pkg.tar.zst
$ echo $?
0

Os avisos mais comuns ao escrever as primeiras receitas: Missing Maintainer tag (falta o comentário # Maintainer:), Description should not contain the package name, licença fora do padrão SPDX, e Dependency included, but may not be needed (que em scripts muitas vezes é um falso alarme). O projeto de empacotamento mostra alguns deles acontecendo de verdade.

O .SRCINFO

O .SRCINFO é o PKGBUILD "traduzido" para texto simples, para que programas (o site do AUR, o yay) leiam os dados sem executar Bash. Ele é gerado, nunca escrito à mão:

$ makepkg --printsrcinfo > .SRCINFO
$ cat .SRCINFO
pkgbase = ola
	pkgdesc = Diz olá no terminal (exemplo do Guia Arch)
	pkgver = 1.0
	pkgrel = 1
	url = https://example.com/ola
	arch = any
	license = MIT
	depends = bash
	source = ola.in
	source = LICENSE
	sha256sums = 471492c49ecd1c40ec7cdc72a76dba60e315476bbb6d2fb88f8f3e3f1ba757da
	sha256sums = 9c0aba2dd3610a99dbd3f3d14411293990385021d09ab087777faa0f68f41bb5

pkgname = ola

Só é obrigatório para publicar no AUR (o servidor recusa um envio sem ele, ou com ele desatualizado). Regere sempre que mudar o PKGBUILD.

Testar a instalação

Instale com pacman -U. Na VM do guia, a instalação foi só mostrada (o pacman respondeu "n" no fim):

#> pacman -U /tmp/a5/ola/ola-1.0-1-any.pkg.tar.zst
carregando pacotes...
resolvendo dependências...
procurando pacotes conflitantes...

Pacotes (1) ola-1.0-1

Tamanho total instalado:  0,00 MiB        « 1,32 KiB arredondado

Depois de instalar, tudo o que você aprendeu em pacman vale para ele: pacman -Qi ola, pacman -Qo /usr/bin/ola, sudo pacman -R ola. E ele aparece em pacman -Qm, porque não veio de um repositório (a não ser que você crie o seu, veja Seu Próprio Repositório).

Uma versão nova

O que mudoupkgverpkgrel
O programa (nova versão do autor)Sobe (1.0 → 1.1)Volta a 1
Só a receita (dependência corrigida, caminho errado)IgualSobe (1 → 2)
Nada, mas você quer recompilarIgualIgual (makepkg -f)

Depois de mudar: updpkgsums, makepkg, namcap, makepkg --printsrcinfo > .SRCINFO. O pacman só considera "atualização" um pacote com pkgver-pkgrel maior que o instalado.

Quando não funciona

"Verificações de integridade faltando para: source"

O que aconteceu: não há somas no PKGBUILD (ou há menos somas que arquivos).

Como resolver: updpkgsums.

"ola.in ... FALHOU"

O que aconteceu: você mudou um arquivo de source depois de calcular as somas.

Como resolver: updpkgsums e makepkg -f. (Num pacote de outra pessoa, é o contrário: não atualize a soma sem saber por que o arquivo mudou.)

"Uma falha ocorreu em check()"

O que aconteceu: um comando do check() terminou com erro. O makepkg roda as funções com set -e: o primeiro comando que falhar para tudo.

Como resolver: leia a saída logo acima da mensagem; é a do teste que falhou. Um caso real está no projeto de empacotamento. Para gerar o pacote sem os testes (só para investigar), makepkg --nocheck.

"install: não foi possível criar arquivo comum '/usr/bin/ola': Permissão negada"

O que aconteceu: faltou o $pkgdir no destino do install, e o comando tentou escrever no sistema de verdade.

Como resolver: todo destino em package() começa com "$pkgdir".

Resumo

  • PKGBUILD = variáveis (o que é) + funções (como montar), em Bash.
  • pkgver é do programa; pkgrel é da receita.
  • prepare → build → check → package; só package() é obrigatória.
  • $srcdir = onde estão as fontes; $pkgdir = a raiz falsa que vira o pacote.
  • updpkgsums, makepkg, namcap, makepkg --printsrcinfo > .SRCINFO, pacman -U.

Na Arch Wiki: a referência de cada variável e função está em PKGBUILD (em português: PKGBUILD (Português)).
