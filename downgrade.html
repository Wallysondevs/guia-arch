Voltar um pacote (downgrade)

Você atualizou o sistema e um programa começou a falhar. Enquanto a correção não chega, dá para voltar aquele pacote para a versão anterior: é o downgrade (o contrário de upgrade). O Arch não guarda "a versão de ontem" nos repositórios, mas você tem três lugares onde procurar: o cache do seu pacman, o Arquivo do Arch Linux e a ferramenta downgrade, que junta os dois.

Você vai aprender
  • Voltar um pacote pelo cache, com pacman -U.
  • Achar qualquer versão antiga no Arch Linux Archive (archive.archlinux.org).
  • Usar a ferramenta downgrade (do AUR).
  • Segurar o pacote na versão antiga com IgnorePkg, sem esquecer de soltar depois.
  • Por que o downgrade é sempre temporário, e como voltar o sistema inteiro para uma data.
Downgrade é um remendo

O Arch só é testado com todos os pacotes na versão mais nova. Um pacote antigo no meio de um sistema novo é uma "atualização parcial" ao contrário, e pode quebrar outros programas. Use o downgrade para ganhar tempo, avise o problema (a correção costuma sair em dias) e volte a atualizar normalmente assim que puder.

Antes de tudo: qual pacote mudou?

Toda instalação, atualização e remoção fica registrada em /var/log/pacman.log. Para ver as atualizações recentes:

$ grep '\[ALPM\] upgraded' /var/log/pacman.log | tail -5

Na máquina da ana não sai nada: ela foi instalada há pouco e ainda não recebeu nenhuma atualização. Num sistema em uso, cada linha tem este formato (exemplo ilustrativo):

[2026-10-20T09:14:02-0300] [ALPM] upgraded tree (2.3.1-1 -> 2.3.2-1)

Data e hora, o pacote e as versões de → para. Os pacotes atualizados logo antes de o problema aparecer são os suspeitos. Se puder, confira também as notícias em archlinux.org/news: às vezes o "defeito" é uma mudança que pede uma ação sua (veja Atualizar o Sistema).

Nos exemplos desta aula, o pacote é o tree (o programa que desenha pastas em árvore): pequeno e sem dependências. A ana tem a versão 2.3.2; vamos voltar para a 2.3.1. Todas as transações foram feitas na máquina de laboratório e respondidas com "n": nada foi instalado de verdade.

$ pacman -Q tree
tree 2.3.2-1

Missão: antes de voltar um pacote, anote a versão atual. Mostre a versão instalada do tree.

1. Pelo cache do pacman

Todo pacote que o pacman baixa fica guardado em /var/cache/pacman/pkg/, e ele não apaga as versões antigas sozinho. Então, depois de uma atualização, a versão anterior quase sempre ainda está ali:

$ ls /var/cache/pacman/pkg | grep '^tree-'
tree-2.3.1-1-x86_64.pkg.tar.zst
tree-2.3.1-1-x86_64.pkg.tar.zst.sig
tree-2.3.2-1-x86_64.pkg.tar.zst
tree-2.3.2-1-x86_64.pkg.tar.zst.sig

(Na ana, a 2.3.1 está no cache porque foi baixada pelo Arquivo, na seção 2. Num sistema em uso, ela estaria lá desde a atualização.) O nome do arquivo conta tudo:

tree
O nome do pacote.
2.3.1-1
Versão do programa (2.3.1) e lançamento do pacote (-1).
x86_64
A arquitetura (any para pacotes sem programa compilado).
.pkg.tar.zst
Um arquivo tar comprimido com zstd.
.sig
A assinatura do pacote, que o pacman confere (veja Chaves e Assinaturas).

Para instalar um arquivo de pacote, o pacman usa o -U (upgrade: instalar a partir de um arquivo ou URL):

$ sudo pacman -U /var/cache/pacman/pkg/tree-2.3.1-1-x86_64.pkg.tar.zst
carregando pacotes...
atenção: fazendo downgrade do pacote tree (2.3.2-1 => 2.3.1-1)     « o pacman avisa que é uma volta
resolvendo dependências...
procurando pacotes conflitantes...

Pacotes (1) tree-2.3.1-1

Tamanho total instalado:  0,09 MiB
Alteração no tamanho:     0,00 MiB

:: Continuar a instalação? [S/n] n
$ echo $?
1

Sem "Tamanho total download": o arquivo já está no disco. O código 1 é porque respondemos n; com S, o pacote volta e o código é 0. Se você apontar a mesma versão que já tem, o pacman só reinstala:

$ sudo pacman -U /var/cache/pacman/pkg/tree-2.3.2-1-x86_64.pkg.tar.zst
carregando pacotes...
atenção: tree-2.3.2-1 está atualizado -- reinstalando
…
Guarde algumas versões no cache

Se você apaga o cache inteiro (pacman -Scc), perde essa saída de emergência. O paccache -r (do pacote pacman-contrib) apaga só o excesso e mantém as 3 últimas versões de cada pacote: o equilíbrio certo. Veja Cache e Órfãos.

2. Pelo Arch Linux Archive

Se o cache foi limpo, existe o Arch Linux Archive (ALA), o arquivo oficial em archive.archlinux.org, que guarda todas as versões publicadas, organizadas de dois jeitos:

PastaO que temExemplo
/packages/Cada pacote, todas as versões, por inicial/packages/t/tree/
/repos/AAAA/MM/DD/Uma "fotografia" dos repositórios como estavam naquele dia/repos/2026/09/15/

As últimas versões do tree, lidas da página do Arquivo:

$ curl -s https://archive.archlinux.org/packages/t/tree/ | grep -o "tree-[0-9][^\"<]*pkg.tar.zst" | sort -uV | tail -6

tree-2.1.1-2-x86_64.pkg.tar.zst
tree-2.1.3-1-x86_64.pkg.tar.zst
tree-2.2.1-1-x86_64.pkg.tar.zst
tree-2.3.1-1-x86_64.pkg.tar.zst
tree-2.3.2-1-x86_64.pkg.tar.zst

A URL de um pacote é sempre montada do mesmo jeito:

https://archive.archlinux.org/packages/

t/
A primeira letra do nome.

O nome do pacote.
tree-2.3.1-1-x86_64.pkg.tar.zst

O pacman -U aceita a URL direto: ele baixa o pacote (e a assinatura) para o cache e segue como antes:

3. A ferramenta downgrade (AUR)

O downgrade procura a versão no cache e no Arquivo, mostra um menu para você escolher e chama o pacman -U. Ele está no AUR; a ana o compilou em ~/aur/downgrade (veja makepkg; com yay, seria yay -S downgrade). Ele depende do fzf, que desenha o menu.

$ pacman -Q downgrade fzf

$ downgrade --help

Escolher a versão direto

O downgrade aceita filtros de versão (=, <, <=, >, >=). Com tree=2.3.1 só há uma opção, e ele vai direto para o pacman, sem menu. No laboratório, a opção --pacman trocou o pacman pelo previa (o script que responde "n"); no seu computador, o comando é só sudo downgrade 'tree=2.3.1':

#> downgrade --pacman previa --ignore never 'tree=2.3.1'
:: Obtendo pacotes...
 tree-2.3.1-1-x86_64 sendo baixado...
carregando pacotes...
resolvendo dependências...
atenção: fazendo downgrade do pacote tree (2.3.2-1 => 2.3.1-1)
procurando pacotes conflitantes...

Pacotes (1) tree-2.3.1-1

Tamanho total instalado:  0,09 MiB
Alteração no tamanho:     0,00 MiB

:: Continuar a instalação? [S/n] n

Por baixo, é o mesmo pacman -U com a URL do Arquivo. Quando a instalação acontece de verdade, o downgrade pergunta no fim adicionar tree em IgnorePkg? [s/N]: responder s segura o pacote nessa versão (próxima seção). O --ignore never do exemplo pula essa pergunta.

Forma de voltarQuando usar
sudo pacman -U /var/cache/pacman/pkg/arquivoA versão antiga está no cache (o caso mais comum, se você não limpa tudo)
sudo pacman -U https://archive.archlinux.org/packages/…Cache limpo; você sabe qual versão quer; sem instalar nada do AUR
sudo downgrade pacoteO mais cômodo: lista cache e Arquivo juntos e oferece o IgnorePkg

Segurar a versão: IgnorePkg

Depois do downgrade, o próximo pacman -Syu traria a versão nova de volta, com o defeito. Para impedir, o pacote vai para a lista IgnorePkg do /etc/pacman.conf, que vem comentada:

$ grep -n "IgnorePkg\|IgnoreGroup\|^\[options\]" /etc/pacman.conf
9:[options]
24:# Pacman won't upgrade packages listed in IgnorePkg and members of IgnoreGroup
25:#IgnorePkg   =
26:#IgnoreGroup =

Para não mexer no arquivo real da ana, o teste foi numa cópia, apontada com --config. Tirar o # e escrever o nome:

#> cp /etc/pacman.conf /tmp/a7/pacman.conf
#> sed -i 's/^#IgnorePkg   =$/IgnorePkg   = tree/' /tmp/a7/pacman.conf
#> grep -n "IgnorePkg" /tmp/a7/pacman.conf
24:# Pacman won't upgrade packages listed in IgnorePkg and members of IgnoreGroup
25:IgnorePkg   = tree
#> pacman --config /tmp/a7/pacman.conf -S tree
:: tree está no IgnorePkg/IgnoreGroup. Instalar mesmo assim? [S/n] n
atenção: ignorando alvo: tree
nada para fazer

No seu computador, edite o /etc/pacman.conf com sudo nano. Vários pacotes vão separados por espaço (IgnorePkg = tree htop). Durante um pacman -Syu com uma versão nova disponível, o aviso é este (ilustrativo):

atenção: tree: ignorando atualização do pacote (2.3.1-1 => 2.3.2-1)

O pacote downgrade traz o pacignore, que faz essa edição por você:

#> pacignore check -c /tmp/a7/pacman.conf tree; echo $?
0
#> pacignore check -c /etc/pacman.conf tree; echo $?
1

check devolve 0 se o pacote está ignorado e 1 se não está. Os outros subcomandos são ls (lista), add e rm (acrescenta e tira); -c escolhe o arquivo (o padrão é o /etc/pacman.conf).

Missão: veja se a ana está segurando algum pacote: mostre as linhas do /etc/pacman.conf que falam de IgnorePkg, com o número da linha.

Não esqueça o IgnorePkg ligado

Um pacote ignorado para sempre vai ficando cada vez mais velho, até que uma atualização de outra biblioteca o quebre de vez. Anote o motivo, acompanhe a correção e tire o nome do IgnorePkg assim que a versão nova funcionar (sudo pacignore rm tree ou editando o arquivo).

Por que o downgrade é temporário: dependências

Com o tree, que não depende de nada, foi fácil. Com bibliotecas, as versões estão amarradas. O systemd, por exemplo, exige o systemd-libs exatamente da mesma versão:

$ pacman -Qi systemd | grep "^Depende"
Depende de           : systemd-libs=262  acl  bash  cryptsetup  dbus  dbus-units  glibc  kbd  kmod  hwdata  libgcrypt  libxcrypt  libidn2  lz4  pam  libelf  libgcc  libseccomp  util-linux  xz  pcre2  audit  openssl

Tentativa real de voltar só o systemd-libs:

$ sudo pacman -U https://archive.archlinux.org/packages/s/systemd-libs/systemd-libs-261.3-1-x86_64.pkg.tar.zst
:: Obtendo pacotes...
 systemd-libs-261.3-1-x86_64
carregando pacotes...
atenção: fazendo downgrade do pacote systemd-libs (262-1 => 261.3-1)
resolvendo dependências...
procurando pacotes conflitantes...
erro: falha ao preparar a transação (não foi possível satisfazer as dependências)
:: a instalação de systemd-libs (261.3-1) quebra a dependência "systemd-libs=262" necessária por systemd

O pacman se recusou, e ainda bem. A solução seria voltar juntos todos os pacotes amarrados (aqui, systemd, systemd-libs e companhia), passando vários arquivos no mesmo pacman -U ou vários nomes no mesmo downgrade. Quanto mais fundo no sistema (glibc, systemd, mesa), mais pacotes vêm junto e maior o risco. Por isso:

  • Downgrade de um programa "folha" (um editor, um jogo, o tree): tranquilo.
  • Downgrade de biblioteca central: só voltando o grupo inteiro, e por pouco tempo.
  • Nunca force com pacman -Udd (ignorar dependências): é o caminho mais curto para um sistema que não inicia.

Voltar o sistema inteiro para uma data

Quando a atualização quebrou "tudo" e você não sabe qual pacote culpar, o Arquivo permite apontar o pacman para os repositórios como eram num dia. Todos os pacotes voltam juntos, coerentes entre si. O teste abaixo foi feito com uma cópia da configuração e uma cópia do banco de dados de pacotes (--dbpath), para não tocar no pacman de verdade da ana.

1. Trocar o espelho pelo Arquivo (numa cópia)

No pacman.conf, as linhas Include = /etc/pacman.d/mirrorlist dos repositórios viram um Server com a data:

#> cp /etc/pacman.conf /tmp/a7/pacman-data.conf
#> sed -i "s|^Include = /etc/pacman.d/mirrorlist|Server = https://archive.archlinux.org/repos/2026/09/15/\$repo/os/\$arch|" /tmp/a7/pacman-data.conf
#> grep -n "^Server\|^\[" /tmp/a7/pacman-data.conf
9:[options]
78:[core]
79:Server = https://archive.archlinux.org/repos/2026/09/15/$repo/os/$arch
84:[extra]
85:Server = https://archive.archlinux.org/repos/2026/09/15/$repo/os/$arch

$repo e $arch o pacman troca sozinho (por core/extra e x86_64). No seu computador, a troca seria no próprio /etc/pacman.conf (ou no mirrorlist, deixando só essa linha).

2. Sincronizar e "atualizar para trás"

-Syy

uu
Dois u: atualiza permitindo downgrade (com um só, o pacman ignoraria versões mais velhas).

Antes de voltar o sistema inteiro
  • É uma medida de emergência, não um modo de vida: o sistema fica sem as correções de segurança desse período.
  • Configurações gravadas pela versão nova (de um navegador, de um banco de dados) podem não abrir na antiga.
  • Depois de resolver, volte o pacman.conf para o Include = /etc/pacman.d/mirrorlist e rode sudo pacman -Syu. Esquecer a data no arquivo congela o sistema naquele dia.
  • Com snapshots do Btrfs, voltar o sistema é um clique; sem eles, este é o caminho.

Quando não funciona

"quebra a dependência … necessária por …" 
erro: falha ao preparar a transação (não foi possível satisfazer as dependências)
:: a instalação de systemd-libs (261.3-1) quebra a dependência "systemd-libs=262" necessária por systemd

O que aconteceu: outro pacote exige a versão atual.

Como resolver: volte os dois juntos (sudo downgrade systemd systemd-libs, escolhendo a mesma versão nos dois), ou volte o sistema inteiro para uma data. Não use -dd.

"downgrade deve ser executado como root"

Como resolver: sudo downgrade pacote.

"tree está no IgnorePkg/IgnoreGroup. Instalar mesmo assim?"

O que aconteceu: você (ou o downgrade) pôs o pacote no IgnorePkg. Responder S instala a versão nova só desta vez.

Como resolver: se o problema já foi corrigido, tire o nome do IgnorePkg (sudo pacignore rm tree) e atualize.

Erro de assinatura ou "chave desconhecida" num pacote muito antigo

O que aconteceu: o pacote foi assinado por uma chave de empacotador que não está mais no chaveiro atual (o pacman confere a assinatura de todo pacote, inclusive os do Arquivo).

Como resolver: prefira versões recentes. Veja Chaves e Assinaturas antes de pensar em desligar a verificação, o que não é recomendado.

Resumo

  • Descubra o culpado no /var/log/pacman.log; volte só ele.
  • Cache: sudo pacman -U /var/cache/pacman/pkg/…. Arquivo: sudo pacman -U https://archive.archlinux.org/packages/…. Cômodo: sudo downgrade pacote.
  • Segure com IgnorePkg, e solte assim que a correção sair.
  • Bibliotecas amarradas voltam juntas ou não voltam; nunca -dd.
  • Sistema inteiro: Server = …/repos/AAAA/MM/DD/… + pacman -Syyuu, e depois volte ao espelho normal.
