Arch Introdução

O Arch Linux é uma distribuição Linux leve e independente, que entrega um sistema mínimo e deixa você montar o resto peça por peça. Ele é atualizado continuamente (não tem "versão 12" nem "versão 24.04"), tem um gerenciador de pacotes próprio, o pacman, e é famoso pela documentação: a Arch Wiki, usada até por quem não usa Arch.

Você vai aprender
  • O que é uma distribuição e o que faz do Arch uma distribuição diferente.
  • A história do Arch, de Judd Vinet em 2002 até hoje.
  • Os cinco princípios do "Arch Way": simplicidade, modernidade, pragmatismo, foco no usuário e versatilidade.
  • Os três pilares: pacman, AUR e Arch Wiki.
  • As distribuições derivadas (Manjaro, EndeavourOS, CachyOS, Garuda, SteamOS) e como elas se diferenciam do Arch "puro".

Primeiro, o que é uma distribuição?

O Linux, a rigor, é só o kernel: o programa que conversa com o hardware (processador, memória, disco, placa de rede). Sozinho, ele não abre uma janela nem lista arquivos. Para virar um sistema usável, ele precisa de centenas de outros programas: o shell (Bash), os comandos básicos (ls, cp…), o systemd que liga os serviços, um gerenciador de pacotes e, se você quiser, uma interface gráfica.

Uma distribuição é quem junta tudo isso, escolhe as versões, testa, empacota e entrega pronto. Pense numa cozinha: o kernel é o fogão; a distribuição é o restaurante que decide o cardápio. O Ubuntu é um restaurante com prato feito: você chega e já tem desktop, navegador e tudo configurado. O Arch é uma cozinha bem equipada com a despensa cheia: você escolhe cada ingrediente e monta o seu prato.

Um pouco de história

O Arch nasceu em 2001, quando o programador canadense Judd Vinet quis uma distribuição simples e elegante, inspirada no CRUX (uma distribuição minimalista da época), mas com um gerenciador de pacotes que resolvesse dependências sozinho. Ele mesmo escreveu esse gerenciador: o pacman. A primeira versão do Arch, a 0.1 "Homer", saiu em 11 de março de 2002.

O nome dele está até hoje dentro do pacman. Na VM do guia:

$ pacman --version

 .--.                  Pacman v7.1.0 - libalpm v16.0.1     « versão do pacman e da biblioteca libalpm
/ _.-' .-.  .-.  .-.   Copyright (C) 2006-2025 Pacman Development Team
\  '-. '-'  '-'  '-'   Copyright (C) 2002-2006 Judd Vinet   « o criador do Arch e do pacman
 '--'
                       Este programa pode ser redistribuído livremente
                       sob os termos da Licença Pública Geral GNU.

O desenho à esquerda é o próprio Pac-Man comendo as bolinhas: o nome pacman vem de package manager e a brincadeira com o jogo é proposital.

O Arch é independente: não é baseado em nenhuma outra distribuição (o Ubuntu é baseado no Debian; o Arch não é baseado em nada). E é feito por voluntários, sem empresa por trás.

O "Arch Way": os cinco princípios

A página principal da Arch Wiki resume a filosofia do projeto em cinco princípios. Conhecê-los explica quase todas as "estranhezas" que você vai encontrar.

1. Simplicidade

Para o Arch, simples quer dizer sem acréscimos nem modificações desnecessárias: os programas são empacotados como os autores originais (o upstream) os lançaram, com o mínimo de mudanças. É a ideia conhecida como KISS (Keep It Simple, Stupid, "mantenha simples"). Simples não quer dizer fácil: quer dizer que não há mágica escondida. A configuração fica em arquivos de texto que você lê e entende. O nome da máquina, por exemplo, é um arquivo de uma linha:

$ cat /etc/hostname
notebook                       « só isso: o nome da máquina, escrito na instalação

2. Modernidade

O Arch entrega as versões novas dos programas pouco depois de lançadas. Em outubro de 2026, a VM tinha o kernel 7.2.10, lançado dias antes. Foi um dos primeiros a adotar o systemd, o Wayland e o PipeWire.

3. Pragmatismo

As decisões são técnicas e práticas, não ideológicas. O repositório oficial tem software livre e também programas proprietários quando eles são úteis (o driver da NVIDIA, o firmware de placas Wi-Fi).

4. Centrado no usuário

O Arch não tenta agradar a todo mundo: ele foi feito para quem quer entender e cuidar do próprio sistema. Espera-se que você leia a documentação antes de pedir ajuda, e que contribua de volta (corrigindo a Wiki, relatando bugs). Em troca, nada é decidido por você: nenhum programa é instalado "porque sim".

5. Versatilidade

A partir da mesma base mínima, você monta um servidor sem tela, um desktop KDE, uma estação de jogos ou um notebook com Hyprland. O Arch não vem "com cara" de nada.

"O que você instala é o que você tem"

Essa frase resume os princípios na prática. A VM do guia foi instalada com o mínimo e depois recebeu as ferramentas das aulas. O pacman sabe exatamente o que foi pedido de propósito (-Qe, de explicit) e o que veio junto como dependência:

$ pacman -Q | wc -l
408                            « todos os pacotes instalados
$ pacman -Qe | wc -l
45                             « só os que alguém pediu pelo nome
$ pacman -Qi base | grep -E "^(Nome|Versão|Descrição|Depende)"
Nome                 : base
Versão               : 3-3
Descrição            : Minimal package set to define a basic Arch Linux installation
Depende de           : filesystem  gcc-libs  glibc  bash  coreutils  file  findutils  gawk  grep  procps-ng  sed  tar  gettext  pciutils  psmisc  shadow  util-linux  bzip2  gzip  xz  licenses  pacman  archlinux-keyring  systemd  systemd-sysvcompat  iputils  iproute2

O base é um metapacote: ele não tem programa nenhum, só uma lista de dependências que forma o sistema mínimo. Leia a lista com calma: não há editor de texto, não há sudo, não há man, não há rede sem fio, não há desktop. Logo depois da instalação, a VM tinha 193 pacotes; hoje tem 408 porque recebeu, de propósito, as ferramentas das aulas. Cada um deles está lá porque alguém pediu.

Missão: veja a lista dos pacotes que a Ana instalou de propósito com pacman -Qe. Procure nela o nano, o sudo e o linux. Depois conte quantos são com pacman -Qe | wc -l.

Rolling release em uma frase

O Arch não lança versões: cada programa é atualizado assim que a nova versão é empacotada e testada, e o seu sistema acompanha com um único comando, sudo pacman -Syu. Você instala uma vez e nunca mais "atualiza a versão". O preço é que as mudanças chegam toda semana, e às vezes pedem que você leia uma notícia antes de atualizar. A aula Rolling Release explica tudo isso com calma.

Os três pilares: pacman, AUR e Wiki

pacman: os repositórios oficiais

Os pacotes oficiais ficam em repositórios (servidores com milhares de pacotes) mantidos pela equipe do Arch. Os dois principais são o core (o essencial para o sistema ligar) e o extra (todo o resto). Existe ainda o multilib, com programas de 32 bits como o Steam, que você ativa se precisar. Na VM do guia:

$ pacman -Sl | cut -d" " -f1 | sort | uniq -c
    299 core                   « o essencial: kernel, systemd, pacman, bash…
  15031 extra                  « desktops, navegadores, servidores, linguagens…
pacman -Sl
Sync list: lista todos os pacotes dos repositórios, um por linha, começando pelo nome do repositório.
| cut -d" " -f1
Fica só com a primeira palavra de cada linha (o repositório).
| sort | uniq -c
Agrupa as linhas iguais e conta quantas há de cada.

São pouco mais de 15 mil pacotes oficiais (em outubro de 2026). O pacman instala, remove e atualiza esses pacotes resolvendo as dependências sozinho. Ele é o assunto de pacman: o Básico.

AUR: os pacotes da comunidade

O AUR (Arch User Repository) é um repositório mantido pelos próprios usuários. Ele não guarda programas prontos, e sim receitas (arquivos PKGBUILD) que dizem como baixar e compilar cada programa. Em outubro de 2026, a página do AUR mostrava 114.756 pacotes. Quase tudo que existe para Linux está lá: o Google Chrome, o VS Code da Microsoft, drivers de impressora…

O AUR não é oficial

Qualquer pessoa pode publicar um pacote no AUR, e ninguém revisa antes. Em junho de 2026, uma notícia do Arch avisou sobre pacotes maliciosos ativos no AUR. Antes de instalar algo de lá, você precisa ler a receita. O Nível 2 ensina como: O que é o AUR e AUR com Segurança.

Arch Wiki: a documentação

A Arch Wiki (wiki.archlinux.org) tem milhares de páginas sobre instalação, hardware, programas e solução de problemas. Ela é tão completa que usuários de Ubuntu, Fedora e até de BSD a consultam. No Arch, ela substitui o instalador gráfico e o assistente de configuração: quando você não sabe algo, a resposta é "leia a Wiki". A aula A Arch Wiki ensina a ler, buscar e pedir ajuda do jeito certo.

Distribuições derivadas

Como o Arch é uma ótima base, várias distribuições partem dele e acrescentam o que ele não tem: instalador gráfico, desktop pronto, configurações escolhidas por alguém. Elas usam o pacman e o AUR, mas não são o Arch: têm outros repositórios, outros padrões e outra equipe.

Muita coisa da Arch Wiki vale também para as derivadas, mas os fóruns do Arch só dão suporte ao Arch de verdade. Se você usa Manjaro e um pacote do AUR quebrou, a causa pode ser justamente o atraso dos repositórios dele: peça ajuda no fórum do Manjaro. Este guia trata do Arch oficial; a comparação completa com outras famílias está em Arch × Debian × Fedora.

Quando não funciona

Segui um tutorial e o comando não existe 
$ apt install htop
bash: apt: comando não encontrado
$ echo $?
127                            « 127 = o shell não achou o programa

Causa: o tutorial era de Debian/Ubuntu. O Arch não tem apt.

Como confirmar: cat /etc/os-release mostra ID=arch.

Como resolver: traduza o comando para o pacman (sudo pacman -S htop) usando a tabela pacman × apt × dnf, ou procure o assunto na Arch Wiki, que é escrita para o seu sistema.

O tutorial era de Manjaro (ou de outra derivada)

Causa: comandos como pamac, mhwd ou manjaro-settings-manager só existem no Manjaro; o mesmo vale para as ferramentas próprias do Garuda e do CachyOS.

Como resolver: procure o equivalente no Arch (quase sempre um pacote oficial e um arquivo de configuração) na Arch Wiki. Os comandos do pacman desses tutoriais, em geral, funcionam igual.

Resumo

  • O Arch é uma distribuição independente, criada por Judd Vinet (primeira versão em março de 2002), mantida por voluntários.
  • Os princípios: simplicidade (KISS, sem modificações desnecessárias), modernidade, pragmatismo, foco no usuário e versatilidade.
  • É rolling release: sem versões, atualizado com sudo pacman -Syu.
  • Os pilares: pacman (repositórios core e extra), AUR (receitas da comunidade, sem revisão) e Arch Wiki.
  • "O que você instala é o que você tem": o base é mínimo; editor, sudo, man e desktop são escolhas suas.
  • Manjaro, EndeavourOS, CachyOS, Garuda e SteamOS são derivadas: parecidas, mas com repositórios e decisões próprios.

Na Arch Wiki: os princípios estão na página Arch Linux (em português); as perguntas comuns, em Frequently asked questions (em português); a história, na seção History da mesma página; os repositórios, em Official repositories (em português); o AUR, em Arch User Repository (em português); e as derivadas, em Arch-based distributions.
