Arch touch e mkdir

Nesta aula você cria arquivos e pastas pelo terminal. São dois comandos: mkdir cria pastas e touch cria arquivos vazios. Eles parecem simples, mas têm truques que economizam muito trabalho, como criar 12 pastas, ou a estrutura inteira de um projeto, com um comando só.

Você vai aprender
  • O que cada parte dos comandos mkdir e touch faz, e o que eles devolvem.
  • Seis formas diferentes de criar várias pastas, e quando usar cada uma.
  • Como criar um caminho inteiro de pastas com mkdir -p.
  • Como o touch cria arquivos e muda datas sem apagar nada.
  • As mensagens de erro reais do Arch e o que fazer com cada uma.

Os exemplos são de uma instalação real do Arch (coreutils 9.12), com a usuária ana na máquina notebook. Você vai usar o ls o tempo todo para conferir o que criou; se ainda não o conhece, veja antes a aula ls.

mkdir: criar uma pasta

mkdir vem de make directory, "criar diretório". Diretório é o nome técnico de pasta.

mkdir
O programa. Ele cria pastas.
estudos
O argumento: o nome da pasta que você quer criar. Sem caminho, ela nasce dentro da pasta atual.
$ mkdir estudos
$ ls
'Área de trabalho'   Documentos   estudos      Imagens   Música    Vídeos
 aur                 Downloads    frutas.txt   Modelos   Público

O mkdir não mostrou nada. No Linux, silêncio significa sucesso: o comando só fala quando dá erro ou quando você pede. Por isso usamos o ls logo depois, para conferir. A pasta nova apareceu entre "Downloads" e "frutas.txt", porque o ls ordena pelo idioma, ignorando maiúsculas.

Pedindo para o mkdir falar: -v

mkdir
O programa.
-v
Uma opção (de verbose, "detalhado"): conta o que foi feito.
aulas
O nome da pasta.
$ mkdir -v aulas
mkdir: foi criado o diretório 'aulas'

O que o comando devolve

Além do que aparece na tela, todo comando devolve um código de saída: 0 quando deu certo e outro número quando deu errado. Você vê esse código com echo $?, logo depois do comando:

$ mkdir provas
$ echo $?
0                                                 « 0 = deu certo
$ mkdir provas
mkdir: não foi possível criar o diretório “provas”: Arquivo existe
$ echo $?
1                                                 « 1 = deu errado

A mensagem segue sempre o mesmo modelo: quem reclamou (mkdir:), o que tentou fazer (criar o diretório "provas") e, depois dos dois-pontos, o motivo (Arquivo existe: já existe algo com esse nome). No Arch a frase vem inteira em português; repare que o erro põe o nome entre aspas curvas (“provas”) e o -v, entre aspas retas ('aulas').

As permissões de uma pasta nova

$ mkdir nova
$ ls -ld nova
drwxr-xr-x 2 ana ana 4096 16 out 14:56 nova

A pasta nasce com drwxr-xr-x: a dona (ana) pode tudo; o grupo e os outros podem entrar e ver o conteúdo, mas não criar nada nela. Quem decide isso é a umask, uma "máscara" que o Arch define como 022 para todos os usuários (confira com o comando umask). A aula Entendendo Permissões explica as letras e a umask.

Criar várias pastas: 6 formas diferentes

A Ana quer uma pasta para cada mês do semestre: jan, fev, mar, abr, mai e jun. Todas as formas a seguir chegam ao mesmo resultado; o que muda é a situação em que cada uma é mais prática.

Forma 1: vários nomes separados por espaço

mkdir
O programa.
jan fev mar
Três argumentos. Cada um vira uma pasta.
$ mkdir jan fev mar
$ ls
fev  jan  mar

É a forma mais usada no dia a dia. "fev" veio antes de "jan" porque o ls ordena alfabeticamente; ele não sabe que são meses.

Forma 2: chaves { }

Quando os nomes têm uma parte em comum, as chaves evitam repetir. Quem entende as chaves é o shell (o Bash, o programa que lê o que você digita), não o mkdir: o Bash transforma {jan,fev,mar} em jan fev mar antes de chamar o comando. O echo, que só repete o que recebe, mostra essa transformação:

relatorio-
O começo, igual para todos.
{jan,fev,mar}
As partes que mudam, separadas por vírgula, sem espaços.
.txt
O final, igual para todos.
$ echo relatorio-{jan,fev,mar}.txt
relatorio-jan.txt relatorio-fev.txt relatorio-mar.txt
$ mkdir rel-{abr,mai,jun}
Atenção às chaves: sem espaço depois da vírgula

Com espaço, o Bash não reconhece as chaves e passa o texto do jeito que está. Veja o estrago:

$ echo {jan, fev}
{jan, fev}
$ mkdir {abr, mai}
$ ls
{abr,  fev  jan  mai}  mar

Foram criadas duas pastas com nomes estranhos, {abr, e mai}. Com uma opção só, como {jan}, as chaves também não fazem nada. A aula Curingas compara as chaves com os curingas * e ?, e o Guia Bash tem uma aula inteira sobre chaves.

Forma 3: sequências {1..12}

Com dois pontos entre o começo e o fim, as chaves geram uma sequência:

$ echo mes{1..12}
mes1 mes2 mes3 mes4 mes5 mes6 mes7 mes8 mes9 mes10 mes11 mes12

Mas, sem zeros, a ordem do ls fica estranha, porque ele compara caractere por caractere ("aula10" vem antes de "aula2"):

$ mkdir aula{1..12}
$ ls -d aula*
aula1   aula11  aula2  aula4  aula6  aula8
aula10  aula12  aula3  aula5  aula7  aula9

Com um zero na frente do primeiro número, todos ficam do mesmo tamanho, e a ordem fica certa:

$ mkdir mes{01..12}
$ ls
mes01  mes03  mes05  mes07  mes09  mes11
mes02  mes04  mes06  mes08  mes10  mes12

Missão 1: você está na pasta cursos. Crie, com um comando só, as pastas aula01 até aula10, com o zero na frente. Confira a ordem com ls.

Forma 4: laço for

Um laço repete um comando para cada item de uma lista. É mais longo, mas permite fazer mais de uma coisa por pasta.

for mes in abr mai jun
Para cada palavra da lista, guarde-a na variável mes…
;
Separa as partes do comando.
do mkdir "$mes"; echo "criei $mes"
…e rode estes comandos. $mes é trocado pela palavra da vez.
; done
Fim do laço.
$ for mes in abr mai jun; do mkdir "$mes"; echo "criei $mes"; done
criei abr
criei mai
criei jun

Laços em detalhe estão no Guia Bash (o laço for).

Forma 5: a partir de uma lista em arquivo

Se os nomes já estão num arquivo de texto, um por linha, o xargs lê o arquivo e entrega os nomes ao mkdir:

$ cat clientes.txt
padaria
oficina
mercado
$ xargs mkdir < clientes.txt
$ ls
clientes.txt  mercado  oficina  padaria
xargs
Lê palavras da entrada e as passa como argumentos para outro comando.
mkdir
O comando que recebe as palavras.
< clientes.txt
Usa o arquivo como entrada (veja Redirecionamento).

Se algum nome tiver espaço, use xargs -d '\n' mkdir < clientes.txt, que separa só por linha. O xargs é assunto de Pipes e xargs.

Forma 6: pelo gerenciador de arquivos

O Arch não vem com ambiente gráfico; depois de instalar um (veja Instalar um Desktop), o gerenciador de arquivos cria pastas pelo menu do botão direito ou por um atalho de teclado, como Ctrl+Shift+N no Arquivos do GNOME e F10 no Dolphin do KDE. Para uma ou duas pastas é tão rápido quanto o terminal. Para dez ou mais, o terminal ganha.

Missão 2: você está na pasta semestre. Crie as pastas jan, fev, mar, abr, mai e jun. Use pelo menos duas formas diferentes e confira com ls.

Pastas dentro de pastas: -p

Tente criar site/css quando a pasta site ainda não existe:

$ mkdir site/css
mkdir: não foi possível criar o diretório “site/css”: Arquivo ou diretório inexistente
$ echo $?
1

O mkdir só cria o último nível do caminho. Como site não existe, ele não acha onde pôr a css. A opção -p (de parents, "pais") cria todas as pastas que faltam no caminho:

mkdir
O programa.
-p
Cria as pastas "pais" que faltarem e não reclama se a pasta já existir.
-v
Mostra cada pasta criada. -pv é o mesmo que -p -v.
site/css
O caminho completo que você quer.
$ mkdir -pv site/css
mkdir: foi criado o diretório 'site'
mkdir: foi criado o diretório 'site/css'
$ mkdir -pv site/css                  « de novo: tudo já existe
$ echo $?
0                                      « nenhuma mensagem e nenhum erro

Repare na segunda vez: como as duas pastas já existiam, o -p não criou nada, não disse nada e devolveu 0. É exatamente o que você quer num script: "garanta que esta pasta exista".

Uma estrutura inteira de uma vez

Juntando -p com chaves (inclusive chaves dentro de chaves), você monta a estrutura de um projeto num comando só. As duas formas abaixo dão o mesmo resultado:

# forma longa: um caminho por pasta
mkdir -p loja/src loja/docs loja/testes/unidade loja/testes/integracao
# forma curta: com chaves
mkdir -p loja/{src,docs,testes/{unidade,integracao}}

Para ver a estrutura criada, o tree desenha a árvore. Ele não vem no base do Arch: instale com sudo pacman -S tree (veja pacman: o Básico). Sem ele, o find lista tudo o que há dentro:

$ mkdir -p loja/{src,docs,testes/{unidade,integracao}}
$ tree loja
loja
├── docs
├── src
└── testes
    ├── integracao
    └── unidade

6 directories, 0 files
$ find loja
loja
loja/docs
loja/src
loja/testes
loja/testes/unidade
loja/testes/integracao

O find mostra os itens na ordem em que estão gravados no disco, que pode variar de uma máquina para outra. Você vai conhecê-lo em find e locate.

Dica para scripts

Em scripts, use sempre mkdir -p: se a pasta já existir, ele não dá erro e o script continua.

Missão 3: crie, com um único comando, a pasta app contendo src, docs e testes. Confira com ls app.

Já escolhendo as permissões: -m

Com -m (de mode, "modo") a pasta já nasce com as permissões que você quiser, em vez das da umask. 700 quer dizer "só a dona entra":

$ mkdir -m 700 privado
$ ls -ld privado
drwx------ 2 ana ana 4096 16 out 14:56 privado

touch: criar arquivos vazios

touch significa "tocar". Ele "toca" no arquivo para atualizar a data de modificação. Se o arquivo não existe, ele cria um vazio. Por isso é usado para criar arquivos.

touch
O programa.
anotacoes.txt
O arquivo a criar (ou a "tocar", se já existir).
$ touch anotacoes.txt
$ echo $?
0
$ ls -l anotacoes.txt
-rw-r--r-- 1 ana ana 0 16 out 14:56 anotacoes.txt       « tamanho 0: vazio

A linha mostra um arquivo comum (-), da ana, com 0 bytes e a data e hora de agora. As permissões rw-r--r-- (a dona lê e escreve; os outros só leem) vêm da mesma umask 022 do Arch. Compare com um arquivo antigo da Ana, criado de outro jeito, com permissão de escrita para o grupo:

$ ls -l notas.txt novo.txt
-rw-rw-r-- 1 ana ana 69 14 out 17:40 notas.txt        « antigo: o grupo também escreve (rw-rw-r--)
-rw-r--r-- 1 ana ana  0 16 out 15:05 novo.txt         « criado agora, com a umask 022 do Arch

Vários arquivos de uma vez

O touch aceita vários nomes, chaves e sequências, como o mkdir:

$ touch index.html style.css script.js
$ touch capitulo{1..3}.md
$ ls
capitulo1.md  capitulo2.md  capitulo3.md  index.html  script.js  style.css

Missão 4: você está na pasta site. Crie os arquivos vazios index.html, style.css e script.js, e também capitulo1.md, capitulo2.md e capitulo3.md (estes, com chaves). Confira com ls -l: todos têm tamanho 0?

O touch não apaga o conteúdo

Se o arquivo já existe, o touch só muda a data. O conteúdo fica intacto:

$ cat notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ ls -l notas.txt
-rw-rw-r-- 1 ana ana 69 14 out 17:40 notas.txt
$ touch notas.txt
$ ls -l notas.txt
-rw-rw-r-- 1 ana ana 69 16 out 14:56 notas.txt         « só a data mudou: 69 bytes continuam lá
$ cat notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos

Para que serve "tocar" num arquivo? Alguns programas decidem o que fazer pela data: o make recompila o que mudou, scripts de backup copiam o que é recente, e a ordem do ls -lt muda.

Escolher a data: -d

Com -d (de date) você escolhe a data que o arquivo vai ter, em vez de "agora". É útil para testar scripts que apagam arquivos antigos:

touch
O programa.
-d "2026-01-01 08:00"
A data desejada, entre aspas porque tem espaço. O formato mais seguro é ANO-MÊS-DIA HORA:MINUTO.
antigo.log
O arquivo (criado, se não existir).
$ touch -d "2026-01-01 08:00" antigo.log
$ ls -l antigo.log
-rw-r--r-- 1 ana ana 0  1 jan  2026 antigo.log          « mais de 6 meses: o ls mostra o ano
$ touch -d "2026-10-10 21:14" recente.log
$ ls -l recente.log
-rw-r--r-- 1 ana ana 0 10 out 21:14 recente.log

O -d também entende expressões em inglês, como yesterday ("ontem") e "2 days ago" ("2 dias atrás"). Em português, não:

$ touch -d yesterday ontem.txt
$ touch -d "2 days ago" anteontem.txt
$ ls -l ontem.txt anteontem.txt
-rw-r--r-- 1 ana ana 0 14 out 15:05 anteontem.txt
-rw-r--r-- 1 ana ana 0 15 out 15:05 ontem.txt
$ touch -d ontem x.txt
touch: formato de data inválido “ontem”

Outras opções do touch

$ touch -t 202601010800 a.txt                      « -t: data colada, AAAAMMDDhhmm
$ ls -l a.txt
-rw-r--r-- 1 ana ana 0  1 jan  2026 a.txt
$ touch -r ~/Documentos/notas.txt copia-data.txt   « -r: copia a data de outro arquivo
$ ls -l copia-data.txt
-rw-r--r-- 1 ana ana 0 14 out 17:40 copia-data.txt
$ touch -c fantasma.txt                            « -c: só toca se existir; não cria
$ echo $?
0
$ ls fantasma.txt
ls: não foi possível acessar 'fantasma.txt': Arquivo ou diretório inexistente

Missão 5: crie o arquivo antigo.log com a data de 1º de janeiro de 2026, às 8h. Confira com ls -l antigo.log: aparece a hora ou o ano?

Outras formas de criar um arquivo

O touch cria arquivos vazios. Quando você já quer escrever algo dentro, há outros caminhos:

ComandoO que fazCuidado
touch arq.txtCria vazio ou só atualiza a dataNunca apaga conteúdo
echo "texto" > arq.txtCria com uma linha de textoApaga o conteúdo anterior
echo "texto" >> arq.txtAcrescenta uma linha no fim (cria se não existir)Seguro: não apaga nada
> arq.txtCria vazio ou esvazia o arquivoApaga o conteúdo sem perguntar
nano arq.txtAbre um editor de textoO base do Arch não traz editor: instale com sudo pacman -S nano (veja nano e vim)
$ echo "Lista de compras" > compras.txt
$ echo "pão" >> compras.txt
$ cat compras.txt
Lista de compras
pão
$ > compras.txt                       « um > sozinho: esvazia
$ ls -l compras.txt
-rw-r--r-- 1 ana ana 0 16 out 15:05 compras.txt
Atenção: > apaga, >> acrescenta

Um > no lugar de >> apaga tudo o que havia no arquivo, sem perguntar e sem lixeira. Na dúvida, use >>. Os dois são explicados em Redirecionamento.

Missão 6: crie o arquivo compras.txt com três linhas: pão, leite e café. Use echo com > e >>, e confira com cat compras.txt.

Quando não funciona

"Arquivo existe" 
$ mkdir fotos
mkdir: não foi possível criar o diretório “fotos”: Arquivo existe
$ mkdir notas.txt
mkdir: não foi possível criar o diretório “notas.txt”: Arquivo existe

O que aconteceu: já existe uma pasta, ou um arquivo, com esse nome. Repare que a mensagem diz "Arquivo" mesmo quando o que existe é uma pasta: para o sistema, pasta também é um tipo de arquivo.

Como confirmar: ls -ld fotos mostra o que existe e se é pasta (d) ou arquivo (-).

Como resolver: se a ideia era só "garantir que a pasta exista", use mkdir -p fotos, que não reclama. Se é um arquivo, escolha outro nome.

"Arquivo ou diretório inexistente" no mkdir e no touch 
$ mkdir projetos/2026/janeiro
mkdir: não foi possível criar o diretório “projetos/2026/janeiro”: Arquivo ou diretório inexistente
$ touch pasta-que-nao-existe/a.txt
touch: não foi possível tocar 'pasta-que-nao-existe/a.txt': Arquivo ou diretório inexistente

O que aconteceu: alguma pasta do caminho ainda não existe. Aqui, projetos existia, mas 2026 não.

Como resolver: crie o caminho com -p. O -v mostra que só as que faltavam foram criadas:

$ mkdir -pv projetos/2026/janeiro
mkdir: foi criado o diretório 'projetos/2026'
mkdir: foi criado o diretório 'projetos/2026/janeiro'

O touch não tem -p: crie a pasta antes (mkdir -p pasta) e depois o arquivo.

"Permissão negada" 
$ mkdir /opt/meuapp
mkdir: não foi possível criar o diretório “/opt/meuapp”: Permissão negada
$ echo $?
1
$ touch /etc/teste.conf
touch: não foi possível tocar '/etc/teste.conf': Permissão negada

O que aconteceu: fora da sua pasta pessoal (e de /tmp), quase tudo pertence ao administrador, o root.

Como resolver: antes, pense se o arquivo não deveria estar na sua pasta pessoal. Se precisa mesmo criar ali, use sudo, que pede a sua senha (a ana está no grupo wheel; veja sudo, root e Usuários). Na primeira vez, o sudo mostra um aviso:

$ sudo mkdir /opt/meuapp

Presumimos que você recebeu as instruções de sempre do administrador
de sistema local. Basicamente, resume-se a estas três coisas:

    #1) Respeite a privacidade dos outros.
    #2) Pense antes de digitar.
    #3) Com grandes poderes vêm grandes responsabilidades.

Por motivos de segurança, a senha que você digitar não será visível.

[sudo] senha para ana:
$ ls -ld /opt/meuapp
drwxr-xr-x 2 root root 4096 16 out 14:56 /opt/meuapp     « criada pelo root, é do root

Repare que a pasta criada com sudo pertence ao root, e não à ana. Para mudar o dono, use chown (veja Entendendo Permissões).

Missão 7: tente criar a pasta /opt/meuapp e leia o erro. Depois crie-a com sudo (a senha da ana é ana) e confira o dono com ls -ld /opt/meuapp.

"Não é um diretório" 
$ mkdir -p notas.txt/x
mkdir: não foi possível criar o diretório “notas.txt”: Não é um diretório

O que aconteceu: no caminho existe um arquivo com o nome que deveria ser de uma pasta. O -p não transforma arquivo em pasta.

Como resolver: escolha outro nome, ou renomeie o arquivo com mv (veja Mover e Renomear).

Nome com espaço virou duas pastas 
$ mkdir Meus Projetos
$ ls
Meus  Projetos

O que aconteceu: o espaço separa argumentos, e o mkdir recebeu dois nomes. Não houve erro: ele fez exatamente o que você pediu.

Como resolver: apague as duas com rmdir (que só remove pastas vazias; veja rm e rmdir) e crie de novo com aspas. Ou evite espaços: meus-projetos.

$ rmdir Meus Projetos
$ mkdir "Meus Projetos"
$ ls
'Meus Projetos'

Missão 8: crie, na pasta pessoal, uma pasta chamada Meus Projetos (com espaço). Se criar duas por engano, apague-as com rmdir e tente de novo.

"falta operando" 
$ mkdir
mkdir: falta operando
Tente "mkdir --help" para mais informações.
$ touch
touch: falta o operando arquivo
Tente "touch --help" para mais informações.

O que aconteceu: faltou o nome. "Operando" é o argumento sobre o qual o comando age.

"formato de data inválido" 
$ touch -d "2026-13-01" x.txt
touch: formato de data inválido “2026-13-01”

O que aconteceu: não existe mês 13. O -d também recusa datas em português ("ontem", "32 de outubro"). Nesse caso o arquivo não é criado.

Como resolver: use AAAA-MM-DD hh:mm, ou as palavras em inglês (yesterday, "2 days ago").

Resumo

  • mkdir nome cria uma pasta; mkdir a b c cria várias; nada aparece quando dá certo (código 0).
  • Chaves {a,b} e sequências {01..12} são expandidas pelo Bash e funcionam com qualquer comando; sem espaço depois da vírgula.
  • mkdir -p cria o caminho inteiro e não reclama se a pasta já existir; -v mostra o que foi criado.
  • touch cria arquivos vazios e nunca apaga conteúdo; -d, -t e -r escolhem a data.
  • No Arch, itens novos nascem com rw-r--r-- (arquivos) e rwxr-xr-x (pastas), por causa da umask 022.
  • > apaga, >> acrescenta. Fora da pasta pessoal, criar exige sudo.

Na Arch Wiki: o mkdir e o touch fazem parte do coreutils, apresentado em Core utilities (em português: Core utilities (Português)). As permissões com que os itens nascem são explicadas em Umask e em File permissions and attributes. As chaves e os laços são recursos do Bash.
