Processos e kill

Todo programa em execução é um processo: o navegador, o terminal, o sshd que espera conexões, até o comando ls enquanto lista. Nesta aula você aprende a ver quais processos existem, quanto cada um gasta e como encerrar o que travou, do jeito educado (kill) ao jeito à força (kill -9).

Você vai aprender
  • O que são PID, processo pai e estado de um processo.
  • Listar processos com ps aux, ps -ef e pgrep -a.
  • Acompanhar em tempo real com top e htop.
  • Encerrar com kill, pkill e killall, e a diferença entre os sinais TERM e KILL.
  • Os erros reais ("Processo inexistente", "Operação não permitida", "nenhum processo localizado").

O que é um processo

Pense numa cozinha: a receita é o programa (o arquivo /usr/bin/sleep, parado no disco); o prato sendo feito é o processo. Você pode cozinhar a mesma receita três vezes ao mesmo tempo: são três processos do mesmo programa. Cada processo tem:

AtributoO que é
PIDProcess ID: o número do processo, único enquanto ele vive. É por ele que você o encerra.
PPIDParent PID: quem o criou. Todo processo tem um pai; o avô de todos é o systemd, PID 1.
DonoO usuário que o rodou. Você só pode encerrar os seus (o root pode todos).
EstadoRodando, dormindo (esperando algo), parado…

ps: a foto dos processos

ps sozinho

ps (process status) sem nada mostra só os processos do seu terminal:

$ ps
    PID TTY          TIME CMD
   7592 pts/0    00:00:00 bash      « o seu shell
   7644 pts/0    00:00:00 ps        « o próprio ps

TTY é o terminal (pts/0 = o primeiro pseudoterminal: uma janela de terminal ou uma conexão SSH); TIME é quanto tempo de processador ele já usou; CMD, o comando.

ps aux: todos os processos

ps
Lista processos.
a
all: de todos os usuários, não só os seus.
u
user: formato com o dono, uso de CPU e memória.
x
Inclui os processos sem terminal (serviços, que são a maioria).

pgrep: achar pelo nome

O jeito mais comum de procurar é ps aux | grep nome. Funciona, mas tem uma pegadinha: o próprio grep aparece no resultado.

root       20369  0.0  0.3  21484 14624 ?        Ss   13:25   0:00 sshd-session: root [postauth]
…                                                                    « (uma linha por conexão SSH aberta)
ana        26573  0.0  0.2  21616  9196 ?        S    13:27   0:00 sshd-session: ana@notty
ana        26603  0.0  0.1   6968  4340 ?        S    13:27   0:00 grep --color=auto sshd     « o próprio grep!

O pgrep (process grep) foi feito para isso: procura pelo nome e devolve os PIDs, sem se incluir.

pgrep
Procura processos pelo nome.
-a
all: mostra o comando completo ao lado do PID. Sem ele, só os números.
sshd
Um pedaço do nome (é uma expressão regular, como no grep).
$ pgrep -a sshd
310 sshd: /usr/bin/sshd -D [listener] 0 of 10-100 startups     « o servidor
1501 sshd-session: ana [postauth]                                « as conexões ("sshd-session" contém "sshd")
1507 sshd-session: ana@notty
$ pgrep -x sshd
310                                                              « -x = nome exato: só o servidor
$ pgrep -l Network
289 NetworkManager                                               « -l = PID e nome curto

"Não apareceu nada"

Se o pgrep não acha nada, ele não escreve nada. O único sinal é o código de saída:

$ pgrep -a firefox; echo $?
1                                « 1 = nenhum processo com esse nome
$ pgrep networkmanager; echo $?
1                                « diferencia maiúsculas!
$ pgrep -i networkmanager
289                              « -i ignora maiúsculas/minúsculas
O nome do processo nem sempre é o nome do programa

O Chromium roda como chrome; o Visual Studio Code, como code ou electron; um script Python aparece como python3. Quando pgrep nome volta vazio, procure na linha de comando inteira com -f (full): pgrep -af meu_script.py. E use -u ana para ver só os de um usuário.

Missão: há um sleep rodando em segundo plano. Mostre o PID dele e o comando completo com o pgrep.

kill: mandar um sinal

Sinais

Apesar do nome, kill não "mata": ele manda um sinal a um processo. Um sinal é um recado curto do sistema: "termine", "pare", "continue", "releia a configuração". O processo decide o que fazer com a maioria deles. A lista completa:

$ kill -l
 1) SIGHUP	 2) SIGINT	 3) SIGQUIT	 4) SIGILL	 5) SIGTRAP
 6) SIGABRT	 7) SIGBUS	 8) SIGFPE	 9) SIGKILL	10) SIGUSR1
11) SIGSEGV	12) SIGUSR2	13) SIGPIPE	14) SIGALRM	15) SIGTERM
16) SIGSTKFLT	17) SIGCHLD	18) SIGCONT	19) SIGSTOP	20) SIGTSTP
…

Na prática, você usa uns poucos:

NúmeroNomeRecadoO processo pode ignorar?
15TERM"Termine, por favor." Salva, fecha arquivos e sai. É o padrão do kill.Sim
9KILLQuem age é o kernel: o processo some na hora, sem chance de salvar nada.Não
2INTInterromper: o mesmo que Ctrl+C no terminalSim
1HUP"O terminal fechou"; muitos serviços entendem como "releia a configuração"Sim
19 / 18STOP / CONTCongelar / descongelar (o Ctrl+Z manda o parecido TSTP)STOP: não

A forma do comando

kill
Manda um sinal. No Bash, é um comando interno (type kill → kill é um comando interno do shell); por isso também aceita %1 (um job do terminal).
-15 / -TERM / -SIGTERM
O sinal, por número ou nome. Opcional: sem ele, é TERM.
5853
Um ou mais PIDs.

Uma sessão real na VM, com sleep fazendo o papel do programa (o & roda em segundo plano e mostra [job] PID):

$ sleep 600 &
[1] 8262                        « job 1, PID 8262
$ kill %1                       « TERM para o job 1 (podia ser: kill 8262)
$ sleep 0.2; jobs
[1]+  Terminado                  sleep 600     « terminou pelo TERM
$ sleep 600 &
[1] 8447
$ kill -9 $!                    « $! = PID do último processo em segundo plano
$ sleep 0.2; jobs
[1]+  Morto                      sleep 600     « "Morto" = levou KILL

O kill que dá certo não escreve nada e devolve 0. Para conferir, procure o processo de novo:

$ sleep 700 &
[1] 40536
$ pgrep -a sleep
40536 sleep 700
$ kill $!
$ echo $?
0                               « sinal entregue
$ pgrep -a sleep
$ echo $?
1                               « sumiu

Congelar e descongelar

$ sleep 950 &
[1] 5865
$ kill -STOP %1
$ ps -o pid,stat,cmd -p $!
    PID STAT CMD
   5865 T    sleep 950          « T = parado
$ kill -CONT %1
$ ps -o pid,stat,cmd -p $!
    PID STAT CMD
   5865 S    sleep 950          « S = dormindo de novo (voltou a rodar)
$ kill -9 %1

Útil para pausar uma compilação pesada enquanto você usa o computador e retomá-la depois.

Comece pelo TERM; o -9 é o último recurso

Com kill -9, o programa não tem chance de salvar nada nem de apagar os arquivos de trava. O exemplo clássico no Arch: matar o pacman no meio de uma instalação deixa o arquivo /var/lib/pacman/db.lck para trás, e o próximo pacman reclama não foi possível travar a base de dados (veja Atualizar o Sistema). Mande TERM, espere uns segundos, e só então use -9. E nunca mate o pacman durante uma atualização.

pkill e killall: pelo nome

Em vez de procurar o PID e depois matar, dá para mandar o sinal direto pelo nome.

pkill sleep
Manda TERM a todo processo cujo nome contém "sleep" (as mesmas regras do pgrep: -f, -u, -x, -i).
killall sleep
Manda TERM a todo processo cujo nome é exatamente "sleep". Vem do pacote psmisc.
$ pacman -Qo $(command -v killall)
/usr/bin/killall pertence a psmisc 23.7-2
$ sleep 800 & sleep 801 &
[3] 5857
[4] 5858
$ killall sleep                « os dois de uma vez
$ echo $?
0
$ killall sleep
sleep: nenhum processo localizado      « o killall avisa quando não acha
$ echo $?
1
$ sleep 900 &
[1] 5861
$ pkill -f 'sleep 9'           « -f: procura na linha de comando inteira
$ echo $?
0
$ pkill sleep
$ echo $?
1                              « o pkill não avisa: só o código 1 diz "não achei"
Confira antes com o pgrep

pkill casa pedaços: pkill ssh pegaria o sshd e todas as sessões SSH (inclusive a sua, se você estiver conectado por SSH). Rode pgrep -a padrão primeiro e veja o que seria atingido. O killall é mais seguro nesse ponto (nome exato), e killall -i nome pergunta antes de cada um.

Missão: encerre o sleep que está rodando, usando o nome dele (sem digitar o PID). Depois confira com pgrep sleep; echo $?.

Serviços: use o systemctl

Processos de serviços (nginx, sshd, NetworkManager) não devem ser mortos com kill: o systemd pode reiniciá-los na hora ou ficar com o estado errado. Use sudo systemctl stop nginx ou restart (veja systemctl e Serviços).

Prioridade: nice e renice

Quando dois processos disputam o processador, ganha quem tem mais prioridade. O nice ("gentil") vai de −20 (egoísta) a 19 (gentil, deixa os outros passarem). Um usuário comum pode deixar o seu processo mais gentil, mas não voltar atrás:

$ sleep 300 &
[1] 26656
$ renice -n 10 -p $!
26656 (process ID) com prioridade antiga 0, prioridade nova 10
$ ps -o pid,ni,cmd -p $!
    PID  NI CMD
  26656  10 sleep 300
$ renice -n 0 -p $!
renice: falha ao definir prioridade pra 26656 (process ID): Permissão negada     « só o root diminui o nice

Para começar um programa já gentil: nice -n 19 makepkg. Bom para compilar algo do AUR sem travar o resto.

Quando não funciona

"Processo inexistente" 
$ kill 99999
bash: kill: (99999) - Processo inexistente
$ echo $?
1

O que aconteceu: não há processo com esse PID: ele já terminou, ou o número foi digitado errado.

Como resolver: procure de novo com pgrep -a nome. Os PIDs mudam a cada execução; não reaproveite um número de ontem.

"Operação não permitida" 
$ kill -9 310
bash: kill: (310) - Operação não permitida

O que aconteceu: o 310 é o sshd, do root. Um usuário comum só manda sinais para os próprios processos.

Como confirmar: ps -o user,pid,cmd -p 310.

Como resolver: se é mesmo para encerrar, use sudo; se é um serviço, sudo systemctl stop/restart. (E pense duas vezes: matar o sshd derruba o acesso remoto.)

"nenhum processo localizado" / pkill sem saída 
$ killall firefox
firefox: nenhum processo localizado
$ echo $?
1

O que aconteceu: não há processo com esse nome exato. O programa pode estar fechado, ou o processo tem outro nome (chrome para o Chromium, python3 para um script).

Como resolver: pgrep -ai parte-do-nome ou pgrep -af parte-do-comando para descobrir o nome real.

O processo não morre nem com -9

O que aconteceu: se o STAT é D, ele está preso esperando o disco (ou um pendrive/rede que sumiu) e nem o KILL o alcança até a espera acabar. Se é Z (zumbi), ele já morreu: só ocupa uma linha na tabela até o pai recolhê-lo.

Como resolver: para D, resolva o disco (reconecte o dispositivo, espere); para Z, encerre o pai (veja o PPID com ps -o pid,ppid,stat,cmd -p PID). Se nada resolver, veja Quando o Sistema Trava.

Resumo

  • Processo = programa rodando; cada um tem PID, pai (PPID), dono e estado.
  • ps aux/ps -ef tiram a foto; top/htop mostram o filme.
  • pgrep -a nome acha sem se incluir; resultado vazio = código 1.
  • kill manda TERM (educado); kill -9 manda KILL (à força, último recurso).
  • pkill casa pedaços do nome; killall (psmisc), o nome exato. Confira com pgrep antes.
  • Serviços se param com systemctl, não com kill.
