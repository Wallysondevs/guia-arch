Projeto: Instalação Completa do Zero

Neste projeto você instala o Arch Linux inteiro numa máquina virtual, do botão "Nova" do VirtualBox até um sistema atualizado, com ferramentas de compilação e o yay para o AUR. É o mesmo caminho que o coordenador do guia fez para criar a VM de laboratório: os comandos abaixo são exatamente os que ele rodou, e os "o que você deve ver" são trechos das saídas reais. As explicações ficam nas aulas; aqui é o roteiro para seguir de uma vez, conferindo cada etapa.

Antes de começar
  • Tempo: de 2 a 3 horas na primeira vez (a maior parte esperando downloads). Dá para parar entre etapas: desligue a VM só depois de um ponto de verificação.
  • Precisa de: um computador com 8 GB de RAM ou mais, 35 GB livres em disco, internet e o VirtualBox instalado.
  • Leia antes (ou tenha aberta) a aula de cada etapa: o projeto diz o que fazer; a aula explica por que e o que fazer quando dá errado.
  • No live, os prompts aparecem como root@archiso ~ #; dentro do arch-chroot, como [root@archiso /]#; no sistema instalado, [ana@notebook ~]$.

Etapa 1: a máquina virtual

  1. Crie a VM no VirtualBox com: tipo Linux / Arch Linux (64-bit), 4096 MB de RAM, 2 CPUs, disco 30 GB VDI dinamicamente alocado. Os detalhes e o porquê de cada valor estão em Baixar e Verificar a ISO.
  2. Ligue o EFI: Configurações → Sistema → Placa-mãe → Habilitar EFI. Sem isso, a VM liga em modo BIOS e as etapas 4 e 8 não batem com o guia.
  3. Rede: deixe o padrão (NAT). A VM terá internet pelo seu computador.

O que você deve ver: a VM na lista do VirtualBox, desligada, com "EFI" marcado nas configurações de sistema.

Etapa 2: a ISO conferida

  1. Baixe a ISO mais recente e o sha256sums.txt de um espelho (o guia usou a archlinux-2026.06.01-x86_64.iso).
  2. Confira a soma, na pasta do download: 
    $ sha256sum -c --ignore-missing sha256sums.txt
archlinux-2026.06.01-x86_64.iso: OK
  3. Coloque a ISO no drive óptico da VM (Configurações → Armazenamento).

O que você deve ver: OK (e não FAILED). A conferência com assinatura PGP está na aula Baixar e Verificar a ISO.

Etapa 3: o ambiente live

  1. Ligue a VM e escolha a primeira opção do menu da ISO. Espere o prompt root@archiso ~ #.
  2. Teclado, modo de boot, rede e relógio: 
    #> loadkeys br-abnt2
#> cat /sys/firmware/efi/fw_platform_size
64
#> ping -c 3 archlinux.org
PING archlinux.org (209.126.35.79) 56(84) bytes of data.
64 bytes from 209.126.35.79: icmp_seq=1 ttl=64 time=44.0 ms
…
3 packets transmitted, 3 received, 0% packet loss, time 5616ms
#> timedatectl
               Local time: Fri 2026-10-16 15:01:23 UTC
…
System clock synchronized: yes
              NTP service: active
…

O que você deve ver: 64 (UEFI de 64 bits), 0% packet loss e System clock synchronized: yes. Se o arquivo fw_platform_size não existe, você está em modo BIOS: volte à etapa 1 e ligue o EFI. Aula: O Ambiente Live.

Etapa 4: particionar

Este passo apaga o disco

Na VM o disco está vazio e não há risco. Num computador de verdade, confira três vezes o nome do disco com lsblk antes do w do fdisk.

  1. Ache o disco: 
    #> lsblk
NAME  MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
loop0   7:0    0 986M  1 loop /run/archiso/airootfs
sda     8:0    0  30G  0 disk                         « o disco da VM
sr0    11:0    1 1.5G  1 rom  /run/archiso/bootmnt
  2. Particione com fdisk /dev/sda, digitando estas respostas (cada linha, um Enter; "Enter" sozinho aceita o padrão):
    DigiteO que faz
    gnova tabela GPT
    n, Enter, Enter, +1Gpartição 1, 1 GiB
    t, 1tipo da partição 1: EFI System
    n, Enter, Enter, +4Gpartição 2, 4 GiB
    t, 2, 19tipo da partição 2: Linux swap
    n, Enter, Enter, Enterpartição 3, o resto do disco
    pmostra a tabela (confira!)
    wgrava e sai
    (Na VM do guia, essas respostas foram enviadas ao fdisk com um printf, para gravar a saída; o resultado é o mesmo.)

O que você deve ver no p, antes do w:

Device        Start      End  Sectors Size Type
/dev/sda1      2048  2099199  2097152   1G EFI System
/dev/sda2   2099200 10487807  8388608   4G Linux swap
/dev/sda3  10487808 62912511 52424704  25G Linux filesystem

Três partições: 1G EFI System, 4G Linux swap, 25G Linux filesystem. Aula: Particionar o Disco.

Etapa 5: formatar e montar

  1. Formate (FAT32 na EFI, swap, ext4 na raiz): 
    #> mkfs.fat -F 32 /dev/sda1
mkfs.fat 4.2 (2021-01-31)
#> mkswap /dev/sda2
Setting up swapspace version 1, size = 4 GiB (4294963200 bytes)
no label, UUID=02576132-0458-4975-916f-94e08af9a31c
#> mkfs.ext4 /dev/sda3
mke2fs 1.47.4 (6-Mar-2025)
…
Writing superblocks and filesystem accounting information: done
  2. Monte, a raiz primeiro: 
    #> mount /dev/sda3 /mnt
#> mount --mkdir /dev/sda1 /mnt/boot
#> swapon /dev/sda2

O que você deve ver no lsblk -f (os UUIDs serão outros na sua máquina):

#> lsblk -f
NAME   FSTYPE   FSVER            LABEL       UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
…
sda
|-sda1 vfat     FAT32                        C509-6CB1                              1022M     0% /mnt/boot
|-sda2 swap     1                            02576132-0458-4975-916f-94e08af9a31c                [SWAP]
`-sda3 ext4     1.0                          75d167c8-1dad-4d0a-a0ae-b063058a18e9   23.2G     0% /mnt

As três colunas da direita são o que importa: /mnt/boot, [SWAP], /mnt. Aula: Formatar e Montar.

Etapa 6: espelhos e pacstrap

  1. Escolha os espelhos mais rápidos do Brasil: 
    #> reflector --country Brazil --protocol https --latest 5 --sort rate --save /etc/pacman.d/mirrorlist
[2026-10-16 15:02:03] WARNING: failed to rate http(s) download (https://archlinux.c3sl.ufpr.br/extra/os/x86_64/extra.db): Download timed out after 5 second(s).
[2026-10-16 15:02:09] WARNING: failed to rate http(s) download (https://mirrors.ic.unicamp.br/archlinux/extra/os/x86_64/extra.db): Download timed out after 5 second(s).
    Os WARNING são normais: espelhos lentos na hora do teste ficam de fora.
  2. Instale o sistema base (troque intel-ucode por amd-ucode se o seu processador for AMD): 
    #> pacstrap -K /mnt base linux linux-firmware intel-ucode networkmanager sudo nano vim man-db man-pages texinfo grub efibootmgr openssh
    Se ele perguntar entre provedores (iptables, mkinitcpio), aceite o padrão com Enter.

O que você deve ver: Packages (193) (o número muda com o tempo), Total Download Size: 765.50 MiB, a instalação de cada pacote e, no fim, os ganchos até (18/18) Updating the info directory file..., sem nenhuma linha error no final. Um aviso é esperado no meio: WARNING: sd-vconsole: "/etc/vconsole.conf" not found (resolvido na etapa 7). Aula: Espelhos e pacstrap.

Etapa 7: configurar o sistema

Tudo explicado em Configurar o Sistema. Na VM do guia, cada comando dentro do chroot foi rodado de fora como arch-chroot /mnt comando; aqui está o jeito normal, entrando uma vez.

  1. fstab (uma vez só!), ainda fora do chroot: 
    #> genfstab -U /mnt >> /mnt/etc/fstab
#> cat /mnt/etc/fstab
…
# /dev/sda3
UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9	/         	ext4      	rw,relatime	0 1
…
    Confira: três linhas UUID= (raiz, /boot, swap), cada uma uma vez só.
  2. Entre no sistema novo: 
    #> arch-chroot /mnt
  3. Fuso, idioma, teclado, nome: 
    #> ln -sf /usr/share/zoneinfo/America/Sao_Paulo /etc/localtime
#> hwclock --systohc
#> nano /etc/locale.gen                      « tire o # de en_US.UTF-8 UTF-8 e pt_BR.UTF-8 UTF-8
#> locale-gen
Generating locales...
  en_US.UTF-8... done
  pt_BR.UTF-8... done
Generation complete.
#> echo 'LANG=pt_BR.UTF-8' > /etc/locale.conf
#> echo 'KEYMAP=br-abnt2' > /etc/vconsole.conf
#> echo notebook > /etc/hostname
    Confira: os dois idiomas com done.
  4. initramfs: 
    #> mkinitcpio -P
…
  -> Running build hook: [sd-vconsole]
…
==> Initcpio image generation successful
    Confira: successful e nenhum WARNING do sd-vconsole.
  5. Senhas, usuária e sudo: 
    #> passwd
New password:
Retype new password:
passwd: password updated successfully
#> useradd -m -G wheel -s /bin/bash ana
#> passwd ana
New password:
Retype new password:
passwd: password updated successfully
#> EDITOR=nano visudo                       « tire o # de: %wheel ALL=(ALL:ALL) ALL
#> visudo -c
/etc/sudoers: parsed OK
#> id ana
uid=1000(ana) gid=1000(ana) groups=1000(ana),998(wheel)
  6. Rede (e SSH) no boot: 
    #> systemctl enable NetworkManager sshd

  1. Instale e gere o menu, ainda no chroot:

    #> efibootmgr

Tire um snapshot agora

Antes de reiniciar, é um ótimo momento para um snapshot da VM (Máquina → Criar Snapshot com ela ligada, ou depois de desligar). Se o primeiro boot der errado, você volta a este ponto em segundos. A VM do guia tem os snapshots instalacao-base e pronto-para-aulas.

Etapa 9: primeiro boot

  1. Saia, desmonte, reinicie: 
    #> exit
#> umount -R /mnt
#> reboot
  2. Ejete a ISO (Dispositivos → Discos Ópticos → Remover disco do drive virtual).
  3. Espere o menu do GRUB (5 segundos) e a tela notebook login:. Entre como ana.
  4. Confira: 
    $ hostnamectl
 Static hostname: notebook
…
$ localectl
System Locale: LANG=pt_BR.UTF-8
    VC Keymap: br-abnt2
   X11 Layout: (unset)
$ systemctl --failed
  UNIT LOAD ACTIVE SUB DESCRIPTION

0 loaded units listed.
$ pacman -Q | wc -l
193
$ df -h /
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda3        25G  2.3G   21G  10% /

O que você deve ver: notebook, pt_BR.UTF-8, br-abnt2, zero serviços com falha e uns 2,3 GB usados. O checklist completo (rede, fuso, sudo) está em Primeiro Boot.

Etapa 10: pós-instalação

  1. Ligue o relógio pela internet (a instalação manual não liga; veja Primeiro Boot): sudo timedatectl set-ntp true.
  2. Atualize tudo e instale as ferramentas de compilação e o Git. Na VM do guia, o coordenador fez isso numa transação só, junto com os pacotes das outras aulas; para o projeto, basta: 
    $ sudo pacman -Syu
$ sudo pacman -S --needed base-devel git
    O -Syu sincroniza e atualiza o sistema inteiro (Atualizar o Sistema); o --needed pula o que já estiver instalado. Se o pacman perguntar entre provedores, aceite o padrão.
  3. Instale o yay (ajudante do AUR) compilando o pacote yay-bin: 
    $ mkdir -p ~/aur && cd ~/aur && git clone https://aur.archlinux.org/yay-bin.git
Clonando em 'yay-bin'...
$ cd yay-bin
$ makepkg -s --noconfirm
==> Criando o pacote: yay-bin 13.0.1-1 (sex 16 out 2026 12:59:31)
…
==> Validando source_x86_64 arquivos com sha256sums...
    yay_13.0.1_x86_64.tar.gz ... Passou
…
==> Compilação concluída: yay-bin 13.0.1-1 (sex 16 out 2026 12:59:43)
$ sudo pacman -U yay-bin-*.pkg.tar.zst
…
Pacotes (2) yay-bin-13.0.1-1  yay-bin-debug-13.0.1-1
…
:: Continuar a instalação? [S/n]
…
instalando yay-bin...
    Esses são os comandos da VM do guia (lá, o pacman -U foi rodado como root, com --noconfirm). O makepkg -s baixa e confere a fonte (Passou) e cria o pacote; o pacman -U instala o arquivo .pkg.tar.zst gerado. No dia a dia, makepkg -si faz as duas coisas de uma vez (o -i chama o pacman -U no fim, pedindo a senha do sudo). Antes de compilar qualquer coisa do AUR, leia o PKGBUILD (AUR com Segurança).
  4. Confira: 
    $ yay --version
yay v13.0.1 - libalpm v16.0.1
$ pacman -Qm
yay-bin 13.0.1-1
yay-bin-debug 13.0.1-1
    O pacman -Qm lista os pacotes que não vieram dos repositórios oficiais: os do AUR (o -debug é gerado junto pelo makepkg). Aulas: O que é o AUR, makepkg, yay e paru.

Projeto concluído. Você tem um Arch mínimo, em português, com sudo, rede, GRUB e acesso ao AUR. Próximos projetos: Montar um Desktop KDE e Btrfs com Snapshots Automáticos.

Checklist final

  1. A VM liga sozinha, sem a ISO, e mostra o menu do GRUB.
  2. notebook login: aparece e a ana entra com a senha dela.
  3. localectl mostra pt_BR.UTF-8 e br-abnt2; timedatectl mostra America/Sao_Paulo.
  4. ping -c 3 archlinux.org responde.
  5. systemctl --failed mostra 0 loaded units listed.
  6. sudo whoami responde root.
  7. pacman -Syu diz que não há nada a fazer.
  8. yay --version responde.

Missão: no terminal simulado (que imita a VM do guia já instalada), faça o item 5 do checklist.

Missão: faça a primeira parte do item 3 do checklist: confira idioma e teclado com um comando só (o localectl, ou um cat dos dois arquivos que você escreveu na etapa 7).
