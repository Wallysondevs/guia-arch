Arch tar, zip, gzip

Para mandar uma pasta por e-mail, guardar um backup ou baixar um programa, você vai lidar com arquivos compactados: .tar.gz, .zip, .tar.zst. No Linux, o mais comum é o tar, que parece assustador (tar -czvf?) até você descobrir que cada letra é uma palavra. E no Arch há um bônus: todo pacote que o pacman instala é um arquivo .tar.zst que você pode abrir com o tar.

Você vai aprender
  • A diferença entre empacotar (juntar) e compactar (encolher).
  • O que significa cada letra de tar -czvf, tar -tf e tar -xf.
  • Por que o Arch usa zstd nos pacotes, e como olhar dentro de um .pkg.tar.zst.
  • Compactar um arquivo só com gzip, xz e zstd.
  • Instalar e usar zip/unzip e o 7z, e escolher o formato certo.

O simulador desta página não roda tar, gzip nem zip: as sessões abaixo foram conferidas num Arch real. As missões usam o que o simulador conhece (o pacman e o cache de pacotes). Pratique o resto no seu terminal, numa pasta de teste.

O que já vem instalado

O base do Arch traz o tar e quatro compactadores. Todos são dependências do próprio sistema (o pacman precisa do zstd para abrir os pacotes):

$ pacman -Q tar gzip bzip2 xz zstd
tar 1.35-5
gzip 1.15-1
bzip2 1.0.8-6
xz 5.8.4-1
zstd 1.5.7-3

O zip, o unzip e o 7z não vêm:

$ zip -r site.zip site
bash: zip: comando não encontrado
$ unzip fotos.zip
bash: unzip: comando não encontrado
$ 7z
bash: 7z: comando não encontrado

Mais abaixo você vê como instalar. Para trabalhar só entre máquinas Linux, o tar basta.

Empacotar não é compactar

Pense numa mudança de casa. Empacotar é pôr tudo numa caixa só, para não perder nada. Compactar é tirar o ar da caixa, como num saco a vácuo, para ela ocupar menos espaço. No Linux, cada tarefa costuma ter o seu programa:

TarefaO que fazProgramaResultado
EmpacotarJunta muitos arquivos e pastas num arquivo só, sem encolhertarsite.tar
CompactarEncolhe um arquivogzip, bzip2, xz, zstdlog.gz
As duas coisasEmpacota e compacta em seguidatar com z, j, J ou --zstdsite.tar.gz
As duas coisasEmpacota e compacta, formato do Windowszip, 7zsite.zip

Por isso a extensão .tar.gz tem duas partes: "um pacote tar, compactado com gzip". A forma curta .tgz significa a mesma coisa.

Criar um .tar.gz

A pasta site tem uma página, um CSS e um rascunho. Vamos empacotar e compactar tudo:

tar
O programa (de tape archive, "arquivo em fita", da época dos backups em fita magnética).
-c
criar um pacote novo (create).
z
compactar com gzip.
v
verboso: mostrar cada arquivo enquanto trabalha.
f site.tar.gz
file: o nome do arquivo a criar. O nome vem logo depois do f, por isso o f fica por último.
site
O que colocar dentro: pastas e arquivos, quantos quiser.
$ tar -czvf site.tar.gz site
site/
site/css/
site/css/style.css
site/rascunho.tmp
site/index.html
$ ls -lh site.tar.gz
-rw-r--r-- 1 ana ana 247 16 out 15:05 site.tar.gz

As linhas que aparecem são o efeito do v: o tar conta o que está guardando. Sem o v, ele trabalha em silêncio e só a volta do prompt avisa que acabou (código 0). A ordem dos arquivos é a do disco, não alfabética.

Como decorar

criar · zipado · vendo · file. E para extrair, troque o c pelo x: extrair · zipado · vendo · file. O hífen é opcional: tar czvf funciona igual.

Deixar arquivos de fora: --exclude

$ tar -czf site.tar.gz --exclude="*.tmp" site
$ tar -tzf site.tar.gz
site/
site/css/
site/css/style.css
site/index.html                      « o rascunho.tmp ficou de fora

Conferir antes de extrair: -t

Antes de abrir um pacote que você baixou, veja o que tem dentro. O t (de table of contents, "sumário"; a forma longa é --list) mostra o conteúdo sem extrair nada:

tar
O programa.
-t
Listar o conteúdo.
f site.tar.gz
De qual arquivo.
$ tar -tf site.tar.gz
site/
site/css/
site/css/style.css
site/index.html

Por que isso importa? Alguns pacotes têm tudo dentro de uma pasta (site/…), e outros têm os arquivos soltos. Extrair um pacote "solto" na pasta Downloads espalha dezenas de arquivos misturados com os seus. Olhando antes, você sabe se precisa criar uma pasta para ele.

Com v, a lista vem com detalhes, como um ls -l:

$ tar -tvf site.tar.gz
drwxr-xr-x ana/ana           0 2026-10-16 15:05 site/
drwxr-xr-x ana/ana           0 2026-10-16 15:05 site/css/
-rw-r--r-- ana/ana           5 2026-10-16 15:05 site/css/style.css
-rw-r--r-- ana/ana          14 2026-10-16 15:05 site/index.html
ColunaSignificado
drwxr-xr-xTipo e permissões, guardadas dentro do pacote (o tar preserva as permissões; o zip, nem sempre)
ana/anaDono e grupo
14Tamanho em bytes (pastas mostram 0)
2026-10-16 15:05Data de modificação, no formato ano-mês-dia
site/index.htmlO caminho dentro do pacote

Extrair: -x

tar
O programa.
-x
extrair (extract).
v
Mostrar cada arquivo.
f site.tar.gz
O pacote.
-C restaurado
Extrair dentro da pasta restaurado (de change directory). A pasta precisa existir. Sem o -C, extrai na pasta atual.
$ mkdir restaurado
$ tar -xvf site.tar.gz -C restaurado
site/
site/css/
site/css/style.css
site/index.html
$ ls restaurado
site
Não precisa dizer o tipo de compactação para extrair

Para criar, você diz z, j, J ou --zstd. Para extrair e listar, o GNU tar descobre o tipo sozinho, pelo conteúdo: tar -xf arquivo.tar.zst funciona. Escrever a letra também funciona, desde que seja a certa (veja os erros no fim da página).

Extrair sobrescreve sem perguntar

Se já existir um arquivo com o mesmo nome no destino, o tar substitui pelo do pacote, em silêncio. Por isso, extraia numa pasta nova com -C quando não tiver certeza.

Extrair só um arquivo

Coloque o caminho, exatamente como aparece no tar -tf, no fim do comando:

$ tar -xf ../site.tar.gz site/index.html
$ ls site
index.html

Os pacotes do Arch são .tar.zst

Aqui o Arch fica interessante. Quando o pacman baixa um programa, ele guarda o arquivo no cache, /var/cache/pacman/pkg/. Olhe a extensão:

$ ls -l /var/cache/pacman/pkg/which-*
-rw-r--r-- 1 root root 16798 31 mai 05:37 /var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst
-rw-r--r-- 1 root root   310 31 mai 05:37 /var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst.sig

.pkg.tar.zst = "um pacote do Arch, que é um tar compactado com zstd". (O .sig ao lado é a assinatura digital; veja Chaves e Assinaturas.) Como é um tar comum, você pode listar o conteúdo com tar -tf, sem instalar nada e sem sudo:

$ tar -tf /var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst
.BUILDINFO                         « como o pacote foi compilado
.MTREE                             « lista de arquivos com somas de verificação
.PKGINFO                           « a "ficha" do pacote
usr/
usr/bin/
usr/bin/which                      « o programa em si
usr/share/
usr/share/info/
usr/share/info/which.info.gz
usr/share/man/
usr/share/man/man1/
usr/share/man/man1/which.1.gz      « o manual (compactado com gzip!)

Os caminhos não começam com /: o pacman extrai tudo a partir da raiz do sistema, então usr/bin/which vira /usr/bin/which. Os três arquivos com ponto são do próprio pacman. O -O (letra o maiúscula, de output) extrai um arquivo para a tela em vez do disco; assim você lê a ficha sem criar nada:

$ tar -xOf /var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst .PKGINFO
# Generated by makepkg 7.1.0
# using fakeroot version 1.38.1
pkgname = which
pkgbase = which
xdata = pkgtype=pkg
pkgver = 2.25-1
pkgdesc = A utility to show the full path of commands
url = https://savannah.gnu.org/projects/which/
builddate = 1780216630
packager = Tobias Powalowski <tpowa@archlinux.org>
size = 31290
arch = x86_64
license = GPL-3.0-or-later
depend = bash
depend = glibc

É dessa ficha que o pacman -Qi tira a versão, a descrição e as dependências. E repare: o pacote de 16 KiB guarda 31 KiB de arquivos (size = 31290), quase a metade.

Os pacotes que você compila do AUR saem no mesmo formato. Quem decide é o /etc/makepkg.conf (veja makepkg):

$ grep -E "^(PKGEXT|SRCEXT|COMPRESSZST)" /etc/makepkg.conf
COMPRESSZST=(zstd -c -T0 -)        « -T0 = usar todos os núcleos do processador
PKGEXT='.pkg.tar.zst'              « pacotes: tar + zstd
SRCEXT='.src.tar.gz'               « pacotes de código-fonte: tar + gzip
$ file /var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst
/var/cache/pacman/pkg/which-2.25-1-x86_64.pkg.tar.zst: Zstandard compressed data (v0.8+), Dictionary ID: None
Por que zstd?

Até o fim de 2019 o Arch usava .pkg.tar.xz. A troca para o zstd foi feita porque ele descompacta muito mais rápido, com um tamanho só um pouco maior. Para quem atualiza o sistema toda semana, centenas de pacotes, isso faz diferença. Você vai ver os números no teste mais abaixo.

Olhar, sim; instalar à mão, não

Extrair um pacote com sudo tar -xf … -C / coloca os arquivos no sistema sem o pacman saber: ele não registra, não confere conflitos e não sabe remover depois. Para instalar um arquivo de pacote, use sudo pacman -U arquivo.pkg.tar.zst (veja pacman Avançado).

Missão 1: encontre no cache do pacman (/var/cache/pacman/pkg) o arquivo do pacote which. Dica: ls da pasta, com um | grep which (veja grep). Qual é a extensão dele?

Missão 2: confirme no /etc/makepkg.conf qual extensão o makepkg usa para os pacotes que ele cria. Procure a linha PKGEXT com o grep.

gzip, bzip2, xz ou zstd?

A opção do tar escolhe o compactador. Cada um equilibra de um jeito o tamanho final e a velocidade:

Opção do tarCompactadorExtensãoTamanhoVelocidadeUso típico
zgzip.tar.gzBomRápidoO mais compatível: abre em qualquer sistema
jbzip2.tar.bz2MelhorLentoArquivos antigos; hoje quase ninguém escolhe
Jxz.tar.xzO menorO mais lento para criarDistribuir código-fonte, arquivar por muito tempo
--zstdzstd.tar.zstBomO mais rápido, principalmente para extrairOs pacotes do Arch; backups frequentes

Um teste real, com uma pasta de 8,6 MB de texto (a lista de todos os arquivos dos pacotes instalados, pacman -Ql, mais o log do boot). O time na frente mede quanto cada comando demorou (a linha real; as linhas user e sys foram cortadas com …):

Fotos, vídeos e .zip já vêm compactados

JPG, MP4, MP3 e PDF já são formatos comprimidos. Compactar de novo economiza quase nada. Para eles, um .tar sem compactação (tar -cf) é mais rápido e dá praticamente o mesmo tamanho. Texto (logs, CSV, código) é o que mais encolhe: aqui, 91%.

Deixar o tar escolher: -a

Com -a (auto-compress), o tar escolhe o compactador pela extensão do nome que você deu. O file confirma o tipo real de cada um, pelo conteúdo:

$ tar -caf auto.tar.zst site
$ file site.tar.gz site.tar.xz site.tar.bz2 site.tar.zst auto.tar.zst
site.tar.gz:  gzip compressed data, from Unix, original size modulo 2^32 10240
site.tar.xz:  XZ compressed data, checksum CRC64
site.tar.bz2: bzip2 compressed data, block size = 900k
site.tar.zst: Zstandard compressed data (v0.8+), Dictionary ID: None
auto.tar.zst: Zstandard compressed data (v0.8+), Dictionary ID: None

gzip, xz e zstd sozinhos: um arquivo só

Para encolher um único arquivo, como um log, não precisa de tar:

$ ls -l acesso.log
-rw-r--r-- 1 ana ana 389 16 out 15:05 acesso.log
$ gzip acesso.log
$ ls -l acesso.log*
-rw-r--r-- 1 ana ana 173 16 out 15:05 acesso.log.gz    « o original sumiu
$ gunzip acesso.log.gz
$ ls acesso.log*
acesso.log
$ gzip -k acesso.log
$ ls -l acesso.log*
-rw-r--r-- 1 ana ana 389 16 out 15:05 acesso.log
-rw-r--r-- 1 ana ana 173 16 out 15:05 acesso.log.gz    « com -k os dois ficam
$ gzip -l acesso.log.gz
         compressed        uncompressed  ratio uncompressed_name
                173                 389  63,0% acesso.log

Por padrão, o gzip substitui o original pela versão .gz. Para manter os dois, use -k (de keep, "manter"). O -l (list) mostra quanto encolheu: 63% (com vírgula, por causa do pt_BR). Para ler um .gz sem descompactar, use zcat, zless ou zgrep, as versões "z" de cat, less e grep:

$ zcat acesso.log.gz | head -2
192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
$ zgrep -c 404 acesso.log.gz
1

O xz funciona igual ao gzip (xz, unxz, xz -k, xzcat). O zstd tem duas diferenças: ele mostra o resultado, e ele mantém o original (o contrário do gzip). Para apagar o original, use --rm:

$ xz acesso.log
$ ls -l acesso.log*
-rw-r--r-- 1 ana ana 212 16 out 15:05 acesso.log.xz
$ unxz acesso.log.xz
$ zstd acesso.log
acesso.log           : 40.62%   (   389 B =>    158 B, acesso.log.zst)
$ ls -l acesso.log*
-rw-r--r-- 1 ana ana 389 16 out 15:06 acesso.log      « o original continua
-rw-r--r-- 1 ana ana 158 16 out 15:06 acesso.log.zst
$ zstd --rm -f acesso.log
acesso.log           : 40.62%   (   389 B =>    158 B, acesso.log.zst)
$ ls acesso.log*
acesso.log.zst
$ zstd -d acesso.log.zst
acesso.log.zst      : 389 bytes

O 40.62% do zstd é o tamanho final em relação ao original (o arquivo ficou com 40% do tamanho). O 63,0% do gzip -l é o contrário: quanto foi economizado. E o zstd escreve o número com ponto, sem seguir o pt_BR. Para descompactar: zstd -d, unzstd; para ler: zstdcat.

-l lista (como o tar -t) e -d escolhe a pasta de destino (como o tar -C, mas aqui a pasta é criada se não existir). Diferente do tar, se você extrair de novo no mesmo lugar, o unzip pergunta antes de sobrescrever:

$ unzip site.zip
Archive:  site.zip
replace site/css/style.css? [y]es, [n]o, [A]ll, [N]one, [r]ename: N

Responda y (sim), n (não), A (sim para todos), N (não para todos) ou r (extrair com outro nome). Para sobrescrever sem perguntar, use unzip -o. Para proteger com senha, use zip -e -r segredo.zip pasta: ele pergunta a senha duas vezes (Enter password: e Verify password:).

Para acrescentar um arquivo a um zip que já existe, é o mesmo comando; para tirar um, -d:

$ zip site.zip Documentos/notas.txt
  adding: Documentos/notas.txt (stored 0%)
$ zip -d site.zip site/rascunho.tmp            « -d = delete: tira de dentro do zip
deleting: site/rascunho.tmp

O .7z é comum em downloads do Windows. No Arch, o pacote se chama 7zip (é o 7-Zip oficial, que substituiu o antigo p7zip):

Quando não funciona

"Recusando a criar um arquivo-tar vazio" 
$ tar -czf backup.tar.gz
tar: Recusando a criar um arquivo-tar vazio
Tente "tar --help" ou "tar --usage" para mais informações.
$ echo $?
2

O que aconteceu: faltou dizer o que colocar no pacote.

Como resolver: acrescente as pastas ou arquivos no fim: tar -czf backup.tar.gz Documentos.

"a opção exige um argumento -- "f"" 
$ tar -czvf
tar: a opção exige um argumento -- "f"
Tente "tar --help" ou "tar --usage" para mais informações.

O que aconteceu: o f espera o nome do arquivo logo em seguida. Também acontece com tar -cfzv nome: aí o tar acha que o arquivo se chama "zv".

Como resolver: deixe o f por último, colado ao nome: -czvf nome.tar.gz.

"Este não parece ser um arquivo-tar" 
$ tar -xf site.zip
tar: Este não parece ser um arquivo-tar
tar: Pulando para o próximo cabeçalho
tar: Saindo com status de falha em razão de erros anteriores

O que aconteceu: o arquivo não é um pacote tar. Aqui é um .zip; às vezes é um download que não terminou, ou um arquivo com a extensão errada.

Como confirmar: file arquivo diz o tipo real, pelo conteúdo. Como resolver: use o programa certo (unzip, 7z).

"gzip: stdin: not in gzip format" 
$ tar -xzf site.tar.zst

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error is not recoverable: exiting now

O que aconteceu: o z mandou o tar usar o gzip, mas o arquivo é zstd. É comum ao copiar um comando antigo (-xzf) para um arquivo moderno.

Como resolver: tire a letra e deixe o tar descobrir: tar -xf site.tar.zst.

Erro com "(child)" ao extrair 
$ tar -xzf projeto.tar.gz
tar (child): projeto.tar.gz: Função open falhou: Arquivo ou diretório inexistente
tar (child): Error is not recoverable: exiting now
tar: Child returned status 2
tar: Error is not recoverable: exiting now

O que aconteceu: o arquivo não existe na pasta atual. "child" (filho) é o gzip que o tar chamou para descompactar; o erro aparece duas vezes, uma de cada programa, metade em inglês.

Como resolver: confira com ls e use Tab para completar o nome.

"Removendo "/" inicial dos nomes dos membros" 
$ tar -czf hostname.tar.gz /etc/hostname
tar: Removendo "/" inicial dos nomes dos membros
$ tar -tf hostname.tar.gz
etc/hostname

O que aconteceu: não é erro, é um aviso de segurança. O tar guarda etc/hostname em vez de /etc/hostname, para que, ao extrair, o arquivo vá para a pasta atual e não sobrescreva o do sistema. (Os pacotes do Arch são feitos do mesmo jeito, sem a barra.)

"zip: comando não encontrado" / "cannot find or open" 
$ zip -r site.zip site
bash: zip: comando não encontrado
$ unzip fotos.zip
unzip:  cannot find or open fotos.zip, fotos.zip.zip or fotos.zip.ZIP.

O que aconteceu: no primeiro, os pacotes zip e unzip não vêm no Arch. No segundo, o unzip existe, mas o arquivo não está na pasta atual (talvez em Downloads).

Como resolver: sudo pacman -S zip unzip; e unzip ~/Downloads/fotos.zip -d ~/fotos.

"already exists; not overwritten" 
$ gzip acesso.log
gzip: acesso.log.gz already exists;	not overwritten
$ echo $?
2

O que aconteceu: já existe um acesso.log.gz (de um gzip -k anterior). O gzip não apaga nada sem você pedir.

Como resolver: apague ou renomeie o .gz antigo, ou force com gzip -f.

Resumo

  • tar empacota; gzip/xz/zstd compactam; .tar.gz é "pacote compactado".
  • Criar: tar -czvf nome.tar.gz pasta (criar · gzip · ver · file). Conferir: tar -tf. Extrair: tar -xf nome -C destino.
  • O f vem por último, colado ao nome do arquivo; para extrair, o tar descobre o compactador sozinho.
  • Todo pacote do Arch é um .pkg.tar.zst: dá para olhar dentro com tar -tf e ler a ficha com tar -xOf … .PKGINFO.
  • zstd: o mais rápido; xz: o menor; gzip: o mais compatível. O gzip apaga o original; o zstd, não.
  • zip, unzip e 7z não vêm no Arch: sudo pacman -S zip unzip 7zip.
