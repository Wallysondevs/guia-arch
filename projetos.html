Arch Como Usar os Projetos

As aulas ensinam uma peça por vez. Os projetos juntam as peças para construir algo inteiro: um Arch instalado do zero, um desktop KDE, um sistema com snapshots automáticos, um pacote seu, um servidor caseiro. É aqui que o conhecimento "gruda", porque você precisa decidir a ordem, conferir cada passo e consertar o que der errado.

Você vai aprender
  • O que cada projeto constrói e quais aulas ele usa.
  • Por que fazer os projetos numa máquina virtual (e como montá-la com UEFI).
  • Usar snapshots para voltar no tempo quando algo quebrar.
  • Uma ordem sugerida e como registrar o que você fez.

A regra de ouro: numa máquina virtual

Uma máquina virtual é um computador simulado dentro do seu. Se você apagar a partição errada ou estragar o GRUB lá dentro, o seu computador de verdade nem percebe. E com snapshots você volta ao minuto anterior ao erro.

Não faça os projetos na sua máquina principal

O projeto de instalação apaga o disco inteiro; o de snapshots refaz a raiz; o de servidor mexe em firewall e SSH. Numa VM, isso é aprendizado. No seu notebook, pode ser a perda dos seus arquivos.

Todo este guia foi conferido numa VM assim: VirtualBox 7.2, chamada arch-guia, com o Arch real dentro. As configurações dela, vistas do computador de fora:

ostype="Arch Linux (64-bit)"
memory=4096
firmware="EFI"
cpus=2
nested-hw-virt="off"

Montar a sua VM

  1. Instale um programa de VMs. No Linux, o virt-manager (QEMU/KVM) é o mais rápido; o VirtualBox funciona em Linux, Windows e macOS. Os passos abaixo usam o VirtualBox.
  2. Baixe a ISO do Arch e confira a assinatura, como em Baixar e Verificar a ISO.
  3. Crie a VM: Novo → nome arch-lab, tipo Linux, versão "Arch Linux (64-bit)", a ISO, e marque Pular instalação desassistida. Memória: 4 GB (2 GB bastam sem desktop). Processadores: 2. Disco: 30 GB (o arquivo só cresce conforme o uso).
  4. Ligue a UEFI: Configurações → Sistema → Placa-mãe → Habilitar EFI. Sem isso, a VM dá boot em modo BIOS e as aulas de particionamento e bootloader (UEFI) não batem.
  5. Rede: deixe "NAT". Para entrar por SSH a partir do computador de fora, crie um redirecionamento de porta (Rede → Avançado → Redirecionamento de portas: TCP, porta do hospedeiro 2222 → porta do convidado 22).

Snapshots: o botão "desfazer"

Um snapshot congela o estado da VM inteira (disco e configurações). A VM do guia tem dois, um dentro do outro:

   Name: instalacao-base (UUID: 526cee97-99c6-4dc3-bde3-36ed514395ed)
   Description: Arch recém-instalado (pacstrap base + GRUB), usuária ana, antes dos pacotes das aulas
      Name: pronto-para-aulas (UUID: e0a7beac-eb36-4871-bd99-c26e9d4f1b48) *
      Description: Base + pacotes das aulas + pasta da ana igual à máquina fictícia (frutas.txt, Documentos, Downloads…). Estado para os autores.

O * marca o snapshot atual. Pelo terminal do computador de fora (com a VM desligada para restaurar):

Quero…Comando (no hospedeiro)
Tirar um snapshotVBoxManage snapshot arch-lab take antes-do-projeto --description "texto"
ListarVBoxManage snapshot arch-lab list
Voltar a um snapshotVBoxManage snapshot arch-lab restore antes-do-projeto
Apagar um snapshot (o estado atual fica)VBoxManage snapshot arch-lab delete antes-do-projeto

No VirtualBox gráfico: selecione a VM → ícone de lista → Snapshots → Tirar / Restaurar. No virt-manager: botão "Gerenciar snapshots" (o disco precisa ser qcow2).

Um snapshot por projeto

Tire um snapshot antes de cada projeto, com um nome claro (antes-desktop, antes-servidor). Se travar num passo, você volta e tenta de novo, sem medo. Snapshot da VM não substitui o que você aprende em Snapshots (snapper): lá o próprio Arch volta no tempo, sem programa de fora, o que serve também na máquina real.

Ordem sugerida

  1. Instalação Completa do Zero: a base de todos os outros. Tire um snapshot no fim ("arch-limpo").
  2. Montar um Desktop KDE (se você quer usar o Arch no dia a dia) ou pule direto para o servidor.
  3. Servidor Caseiro: a partir do "arch-limpo", sem interface gráfica.
  4. Btrfs com Snapshots Automáticos: pede uma instalação nova com Btrfs (outra VM ou outro disco virtual).
  5. Empacotar um Programa Seu: em qualquer uma das VMs.

Como trabalhar num projeto

  • Leia o passo inteiro antes de digitar. Principalmente os div.warning.
  • Confira a saída. Cada passo diz o que deve aparecer. Se aparecer outra coisa, pare: o erro do passo 3 vira o mistério do passo 9.
  • Anote. Um arquivo ~/diario.txt com o que você mudou (arquivo, linha, por quê) torna fácil desfazer e repetir.
  • Desfaça no fim (ou restaure o snapshot), para o próximo projeto começar do estado conhecido.
  • Quando travar: leia a mensagem inteira, procure-a em Solução de Problemas e na Arch Wiki.
Ilustrativo × real

Em todo o guia, as saídas de terminal vêm da VM real. Quando um passo não pôde ser executado lá (instalar um desktop inteiro, mexer em chaves do firmware, um domínio de verdade), o texto avisa que é ilustrativo e mostra o tamanho real da instalação com uma prévia do pacman respondida com "não".

Resumo

  • Cinco projetos: instalação, desktop KDE, Btrfs com snapshots, pacote próprio, servidor caseiro.
  • Sempre numa VM com EFI ligado, 2–4 GB de RAM e 30 GB de disco.
  • Snapshot antes de cada projeto; restaure quando travar.
  • Leia o passo, confira a saída, anote, desfaça no fim.
