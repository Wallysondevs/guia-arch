Microcode

O processador também tem um "programa" por dentro: o microcode. Intel e AMD lançam correções para ele, contra defeitos e falhas de segurança (como Spectre e Meltdown). Essas correções podem vir numa atualização da BIOS ou ser entregues pelo Linux a cada boot. No Arch, são os pacotes intel-ucode e amd-ucode, e instalar o certo faz parte da instalação.

Você vai aprender
  • O que é microcode e por que a atualização precisa ser carregada em todo boot.
  • Escolher entre intel-ucode e amd-ucode.
  • Os dois caminhos pelos quais ele entra no boot: a linha initrd do GRUB e o hook microcode do mkinitcpio.
  • Conferir se carregou com journalctl -k --grep=microcode, e entender o que a máquina da ana mostra.

O que é microcode

As instruções que os programas mandam para o processador (somar, copiar, comparar) são executadas, lá dentro, por uma camada de pequenos passos internos. Essa camada é o microcode. Ele vem gravado no chip, mas pode ser substituído temporariamente por uma versão corrigida, carregada logo no início do boot.

  • Temporário: a correção fica na memória do processador e some ao desligar. Por isso precisa ser carregada em todo boot.
  • Cedo: quanto antes, melhor; o ideal é antes de o kernel começar a usar os recursos que a correção muda. Por isso ele vai junto com o initramfs, na parte chamada early (cedo).
  • Sem risco de "estragar" o processador: nada é gravado no chip. Se algo der errado, basta não carregar.

intel-ucode ou amd-ucode?

Depende só do fabricante do processador. Descubra com:

$ grep -m1 "model name" /proc/cpuinfo
model name	: Intel(R) Xeon(R) CPU E5-2630 v4 @ 2.20GHz

/proc/cpuinfo é um arquivo virtual com os dados de cada núcleo; -m1 para na primeira linha encontrada. O processador da máquina da ana (na verdade, o do computador onde a máquina virtual roda) é Intel.

O pacote traz o microcode de duas formas: arquivos separados por modelo (família-modelo-revisão em hexadecimal, como 06-05-00) e um /boot/intel-ucode.img, que é um pequeno arquivo cpio com tudo dentro de GenuineIntel.bin, no caminho exato onde o kernel procura o microcode "cedo".

Como ele entra no boot

Na máquina da ana, por dois caminhos ao mesmo tempo. Os dois funcionam; ter os dois não atrapalha.

Caminho 1: o GRUB carrega o intel-ucode.img

Quando a ana rodou o grub-mkconfig na instalação, ele achou o arquivo e o colocou na linha do initramfs, antes dele:

#> arch-chroot /mnt grub-mkconfig -o /boot/grub/grub.cfg
Generating grub configuration file ...
Found linux image: /boot/vmlinuz-linux
Found initrd image: /boot/intel-ucode.img /boot/initramfs-linux.img      « microcode primeiro
…

No menu gerado, cada entrada tem uma linha initrd com os dois arquivos, nesta ordem:

$ grep -E '^\s+(linux|initrd)\s' /boot/grub/grub.cfg
	linux	/vmlinuz-linux root=UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9 rw  loglevel=3 quiet
	initrd	/intel-ucode.img /initramfs-linux.img
		linux	/vmlinuz-linux root=UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9 rw  loglevel=3 quiet
		initrd	/intel-ucode.img /initramfs-linux.img
		linux	/vmlinuz-linux-lts root=UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9 rw  loglevel=3 quiet
		initrd	/intel-ucode.img /initramfs-linux-lts.img

O GRUB junta os arquivos da linha initrd um atrás do outro na memória; o kernel encontra o microcode logo no começo. Os caminhos começam em / porque, para o GRUB, a raiz é a própria partição /boot.

Instalou o microcode depois? Rode o grub-mkconfig

O grub-mkconfig só acrescenta o intel-ucode.img se ele existir quando você rodar o comando. Se você instalar o pacote depois, rode de novo sudo grub-mkconfig -o /boot/grub/grub.cfg. No systemd-boot, a linha initrd /intel-ucode.img vai à mão no arquivo de entrada, antes da linha do initramfs (veja Bootloader).

Caminho 2: o hook microcode do mkinitcpio

O HOOKS padrão do /etc/mkinitcpio.conf tem o hook microcode (veja mkinitcpio). Ele põe o microcode dentro do próprio initramfs, numa parte separada, sem compressão, chamada early CPIO:

$ mkinitcpio -H microcode
==> Help for hook 'microcode':
This hook adds early microcode update files for Intel and AMD processors. If
individual microcode files exist in /lib/firmware/, they are included in a
uncompressed initramfs image which is prepended to the main initramfs image.
If individual microcode files are not available, but /boot/amd-ucode.img or
/boot/intel-ucode.img exist, they are extracted and used instead.

If the autodetect hook runs before this hook, it will only add early microcode
update files for the processor of the system the image is built on.

Em português: o hook copia os arquivos por modelo de /usr/lib/firmware/ para uma imagem não comprimida, colocada na frente do initramfs. E, como o autodetect vem antes dele na ana, entra só o arquivo do processador desta máquina. É a linha que você vê no mkinitcpio -P: -> Early uncompressed CPIO image generation successful.

Conferir se carregou

As mensagens do kernel ficam no journal. Para filtrar só as do microcode:

journalctl
Lê o journal (veja Logs).
-k
kernel: só mensagens do kernel, do boot atual.
--grep=microcode
Só as linhas com essa palavra (sem diferenciar maiúsculas).
$ sudo journalctl -k --grep=microcode
out 16 13:06:28 archlinux kernel: x86/CPU: Model not found in latest microcode list
$ sudo dmesg | grep -i microcode
[    0.000000] x86/CPU: Model not found in latest microcode list

O dmesg (display messages) mostra o mesmo registro do kernel, contando o tempo em segundos desde o boot. O nome archlinux no journal, em vez de notebook, não é erro: no instante zero do boot o nome da máquina ainda não foi definido.

O que essa mensagem quer dizer

O kernel guarda uma tabela com a versão de microcode mais recente de cada modelo de processador, para avisar quem está com microcode velho. Model not found in latest microcode list quer dizer: "este modelo não está na tabela, não sei dizer se o seu microcode é o mais novo". Não é um erro e não impede nada. E, na máquina da ana, nenhuma atualização foi carregada, por dois motivos que dá para conferir:

  1. É uma máquina virtual. Quem manda no processador é o computador hospedeiro; o Linux não aplica microcode dentro de uma VM. O sinal disso é a marca hypervisor nos dados do processador, e a ausência da pasta de microcode no /sys: 
    $ grep -m1 "^flags" /proc/cpuinfo | tr " " "\n" | grep -c hypervisor
1
$ grep -m1 "^microcode" /proc/cpuinfo
microcode	: 0xb000040
$ cat /sys/devices/system/cpu/cpu0/microcode/version
cat: /sys/devices/system/cpu/cpu0/microcode/version: Arquivo ou diretório inexistente

    O 0xb000040 é a versão que o processador informa (a do hospedeiro).

  2. Não há arquivo para este modelo no pacote. Família 6, modelo 79, revisão 1 dá o nome 06-4f-01 (79 em hexadecimal é 4f), e o pacote não traz esse arquivo. Por isso a parte early do initramfs da ana não tem microcode nenhum: 
    $ grep -m4 -E "^(cpu family|model|stepping)" /proc/cpuinfo
cpu family	: 6
model		: 79
model name	: Intel(R) Xeon(R) CPU E5-2630 v4 @ 2.20GHz
stepping	: 1
$ ls /usr/lib/firmware/intel-ucode | grep 06-4f
$ lsinitcpio --early /boot/initramfs-linux.img | grep -i microcode
$ echo $?
1

Num computador de verdade (ilustrativo)

Num notebook ou PC, fora de máquina virtual, com um processador que recebeu correção, o mesmo comando mostra algo parecido com isto (os números mudam de máquina para máquina):

$ sudo journalctl -k --grep=microcode
out 16 09:12:03 notebook kernel: microcode: Current revision: 0x000000fa
out 16 09:12:03 notebook kernel: microcode: Updated early from: 0x000000f4

Updated early from = a versão gravada no chip era a f4, e o Linux carregou a fa no início do boot. Se aparecer só Current revision, o chip (ou a BIOS) já tinha a versão mais nova que o pacote oferece: também está certo.

Quando não funciona

Nenhuma linha sobre microcode

O que aconteceu: o pacote não está instalado, ou o initramfs/menu foram gerados antes dele.

Como confirmar: pacman -Q intel-ucode amd-ucode, ls /boot e grep initrd /boot/grub/grub.cfg.

Como resolver: instale o pacote do seu fabricante, rode sudo mkinitcpio -P e sudo grub-mkconfig -o /boot/grub/grub.cfg, e reinicie.

"Model not found in latest microcode list"

O que aconteceu: o kernel não conhece a versão mais recente para o seu modelo. Comum em máquinas virtuais e em processadores muito antigos ou muito novos.

Como resolver: nada a fazer. Mantenha o pacote atualizado com o sistema (Atualizar o Sistema) e, num computador de verdade, a BIOS também.

Instalei o pacote errado (amd-ucode num Intel)

O que aconteceu: nada de ruim: o processador ignora microcode de outro fabricante. Só não houve atualização.

Como resolver: instale o certo; o outro pode ser removido com sudo pacman -Rns amd-ucode (e um grub-mkconfig para tirá-lo do menu).

Resumo

  • Microcode é a camada interna do processador; as correções da Intel/AMD são carregadas na memória a cada boot.
  • Intel → intel-ucode; AMD → amd-ucode. A ana tem o intel-ucode 20260925-1.
  • Ele entra pela linha initrd do GRUB (gerada pelo grub-mkconfig) e pelo hook microcode do mkinitcpio.
  • Confira com sudo journalctl -k --grep=microcode. Numa máquina virtual, nada é atualizado: é normal.
