Arch rm e rmdir

O rm apaga arquivos (e, com uma opção, pastas inteiras), e o rmdir apaga pastas vazias. Os dois são rápidos e quase nunca pedem confirmação. Por isso esta aula ensina, junto com os comandos, os hábitos que evitam apagar o que não devia.

No terminal não há lixeira

O que o rm apaga não vai para a lixeira do desktop e não volta com "desfazer". Antes de qualquer rm, confira o que vai sair. Se você quer uma segunda chance, use a lixeira pelo terminal, mostrada no fim desta aula.

Você vai aprender
  • Apagar arquivos com rm e pastas com rmdir e rm -r.
  • Pedir confirmação com -i e -I, e por que o -f é perigoso.
  • Apagar um arquivo cujo nome começa com -, usando --.
  • O perigo do rm -rf com uma variável vazia, e a proteção que existe (e a que não existe).
  • Mandar para a lixeira pelo terminal, com gio trash ou com o pacote trash-cli.

Os exemplos foram feitos num Arch Linux real (coreutils 9.12), numa pasta de treino chamada lixo, dentro da pasta pessoal da ana.

A ideia: apagar é tirar o nome da lista

Uma pasta é como o índice de um livro: uma lista de nomes que apontam para os dados guardados no disco. O rm risca o nome do índice. Quando nenhum nome aponta mais para aqueles dados, o espaço que eles ocupavam fica marcado como livre e logo é reaproveitado por outros arquivos. Na prática: o arquivo some na hora, e não há um "lugar" de onde trazê-lo de volta.

Por isso, para apagar um arquivo você precisa de permissão para escrever na pasta que o contém (é a lista dela que muda), e não necessariamente no arquivo. Veja Entendendo Permissões.

rm: apagar arquivos

rm vem de remove, "remover".

rm
O programa que apaga.
a.txt
O arquivo a apagar. Podem ser vários: rm a.txt b.txt.
$ ls
a.txt  b.txt  cheio.txt  c.log  d.log  e.log  f.log  foto.jpg  vazia  velho
$ rm a.txt
$ echo $?
0                                  « 0 = apagado, sem aviso nenhum
$ rm -v b.txt
removido 'b.txt'                   « com -v, o rm conta o que fez

O que o comando devolve quando falha

$ rm nada
rm: não foi possível remover 'nada': Arquivo ou diretório inexistente
$ echo $?
1

Silêncio e código 0 = apagado. Mensagem e código 1 = algo deu errado (aqui, o arquivo não existia).

Pedir confirmação: -i e -I

-i: pergunta a cada arquivo

O -i (de interactive, "interativo") pergunta antes de cada arquivo. Responda s para apagar ou n para manter. A pergunta diz até o tipo do arquivo:

$ rm -i foto.jpg
rm: remover arquivo comum vazio 'foto.jpg'? n        « "vazio": o arquivo tem 0 bytes
$ rm -i cheio.txt
rm: remover arquivo comum 'cheio.txt'? n             « arquivo com conteúdo

"Arquivo comum" (regular file) quer dizer um arquivo normal, não uma pasta nem um link.

-I: pergunta uma vez só

O -I (i maiúsculo) pergunta uma vez, e só quando vai apagar mais de três arquivos ou apagar de forma recursiva. É menos chato que o -i e ainda segura um curinga que pegou mais do que você imaginava:

$ rm -I *.log
rm: remover 4 argumentos? n                          « *.log virou 4 arquivos
$ rm -rI velho
rm: remover 1 argumento recursivamente? n
$ rm -I c.log d.log                                  « só 2: NÃO pergunta e apaga

Repare na última linha: com dois arquivos, o -I não perguntou nada e apagou. Ele protege contra apagar muita coisa, não contra apagar a coisa errada.

Arquivos protegidos contra escrita

Se o arquivo não tem permissão de escrita, o rm pergunta mesmo sem -i, para você pensar duas vezes:

$ chmod -w cheio.txt                « tira a permissão de escrita (veja a aula chmod)
$ rm cheio.txt
rm: remover arquivo comum 'cheio.txt' protegido contra escrita? n
Fazer o rm sempre perguntar

O .bashrc padrão do Arch não traz apelidos para o rm. Se quiser uma rede de segurança, acrescente alias rm='rm -I' ao seu ~/.bashrc (veja .bashrc, alias, PATH). O -I incomoda pouco e pega o pior tipo de erro.

Apagar pastas

rmdir: só pastas vazias

rmdir vem de remove directory, "remover diretório". Ele só apaga pastas vazias, e isso é uma proteção: você nunca perde arquivos com ele.

$ rmdir vazia
$ rmdir velho
rmdir: falhou em remover 'velho': Diretório não vazio

Com -p (de parents, "pais"), ele apaga a pasta e também as de cima, se ficarem vazias. Com -v, conta o que fez:

$ mkdir -p p1/p2/p3
$ rmdir -pv p1/p2/p3
rmdir: removendo o diretório 'p1/p2/p3'
rmdir: removendo o diretório 'p1/p2'
rmdir: removendo o diretório 'p1'

A pasta "vazia" que não está vazia

Arquivos cujo nome começa com ponto são ocultos: o ls comum não mostra. O rmdir enxerga:

$ ls oculta
$ rmdir oculta
rmdir: falhou em remover 'oculta': Diretório não vazio
$ ls -A oculta
.escondido                          « -A mostra os ocultos

rm -r: a pasta e tudo o que há dentro

Sem opção, o rm recusa pastas:

$ rm velho
rm: não foi possível remover 'velho': É um diretório

O -r (de recursive, "recursivo") entra na pasta e apaga tudo, de dentro para fora: primeiro os arquivos, depois a pasta.

rm
O programa.
-rv
-r apaga a pasta e o conteúdo; -v mostra cada item. (-R é igual a -r.)
velho
A pasta.
$ ls -A velho
x.txt  y.txt
$ rm -rv velho
removido 'velho/y.txt'
removido 'velho/x.txt'
foi removido o diretório: 'velho'

Com -r e -i juntos, o rm pergunta até antes de entrar na pasta: rm: entrar no diretório 'velho'?.

-d: pasta vazia com o próprio rm

O rm -d apaga uma pasta só se ela estiver vazia, como o rmdir:

$ mkdir v2
$ rm v2
rm: não foi possível remover 'v2': É um diretório
$ rm -d v2

Missão: você está na pasta lixo. Apague a pasta vazia com rmdir, a pasta velho com tudo dentro e os dois arquivos .log. A foto.jpg e os .txt têm de ficar.

Confira antes de apagar com curingas

Antes de um rm com curinga, troque rm por echo: o shell mostra a lista de nomes em que o curinga se transforma, sem apagar nada. Se a lista estiver certa, rode o rm (veja Curingas):

$ echo *.log
e.log f.log
$ rm -v *.log
removido 'e.log'
removido 'f.log'

-f: forçar, sem perguntas e sem reclamar

O -f (de force, "forçar") faz duas coisas: não pergunta nada (nem nos arquivos protegidos) e não reclama de arquivos que não existem. Até o código de saída fica 0:

$ rm -f nada
$ echo $?
0                                  « sem -f seria erro e código 1
$ rm -f cheio.txt                  « o protegido contra escrita sai sem pergunta

Isso é útil em scripts ("apague se existir"). Digitado à mão, é perigoso: o -f desliga justamente os avisos que poderiam salvar você.

Arquivos cujo nome começa com -

Às vezes aparece um arquivo chamado, por exemplo, -arquivo (um erro de digitação, um programa mal-comportado). O rm acha que é uma opção:

$ ls
-arquivo  foto.jpg  oculta
$ rm -arquivo
rm: opção inválida -- “a”
Tente "rm ./-arquivo" para remover o arquivo '-arquivo'.
Tente "rm --help" para mais informações.

O rm leu -arquivo como as opções -a, -r, -q… e parou na primeira que não existe (a). A própria mensagem ensina a saída. Há duas formas:

rm -- -arquivo
O -- quer dizer "acabaram as opções": tudo o que vem depois é nome de arquivo, mesmo começando com hífen. Vale para quase todos os comandos.
rm ./-arquivo
Com ./ na frente, o nome já não começa com hífen, e continua apontando para o mesmo arquivo da pasta atual.
$ rm -- -arquivo
$ touch -- -arquivo                « cria de novo (o touch também precisa do --)
$ rm -v ./-arquivo
removido './-arquivo'

Missão: apareceu um arquivo chamado -arquivo na sua pasta pessoal. Tente rm -arquivo para ver o erro, e depois apague-o do jeito certo.

rm -rf: o comando que merece respeito

rm -rf pasta apaga uma pasta inteira, em silêncio, sem perguntar nada. É útil e muito usado em scripts e tutoriais. Também é o comando que mais destrói dados por acidente. Os acidentes mais comuns:

1. A variável vazia

Em scripts, é comum guardar uma pasta numa variável e apagar o conteúdo dela com rm -rf "$pasta"/*. Se a variável estiver vazia (um erro de digitação no nome, um valor que não chegou), o comando vira outra coisa. Veja com echo, sem apagar nada:

$ pasta=""
$ echo rm -rf "$pasta"/*
rm -rf /bin /boot /dev /etc /home /lib /lib64 /lost+found /mnt /opt /proc /root /run /sbin /srv /sys /tmp /usr /var

Com $pasta vazia, "$pasta"/* virou /*: todas as pastas da raiz do sistema. Como root, isso apagaria o Arch inteiro. Como usuária comum, apagaria tudo o que a ana pode apagar: a pasta pessoal dela inteira.

Defesas contra a variável vazia
  • Em scripts, use "${pasta:?}": se a variável estiver vazia, o Bash para com um erro em vez de rodar o comando (veja Variáveis e Argumentos).
  • Rode o comando com echo na frente antes da primeira vez.
  • Nunca rode sudo rm -rf com curingas ou variáveis sem conferir.

2. Um espaço no lugar errado

rm -rf ~/pasta / (com um espaço antes da barra) são dois alvos: ~/pasta e /. O mesmo vale para rm -rf ~ /Downloads em vez de rm -rf ~/Downloads: o primeiro apaga a sua pasta pessoal inteira.

A proteção que existe (e a que não existe)

O rm do GNU se recusa a apagar a raiz / de forma recursiva:

$ rm -rf /
rm: é perigoso operar recursivamente em '/'
rm: use --no-preserve-root para contornar esta segurança
$ echo $?
1

Essa trava (--preserve-root, ligada por padrão) só protege o / exato. Ela não protege /*, /home, /etc, nem a sua pasta pessoal. A proteção de verdade é o hábito: confira com ls ou echo, prefira -I, e tenha backup ou snapshots (veja Snapshots (snapper)).

Lixeira pelo terminal

A lixeira do desktop (GNOME, KDE, XFCE…) segue um padrão chamado FreeDesktop Trash: os arquivos vão para ~/.local/share/Trash/files/, e um arquivo .trashinfo em ~/.local/share/Trash/info/ guarda o caminho original e a data. Há duas formas de usar essa lixeira pelo terminal no Arch.

gio trash (já vem com o glib2)

O comando gio vem do pacote glib2, que quase todo Arch tem instalado como dependência (do NetworkManager, do polkit e de todo desktop):

$ gio trash frutas.txt
$ echo $?
0
$ ls frutas.txt
ls: não foi possível acessar 'frutas.txt': Arquivo ou diretório inexistente
$ ls -A .local/share/Trash/files .local/share/Trash/info
.local/share/Trash/files:
frutas.txt                                  « o arquivo, guardado

.local/share/Trash/info:
frutas.txt.trashinfo                        « de onde ele veio e quando
$ cat .local/share/Trash/info/frutas.txt.trashinfo
[Trash Info]
Path=/home/ana/frutas.txt
DeletionDate=2026-10-16T14:58:08

O gio trash funciona em qualquer lugar. Já os comandos para listar e devolver (gio trash --list, gio trash --restore) precisam do gvfs, um serviço que vem com os desktops. Num Arch sem desktop (como o da VM, acessado por SSH), eles respondem:

$ gio trash --list
gio: trash:: Operação sem suporte
$ echo $?
1

Nesse caso, devolva o arquivo à mão: mv ~/.local/share/Trash/files/frutas.txt ~/ (e apague o .trashinfo correspondente), ou use o trash-cli.

trash-cli (o pacote próprio para isso)

O trash-cli está no repositório extra. Ele usa a mesma lixeira do desktop e funciona em qualquer terminal, com ou sem interface gráfica. Veja o que a instalação traria (respondendo "n" na pergunta, nada foi instalado):

$ sudo pacman -S trash-cli
resolvendo dependências...
procurando pacotes conflitantes...

Pacotes (3) python-psutil-7.2.2-1  python-six-1.17.0-3  trash-cli-0.24.5.26-3

Tamanho total download:   0,39 MiB
Tamanho total instalado:  2,09 MiB

:: Continuar a instalação? [S/n] n

Depois de instalado (veja pacman: o Básico), os comandos são:

ComandoFaz
trash-put arquivoManda para a lixeira (o trash é um apelido dele)
trash-listLista o que está na lixeira, com data e caminho original
trash-restoreMostra a lista numerada e pergunta qual item devolver
trash-rm padrãoApaga de vez só os itens que casam com o padrão
trash-emptyEsvazia a lixeira (aí não volta mais); trash-empty 30 apaga só o que está lá há mais de 30 dias

Os nomes dos comandos vêm da lista de arquivos do pacote (pacman -Fl trash-cli); o funcionamento deles não foi mostrado aqui porque o pacote não foi instalado na máquina de exemplo.

Qual usar?

  • Arquivo que você tem certeza de que não quer: rm.
  • Algo que talvez queira de volta: gio trash ou trash-put.
  • Pasta: tente rmdir primeiro; se recusar, veja o que há dentro com ls -A antes do rm -r.
  • Muitos arquivos: echo antes, rm -I depois.

Quando não funciona

"É um diretório" 
$ rm velho
rm: não foi possível remover 'velho': É um diretório

O que aconteceu: o rm sem opções só apaga arquivos.

Como resolver: rmdir velho se estiver vazia, ou rm -r velho para apagar com o conteúdo (depois de olhar com ls -A velho).

"Diretório não vazio" 
$ rmdir oculta
rmdir: falhou em remover 'oculta': Diretório não vazio

O que aconteceu: o rmdir só apaga pastas vazias, e às vezes há arquivos ocultos lá dentro.

Como resolver: ls -A oculta mostra tudo. Se pode mesmo sair, rm -r oculta.

"Permissão negada" 
$ rm /etc/hostname
rm: remover arquivo comum '/etc/hostname' protegido contra escrita? s
rm: não foi possível remover '/etc/hostname': Permissão negada

O que aconteceu: o arquivo é do root (por isso a pergunta de "protegido contra escrita"), e mesmo respondendo s a ana não pode mudar a lista do /etc, que também é do root.

Como resolver: pare e pense se é mesmo para apagar um arquivo do sistema; quase nunca é. Arquivos de programas se removem com o pacman, não com rm.

"opção inválida" ao apagar um arquivo

O que aconteceu: o nome começa com hífen e o rm o leu como opção.

Como resolver: rm -- -nome ou rm ./-nome, como a própria mensagem sugere.

"Arquivo ou diretório inexistente" com nome que tem espaço

O que aconteceu: rm lista de compras.txt tenta apagar três arquivos: lista, de e compras.txt. Pior: se algum deles existir, ele é apagado.

Como resolver: aspas ou Tab: rm 'lista de compras.txt'.

Apaguei sem querer

O que aconteceu: o rm não usa lixeira.

Como resolver: pare de gravar no disco (cada arquivo novo pode ocupar o espaço do que foi apagado) e recupere de um backup ou snapshot. Ferramentas de recuperação existem, mas raramente devolvem tudo; a Arch Wiki tem uma página sobre elas (abaixo).

Resumo

  • rm apaga de verdade, sem lixeira; silêncio e código 0 = apagado.
  • rmdir (ou rm -d) apaga pastas vazias; rm -r apaga pastas com conteúdo.
  • -i pergunta a cada arquivo; -I pergunta uma vez (mais de 3 ou recursivo); -f não pergunta nada.
  • Nome com hífen: rm -- -nome ou rm ./-nome.
  • Antes de rm com curinga ou variável, confira com echo; a trava do / não protege mais nada.
  • Lixeira pelo terminal: gio trash (glib2) ou trash-put (pacote trash-cli).
