Arch mv

O mv muda um arquivo ou uma pasta de lugar, ou muda o nome dele. Para o Linux, essas duas coisas são a mesma: trocar o endereço do arquivo. Diferente do cp, depois do mv o original não fica para trás.

Você vai aprender
  • Por que mover e renomear são um comando só, e como o mv decide o que fazer.
  • Mover um arquivo, vários arquivos e pastas inteiras (sem -r).
  • Não sobrescrever nada sem querer: -i, -n, -u e -b.
  • Renomear nomes com espaço, mudar maiúsculas e renomear muitos arquivos de uma vez.
  • Ler as mensagens de erro reais do Arch (uma delas ainda está em inglês).

Os exemplos foram feitos num Arch Linux real (coreutils 9.12), com a usuária ana na pasta pessoal dela. Se ainda não viu, leia antes Copiar (cp): o mv usa a mesma ideia de origem e destino.

O mv também sobrescreve sem perguntar

Se já existir um arquivo com o nome de destino, ele é substituído, e o conteúdo antigo se perde. Não há lixeira nem "desfazer". A seção 5 mostra como se proteger.

A ideia: mudar o endereço

Todo arquivo tem um endereço completo: a pasta onde está + o nome. A frutas.txt da Ana mora em /home/ana/frutas.txt. O mv (de move, "mover") troca esse endereço. Se você troca só o nome, chamamos de renomear; se troca a pasta, de mover; e dá para trocar os dois de uma vez.

mv [opções] ORIGEM DESTINO
ComandoEndereço antesEndereço depoisPasta mudou?Nome mudou?Chamamos de
mv lista.txt compras.txt~/lista.txt~/compras.txtnãosimrenomear
mv compras.txt Documentos/~/compras.txt~/Documentos/compras.txtsimnãomover
mv compras.txt Documentos/mercado.txt~/compras.txt~/Documentos/mercado.txtsimsimmover e renomear

Em forma de desenho, a mesma pasta antes e depois de mv compras.txt Documentos/mercado.txt:

ANTES                              DEPOIS
/home/ana                          /home/ana
├── compras.txt   ───────┐         ├── Documentos
└── Documentos           │         │   ├── mercado.txt   ◄── o mesmo arquivo,
    └── notas.txt        └───────► │   └── notas.txt         com outro endereço
                                   └── (compras.txt não existe mais aqui)

Assim como no cp, o que decide o comportamento é o destino: se é uma pasta que existe, o arquivo vai para dentro dela com o mesmo nome; se não é, ele vira o nome novo.

1. Renomear

mv
O programa que move.
rascunho.txt
A origem: o nome atual.
lista.txt
O destino: o nome novo, na mesma pasta.
$ cp frutas.txt rascunho.txt                « um arquivo para treinar
$ mv rascunho.txt lista.txt
$ echo $?
0                                          « 0 = deu certo
$ ls
'Área de trabalho'   Documentos   frutas.txt   lista.txt   Música    Vídeos
 aur                 Downloads    Imagens      Modelos     Público

Silêncio é sucesso. O rascunho.txt sumiu da lista e apareceu o lista.txt: é o mesmo arquivo, com o mesmo conteúdo, só com outro nome.

Ver o que foi feito: -v

Com -v (verbose, "detalhado"), o mv conta o que fez:

$ mv -v lista.txt compras.txt
renomeado 'lista.txt' -> 'compras.txt'

Missão: renomeie o frutas.txt para lista-frutas.txt, com -v, e confira com ls.

2. Mover para outra pasta

Quando o destino é uma pasta que existe, o arquivo vai para dentro dela, mantendo o nome:

$ mv -v compras.txt Documentos/
renomeado 'compras.txt' -> 'Documentos/compras.txt'
$ ls Documentos
acesso.log  alunos.csv  compras.txt  notas.txt  projetos  relatorio.odt

Repare que o Arch diz "renomeado" mesmo quando você moveu de pasta. Não é erro: para o sistema, mover dentro do mesmo disco é só trocar o endereço, exatamente como renomear.

Trazer de volta para a pasta atual

O destino . (ponto) quer dizer "a pasta onde estou":

$ mv -v Documentos/compras.txt .
renomeado 'Documentos/compras.txt' -> './compras.txt'

Mover e renomear de uma vez

$ mv -v compras.txt Documentos/mercado.txt
renomeado 'compras.txt' -> 'Documentos/mercado.txt'

Para a pasta pessoal: ~

O ~ (til) é um atalho para a sua pasta pessoal. O shell troca o ~ pelo caminho completo antes de o mv rodar, e por isso a mensagem mostra /home/ana:

$ mv -v Documentos/mercado.txt ~/
renomeado 'Documentos/mercado.txt' -> '/home/ana/mercado.txt'

Missão: com um único mv, leve o frutas.txt para a pasta Documentos, já com o nome novo compras.txt.

3. Várias coisas de uma vez

Como no cp: com várias origens, o último argumento é o destino e tem que ser uma pasta.

mv -v
O programa, contando cada passo.
Documentos/alunos.csv Documentos/acesso.log
As origens.
arquivo-morto/
O destino: a pasta, sempre por último.
$ mkdir arquivo-morto
$ mv -v Documentos/alunos.csv Documentos/acesso.log arquivo-morto/
renomeado 'Documentos/alunos.csv' -> 'arquivo-morto/alunos.csv'
renomeado 'Documentos/acesso.log' -> 'arquivo-morto/acesso.log'

Curingas também funcionam: mv *.log arquivo-morto/ leva todos os arquivos terminados em .log (veja Curingas). E o -t PASTA deixa escrever o destino primeiro: mv -t arquivo-morto/ a.txt b.txt.

4. Pastas: sem -r

Aqui o mv é diferente do cp: ele move pastas inteiras sem opção nenhuma. Afinal, ele não copia o conteúdo; só troca o endereço da pasta, e tudo o que está dentro vai junto.

$ mv -v Documentos/projetos arquivo-morto/
renomeado 'Documentos/projetos' -> 'arquivo-morto/projetos'
$ ls arquivo-morto
acesso.log  alunos.csv  projetos
$ mv -v arquivo-morto/projetos Documentos/          « e de volta
renomeado 'arquivo-morto/projetos' -> 'Documentos/projetos'
$ ls -ld Documentos/projetos
drwxrwxr-x 3 ana ana 4096 15 out 09:15 Documentos/projetos     « a data não mudou

Outra diferença em relação ao cp: o arquivo movido mantém a data, as permissões e o dono, porque continua sendo o mesmo arquivo.

Quando o mv precisa copiar: outra partição

Trocar só o endereço funciona dentro de um mesmo sistema de arquivos (uma partição). Para levar um arquivo para outro disco, o mv precisa copiar os dados e depois apagar o original. No Arch dá para ver isso sem pendrive nenhum: a pasta /tmp é um tmpfs, um sistema de arquivos que fica na memória RAM, separado do disco:

$ findmnt -n /tmp
/tmp tmpfs tmpfs rw,nosuid,nodev,nr_inodes=1048576,inode64,huge=advise,usrquota
$ mv -v mercado.txt /tmp/
copiado 'mercado.txt' -> '/tmp/mercado.txt'           « 1º: copia para o tmpfs
removido 'mercado.txt'                                 « 2º: apaga o original
$ mv -v /tmp/mercado.txt .
copiado '/tmp/mercado.txt' -> './mercado.txt'
removido '/tmp/mercado.txt'

Para você, o resultado é o mesmo. A diferença é o tempo: mover 10 GB dentro do mesmo disco é instantâneo; para outro disco, demora o tempo de copiar 10 GB. Lembre também que o /tmp do Arch é apagado a cada reinício, por estar na memória.

Missão: crie a pasta arquivo-morto e mova para dentro dela a pasta Documentos/projetos inteira (lembre: o mv não precisa de -r).

5. Quando o destino já existe

Veja o que acontece quando o nome de destino já está em uso. O a.txt tem as frutas e o b.txt, as anotações da Ana:

$ cp frutas.txt a.txt
$ cp Documentos/notas.txt b.txt
$ mv a.txt b.txt                           « nenhuma pergunta
$ ls a.txt b.txt
ls: não foi possível acessar 'a.txt': Arquivo ou diretório inexistente
b.txt
$ head -1 b.txt
banana                                     « as anotações sumiram

O a.txt virou o b.txt, e o b.txt antigo foi substituído. As mesmas opções do cp protegem você:

-i: perguntar

$ cp frutas.txt a.txt
$ cp Documentos/notas.txt b.txt
$ mv -i a.txt b.txt
mv: sobrescrever 'b.txt'? n                « n e Enter: não mexe em nada
$ echo $?
1
$ ls a.txt b.txt
a.txt  b.txt                               « os dois continuam lá

-n: nunca sobrescrever

$ mv -n a.txt b.txt
$ echo $?
0                                          « nenhum aviso, código 0
$ ls a.txt b.txt
a.txt  b.txt                               « nada mudou

-b: guardar o antigo

$ mv -bv a.txt b.txt
renomeado 'a.txt' -> 'b.txt' (cópia de segurança: 'b.txt~')
$ ls b.txt*
b.txt  b.txt~                              « b.txt~ = as anotações antigas

-u: só se a origem for mais nova

$ cp Documentos/notas.txt c.txt            « c.txt nasce agora: é mais novo
$ mv -uv frutas.txt c.txt                  « frutas.txt é de 14 out: mais velho
$ echo $?
0                                          « não moveu e não avisou
OpçãoSe o destino existe…Quando usar
(nenhuma)Substitui em silêncioQuando você tem certeza
-iPerguntaDigitando à mão
-nNão mexe, em silêncioScripts
-uSubstitui só se a origem for mais novaJuntar duas pastas mantendo o mais recente
-bSubstitui e guarda o antigo como nome~Quando você quer as duas versões
Fazer o mv sempre perguntar

Coloque alias mv='mv -i' no seu ~/.bashrc (veja .bashrc, alias, PATH). O .bashrc padrão do Arch não traz esse apelido.

6. Nomes com espaço e maiúsculas

O shell separa os argumentos pelos espaços. Para ele, lista de compras.txt são três nomes: lista, de e compras.txt. Veja o que acontece:

$ touch 'lista de compras.txt'
$ mv lista de compras.txt lista.txt
mv: alvo 'lista.txt': Arquivo ou diretório inexistente

O mv recebeu quatro argumentos, achou que eram três origens e um destino, e reclamou que o destino lista.txt não é uma pasta. As três formas de dizer "isto é um nome só":

$ mv 'lista de compras.txt' lista-de-compras.txt       « aspas simples
$ mv lista-de-compras.txt "Lista de Compras.txt"       « aspas duplas
$ mv Lista\ de\ Compras.txt lista.txt                  « barra invertida antes de cada espaço
$ ls lista*
lista.txt
Deixe o Tab escrever para você

Digite mv lis e aperte Tab: o Bash completa o nome já com as barras invertidas certas. É o jeito mais seguro de lidar com espaços e acentos (veja Caminhos).

Só mudar maiúsculas e minúsculas

No Linux, FOTO.JPG e foto.jpg são nomes diferentes. Para trocar só a caixa das letras, é um mv normal:

$ mv -v FOTO.JPG foto.jpg
renomeado 'FOTO.JPG' -> 'foto.jpg'

Missão: existe na pasta pessoal um arquivo chamado lista de compras.txt, com espaços. Renomeie para lista-de-compras.txt, com hifens. Primeiro tente sem aspas para ver o erro; depois resolva.

7. Renomear muitos arquivos de uma vez

O mv renomeia um arquivo por vez. Um comando como mv *.JPG *.jpg não funciona: o shell troca os curingas pelos nomes que existem, e o mv recebe uma lista de origens sem uma pasta no fim. Para renomear em lote, há duas formas no Arch.

Forma 1: um laço for (funciona em qualquer Linux)

Um laço repete o mv para cada arquivo. Os laços têm aula própria (Laços); aqui basta entender as partes:

for f in *.JPG
Para cada arquivo terminado em .JPG, guarde o nome na variável f…
do mv -v -- "$f" "${f%.JPG}.jpg"
…renomeie. ${f%.JPG} é o nome sem o .JPG do fim; depois cola .jpg. As aspas protegem nomes com espaço, e o -- protege nomes que começam com hífen.
done
Fim do laço.
$ ls
IMG_001.JPG  IMG_002.JPG  IMG_003.JPG
$ for f in *.JPG; do mv -v -- "$f" "${f%.JPG}.jpg"; done
renomeado 'IMG_001.JPG' -> 'IMG_001.jpg'
renomeado 'IMG_002.JPG' -> 'IMG_002.jpg'
renomeado 'IMG_003.JPG' -> 'IMG_003.jpg'
$ ls
IMG_001.jpg  IMG_002.jpg  IMG_003.jpg
Teste antes com echo

Troque o mv por echo mv: o laço só mostra os comandos que rodaria. Se a lista estiver certa, rode de novo sem o echo.

Forma 2: o rename do Arch (util-linux)

O Arch já vem com um comando rename, do pacote util-linux (que faz parte do base). Ele troca um pedaço de texto do nome por outro:

$ pacman -Qo /usr/bin/rename
/usr/bin/rename pertence a util-linux 2.42.4-1
rename
O programa.
-v
Mostra cada troca.
IMG_
O pedaço do nome a procurar (só a primeira ocorrência em cada nome).
ferias-
O que pôr no lugar.
fotos/*.jpg
Os arquivos.
$ rename -v IMG_ ferias- fotos/*.jpg
`fotos/IMG_001.jpg' -> `fotos/ferias-001.jpg'
`fotos/IMG_002.jpg' -> `fotos/ferias-002.jpg'

Use -n (no-act) para ver o que seria feito sem mudar nada: rename -n -v .jpg .jpeg fotos/*.jpg.

O rename do Arch não é o do Debian

Muitos tutoriais mostram rename 's/\.JPG$/.jpg/' *.JPG, com uma expressão do Perl. Esse é outro programa, o "perl-rename", que o Debian e o Ubuntu chamam de rename. No Arch ele não vem instalado e tem outro nome:

$ perl-rename
bash: perl-rename: comando não encontrado
$ pacman -Ss '^perl-rename$'
extra/perl-rename 1.16.3-1
    Renames multiple files using Perl regular expressions

Quem quiser usá-lo instala com sudo pacman -S perl-rename (veja pacman: o Básico) e chama pelo nome perl-rename.

Missão: você está na pasta fotos, com três arquivos .JPG em maiúsculas. Com um laço for, renomeie todos para terminar em .jpg minúsculo. Dica: rode primeiro com echo mv para conferir.

Quando não funciona

"não foi possível obter estado de" 
$ mv nada x
mv: não foi possível obter estado de 'nada': Arquivo ou diretório inexistente

O que aconteceu: a origem não existe (nome errado ou outra pasta).

Como resolver: confira com ls e use Tab para completar.

"alvo …: Arquivo ou diretório inexistente" com nomes com espaço

O que aconteceu: o shell partiu o nome nos espaços e o mv recebeu várias origens (seção 6).

Como resolver: ponha o nome entre aspas ou use Tab.

"Não é um diretório" 
$ mv frutas.txt Doc/
mv: não foi possível mover 'frutas.txt' para 'Doc/': Não é um diretório

O que aconteceu: a pasta Doc não existe. A barra no fim avisou o mv que o destino devia ser uma pasta.

Atenção: sem a barra, mv frutas.txt Doc não dá erro: renomeia o arquivo para Doc. Use a barra sempre que o destino for uma pasta.

"para um subdiretório de si mesmo" 
$ mv Documentos Documentos/sub
mv: não é possível mover 'Documentos' para um subdiretório de si mesmo, 'Documentos/sub'

O que aconteceu: você tentou pôr uma pasta dentro dela mesma.

Como resolver: escolha um destino fora da pasta.

"Permissão negada" 
$ mv frutas.txt /etc/
mv: não foi possível mover 'frutas.txt' para '/etc/frutas.txt': Permissão negada

O que aconteceu: o /etc pertence ao root. Para mover, você precisa poder escrever na pasta de origem e na de destino.

Como resolver: confira se o destino está certo; se estiver, use sudo mv (veja sudo, root e Usuários).

"não é possível reescrever …: Diretório não vazio" 
$ mv Documentos/projetos d1/
mv: não é possível reescrever 'd1/projetos': Diretório não vazio

O que aconteceu: já existe uma pasta d1/projetos com coisas dentro. O mv só substitui uma pasta por outra se a de destino estiver vazia; ele não mistura o conteúdo das duas.

Como resolver: renomeie uma das pastas, ou junte o conteúdo com cp -a (ou rsync) e depois apague a origem.

"cannot overwrite non-directory … with directory" (em inglês) 
$ mv Documentos/projetos b.txt
mv: cannot overwrite non-directory 'b.txt' with directory 'Documentos/projetos'

O que aconteceu: você tentou trocar um arquivo (b.txt) por uma pasta. Essa mensagem ainda não foi traduzida no coreutils 9.12 do Arch, por isso aparece em inglês no meio das outras em português: "não é possível sobrescrever o não-diretório 'b.txt' com o diretório…".

Como resolver: escolha outro nome para a pasta, ou um destino que seja uma pasta. O contrário funciona: mv b.txt Documentos/projetos põe o arquivo dentro da pasta.

"falta o operando arquivo de destino" 
$ mv frutas.txt
mv: falta o operando arquivo de destino após 'frutas.txt'
Tente "mv --help" para mais informações.

Como resolver: diga para onde mover (ou o nome novo).

Substituí um arquivo sem querer

O que aconteceu: o destino já existia e foi substituído.

Como resolver: pelo terminal não há como desfazer; recupere de um backup ou snapshot (veja Snapshots (snapper)). Para a próxima, -i, -n ou -b.

Resumo

  • Mover e renomear são o mesmo comando: mv ORIGEM DESTINO troca o endereço do arquivo.
  • Destino pasta → vai para dentro; destino nome novo → renomeia; destino arquivo existente → substitui sem perguntar.
  • Pastas não precisam de -r; o arquivo movido mantém data e permissões.
  • Dentro do mesmo disco é instantâneo; para outro sistema de arquivos (como o /tmp), o mv copia e apaga.
  • Proteção: -i, -n, -u, -b. Nomes com espaço: aspas ou Tab.
  • Em lote: laço for, ou o rename do util-linux (o perl-rename é outro pacote).

Na Arch Wiki: a página Core utilities (em português: Core utilities (Português)) descreve o mv e os demais comandos do coreutils. O /tmp em memória é explicado em tmpfs, e para renomear muitos arquivos com mais conforto a Wiki lista programas em List of applications/Utilities.
