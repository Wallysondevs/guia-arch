Arch sed

O sed (de stream editor, "editor de fluxo") edita texto sem abrir o arquivo num editor. Você descreve a mudança, como "troque #Color por Color", e ele aplica em todas as linhas. É a ferramenta para mudar configurações em scripts e fazer substituições em massa — e aparece o tempo todo na Arch Wiki.

Você vai aprender
  • Como o sed processa o texto, linha por linha.
  • A ler e escrever o comando s/procurar/trocar/ parte por parte, com as flags g e I.
  • A diferença entre mostrar o resultado e alterar o arquivo (-i), e como fazer backup antes (-i.bak).
  • A escolher linhas (endereços), apagar (d), imprimir (-n … p) e inserir linhas.
  • A ler as mensagens de erro do GNU sed 4.10 do Arch (que têm um defeito de tradução curioso).

O sed no Arch

O sed vem no pacote sed, que é dependência do meta-pacote base: todo Arch tem. É o GNU sed, a mesma família do sed do Debian e do Ubuntu, só que mais novo (o Arch acompanha as versões do projeto GNU de perto):

$ pacman -Qo /usr/bin/sed
/usr/bin/sed pertence a sed 4.10-2          « pacote sed, versão 4.10, lançamento 2
$ sed --version | head -1
sed (GNU sed) 4.10

Nos exemplos, vamos usar os arquivos da ana: frutas.txt (na pasta pessoal) e, dentro de Documentos, notas.txt, alunos.csv e acesso.log. E, para o exemplo "de verdade", uma cópia do /etc/pacman.conf (veja cat, less, head, tail se ainda não conhece o cat):

$ cat frutas.txt
banana
maçã
laranja
banana
uva
maçã
banana
$ cat Documentos/notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ cp /etc/pacman.conf ~/pacman.conf          « uma cópia para treinar sem risco

Como o sed trabalha

O sed lê o texto uma linha por vez. Para cada linha, aplica os seus comandos e escreve o resultado na saída. Depois passa para a próxima linha.

  arquivo ──► [ lê a linha ] ──► [ aplica os comandos ] ──► [ escreve na tela ] ──┐
                   ▲                                                              │
                   └────────────────────── próxima linha ◄────────────────────────┘

Duas consequências importantes:

  • Por padrão, o resultado vai para a tela (a saída padrão). O arquivo original não muda.
  • O sed funciona com arquivos de qualquer tamanho, porque nunca carrega o arquivo inteiro na memória.

Ele também lê da entrada de um pipe: comando | sed '…'. Por isso aparece tanto no meio de outros comandos.

Substituir texto: o comando s

O uso mais comum do sed é substituir. Primeiro, a linha inteira:

sed
O programa.
's/banana/BANANA/'
O script, ou seja, a instrução para o sed. Fica entre aspas simples para o shell não mexer nos símbolos ($, *, espaços).
frutas.txt
O arquivo a ler. Sem ele, o sed lê a entrada padrão (por exemplo, de um pipe).

Agora, o script por dentro. As barras / separam as partes:

s
O comando: substitute, "substituir".
/banana
O que procurar. Pode ser um texto fixo ou uma expressão regular.
/BANANA
Pelo que trocar.
/
Fim. Depois da última barra vêm as flags (opcionais), como g e I.
$ sed 's/banana/BANANA/' frutas.txt
BANANA                 « trocou
maçã
laranja
BANANA                 « trocou
uva
maçã
BANANA                 « trocou
$ echo $?
0                      « 0 = deu certo
$ cat frutas.txt
banana                 « o arquivo continua igual
maçã
laranja
banana
uva
maçã
banana

O código de saída 0 quer dizer "o sed rodou sem erro". Atenção: ele é 0 mesmo que nada tenha sido trocado. O sed não avisa quando o padrão não aparece (o grep avisa, com o código 1).

Todas as ocorrências da linha: flag g

Sem flag, o sed troca só a primeira ocorrência de cada linha. A flag g (de global) troca todas. Um número troca só aquela ocorrência:

$ echo "a a a" | sed 's/a/X/'
X a a                  « só a primeira
$ echo "a a a" | sed 's/a/X/g'
X X X                  « todas
$ echo "a a a" | sed 's/a/X/2'
a X a                  « só a 2ª ocorrência

Ignorar maiúsculas e minúsculas: flag I

$ echo "Olá Mundo" | sed 's/mundo/Arch/'
Olá Mundo              « não achou: "mundo" ≠ "Mundo"
$ echo "Olá Mundo" | sed 's/mundo/Arch/I'
Olá Arch

Dá para juntar flags: s/a/X/gI troca todas, ignorando maiúsculas.

Missão: mostre o frutas.txt com banana e maçã em maiúsculas (BANANA e MAÇÃ). Dica: dois comandos s separados por ;, ou duas opções -e.

Alterar o arquivo de verdade: -i

A opção -i (de in-place, "no lugar") grava o resultado no próprio arquivo, em vez de mostrar na tela. O exemplo clássico do Arch: o /etc/pacman.conf vem com a opção Color comentada (desligada), e muita gente liga para ver o pacman colorido. Vamos treinar na cópia.

Passo 1 — teste sem -i. Primeiro veja onde está a linha, depois veja o resultado da troca:

$ grep -n '^#Color' pacman.conf
33:#Color                       « linha 33, desligada pelo #
$ sed 's/^#Color/Color/' pacman.conf | grep -n '^Color'
33:Color                        « a troca funcionaria

O ^ quer dizer "começo da linha": só troca o #Color que está logo no início. Os padrões estão explicados mais abaixo.

Passo 2 — aplique com backup.

sed
O programa.
-i.bak
Edita o arquivo e guarda uma cópia do original com a extensão .bak. Sem espaço entre -i e .bak!
's/^#Color/Color/'
A substituição: tira o # do começo da linha #Color.
pacman.conf
O arquivo que será alterado.
$ sed -i.bak 's/^#Color/Color/' pacman.conf
$ echo $?
0                               « nada na tela, código 0: deu certo
$ ls
'Área de trabalho'   Downloads    Modelos       pacman.conf.bak    « o .bak apareceu
 aur                 frutas.txt   Música        Público
 Documentos          Imagens      pacman.conf   Vídeos
$ grep -n 'Color' pacman.conf pacman.conf.bak
pacman.conf:33:Color            « o arquivo mudou
pacman.conf.bak:33:#Color       « a cópia guarda o original
$ diff pacman.conf.bak pacman.conf
33c33                           « a linha 33 foi trocada (c = change)
< #Color
---
> Color

No seu Arch de verdade, o arquivo é do root, então o comando leva sudo (veja sudo, root e Usuários). O resultado é o mesmo da cópia:

$ sudo sed -i.bak 's/^#Color/Color/' /etc/pacman.conf
[sudo] senha para ana:
$ grep -n 'Color' /etc/pacman.conf /etc/pacman.conf.bak
/etc/pacman.conf:33:Color
/etc/pacman.conf.bak:33:#Color

Esta última sessão é ilustrativa: no laboratório o /etc/pacman.conf é compartilhado, então a troca foi feita na cópia (com saída idêntica). Para desfazer: sudo mv /etc/pacman.conf.bak /etc/pacman.conf.

Teste antes de usar -i

Rode primeiro sem -i e confira a saída. Só depois acrescente o -i. Com -i sozinho (sem .bak), não existe "desfazer". Em arquivos do sistema (/etc/…), use sempre -i.bak — um pacman.conf estragado impede o pacman de funcionar.

Missão: há uma cópia do pacman.conf na sua pasta. Ligue a opção Color nela (tire o #), editando o arquivo e guardando o original como pacman.conf.bak. Confira com grep -n Color pacman.conf*.

Formas diferentes de salvar o resultado

FormaExemploQuando usar
Só olharsed 's/a/b/' arqSempre, primeiro, para testar.
Novo arquivosed 's/a/b/' arq > novoQuer manter o original intacto.
No lugar, com backupsed -i.bak 's/a/b/' arqMudança em configuração: dá para voltar.

O > esvazia o arquivo antes de o sed ler, e você perde tudo. Veja Redirecionamento. Para editar o próprio arquivo, use -i.

Caminhos com barras: troque o separador

Para trocar /home/ana por /home/bia, as barras do caminho se misturam com as barras do comando:

$ sed 's//home/ana//home/bia/' frutas.txt
sed: -e expressão #1, carácter 9opção desconhecida para "s"

O sed entendeu s//home/ como "troque nada por home" e achou que ana eram flags. O sed aceita qualquer caractere como separador: é o primeiro que aparece depois do s. Use | ou #. No pacman.conf:

$ sed 's|/etc/pacman.d/mirrorlist|/etc/pacman.d/espelhos|' pacman.conf | grep '^Include'
Include = /etc/pacman.d/espelhos
Include = /etc/pacman.d/espelhos

Outra forma é "escapar" cada barra com \: sed 's/\/etc\/pacman.d/\/opt/'. Funciona, mas é bem mais difícil de ler.

Padrões: expressões regulares

O que você procura pode ser um padrão, e não só um texto fixo. São as mesmas expressões regulares do grep. Os símbolos mais usados:

SímboloSignificaExemplo
.Qualquer caracterec.sa casa com "casa" e "cosa"
*O anterior, zero ou mais vezesColor.* = "Color" e qualquer coisa depois
^Começo da linha^# = linha que começa com #
$Fim da linha^$ = linha vazia
[0-9]Um caractere da lista[0-9] = um dígito
[^,]Um caractere fora da lista[^,]* = tudo até a próxima vírgula
\+O anterior, uma ou mais vezes[0-9]\+ = um número
&Na troca: o texto encontrados/[0-9]\+/[&]/ põe o número entre colchetes

Com o alunos.csv da ana:

$ cd Documentos
$ sed 's/,/;/g' alunos.csv
nome;idade;cidade;nota          « todas as vírgulas viraram ponto e vírgula
Ana;29;Recife;9.5
Bruno;34;Curitiba;7.0
Carla;22;Salvador;8.5
Diego;41;Manaus;6.0
Elisa;27;Porto Alegre;10.0
$ sed 's/[0-9]\+/[&]/' alunos.csv
nome,idade,cidade,nota
Ana,[29],Recife,9.5             « & repetiu o primeiro número encontrado
Bruno,[34],Curitiba,7.0
Carla,[22],Salvador,8.5
Diego,[41],Manaus,6.0
Elisa,[27],Porto Alegre,10.0

O ponto é um caractere especial. Quando você quer o ponto de verdade, escape com \.:

$ sed 's/1.0/X/g' <<< "versão 1.0 e 150"
versão X e X                    « o ponto casou com o "5" de 150!
$ sed 's/1\.0/X/g' <<< "versão 1.0 e 150"
versão X e 150                  « agora só o "1.0"

(O <<< manda um texto como entrada; veja Redirecionamento.)

Grupos e expressões estendidas: -E

No modo normal (básico), +, ?, ( e | são letras comuns; para serem especiais, precisam de barra (\+, \(). Com -E (de extended, "estendida"), eles já são especiais. Veja a diferença:

$ sed 's/[0-9]+/N/' alunos.csv | head -2
nome,idade,cidade,nota
Ana,29,Recife,9.5               « nada mudou: procurou um dígito seguido de "+"
$ sed -E 's/[0-9]+/N/' alunos.csv | head -2
nome,idade,cidade,nota
Ana,N,Recife,9.5                « com -E, o + quer dizer "um ou mais"

Com -E, os parênteses guardam partes do que foi encontrado, e você as devolve com \1, \2… Exemplo: trocar o ponto decimal das notas por vírgula (como as planilhas em português esperam):

-E
Expressões estendidas.
([0-9]+)
Grupo 1: a parte inteira da nota.
\.
Um ponto de verdade.
([0-9]+)$
Grupo 2: a parte decimal, no fim da linha.
\1,\2
Na troca: grupo 1, vírgula, grupo 2.
$ sed -E 's/([0-9]+)\.([0-9]+)$/\1,\2/' alunos.csv
nome,idade,cidade,nota
Ana,29,Recife,9,5
Bruno,34,Curitiba,7,0
Carla,22,Salvador,8,5
Diego,41,Manaus,6,0
Elisa,27,Porto Alegre,10,0
$ sed -E 's/^([^,]+),([^,]+),.*/\2 anos: \1/' alunos.csv
idade anos: nome                « o cabeçalho também "casou"
29 anos: Ana
34 anos: Bruno
22 anos: Carla
41 anos: Diego
27 anos: Elisa

No segundo exemplo, ([^,]+) guardou o nome (grupo 1) e o segundo ([^,]+) guardou a idade (grupo 2); na troca, eles foram escritos em outra ordem. Um exemplo maior, com o acesso.log (um registro de servidor web), que guarda só IP, método, página e código:

$ sed -E 's/^([0-9.]+) .*"(GET|POST) ([^ ]+) .* ([0-9]{3})$/\1 \2 \3 \4/' acesso.log
192.168.0.10 GET / 200
192.168.0.23 GET /contato 200
192.168.0.10 GET /admin 403
192.168.0.57 GET /fotos 404
192.168.0.10 POST /login 200
192.168.0.23 GET / 200

Separar colunas assim funciona, mas é trabalhoso; para colunas, o awk costuma ser mais simples.

Escolher linhas: endereços

Antes de um comando, você pode dizer em quais linhas ele vale. Isso se chama endereço. Sem endereço, o comando vale para todas as linhas.

O comando d (de delete) não escreve a linha. Lembre: "apagar" é só da saída; o arquivo continua igual (sem -i).

Imprimir só algumas linhas: -n + p

A opção -n (de no autoprint) desliga a impressão automática. O comando p (de print) imprime a linha. Juntos, mostram só o que você escolheu. Veja por que os dois andam juntos:

$ sed 'p' frutas.txt | head -4
banana                 « sem -n: o p imprime…
banana                 « …e a impressão automática imprime de novo
maçã
maçã
$ sed -n '2,4p' frutas.txt

laranja
banana
$ sed -n '/ 404$/p' Documentos/acesso.log
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
$ sed -n '/maçã/=' frutas.txt
2                      « o comando = mostra o NÚMERO da linha
6

Com uma faixa de padrões, você recorta um "bloco". A seção [options] do pacman.conf vai do título até a primeira linha vazia (encurtado):

Quando não funciona

Antes dos erros, uma curiosidade do Arch: a tradução pt_BR do GNU sed 4.10 junta o número do caractere com a mensagem, sem os dois-pontos: carácter 15comando "s" não terminado. Leia como "no caractere 15: comando s não terminado". (E é "carácter", com acento, como em Portugal.) Os códigos de saída do sed: 0 deu certo, 1 comando inválido, 2 algum arquivo não pôde ser aberto, 4 erro de leitura ou escrita.

"comando "s" não terminado" 
$ sed 's/banana/BANANA' frutas.txt
sed: -e expressão #1, carácter 15comando "s" não terminado
$ echo $?
1

O que aconteceu: faltou a última barra. O comando s precisa de três: s/a/b/.

Como resolver: sed 's/banana/BANANA/' frutas.txt. O número do "carácter" diz onde o sed se perdeu (o 15º caractere do script é o fim dele).

"opção desconhecida para "s"" 
$ sed 's/banana/BANANA/x' frutas.txt
sed: -e expressão #1, carácter 17opção desconhecida para "s"

O que aconteceu: depois da última barra só podem vir flags válidas (g, I, p, um número…). Aqui, o x não é flag. O mesmo erro aparece quando o texto tem barras /, como um caminho, e o sed acha que o comando acabou antes.

Como resolver: confira as flags; com caminhos, troque o separador: sed 's|/opt/app|/srv/app|'.

"Permissão negada" com -i 
$ sed -i 's/notebook/estudio/' /etc/hostname
sed: não foi possível abrir o arquivo temporário /etc/seds8yaHC: Permissão negada
$ echo $?
4

O que aconteceu: o -i cria um arquivo temporário na mesma pasta e depois troca pelo original. Em /etc, só o root pode criar arquivos. O nome do temporário (seds8yaHC) é sorteado a cada vez.

Como confirmar: ls -l /etc/hostname mostra o dono root (veja Permissões).

Como resolver: teste sem -i; depois rode com sudo e backup: sudo sed -i.bak 's/notebook/estudio/' /etc/hostname. (Para trocar o nome da máquina, o jeito certo no Arch é sudo hostnamectl hostname estudio.)

"não foi possível ler" 
$ sed 's/a/b/' naoexiste.txt
sed: não foi possível ler naoexiste.txt: Arquivo ou diretório inexistente
$ echo $?
2

O que aconteceu: o arquivo não existe na pasta atual (ou o nome está diferente: maiúsculas, acentos).

Como resolver: confira com ls e pwd; use Tab para completar o nome.

Não deu erro, mas não trocou nada

O que aconteceu: o padrão não casou — e o sed devolve 0 mesmo assim. As causas mais comuns são maiúsculas diferentes ("Mundo" × "mundo"), espaços a mais, + sem -E, ou o ^ exigindo começo de linha.

Como confirmar: procure o padrão com grep antes: grep -n 'mundo' arquivo. Se o grep não acha, o sed também não vai achar.

Como resolver: use a flag I para ignorar maiúsculas, -E para + ? ( ) |, e escape símbolos especiais com \: s/1\.0/2.0/.

Uma variável não foi trocada pelo valor 
$ novo=Arch
$ sed 's/Bash/$novo/' notas.txt | grep Estudar
Estudar $novo
$ sed "s/Bash/$novo/" notas.txt | grep Estudar
Estudar Arch

O que aconteceu: dentro de aspas simples, o shell não troca variáveis (veja Sintaxe dos Comandos).

Como resolver: use aspas duplas: sed "s/Bash/$novo/" notas.txt. Cuidado: se o valor tiver /, troque o separador.

Exercícios

1. Trocar todas

Complete para trocar todos os espaços de cada linha por _:

sed 's/ /_/' notas.txt

2. Editar com segurança

Complete para ligar o VerbosePkgLists no pacman.conf, guardando uma cópia .bak:

sudo sed 's/^#VerbosePkgLists/VerbosePkgLists/' /etc/pacman.conf

3. Só as linhas de erro

Complete para mostrar só as linhas que contêm 403:

sed '/403/' acesso.log

4. Sem cabeçalho

Complete para mostrar o alunos.csv sem a primeira linha:

sed '' alunos.csv

5. Você rodou sed 's/^#Color/Color/' pacman.conf e a tela mostrou "Color". O que aconteceu com o arquivo?

6. Qual comando troca o caminho /var/www por /srv/http (a pasta web padrão do Arch) sem dar erro?

7. O sed mostrou sed: -e expressão #1, carácter 15comando "s" não terminado. O que fazer?

Resumo

  • O sed lê linha por linha e mostra o resultado; o arquivo só muda com -i.
  • s/procurar/trocar/ troca a primeira ocorrência por linha; g troca todas; I ignora maiúsculas.
  • Teste sem -i, depois use -i.bak para ter como voltar; em /etc, com sudo.
  • Com barras no texto, troque o separador: s|a|b|. Para + ( ) |, use -E.
  • Endereços escolhem linhas; d apaga, -n … p imprime só o que você quer.
  • No Arch (GNU sed 4.10), os erros aparecem como "carácter 15comando…": o número é a posição do problema.

Na Arch Wiki: não há uma página só do sed; ele aparece em Core utilities (em português), e a Wiki o usa o tempo todo em comandos como o de ligar opções do pacman.conf. O manual completo é o do GNU (info sed, ou gnu.org/software/sed/manual), e o pacote está em archlinux.org/packages/core/x86_64/sed.
