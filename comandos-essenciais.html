Arch Comandos Essenciais

Antes de mergulhar no pacman e no systemd, você precisa andar pelas pastas, ler arquivos, copiar, mover, apagar e procurar. Esta aula é um resumo prático desses comandos, os mesmos de qualquer Linux, com as saídas reais do Arch em português e as poucas diferenças que pegam quem vem de outra distribuição. Para estudar cada um a fundo, siga os links para o Guia Bash.

Você vai aprender
  • Navegar e listar: pwd, cd, ls, ls -l (e a data no formato do Arch).
  • Criar, copiar, mover e apagar: mkdir, cp, mv, rm.
  • Ler e editar: cat, less, nano (que não vem no base).
  • Procurar: grep dentro dos arquivos e find nas pastas.
  • Pedir ajuda: man, e por que o man -f pode dizer "nada apropriado".

Onde estou e o que tem aqui: pwd, ls, cd

$ pwd
/home/ana                      « print working directory: a pasta atual
$ ls
'Área de trabalho'   Documentos   frutas.txt   Modelos   Público
 aur                 Downloads    Imagens      Música    Vídeos

O ls (list) lista a pasta atual em colunas. Nomes com espaço aparecem entre aspas ('Área de trabalho'), para você saber que é um nome só. As cores (pastas em azul, por exemplo) vêm do alias ls='ls --color=auto' do .bashrc do Arch.

Criar, copiar, mover e apagar

Para não bagunçar a pasta da Ana, os exemplos usam uma pasta de treino, a1.

mkdir: criar pasta

$ mkdir a1
$ mkdir a1
mkdir: não foi possível criar o diretório “a1”: Arquivo existe
$ echo $?
1

Na primeira vez, silêncio (deu certo). Na segunda, a pasta já existia. Para não reclamar nesse caso (e criar pastas intermediárias), use mkdir -p.

cp: copiar

$ cp frutas.txt a1/                    « copia para dentro de a1, com o mesmo nome
$ cp frutas.txt a1/feira.txt           « copia com outro nome
$ cp Documentos a1/
cp: -r não especificado; omitindo o diretório 'Documentos'
$ cp -r Documentos/projetos a1/        « -r (recursivo): pastas com tudo dentro
$ ls a1
feira.txt  frutas.txt  projetos

mv: mover ou renomear

$ mv a1/feira.txt a1/compras.txt       « mesmo lugar, nome novo = renomear
$ ls a1
compras.txt  frutas.txt  projetos

O mv não precisa de -r para pastas. Cuidado: se o destino já existir, ele é substituído sem perguntar (use mv -i para perguntar).

rm: apagar

$ rm a1/compras.txt
$ rm a1/projetos
rm: não foi possível remover 'a1/projetos': É um diretório
$ rm a1/nada.txt
rm: não foi possível remover 'a1/nada.txt': Arquivo ou diretório inexistente
$ rm -r a1                             « -r apaga a pasta e tudo dentro
$ ls -d a1
ls: não foi possível acessar 'a1': Arquivo ou diretório inexistente
No terminal não há lixeira

O rm apaga de verdade: não vai para a lixeira e não tem "desfazer". Com sudo, ele apaga até arquivos do sistema. Antes de um rm -r, rode ls com o mesmo caminho e leia o que vai sumir. Nunca rode sudo rm -r com curingas (*) sem conferir. A fundo: Guia Bash: Apagar com Segurança.

O cat (de concatenate) despeja o arquivo inteiro na tela: ótimo para arquivos curtos. Para arquivos longos (um log, o /etc/pacman.conf), use o less, que mostra uma tela por vez:

Necessário para      : man-db                « o less veio junto com o man-db
Motivo da instalação : Instalado como dependência de outro pacote

Nem o less faz parte do base: ele chegou à VM como dependência do man-db (o pacote do man). Num Arch sem o man-db, instale-o com sudo pacman -S less.

Editar: nano (que você instala)

Aqui está a primeira grande diferença do Arch: o base não traz editor de texto. Releia a lista de dependências do base na Introdução: nada de nano, vim ou vi. Na VM, o nano e o vim existem porque foram pedidos de propósito no pacstrap:

$ type nano vim vi
nano é /usr/bin/nano
vim é /usr/bin/vim
bash: type: vi: não encontrado         « nem o vim cria o comando vi
$ pacman -Qi nano | grep -E '^(Nome|Versão|Motivo)'
Nome                 : nano
Versão               : 9.2-1
Motivo da instalação : Instalado explicitamente   « alguém pediu: não veio com o base

Se o seu Arch não tem editor, instale um: sudo pacman -S nano (simples) ou sudo pacman -S vim (poderoso, mas com curva de aprendizado). Para quem começa, o nano:

nano
O editor.
notas.txt
O arquivo a abrir (se não existir, ele é criado ao salvar).
Atalho no nanoFaz
Ctrl+O, EnterSalva (write Out)
Ctrl+XSai (pergunta se quer salvar, quando há mudanças)
Ctrl+WProcura (Where is)
Ctrl+K / Ctrl+URecorta a linha / cola
Alt+UDesfaz

Para arquivos do sistema, use sudoedit /etc/arquivo (ou sudo nano /etc/arquivo). O sudoedit é mais seguro: o editor roda como você, numa cópia, e só a gravação final é feita como root. Ele usa a variável EDITOR; ponha export EDITOR=nano no ~/.bash_profile (veja também o caso do visudo em sudo, root e Usuários).

Procurar dentro dos arquivos: grep

grep
Mostra as linhas que contêm um texto (o nome vem de global regular expression print).
banana
O texto (ou padrão) a procurar.
frutas.txt
Onde procurar: um ou mais arquivos.
$ grep banana frutas.txt
banana
banana
banana
$ grep -c banana frutas.txt
3                              « -c = count: quantas linhas
$ grep -n maçã frutas.txt
2:maçã                         « -n = número da linha
6:maçã
$ grep -i BANANA frutas.txt
banana                         « -i = ignora maiúsculas/minúsculas
banana
banana
$ grep kiwi frutas.txt
$ echo $?
1                              « 1 = não achou (não é erro de comando)

Repare no último caso: nada aparece e o código de saída é 1. O grep devolve 0 quando acha, 1 quando não acha e 2 quando há um erro de verdade (arquivo inexistente, por exemplo). No Arch, o alias grep='grep --color=auto' pinta o trecho encontrado.

No resto do guia, o grep aparece filtrando a saída de outros comandos, com um |: pacman -Qi linux | grep Versão. A fundo: Guia Bash: grep, sed, awk e cia.

Missão: conte quantas linhas do frutas.txt têm banana, usando uma opção do grep (a resposta é só o número). Depois descubra em que linhas está a maçã.

Procurar arquivos: find

find
Percorre pastas e lista o que bate com os testes.
a1
Onde começar (e tudo abaixo dela).
-name '*.txt'
O teste: nome terminado em .txt. As aspas impedem o shell de expandir o * antes da hora.
$ find a1 -name '*.txt'
a1/frutas.txt
$ find a1 -type d                      « -type d = só pastas
a1
a1/projetos
a1/projetos/site
Sempre diga onde procurar

Um find / varre o disco inteiro: demora, enche a tela de "Permissão negada" e pesa no computador. Procure numa pasta específica (find ~/Documentos …). Para saber de qual pacote é um arquivo do sistema, o Arch tem um jeito melhor que o find: pacman -Qo /caminho/do/arquivo (veja pacman: o Básico).

Pedir ajuda: man

Quase todo comando tem um manual: man ls, man pacman, man 5 pacman.conf (a seção 5 é a dos arquivos de configuração). Ele abre dentro do less: as mesmas teclas valem, e q sai.

$ man ls | head -12

     ls - list directory contents

SYNOPSIS
     ls [OPTION]... [FILE]...

DESCRIPTION
     List information about the FILEs (the current directory by default).  Sort
     entries alphabetically if none of -cftuvSUX nor --sort is specified.
O man também não vem no base

O comando man vem do pacote man-db, e os manuais básicos do Linux (das funções do sistema, dos arquivos de /etc) do man-pages. Na VM, os dois foram pedidos no pacstrap; num Arch sem eles, man ls responde bash: man: comando não encontrado. Os manuais vêm em inglês; o pacote man-pages-pt_br traduz parte deles.

$ man nao-existe
Nenhuma entrada de manual para nao-existe
$ man -f ls
ls: nada apropriado.           « o índice dos manuais ainda não foi gerado
$ systemctl list-timers man-db.timer --no-pager
NEXT                        LEFT LAST                        PASSED UNIT         ACTIVATES
Sat 2026-10-17 11:17:27 -03  21h Fri 2026-10-16 12:12:00 -03      - man-db.timer man-db.service

1 timers listed.
Pass --all to see loaded but inactive timers, too.

O man -f (e o apropos, que busca pela descrição) usam um índice dos manuais. Esse índice é montado por um timer do systemd, o man-db.timer, uma vez por dia. Num sistema recém-instalado, ele ainda está vazio, e a resposta é "nada apropriado", mesmo para o ls. Para montar o índice na hora, rode sudo mandb (ilustrativo: na VM, o índice foi deixado como estava, para você ver a mensagem).

Quando não funciona

"bash: nano: comando não encontrado"

Causa: o nano não foi instalado (o base não traz editor). A mensagem segue o mesmo formato de qualquer comando ausente (bash: sl: comando não encontrado, código 127).

Como resolver: sudo pacman -S nano. Sem rede ainda? Configure a rede primeiro (Primeiro Boot e Rede); para editar um arquivo curto sem editor, dá para usar echo 'linha' | sudo tee -a arquivo.

"cp: -r não especificado; omitindo o diretório"

Causa: você tentou copiar uma pasta sem -r.

Como resolver: cp -r pasta destino/.

"rm: não foi possível remover '…': É um diretório"

Causa: o rm sem opções só apaga arquivos.

Como resolver: rmdir pasta se ela estiver vazia, ou rm -r pasta depois de conferir o conteúdo com ls.

"man -f ls" responde "nada apropriado."

Causa: o índice dos manuais ainda não foi gerado (sistema novo).

Como resolver: sudo mandb, ou espere o man-db.timer rodar. O man ls funciona mesmo sem o índice.

O grep não mostrou nada

Causa: o texto não está no arquivo (código 1), ou está com outra capitalização.

Como resolver: confira com echo $?; tente grep -i.

Resumo

  • pwd, ls e cd para se localizar; no Arch, o ls -l mostra a data como 14 out 16:05.
  • mkdir, cp (-r para pastas), mv e rm (sem lixeira!).
  • cat para arquivos curtos, less para longos; nano para editar, mas ele não vem no base.
  • grep procura texto (código 1 = não achou); find pasta -name procura arquivos, sempre numa pasta específica.
  • man vem do man-db; o índice do man -f/apropos é gerado pelo man-db.timer ou por sudo mandb.
