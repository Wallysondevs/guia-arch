Flatpak

O Flatpak é um jeito de instalar aplicativos gráficos que funciona igual em qualquer distribuição. Cada aplicativo vem com as bibliotecas de que precisa e roda numa "caixa de areia" (sandbox), separado do resto do sistema. No Arch, ele não substitui o pacman: é uma alternativa para alguns aplicativos, principalmente os que não estão nos repositórios ou que você quer isolados.

Você vai aprender
  • O que são aplicativo, runtime e remoto (o Flathub) no Flatpak.
  • Como o Flathub chega configurado no Arch e como conferir.
  • Procurar (flatpak search), ver detalhes (flatpak remote-info), instalar, rodar e remover.
  • A diferença entre --system e --user, as permissões e o Flatseal.
  • Quando usar Flatpak, pacman ou AUR.

Três palavras do Flatpak

TermoO que éExemplo
AplicativoO programa, identificado por um ID no formato de domínio invertido.org.gnome.Calculator
RuntimeUm "mini-sistema" compartilhado com as bibliotecas base (GTK, Qt, etc.). Vários aplicativos usam o mesmo runtime.org.gnome.Platform versão 51
Remoto (remote)O repositório de onde vêm os aplicativos. O principal é o Flathub.flathub = https://dl.flathub.org/repo/

Comparando com o pacman: o remoto faz o papel do repositório; o runtime, o papel das dependências, só que em um bloco grande e independente das bibliotecas do seu Arch. Por isso um Flatpak não quebra numa atualização do sistema, e por isso também ocupa mais espaço.

Instalar o Flatpak e conferir o Flathub

O Flatpak é um pacote comum do repositório extra:

$ sudo pacman -S flatpak
…
$ pacman -Qi flatpak | grep -E "^(Versão|Tamanho instalado)"
Versão               : 1:1.18.4-1            « o "1:" é a época: um contador que vence qualquer número de versão
Tamanho instalado    : 8,08 MiB
$ flatpak --version
Flatpak 1.18.4

Na VM do guia, a instalação real do flatpak veio junto com os pacotes das aulas (registro 10-pacotes-aulas), puxando dependências como bubblewrap (a ferramenta da sandbox), ostree e xdg-desktop-portal. Um dos hooks criou o usuário de sistema do Flatpak: Creating user 'flatpak' (Flatpak system helper) with UID 967 and GID 967.

O Flathub já vem configurado

Muitos guias mandam adicionar o Flathub à mão. No Arch atual isso não é preciso: o próprio pacote traz o arquivo do Flathub, e o Flatpak o aplica sozinho na primeira vez que roda:

$ pacman -Ql flatpak | grep remotes.d
flatpak /usr/share/flatpak/remotes.d/
flatpak /usr/share/flatpak/remotes.d/flathub.flatpakrepo    « o "cartão de visita" do Flathub, com a chave dele
$ flatpak remotes
flathub	system                                             « nome e tipo de instalação

Para ter certeza de que é o pacote, e não algo feito depois, testamos com uma instalação do Flatpak vazia, numa pasta temporária (a variável FLATPAK_SYSTEM_DIR troca a pasta do sistema, /var/lib/flatpak, por outra):

#> FLATPAK_SYSTEM_DIR=/tmp/a4/fp flatpak remotes --system
flathub                                                    « nasceu com o Flathub
#> grep applied /var/lib/flatpak/repo/config
xa.applied-remotes=flathub;                                « o Flatpak anota que já aplicou o arquivo

Durante a instalação da VM, rodamos o comando "clássico" mesmo assim. Com --if-not-exists, ele não faz nada quando o remoto já existe, e termina com sucesso (registro 13-flatpak):

#> flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
#> echo $?
0
$ flatpak remotes
flathub	system
remote-add
Adicionar um remoto.
--if-not-exists
Se já existe, não dá erro. Sem ele, a resposta real é erro: O remoto flathub já existe, com código 1.
flathub
O nome que você dá ao remoto.
https://…/flathub.flatpakrepo
O arquivo com o endereço e a chave de assinatura do repositório.

Esse comando continua útil em dois casos: se você apagou o remoto, e para o Flathub do usuário (--user, abaixo), que não vem configurado.

Depois de instalar o Flatpak, reinicie a sessão

Os aplicativos instalados pelo Flatpak só aparecem no menu do ambiente gráfico depois de sair e entrar de novo (o script /etc/profile.d/flatpak.sh, do pacote, ajusta a variável XDG_DATA_DIRS no login).

Procurar: flatpak search

A busca usa um catálogo (dados appstream) que precisa ser baixado. Numa instalação nova, a primeira busca não acha nada:

$ flatpak search calculator
Nenhuma correspondência localizada
$ sudo flatpak update --appstream
Atualizando dados de appstream para remoto flathub
$ flatpak search calculator | head -4
Calculadora de IMC	Calcule seu IMC	io.github.johannesboehler2.BmiCalculator	1.6.2	stable	flathub
Uno Calculator	Linux port of the Microsoft Windows calculator app	uno.platform.uno-calculator	1.2.9	stable	flathub
Yesser Calculator	Extend your calculator	io.github.yesser_studios.Yesser-Calculator	1.3.0	stable	flathub
Modular Calculator	A powerful, scriptable, modular calculator aimed at scientific, engineering or computing work.	io.github.jordanl2.ModularCalculator	1.5.8	stable	flathub

Num terminal, o resultado sai em colunas com título; mandando para outro comando (o | head), sai separado por tabulações, uma coluna por campo. As colunas são: Nome, Descrição, ID de aplicativo, Versão, Ramo (stable) e Remotos. O nome e a descrição vêm traduzidos quando o aplicativo tem tradução. Para escolher as colunas:

$ flatpak search --columns=name,application,version calculadora | head -3
Calculadora	org.kde.kalk	26.08.1
Calculadora	org.gnome.Calculator	51.1
Calculadora de IMC	io.github.johannesboehler2.BmiCalculator	1.6.2

Repare que há várias "Calculadora": é o ID que diz qual é qual. O org.kde.kalk é a do KDE; o org.gnome.Calculator, a do GNOME.

A calculadora tem 5,1 MB, mas o runtime é outra história:

$ flatpak remote-info flathub org.gnome.Platform//51 | grep -E "Tamanho|ID"

O primeiro aplicativo GNOME custa mais de 1 GB, porque traz o runtime. Os seguintes que usam o mesmo runtime saem baratos. É a troca do Flatpak: espaço em disco por independência do sistema.

Instalar, rodar e remover

flatpak install
Instalar.
flathub
De qual remoto (pode omitir se só houver um).
org.gnome.Calculator
O ID do aplicativo.

Na VM do guia não instalamos (seria mais de 400 MB de download). Esta é a saída real até a primeira pergunta, respondida com n:

#> flatpak install flathub org.gnome.Calculator
Procurando por correspondências…
Runtime exigido para org.gnome.Calculator/x86_64/stable (runtime/org.gnome.Platform/x86_64/51) localizado no remoto flathub
Você deseja instalá-lo? [Y/n]: n                     « as letras ficam em inglês: Y = sim
erro: O aplicativo org.gnome.Calculator/x86_64/stable requer o runtime org.gnome.Platform/x86_64/51, que não está instalado
#> echo $?
1

Respondendo Y (ou Enter), o Flatpak mostra uma tabela com tudo o que vai baixar (aplicativo, runtime, traduções) e pede mais uma confirmação. Depois de instalado, os comandos do dia a dia são estes (ilustrativos, pelo mesmo motivo):

ComandoO que faz
flatpak run org.gnome.CalculatorAbre o aplicativo (ou pelo menu do ambiente gráfico)
flatpak list --appLista os aplicativos instalados (sem --app, inclui os runtimes)
flatpak updateAtualiza todos os Flatpaks (o pacman -Syu não faz isso)
flatpak uninstall org.gnome.CalculatorRemove o aplicativo
flatpak uninstall --unusedRemove runtimes que nenhum aplicativo usa mais (os "órfãos" do Flatpak)
flatpak uninstall --delete-data org.gnome.CalculatorRemove e apaga os dados do aplicativo em ~/.var/app/

Na VM, sem nada instalado: flatpak list não mostra nada e devolve 0. O espaço ocupado em /var/lib/flatpak já era de 116 MB, só com o catálogo do Flathub.

--system × --user

O Flatpak tem duas instalações separadas:

--system (padrão)--user
Onde fica/var/lib/flatpak~/.local/share/flatpak
Quem vêTodos os usuáriosSó você
Precisa de senhaSim (root, ou a janela de senha do polkit no ambiente gráfico)Não
Flathub configuradoSim, de fábricaNão: adicione com --user

Por isso, a primeira tentativa de instalar só para você falha. Saída real, como ana:

$ flatpak remotes --user
$ flatpak install --user flathub org.gnome.Calculator
Procurando por correspondências…
erro: Nenhuma ref de remoto localizada para “flathub”      « o remoto flathub do usuário não existe
$ echo $?
1

A solução é adicionar o Flathub também na instalação do usuário:

$ flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
$ flatpak install --user flathub org.gnome.Calculator

(Ilustrativo: na VM, o Flathub do usuário não foi adicionado.) Use --user num computador compartilhado, ou quando não tem a senha de administrador.

Permissões e Flatseal

Cada aplicativo declara o que precisa acessar fora da sandbox. Veja antes de instalar, com --show-metadata:

$ flatpak remote-info --show-metadata flathub org.gnome.Calculator
[Application]
name=org.gnome.Calculator
runtime=org.gnome.Platform/x86_64/51
sdk=org.gnome.Sdk/x86_64/51
command=gnome-calculator

[Context]
shared=ipc;network;                 « rede (cotação de moedas) e memória compartilhada
sockets=fallback-x11;wayland;       « desenhar janelas (Wayland, ou X11 se não houver Wayland)
devices=dri;                        « aceleração gráfica
…

A calculadora não pede acesso aos seus arquivos (filesystems= não aparece). Um editor de imagens pediria, por exemplo, filesystems=home;. Permissões comuns:

PermissãoLibera
filesystems=home / hostSua pasta pessoal / o sistema de arquivos todo
shared=networkInternet
sockets=wayland;x11Mostrar janelas
sockets=pulseaudioSom
devices=allTodos os dispositivos (webcam, controles de jogo…)

Para mudar as permissões de um aplicativo instalado, há o comando flatpak override (ex.: flatpak override --user --nofilesystem=home ID tira o acesso à pasta pessoal) e o aplicativo gráfico Flatseal, que mostra tudo com chaves liga/desliga. Ele próprio é um Flatpak:

$ flatpak search flatseal | head -1
Flatseal	Gerencie as permissões de Flatpaks	com.github.tchx84.Flatseal	2.4.1	stable	flathub
Sandbox não é garantia

Um aplicativo com filesystems=host enxerga quase tudo, e o Flathub aceita aplicativos enviados por terceiros (nem sempre pelos autores originais). Prefira os marcados como "verificados" no site do Flathub e confira as permissões.

Qual usar? No Arch, a ordem costuma ser: repositórios oficiais primeiro (pacman -Ss); se não estiver lá e for um aplicativo gráfico, Flatpak; se não houver Flatpak, ou for uma ferramenta de terminal, o AUR (lendo o PKGBUILD). Evite ter o mesmo programa pelos três caminhos: você não sabe qual está abrindo.

Experimente

Missão: o simulador não roda o Flatpak, mas conhece o pacote dele. Descubra a versão do pacote flatpak instalado na máquina da ana e de quais pacotes ele depende.

Quando não funciona

"Nenhuma ref de remoto localizada para “flathub”" 
$ flatpak install --user flathub org.gnome.Calculator
Procurando por correspondências…
erro: Nenhuma ref de remoto localizada para “flathub”

O que aconteceu: o remoto não existe na instalação escolhida (aqui, a do usuário).

Como confirmar: flatpak remotes --user e flatpak remotes --system.

Como resolver: instale sem --user, ou adicione o Flathub com flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo.

"Nenhuma correspondência localizada" numa busca

O que aconteceu: o catálogo appstream ainda não foi baixado (ou o nome não existe).

Como resolver: sudo flatpak update --appstream e procure de novo; procure também pelo nome em inglês.

"requer o runtime …, que não está instalado"

O que aconteceu: você respondeu n à pergunta do runtime. Sem ele, o aplicativo não instala.

Como resolver: repita e aceite o runtime. Se o problema é espaço, confira antes com flatpak remote-info.

O aplicativo não aparece no menu

O que aconteceu: a sessão gráfica começou antes do Flatpak ser instalado.

Como resolver: saia e entre de novo na sessão. Enquanto isso, flatpak run ID abre o aplicativo.

O aplicativo não enxerga meus arquivos

O que aconteceu: é a sandbox funcionando: ele não tem permissão de filesystems para aquela pasta.

Como resolver: use o seletor de arquivos do próprio aplicativo (ele passa pelo "portal", que pede sua autorização), ou libere a pasta no Flatseal / flatpak override --user --filesystem=~/Documentos ID.

Resumo

  • Flatpak = aplicativo + runtime, vindos de um remoto (o Flathub), rodando numa sandbox.
  • No Arch, sudo pacman -S flatpak já traz o Flathub da instalação do sistema; o do usuário (--user) você adiciona.
  • search (depois de update --appstream), remote-info (tamanho, runtime, permissões), install, run, update, uninstall --unused.
  • Permissões: confira antes; ajuste com o Flatseal ou flatpak override.
  • Repositórios oficiais primeiro; Flatpak para aplicativos gráficos que não estão lá; AUR com cuidado.

Na Arch Wiki: a página Flatpak (em português: Flatpak (Português)) cobre instalação, remotos, --user e permissões. Para comparar as formas de instalar programas, veja também Arch User Repository e a documentação oficial em docs.flatpak.org.
