mkinitcpio e initramfs

Junto com o kernel, o bootloader carrega um segundo arquivo: o initramfs (initial RAM file system), um sistema minúsculo que roda na memória só pelo tempo de encontrar e montar o seu disco. No Arch, quem fabrica esse arquivo é o mkinitcpio (make initial cpio). Na maior parte do tempo ele trabalha sozinho; você precisa entendê-lo quando usa criptografia, LVM, Btrfs em vários discos, ou quando o boot para logo no começo.

Você vai aprender
  • Por que existe o initramfs e onde ele entra no boot.
  • Ler o /etc/mkinitcpio.conf da ana, hook por hook.
  • O que são os presets e o que o mkinitcpio -P mostra na tela.
  • Testar uma mudança sem arriscar o boot, e olhar dentro da imagem com lsinitcpio.
  • Quando acrescentar sd-encrypt, lvm2 ou btrfs, e o que é uma UKI.

O problema do ovo e da galinha

Para montar a partição raiz, o kernel precisa do driver do disco (SATA, NVMe, USB…), do driver do sistema de arquivos e, às vezes, de programas (o cryptsetup, para pedir a senha de um disco criptografado). Só que esses arquivos estão… dentro da partição raiz, que ainda não foi montada.

A solução é levar junto um "kit de primeiros socorros": um arquivo compactado com só o necessário, que o bootloader carrega na memória ao lado do kernel. A ordem do boot fica assim:

  1. Firmware UEFI → inicia o GRUB (a partição EFI, /boot).
  2. GRUB → carrega na memória o kernel (/boot/vmlinuz-linux) e o initramfs (/boot/initramfs-linux.img, junto com o intel-ucode.img; veja Microcode).
  3. Kernel → descompacta o initramfs e roda o programa de dentro dele.
  4. Initramfs → carrega os drivers, acha o disco pelo UUID (root=UUID=75d167c8-…, que o GRUB passou), verifica com fsck e monta a raiz.
  5. switch_root → troca a raiz da memória pela raiz do disco e passa o comando para o systemd do sistema instalado.

O nome mkinitcpio vem de cpio, o formato de arquivo compactado (parecido com um .tar) usado para o initramfs.

Os HOOKS, um por um

Cada hook é uma receita: um script em /usr/lib/initcpio/install/ que, na hora de gerar a imagem, copia para dentro dela os módulos, programas e arquivos de que precisa. A ordem importa: eles rodam da esquerda para a direita.

HookO que põe no initramfs
baseA base: pastas, o busybox (um canivete suíço de comandos) e utilitários como mount. Sempre o primeiro
systemdUm systemd dentro do initramfs, que comanda o boot inicial (inclui o udev, que detecta o hardware e carrega drivers)
autodetectOlha o hardware desta máquina e faz os hooks seguintes copiarem só os módulos necessários. Deixa a imagem bem menor
microcodeA atualização de microcode do processador, carregada antes de tudo (veja Microcode)
modconfAs configurações de /etc/modprobe.d/ (opções e blacklist de módulos; veja Kernels)
kmsOs drivers de vídeo (kernel mode setting), para a tela ganhar a resolução certa cedo e a senha do disco aparecer bonita
keyboardDrivers de teclado (USB, por exemplo), para você conseguir digitar algo no boot
sd-vconsoleO layout do teclado e a fonte do console, lidos de /etc/vconsole.conf (na ana, KEYMAP=br-abnt2). Importa para digitar a senha de um disco criptografado com o ç no lugar
blockDrivers de discos: SATA, NVMe, USB, cartão SD
filesystemsDrivers de sistemas de arquivos (ext4, Btrfs, XFS…)
fsckO verificador do sistema de arquivos da raiz (na ana, o e2fsck), que roda antes de montá-la

Cada hook tem uma ajuda própria, em inglês: mkinitcpio -H nome. Por exemplo:

$ mkinitcpio -H autodetect
==> Help for hook 'autodetect':
This hook shrinks your initramfs to a smaller size by autodetecting the needed
modules. Be sure to verify included modules are correct and none are missing.
This hook must be run before other subsystem hooks in order to take advantage
of auto-detection.  Any hooks placed before 'autodetect' will be installed in
full.

Ou seja: o que vem antes do autodetect entra completo; o que vem depois, só o que esta máquina usa. Por isso ele fica logo no começo.

Dois estilos: busybox e systemd

O initramfs pode ser comandado por scripts simples (com o hook udev) ou pelo systemd (hook systemd). O padrão atual do Arch, e o da ana, é o systemd. Alguns hooks têm duas versões, e não se misturam:

FunçãoEstilo busyboxEstilo systemd (o da ana)
Comandar o boot inicialudevsystemd
Teclado e fontekeymap + consolefontsd-vconsole
Disco criptografado (LUKS)encryptsd-encrypt
LVMlvm2 (serve nos dois)

Muitos tutoriais antigos na internet usam o estilo busybox. Se o seu HOOKS tem systemd, use as versões sd-.

Presets: uma receita por kernel

Cada kernel instalado tem um arquivo de preset em /etc/mkinitcpio.d/, que diz qual kernel usar e onde gravar a imagem:

$ ls /etc/mkinitcpio.d/
linux-lts.preset
linux.preset
$ cat /etc/mkinitcpio.d/linux.preset
# mkinitcpio preset file for the 'linux' package

#ALL_config="/etc/mkinitcpio.conf"
ALL_kver="/boot/vmlinuz-linux"                         « o kernel
#ALL_kerneldest="/boot/vmlinuz-linux"

PRESETS=('default')                                    « só uma imagem
#PRESETS=('default' 'fallback')

#default_config="/etc/mkinitcpio.conf"
default_image="/boot/initramfs-linux.img"              « onde gravar
#default_uki="/efi/EFI/Linux/arch-linux.efi"
#default_options="--splash /usr/share/systemd/bootctl/splash-arch.bmp"

#fallback_config="/etc/mkinitcpio.conf"
#fallback_image="/boot/initramfs-linux-fallback.img"
#fallback_uki="/efi/EFI/Linux/arch-linux-fallback.efi"
#fallback_options="-S autodetect"

Repare na linha PRESETS=('default'): hoje o Arch gera só a imagem padrão. Antigamente vinha também uma fallback ("de reserva"), gerada sem o autodetect (-S autodetect), com todos os drivers, útil se você trocasse o disco de computador. Para tê-la de volta, troque pela linha comentada PRESETS=('default' 'fallback'). Os dois kernels usam o mesmo /etc/mkinitcpio.conf (o #ALL_config comentado é o padrão).

Quando ele roda sozinho

Quase nunca você precisa rodá-lo à mão. Um hook do pacman (/usr/share/libalpm/hooks/90-mkinitcpio-install.hook) o chama no fim de qualquer transação que mexa no que vai dentro do initramfs. Um trecho real do arquivo:

[Trigger]
Type = Path
Operation = Install
Operation = Upgrade
Target = usr/lib/modules/*/vmlinuz

[Action]
Description = Updating linux initcpios...
When = PostTransaction
Exec = /usr/share/libalpm/scripts/mkinitcpio install
NeedsTargets

É ele que aparece no fim das atualizações como (15/18) Updating linux initcpios.... Outros gatilhos do mesmo arquivo: firmware, systemd, cryptsetup, lvm e módulos DKMS. Rode à mão (sudo mkinitcpio -P) quando você mudar o /etc/mkinitcpio.conf ou o /etc/vconsole.conf.

O aviso do vconsole.conf (log real)

No pacstrap, o kernel foi instalado antes de existir o /etc/vconsole.conf, e o mkinitcpio avisou:

  -> Running build hook: [sd-vconsole]
==> WARNING: sd-vconsole: "/etc/vconsole.conf" not found, will use default values
  -> Running build hook: [block]

Um WARNING não é erro: a imagem foi criada, com o teclado americano. Depois a ana criou o arquivo (KEYMAP=br-abnt2) e rodou o mkinitcpio -P mostrado acima, já sem o aviso. É por isso que o guia de instalação manda rodar o mkinitcpio -P depois de configurar o teclado (Configurar o Sistema).

Testar uma mudança sem arriscar o boot

Mudar os HOOKS e gerar direto em /boot é arriscado: se a imagem sair errada, o próximo boot para no começo (e os dois kernels usam o mesmo arquivo de configuração). Dá para gerar uma imagem de teste em outro lugar, a partir de uma cópia da configuração:

-c /tmp/a7/mkinitcpio.conf
config: usa este arquivo em vez do /etc/mkinitcpio.conf.
-k 7.2.10-arch1-1
kernel: para qual versão (a de uname -r).
-g /tmp/a7/teste.img
generate: grava a imagem aqui. O /boot não é tocado.

Primeiro, um erro de digitação proposital (filesytems, sem o "s" do meio):

Quando acrescentar hooks

Com a raiz num ext4 simples, como a da ana, o padrão basta. Você mexe nos HOOKS quando a raiz depende de algo que precisa ser "aberto" antes de montar:

Sua raiz está…AcrescenteOndeAula
Num disco criptografado (LUKS)sd-encryptDepois de block, antes de filesystemsCriptografia (LUKS)
Num volume LVMlvm2 (precisa do pacote lvm2)Depois de block (e depois do sd-encrypt, se houver)LVM
Num Btrfs de vários discosbtrfs (vem com o btrfs-progs)Antes de filesystemsBtrfs
Num Btrfs de um disco sóNadaO filesystems já cuidaBtrfs

Exemplo: criptografia e LVM juntos ficariam HOOKS=(base systemd autodetect microcode modconf kms keyboard sd-vconsole block sd-encrypt lvm2 filesystems fsck). A ordem é a ordem das camadas: primeiro abre a criptografia, depois acha o LVM dentro dela, depois monta o sistema de arquivos.

UKI: kernel e initramfs num arquivo só

Uma UKI (Unified Kernel Image) junta num único arquivo .efi o kernel, o initramfs, o microcode e a linha de comando do kernel. O firmware UEFI (ou o systemd-boot) inicia esse arquivo direto. Vantagens: um arquivo só para assinar no Secure Boot, e a linha de comando não pode ser alterada no boot. O próprio preset da ana já mostra o caminho, comentado:

#default_uki="/efi/EFI/Linux/arch-linux.efi"

Descomentando essa linha (e escrevendo a linha de comando em /etc/kernel/cmdline), o mkinitcpio -P passa a gerar a UKI. A ana usa GRUB com initramfs separado, o caminho mais comum, e não muda para UKI neste guia. Se quiser ir por esse caminho, comece por Bootloader (GRUB e systemd-boot) e pela página da Wiki no fim.

Quando não funciona

"ERROR: Hook '…' cannot be found" 
==> ERROR: Hook 'filesytems' cannot be found
…
==> WARNING: errors were encountered during the build. The image may not be complete.

O que aconteceu: o nome está errado, ou o hook é de um pacote que não está instalado (o lvm2 vem do pacote lvm2; o btrfs, do btrfs-progs).

Como confirmar: ls /usr/lib/initcpio/install/ lista os hooks existentes; pacman -Qo /usr/lib/initcpio/install/lvm2 diz de que pacote vem.

Como resolver: corrija o HOOKS (ou instale o pacote) e rode sudo mkinitcpio -P de novo, até sair sem ERROR. Não reinicie antes.

"WARNING: Possibly missing firmware for module"

O que aconteceu: um módulo incluído pode usar um firmware que não está instalado. Quase sempre é de um hardware que você nem tem.

Como resolver: ignore, a menos que o módulo citado seja de um aparelho seu (aí, procure o firmware com pacman -F nome).

"WARNING: sd-vconsole: "/etc/vconsole.conf" not found"

O que aconteceu: a imagem foi feita antes de você configurar o teclado. O initramfs fica com o teclado americano (importa para digitar a senha de um disco criptografado).

Como resolver: crie o /etc/vconsole.conf (KEYMAP=br-abnt2) e rode sudo mkinitcpio -P.

Mudei os HOOKS e o boot para logo no começo

O que aconteceu: a imagem nova não tem algo de que a raiz precisa (um hook faltando ou fora de ordem). Como os dois kernels usam o mesmo /etc/mkinitcpio.conf, escolher o LTS no GRUB provavelmente não resolve.

Como resolver: inicie pelo pendrive do Arch, monte o sistema, entre com arch-chroot, corrija o arquivo e rode mkinitcpio -P lá dentro (veja Resgate com chroot). Para ter um plano B no próprio menu, ative o preset fallback.

Resumo

  • O initramfs é o mini-sistema que o GRUB carrega com o kernel para achar e montar a raiz; o mkinitcpio o fabrica.
  • O que entra é definido pelos HOOKS de /etc/mkinitcpio.conf, em ordem; a ana usa o padrão, no estilo systemd.
  • Cada kernel tem um preset em /etc/mkinitcpio.d/; hoje só a imagem default é gerada.
  • O pacman roda o mkinitcpio sozinho; você roda sudo mkinitcpio -P depois de mudar a configuração, e só reinicia sem ERROR.
  • LUKS → sd-encrypt; LVM → lvm2; Btrfs de vários discos → btrfs. lsinitcpio -a mostra o que entrou.
