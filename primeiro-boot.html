Arch Primeiro Boot

É a hora da verdade: sair do ambiente live, reiniciar e ver o seu Arch ligar sozinho, do disco. Nesta aula você fecha a instalação do jeito certo, reconhece cada tela que aparece, entra como ana e confere, comando por comando, se tudo o que configurou está valendo. No fim, um checklist e o que fazer se a máquina não ligar.

Você vai aprender
  • Sair do chroot, desmontar as partições e reiniciar sem perder nada.
  • O que aparece no primeiro boot: o menu do GRUB e a tela de login em texto.
  • Conferir sistema, nome, idioma, fuso, rede e serviços com as saídas reais da VM.
  • Conectar no Wi-Fi pelo terminal com nmcli.
  • Diagnosticar quando a máquina não liga ou liga sem rede.

1. Sair do chroot

Você terminou a aula Bootloader dentro do sistema novo, com o prompt [root@archiso /]#. O exit fecha o Bash do chroot e devolve você ao zsh do live:

#> exit
exit

O prompt volta a ser o do live, root@archiso ~ #. (Também funciona Ctrl+D.) Na VM do guia os comandos foram rodados com arch-chroot /mnt comando, um de cada vez, então não houve exit: cada arch-chroot já saía sozinho.

2. Desmontar tudo: umount -R

O Linux não grava tudo no disco na hora: guarda parte na memória para gravar depois. Desmontar obriga essa gravação e fecha as partições com segurança. Desligar sem desmontar pode deixar o sistema de arquivos marcado como "sujo" (foi o que aconteceu com a partição EFI da VM depois de um desligamento forçado; veja Recuperar o Boot).

umount
Desmonta (sem o "n": u-mount).
-R
recursive: desmonta /mnt e tudo o que está montado dentro dele (/mnt/boot e o que o arch-chroot montou), na ordem certa.
/mnt
A raiz do sistema novo.
#> umount -R /mnt
#> swapoff /dev/sda2               « opcional: desliga a swap que o live estava usando
#> echo ok
ok

No log da VM, os três comandos foram numa linha só (umount -R /mnt; swapoff /dev/sda2; echo ok) e só o ok apareceu: nenhuma mensagem quer dizer que deu certo. O swapoff é opcional; o reboot também desligaria a swap.

"umount: /mnt: target is busy."

O que aconteceu: algum programa ainda está usando algo dentro de /mnt; quase sempre é o próprio terminal, que está numa pasta lá dentro (você fez cd /mnt), ou você ainda está no chroot. Na VM do guia, reproduzindo o erro com uma pasta de teste (no sistema instalado a mensagem sai em português; código de saída 32):

#> cd /tmp/a3/m
#> umount -R /tmp/a3/m
umount: /tmp/a3/m: o alvo está ocupado.
#> cd /
#> umount -R /tmp/a3/m
#> echo $?
0

Como resolver: saia do chroot (exit), vá para outra pasta (cd) e tente de novo.

3. Reiniciar e tirar o pendrive

#> reboot

A tela apaga e o computador reinicia. Agora tire o pendrive (ou, na máquina virtual, ejete a ISO). Se você esquecer, alguns computadores ligam o live de novo, porque o pendrive está antes do disco na ordem de boot do firmware. Na VM do guia isso não acontece: o grub-install pôs a entrada GRUB em primeiro no BootOrder (0003,0000,0001,0002; veja Bootloader).

OndeComo tirar a mídia de instalação
Computador de verdadePuxe o pendrive quando a tela apagar (ou já no menu do GRUB).
VirtualBoxMenu Dispositivos → Discos Ópticos → Remover disco do drive virtual; ou, com a VM desligada, Configurações → Armazenamento e remova a ISO.
Ligou o live de novo?Sem problema: nada se perdeu. Desligue (poweroff), tire a mídia e ligue.

4. O que aparece na tela

O menu do GRUB

Primeiro vem o menu do GRUB, com uma contagem de 5 segundos (o GRUB_TIMEOUT=5). Sem tocar em nada, ele liga o primeiro item, Arch Linux. Os itens do primeiro boot são os que o grub-mkconfig criou na instalação:

ItemPara que serve
Arch LinuxO boot normal. É o padrão.
Advanced options for Arch LinuxSubmenu com cada kernel instalado. Como o menu foi gerado no live (em inglês), o nome sai em inglês; quando você gerar de novo no sistema instalado, vira "Opções avançadas para Arch Linux".
UEFI Firmware SettingsReinicia direto na configuração do firmware.
… (EFI BootNext)Um item para cada entrada do firmware (UiApp, CD-ROM, disco, GRUB). Escolher um reinicia por aquela entrada. Normalmente você não usa.

Use as setas para escolher e Enter para ligar. Depois do menu, o boot é quase silencioso (o quiet do GRUB_CMDLINE_LINUX_DEFAULT): a tela fica preta por alguns segundos e aparece o login.

A tela de login

Não há interface gráfica: o Arch instalado assim é só texto. A primeira tela da VM do guia foi esta:

Arch Linux
O nome do sistema (do arquivo /etc/os-release).
7.2.10-arch1-1
A versão do kernel que ligou.
(tty1)
O terminal: o tty1 é o primeiro console de texto. Existem outros: Ctrl+Alt+F2 abre o tty2 (útil quando algo trava; veja Quando o Sistema Trava).
notebook
O nome da máquina, lido de /etc/hostname. Se aparece archlinux ou outro nome, o arquivo não foi escrito.
login:
Esperando o nome de usuário.

A primeira linha vem do arquivo /etc/issue, que tem códigos trocados na hora: \S{PRETTY_NAME} = nome do sistema, \r = versão do kernel, \l = terminal.

$ cat /etc/issue
\S{PRETTY_NAME} \r (\l)

Entrar como ana

Digite ana e Enter. Aparece o pedido de senha; digite a senha que você definiu com passwd ana (nada aparece enquanto digita) e Enter. Se der certo, surge o prompt:

$ whoami
ana

Esse [ana@notebook ~]$ resume a instalação: ana (a usuária do useradd), notebook (o /etc/hostname), ~ (a pasta pessoal, criada pelo -m) e $ (usuária comum, não root). Errou a senha? Aparece uma mensagem de login incorreto e o login: volta; tente de novo, atenção ao teclado (ABNT2) e ao Caps Lock.

$ systemctl --failed

Esta é a melhor resposta possível: zero unidades com falha. Se aparecer alguma, investigue com systemctl status NOME e journalctl -b -u NOME (veja systemctl e Serviços).

6. Wi-Fi pelo terminal (ilustrativo)

A VM do guia usa rede com fio, e o NetworkManager confirma que ela não tem Wi-Fi (WIFI-HW faltando):

$ nmcli general
STATE      CONNECTIVITY  WIFI-HW   WIFI        WWAN-HW   WWAN        METERED
conectado  completa      faltando  habilitado  faltando  habilitado  não (adivinhado)

Num notebook, os passos abaixo conectam no Wi-Fi. Eles não foram executados na VM (não há placa); siga a sequência e leia as mensagens:

  1. Veja se a placa existe. nmcli device deve listar um dispositivo do tipo wifi (o nome costuma ser wlan0 ou wlp2s0). Se ele não aparece, falta o firmware da placa: o pacote linux-firmware resolve na maioria dos casos.
  2. Liste as redes. nmcli device wifi list mostra as redes por perto, com o sinal e a segurança.
  3. Conecte. nmcli device wifi connect "Nome da Rede" --ask: o --ask pergunta a senha sem deixá-la no histórico do Bash. (Também existe password "senha" no fim do comando, mas a senha fica visível.)
  4. Confira. nmcli device deve mostrar a placa como conectada, e ping -c 3 archlinux.org deve responder.
nmcli
O cliente de linha de comando do NetworkManager.
device wifi
Operações de Wi-Fi nos dispositivos.
connect "Nome da Rede"
Conectar a esta rede (o SSID). Aspas por causa dos espaços.
--ask
Pergunta o que faltar (a senha) no terminal.
Prefere menus?

O nmtui (vem com o NetworkManager) abre uma interface de texto com setas: Ativar uma conexão → escolha a rede → digite a senha. A conexão fica salva e liga sozinha nos próximos boots.

Quando não liga

Ligou direto na tela do firmware, ou num "UEFI Interactive Shell"

O que aconteceu: o firmware não achou o bootloader: o grub-install falhou ou não rodou, ou o firmware ignora a entrada GRUB (comum no VirtualBox e em algumas placas).

Como resolver: ligue o pendrive, monte as partições, arch-chroot /mnt e reinstale o GRUB; se o firmware for "teimoso", use o --removable (Bootloader, seção "Quando não funciona"). O roteiro de montar e entrar está em Resgate com chroot.

Caiu em grub> ou grub rescue>

O que aconteceu: grub> = o GRUB ligou mas não achou o grub.cfg (faltou o grub-mkconfig -o …). grub rescue> = nem os módulos ele achou (partição mudou ou foi formatada).

Como resolver: pelo pendrive e chroot, rode grub-mkconfig -o /boot/grub/grub.cfg (e, no segundo caso, o grub-install também). Passo a passo em Recuperar o Boot.

Kernel panic: "Unable to mount root fs", ou o boot para esperando um disco

O que aconteceu: o kernel não achou a partição raiz: o root=UUID=… do GRUB não corresponde a nenhuma partição (formatou de novo depois de gerar o menu?) ou o initramfs não tem o driver do disco.

Como resolver: pelo chroot, confira o UUID com lsblk -f, rode mkinitcpio -P e grub-mkconfig -o /boot/grub/grub.cfg. Veja Recuperar o Boot e mkinitcpio.

Entrou em "emergency mode" pedindo a senha do root

O que aconteceu: o kernel ligou, mas o systemd não conseguiu montar algo do /etc/fstab (UUID errado, linha repetida, partição que não existe).

Como resolver: digite a senha do root (por isso ela é importante), rode findmnt --verify para achar a linha com problema, corrija com nano /etc/fstab e reboot. Detalhes em mount e fstab.

Ligou, mas sem rede

Como confirmar: nmcli device responde que o NetworkManager não está rodando, ou systemctl is-enabled NetworkManager diz disabled.

Como resolver: se o pacote está instalado mas faltou ativar: sudo systemctl enable --now NetworkManager (o --now ativa e já liga). Se o pacote nem foi instalado (esqueceu o networkmanager no pacstrap), não dá para baixá-lo sem rede: ligue o pendrive, monte, arch-chroot /mnt e rode pacman -S networkmanager (o live tem internet), depois systemctl enable NetworkManager.

O teclado digita errado no login (Ç, acentos, /?)

O que aconteceu: o console está com o teclado americano: o /etc/vconsole.conf não foi criado ou tem erro de digitação.

Como resolver: entre (a senha pode exigir procurar as teclas), confira localectl e corrija com sudo localectl set-keymap br-abnt2, que grava o /etc/vconsole.conf por você.

E agora?

O seu Arch está instalado, mas mínimo. A ordem natural dos próximos passos:

  1. Atualize o sistema: sudo pacman -Syu (Atualizar o Sistema).
  2. Entenda o sudo e as contas: sudo, root e Usuários.
  3. Instale programas com o pacman: pacman: o Básico.
  4. Instale uma interface gráfica, se quiser: Instalar um Desktop.

Quer refazer tudo do zero, de uma vez, com tempo estimado de cada etapa? Use o projeto Instalação Completa do Zero.

Resumo

  • exit, umount -R /mnt, reboot e tire a mídia de instalação.
  • O GRUB espera 5 segundos e liga o Arch; o login é em texto: notebook login:.
  • Confira com hostnamectl, localectl, timedatectl, nmcli device, systemctl --failed e sudo whoami.
  • A VM ligou com 193 pacotes, 2,3 GB usados e nenhum serviço com falha. Faltou só o NTP (timedatectl set-ntp true).
  • Wi-Fi: nmcli device wifi connect "REDE" --ask ou nmtui.
  • Não ligou? Pendrive + arch-chroot resolvem quase tudo: Resgate com chroot, Recuperar o Boot.
