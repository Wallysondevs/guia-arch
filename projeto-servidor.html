Projeto: Servidor Caseiro

Neste projeto, a sua VM vira um pequeno servidor de casa: você entra nela por SSH com chave, ela publica um site com nginx, faz backup diário da pasta Documentos sozinha, roda um serviço num container e tem um firewall pronto para ligar. Tudo foi executado na VM do guia, com as saídas reais, e desfeito no fim, como você também vai fazer.

Você vai praticar
  • Juntar systemctl, nginx, timers, Podman e nftables num sistema só.
  • Escrever um script de backup e agendá-lo com um timer do usuário (systemctl --user).
  • Publicar um serviço num container sem root.
  • Planejar um firewall e testar a sintaxe sem aplicar (nft -c).
  • Anotar o estado inicial e desfazer tudo no fim.

Passo 1: SSH com chave

Um servidor é administrado de outro computador. O SSH (sshd) já é o caminho do laboratório: a VM do guia é acessada só por chave, e a única porta aberta é a 22:

No seu computador (o cliente), o caminho é: ssh-keygen -t ed25519, ssh-copy-id ana@IP-DA-VM, testar o login com chave e só então desligar o login por senha no servidor. Cada passo, com as saídas reais e os erros comuns, está em SSH. Faça a aula e volte aqui.

A ordem importa

Desligar PasswordAuthentication antes de testar a chave tranca você para fora. Mantenha uma segunda sessão SSH aberta enquanto mexe no sshd_config, e teste a nova configuração com sudo sshd -t antes de reiniciar o serviço.

Passo 2: o site com nginx

Como em Servidor Web, o site fica numa pasta própria em /srv/http e num arquivo de configuração próprio. Usamos a porta 8080 para não mexer no site padrão.

  1. A página (/srv/http/casa/index.html, criada com sudo mkdir -p /srv/http/casa e sudo nano): 
    <!doctype html>
<meta charset="utf-8">
<title>Servidor da Ana</title>
<h1>Servidor caseiro da Ana</h1>
<p>Rodando num Arch Linux.</p>
  2. O site, com log de acesso separado: 
    server {
    listen 8080;
    server_name _;
    root /srv/http/casa;
    index index.html;
    access_log /var/log/nginx/casa.access.log;

Passo 3: backup diário com um timer do usuário

O backup é da ana e dos arquivos dela, então não precisa de root: usamos o systemd do usuário (systemctl --user), que guarda as units em ~/.config/systemd/user/. A teoria de timers está em Timers e Tarefas.

3a. O script

#!/usr/bin/env bash
# Copia ~/Documentos para um .tar.zst com data e hora; guarda os 7 mais novos.
set -euo pipefail
destino=~/backups
arquivo="$destino/documentos-$(date +%Y-%m-%d_%H%M%S).tar.zst"
tar --zstd -cf "$arquivo" -C ~ Documentos
echo "backup criado: $arquivo ($(du -h "$arquivo" | cut -f1))"
ls -1t "$destino"/documentos-*.tar.zst | tail -n +8 | xargs -r rm --

3b. O serviço e o timer

[Unit]
Description=Backup da pasta Documentos

[Service]
Type=oneshot
ExecStart=%h/a9/bin/backup-docs.sh

[Unit]
Description=Backup diário da pasta Documentos

[Timer]
OnCalendar=daily
Persistent=true
RandomizedDelaySec=10min

[Install]
WantedBy=timers.target
Type=oneshot
Roda, termina e pronto (não é um serviço que fica ligado).
%h
A pasta pessoal do usuário (/home/ana). Units não entendem ~.
OnCalendar=daily
Todo dia à meia-noite.
Persistent=true
Se a máquina estava desligada na hora, roda assim que der.
RandomizedDelaySec=10min
Sorteia um atraso de até 10 minutos (evita todos os timers dispararem juntos).
WantedBy=timers.target

Timers do usuário só rodam com o usuário "logado"

O systemd do usuário existe enquanto a ana tem alguma sessão aberta. Num servidor onde ninguém fica logado, o timer da meia-noite não roda. A solução é o lingering: sudo loginctl enable-linger ana faz o systemd da ana subir no boot e ficar ligado (na VM: loginctl show-user ana -p Linger → Linger=no; não foi alterado). Outra opção é um timer do sistema (/etc/systemd/system) com User=ana no serviço.

Backup no mesmo disco não basta

Se o disco morrer, os backups morrem junto. Depois de funcionar, troque o destino por um disco externo ou mande uma cópia para outra máquina com rsync -a ~/backups/ outra-maquina:backups/ (pelo SSH do passo 1).

Para o container sobreviver a um reboot

Um podman run -d não volta sozinho depois de reiniciar. O jeito do Podman é o Quadlet: um arquivo ~/.config/containers/systemd/casa-web.container que o systemd transforma num serviço (systemctl --user start casa-web), junto com o lingering do passo 3. A Arch Wiki (Podman) tem o modelo.

Passo 5: o firewall planejado

Agora há três portas em uso: 22 (SSH), 80 e 8080 (nginx) e 8081 (container). O plano: bloquear toda entrada e liberar só SSH e nginx; o container fica acessível apenas da própria máquina (atrás do nginx, se um dia for publicado). Num arquivo:

#!/usr/bin/nft -f
# Firewall planejado do servidor caseiro (NÃO aplicado no laboratório)
flush ruleset

table inet filtro {
    chain entrada {
        type filter hook input priority filter; policy drop;

        ct state established,related accept   # respostas do que EU pedi
        ct state invalid drop
        iif "lo" accept                       # a própria máquina
        meta l4proto { icmp, ipv6-icmp } accept   # ping e IPv6 funcionando

        tcp dport 22 accept                   # SSH (PRIMEIRO!)
        tcp dport { 80, 8080 } accept         # nginx: site padrão e site da casa
        # 8081 (container) fica fechado para fora: só localhost
    }
    chain encaminhar {
        type filter hook forward priority filter; policy drop;
    }
    chain saida {
        type filter hook output priority filter; policy accept;
    }
}

Cada regra é explicada em Firewall (nftables e ufw). O que importa aqui é o hábito: testar antes de aplicar. O -c (check) do nft confere o arquivo inteiro sem mudar nada:

#> nft -c -f /tmp/a9/servidor.nft
#> echo $?
0                                            « sintaxe certa
#> nft -c -f /tmp/a9/quebrado.nft             « mesmo arquivo, com "aceita" no lugar de "accept"
/tmp/a9/quebrado.nft:14:64-64: Error: syntax error, unexpected newline
expected any of: ., ==, !=, <, >, >=, <=, <<, >>, &, ^, !, @, vmap, map, reset, destroy, <number>, <string>, …
        tcp dport 22 aceita                   # SSH (PRIMEIRO!)
                                                               ^
#> echo $?
1
#> nft list ruleset | wc -l
0                                            « nada foi aplicado

A mensagem aponta arquivo, linha 14 e coluna; a seta ^ marca onde o nft desistiu de entender. Num servidor de verdade, depois do -c, você aplicaria com sudo systemctl enable --now nftables (que lê /etc/nftables.conf) com uma segunda sessão SSH aberta, para conferir que ainda consegue entrar.

Por que o firewall não foi ligado na VM do guia

A VM é compartilhada e acessada por SSH; uma regra errada derrubaria todos os autores. Na sua VM, ligue: é parte do projeto. Se se trancar fora, entre pela janela do VirtualBox (o console local não passa pelo firewall) e rode sudo nft flush ruleset.

Quando não funciona

"curl: (7) Failed to connect to localhost port 8080"

Causa: nginx parado, ou o include fora do bloco http { }. Confira: systemctl status nginx, sudo nginx -T | grep -n 8080 (o -T maiúsculo imprime a configuração completa, com os includes). Resolva: corrija e sudo systemctl reload nginx.

O timer existe, mas o backup nunca roda à noite

Causa: sem lingering, o systemd da ana não está rodando quando ninguém está logado. Confira: loginctl show-user ana -p Linger. Resolva: sudo loginctl enable-linger ana.

"Failed to connect to bus" no systemctl --user

Causa: você está como root ou num su/sudo -u ana, sem a sessão de usuário. Resolva: entre como ana de verdade (SSH ou login) e rode sem sudo.

"the container name "casa-web" is already in use"

Causa: um container parado com o mesmo nome. Resolva: podman ps -a, podman rm casa-web (ou use --replace no run).

Liguei o firewall e o site sumiu para os outros computadores

Causa: porta não liberada na chain de entrada. Confira: sudo nft list ruleset. Resolva: acrescente a porta, teste com nft -c -f e recarregue com sudo systemctl reload nftables.

Resumo

  • Anote o estado inicial; desfaça no fim (ou restaure o snapshot).
  • nginx: site em /srv/http, arquivo em sites-enabled/, nginx -t, enable --now.
  • Backup: script com set -euo pipefail + .service oneshot + .timer em ~/.config/systemd/user; lingering para servidores.
  • Container rootless numa porta alta, com volume :ro; podman logs quando ele some.
  • Firewall: política drop na entrada, SSH primeiro, nft -c -f antes de aplicar.
