Arch Funções

Uma função é um bloco de comandos com nome. Você escreve uma vez e chama quantas vezes quiser, como se fosse um comando novo. Funções deixam scripts grandes organizados em partes pequenas, cada uma com um trabalho só, como o script de manutenção do Arch que você vai montar no fim desta aula.

Você vai aprender
  • Como definir e chamar uma função, e passar argumentos para ela.
  • A diferença entre return (código de saída: "está instalado?") e echo (resultado: "qual a versão?").
  • Por que usar local nas variáveis da função.
  • Como reaproveitar funções com source e fazer limpeza automática com trap.
  • Como organizar um script real inteiro em funções, com uma função main.

Antes, leia Condicionais e Laços. Os exemplos rodam na máquina notebook, com a usuária ana; as saídas vêm de um Arch Linux real.

Definir e chamar

Pense numa função como uma receita com nome dentro do livro de receitas (o script). Em vez de copiar os passos toda vez, você escreve "faça o molho" e todo mundo sabe o que é.

nome_da_funcao() {
  comandos
}

nome_da_funcao arg1 arg2
titulo()
O nome da função. Os parênteses vazios dizem "isto é uma função". Nunca se coloca nada dentro deles.
{
Abre o corpo da função.
echo "== $1 =="
O que a função faz. $1 é o primeiro argumento que ela recebeu.
}
Fecha o corpo.
#!/usr/bin/env bash
titulo() {
  echo "== $1 =="
}

titulo "Pacotes do AUR"
pacman -Qqm
titulo "Kernel"
uname -r
$ ./titulo.sh
== Pacotes do AUR ==
downgrade
paru-bin
yay-bin
yay-bin-debug
== Kernel ==
7.2.10-arch1-1
  • Definir a função não executa nada. Ela só roda quando é chamada.
  • A função precisa estar definida antes da linha que a chama, ou seja, mais acima no arquivo.
  • Para chamar, escreva o nome como um comando, sem parênteses: titulo "Kernel".

Também funciona no terminal

Funções não são só para scripts. Crie uma direto no terminal e veja como o Bash a enxerga:

$ versao() { pacman -Q "$1" | cut -d' ' -f2; }
$ versao bash
5.3.20-1
$ type versao
versao é uma função
versao ()
{
    pacman -Q "$1" | cut -d' ' -f2
}

Ela dura até você fechar o terminal. Para ter sempre, coloque no ~/.bashrc (veja .bashrc, alias, PATH).

Missão: crie no terminal a função versao() { pacman -Q "$1" | cut -d' ' -f2; } (atenção ao ; antes do }) e chame versao bash. Depois veja a definição com type versao e experimente versao pacman.

Outra forma de escrever

O Bash também aceita function titulo { … }. Funciona igual, mas a forma titulo() { … } é a mais comum e também roda em outros shells.

O que a função devolve: echo ou return

Esta é a parte que mais confunde. Uma função pode devolver duas coisas diferentes:

echo (saída)return (código)
O que éTexto escrito na telaNúmero de 0 a 255, o código de saída
Para quêDevolver um resultado ("qual a versão do pacman?")Responder sim ou não ("o htop está instalado?")
Como pegarvalor=$(funcao)if funcao; then ou $?

Devolver um resultado com echo

#!/usr/bin/env bash
versao() {
  local linha
  linha=$(pacman -Q "$1")
  echo "${linha#* }"
}

v=$(versao pacman)
echo "O pacman está na versão $v"
linha=$(pacman -Q "$1")
Guarda "pacman 7.1.0.r9.g54d9411-3".
echo "${linha#* }"
Escreve a linha sem o começo até o primeiro espaço: só a versão. Esse echo é o "resultado" da função.
v=$(versao pacman)
Captura o que a função escreveu, em vez de deixar ir para a tela.
$ ./versao.sh
O pacman está na versão 7.1.0.r9.g54d9411-3

Responder "sim ou não" com o código

Uma função que só testa algo pode usar o código do último comando. Aqui, o código do pacman -Qi vira o código da função:

#!/usr/bin/env bash
instalado() {
  pacman -Qi "$1" > /dev/null 2>&1
}

if instalado htop; then
  echo "htop está instalado"
fi

instalado firefox
echo "Código devolvido para firefox: $?"
$ ./instalado.sh
htop está instalado
Código devolvido para firefox: 1

Repare como if instalado htop se lê quase como português. Com return, você escolhe o código explicitamente: return 0 (sucesso) ou return 1 (falha). Sem return, a função devolve o código do último comando que rodou.

return não devolve texto nem números grandes

return 300 não devolve 300: o código só vai de 0 a 255, e 300 vira 44 (300 − 256). Para devolver um valor, use echo.

$ f() { return 300; }
$ f; echo $?
44

Missão: o laço já chama instalado "$p", mas a função ainda não existe. Escreva, antes do laço, a função instalado() que devolve o código do pacman -Qi "$1" (sem mostrar nada na tela) e clique em Rodar. A saída deve ter htop: sim e firefox: não.

#!/usr/bin/env bash
# escreva a função instalado() aqui


for p in htop firefox vim; do
  if instalado "$p"; then
    echo "$p: sim"
  else
    echo "$p: não"
  fi
done

Variáveis locais: local

Por padrão, uma variável criada dentro da função vale no script inteiro. Isso pode estragar uma variável de mesmo nome usada em outro lugar. Com local, ela só existe dentro da função.

#!/usr/bin/env bash
pacote="global"

sem_local() { pacote="mudei"; }
com_local() { local pacote="só aqui dentro"; echo "dentro: $pacote"; }

com_local
echo "depois de com_local: $pacote"
sem_local
echo "depois de sem_local: $pacote"
$ ./local.sh
dentro: só aqui dentro
depois de com_local: global                « o local não vazou
depois de sem_local: mudei                 « sem local, a variável de fora foi alterada
Regra prática

Toda variável criada dentro de uma função leva local, a não ser que você queira mesmo mudar uma variável do script. Em laços dentro de funções, inclusive a do for: local p; for p in ….

Reaproveitar funções: source

Funções que você usa em vários scripts podem morar num arquivo separado, uma "biblioteca". O source (ou o atalho .) carrega esse arquivo dentro do script atual. Aqui, mensagens no estilo do makepkg, com ==> na frente:

# lib.sh — funções reaproveitáveis (não precisa de shebang nem chmod +x)
info() { echo "==> $*"; }
erro() { echo "==> ERRO: $*" >&2; }
#!/usr/bin/env bash
source "$(dirname "$0")/lib.sh"

info "Contando os pacotes do AUR"
info "Você tem $(pacman -Qqm | wc -l) pacotes do AUR"
erro "Exemplo de mensagem de erro"
source
Lê o arquivo e executa no script atual, como se o conteúdo estivesse colado ali.
"$(dirname "$0")
A pasta onde o script está. Assim ele acha a lib.sh de qualquer lugar de onde for chamado.
/lib.sh"
O arquivo da biblioteca.
$ ./usa-lib.sh
==> Contando os pacotes do AUR
==> Você tem 4 pacotes do AUR
==> ERRO: Exemplo de mensagem de erro

É exatamente assim que o makepkg lê um PKGBUILD: o PKGBUILD é um arquivo Bash cheio de variáveis e funções (build(), package()), e o makepkg o carrega com source e chama as funções na ordem certa.

Limpeza automática: trap

Scripts às vezes criam arquivos temporários. O trap ("armadilha") registra uma função para rodar quando o script termina, mesmo que termine por erro ou por Ctrl+C.

#!/usr/bin/env bash
tmp=$(mktemp)

limpar() {
  rm -f "$tmp"
  echo "Arquivo temporário apagado."
}
trap limpar EXIT

pacman -Qqe > "$tmp"
echo "Guardei $(wc -l < "$tmp") nomes em $tmp"
exit 0
mktemp
Cria um arquivo vazio com nome aleatório em /tmp e mostra o caminho.
trap
Registra o que fazer quando algo acontecer.
limpar
A função que será chamada.
EXIT
Quando: na saída do script, por qualquer motivo.
$ ./temporario.sh
Guardei 45 nomes em /tmp/tmp.HZVPyWAMIR
Arquivo temporário apagado.

O nome muda a cada execução. No Arch, /tmp fica na memória (é um tmpfs) e é esvaziado a cada boot, mas não conte com isso: limpe você mesmo. O próprio checkupdates usa um trap … EXIT para apagar a trava do banco temporário dele.

Exemplo completo: o relatório de manutenção

Este script junta as aulas de shell script num relatório da saúde do Arch. Ele só mostra, não muda nada. Cada função tem um trabalho; a main coordena tudo.

#!/usr/bin/env bash
# manutencao — um relatório rápido da saúde do Arch
# Uso: manutencao        (não muda nada; só mostra)

set -uo pipefail

titulo() {
  echo
  echo "== $1 =="
}

atualizacoes() {
  local lista codigo
  lista=$(checkupdates)
  codigo=$?
  case $codigo in
    0) echo "$(wc -l <<< "$lista") atualização(ões) pendente(s). Rode: sudo pacman -Syu" ;;
    2) echo "Nada para atualizar." ;;
    *) echo "Não consegui consultar os espelhos (código $codigo)." ;;
  esac
}

orfaos() {
  local lista
  lista=$(pacman -Qdtq)
  if [ -z "$lista" ]; then
    echo "Nenhum pacote órfão."
  else
    echo "Órfãos: $(echo $lista)"
    echo "Para remover: sudo pacman -Rns \$(pacman -Qdtq)"
  fi
}

cache() {
  local tamanho
  tamanho=$(du -sh /var/cache/pacman/pkg 2>/dev/null | cut -f1)
  echo "O cache do pacman ocupa $tamanho."
  paccache -dk2
}

servicos_falhos() {
  local qtd
  qtd=$(systemctl --failed --no-legend | wc -l)
  if (( qtd == 0 )); then
    echo "Nenhum serviço falhou."
  else
    systemctl --failed --no-legend
  fi
}

aur() {
  local p
  for p in $(pacman -Qqm); do
    [[ $p == *-debug ]] && continue
    echo "  $(pacman -Q "$p")"
  done
}

main() {
  echo "Relatório de $(uname -n), kernel $(uname -r)"
  titulo "Atualizações";    atualizacoes
  titulo "Órfãos";          orfaos
  titulo "Cache";           cache
  titulo "Serviços";        servicos_falhos
  titulo "Pacotes do AUR";  aur
}

main "$@"

O paccache não achou nada para apagar porque o cache da Ana tem uma versão só de cada pacote (ela instalou tudo há pouco). Com -k0 ("não guarde nenhuma"), o ensaio mostra quanto o cache inteiro ocupa:

Para apagar de verdade, troque o -d por -r (remove) e use sudo: sudo paccache -rk2. O pacman-contrib também traz o paccache.timer, que faz isso toda semana (veja Timers). O checkupdates e o paccache não funcionam no terminal simulado.

Por que uma função main?

Com tudo em funções e uma só chamada no fim, você lê o script de cima para baixo como um índice (a main), e nenhuma função é chamada antes de estar definida, porque a última linha só roda depois que o Bash leu o arquivo inteiro.

Uma função útil para o seu .bashrc

pacinfo() { pacman -Qi "$1" | grep -E '^(Nome|Versão|Tamanho instalado|Data de instalação)'; } mostra só as quatro linhas que você costuma procurar na ficha de um pacote. Um alias não conseguiria, porque precisa pôr o argumento no meio do comando.

Quando não funciona

"comando não encontrado" ao chamar a função 
$ cat saudar-antes.sh
#!/usr/bin/env bash
titulo "Kernel"
titulo() {
  echo "== $1 =="
}
$ ./saudar-antes.sh
./saudar-antes.sh: linha 2: titulo: comando não encontrado

O que aconteceu: a chamada está acima da definição no arquivo. O Bash lê de cima para baixo e ainda não conhecia a função.

Como resolver: mova as definições para o topo e as chamadas para o fim. Ou use o padrão main no fim do arquivo.

O terminal mostra > depois de definir a função 
$ f() { echo oi }
>

O que aconteceu: numa linha só, o último comando antes do } precisa de ;. Sem ele, o Bash acha que o } é um argumento do echo e continua esperando o fechamento.

Como resolver: Ctrl+C e escreva f() { echo oi; }, com ; e espaço depois do {.

"erro de sintaxe próximo ao token inesperado `('" ao criar a função ls ou grep 
$ ls() { ls -l "$@"; }
bash: erro de sintaxe próximo ao token inesperado `('
$ alias
alias grep='grep --color=auto'
alias ls='ls --color=auto'

O que aconteceu: o ~/.bashrc do Arch já define os aliases ls e grep. O alias é trocado antes de tudo, então o Bash leu ls --color=auto() {, que não é uma definição válida.

Como resolver: dê outro nome à função (lsl), ou desfaça o alias antes (unalias ls).

"excedido o nível máximo de aninhamento": a função chama a si mesma 
$ FUNCNEST=20
$ pacman() { pacman -Q "$@"; }
$ pacman bash
bash: pacman: excedido o nível máximo de aninhamento de avaliação (20)

O que aconteceu: dentro da função pacman, o nome pacman chama… a própria função, de novo e de novo. Aqui limitamos a 20 níveis com FUNCNEST para ver a mensagem; sem esse limite, o Bash segue se chamando até esgotar a memória e cair.

Como resolver: dentro da função, use command pacman, que pula as funções e chama o programa de verdade. Ou, melhor, não dê a uma função o nome de um comando existente.

$ pacman() { command pacman -Q "$@"; }
$ pacman bash
bash 5.3.20-1
"local: somente pode ser usado em uma função" 
$ local x=1
bash: local: somente pode ser usado em uma função

O que aconteceu: local só existe dentro de funções.

Como resolver: fora de funções, crie a variável normalmente: x=1.

"return: possível retornar … apenas de uma função" 
$ return 1
bash: return: possível retornar (`return') apenas de uma função ou script carregado (com `source')

O que aconteceu: return sai de uma função. Para encerrar o script inteiro, o comando é outro.

Como resolver: no corpo principal do script, use exit 1.

Resumo

  • Defina com nome() { …; } antes de chamar; chame como um comando, sem parênteses.
  • $1, $@ e $# dentro da função são os argumentos dela.
  • echo devolve resultados (pegue com $(…)); return devolve só o código de 0 a 255, ótimo para if instalado htop.
  • Use local em toda variável da função; source reaproveita bibliotecas; trap … EXIT garante a limpeza.
  • Organize scripts grandes em funções pequenas e uma main "$@" no fim. Cuidado com nomes que já são aliases ou comandos.
