Arch Terminal Simulado

As aulas deste guia têm um terminal e um editor de script que rodam dentro da própria página. Eles imitam um Arch Linux de verdade: o Bash 5.3, os comandos do dia a dia e também o pacman, o sudo e o systemctl, numa máquina fictícia igual à VM onde o guia foi conferido. Nada do que você digita sai do navegador: pode "instalar", remover e errar à vontade, e um clique em Reiniciar traz tudo de volta.

Você vai aprender
  • Como usar as caixas "Experimente": digitar, teclas, missões e botões.
  • Como usar o editor de script: Rodar, Restaurar e argumentos.
  • O que existe na máquina fictícia: usuária, disco, pacotes, serviços e arquivos.
  • O que funciona (pacman, sudo, systemctl…) e o que não funciona.

Por que um terminal simulado?

Aprender Arch envolve comandos que, num computador de verdade, dão medo: remover pacotes, parar serviços, virar root. Aqui esse medo não existe: o simulador é um programa da página, não o seu sistema. Você pode rodar sudo pacman -Rs no que quiser, parar o sshd, apagar a pasta da Ana. Ao clicar em Reiniciar, a máquina volta ao estado inicial.

Ele não é um Linux de verdade: é um interpretador de Bash escrito em JavaScript, com os dados reais da VM do guia (os pacotes instalados, os serviços, as mensagens em português). Por isso as respostas devem ser as mesmas que você veria num Arch. Quando quiser ir além do que ele sabe (instalar de verdade, editar arquivos com o nano, usar a rede), use uma máquina virtual com Arch (veja O Arch É para Você?).

O terminal: caixas "Experimente você mesmo"

  1. Clique dentro da janela escura do terminal.
  2. Digite um comando, por exemplo pacman -Q bash, e aperte Enter.
  3. Leia a resposta. Um prompt novo ([ana@notebook ~]$) aparece quando o comando termina.
  4. Se a caixa tiver uma missão, um aviso de missão cumprida aparece embaixo da janela quando você chegar ao objetivo.

Cada caixa é uma máquina independente: o que você instala ou apaga numa não aparece nas outras, nem em outra página.

Missão: explore à vontade. Comece por ls, depois pacman -Q bash. Experimente também uname -r, cat /etc/os-release e help.

Perguntas do sudo e do pacman

Como num Arch real, o sudo pede a senha da Ana e o pacman pede confirmação antes de mudar algo:

PerguntaO que responder no simulador
[sudo] senha para ana:ana e Enter. Nada aparece enquanto você digita (nem asteriscos): é assim no Arch real. Depois de acertar, o sudo não pergunta de novo por 5 minutos.
:: Continuar a instalação? [S/n] ou :: Deseja remover estes pacotes? [S/n]Enter ou S confirma; n cancela. A letra maiúscula é a resposta padrão.

A aula sudo, root e Usuários explica o sudo com calma, e pacman: o Básico, as perguntas do pacman.

O editor de script: "Experimente: edite e rode o script"

Algumas aulas trazem um script para você mudar e rodar, como um "Try it Yourself":

  1. O código aparece num editor de verdade: clique e altere o que quiser.
  2. Se o script usa argumentos ($1, $2…), eles ficam num campo próprio; você pode mudá-los.
  3. Clique em Rodar. O simulador grava o código num arquivo na pasta da Ana e executa bash arquivo.sh argumentos.
  4. Aparecem a saída e o código de saída (0 = deu certo).
Botão / campoFaz
RodarGrava e executa o script, mostrando a saída e o código de saída.
RestaurarVolta o código ao original da aula (desfaz as suas mudanças).
Ver soluçãoMostra uma versão do script que cumpre a missão.
ArgumentosO que vai depois do nome do script. Ex.: bash htop vira $1=bash e $2=htop.
EntradaQuando o script usa read, o simulador abre um campo para você digitar a resposta.

Quando você tenta algo que o simulador não sabe fazer, ele responde com uma linha que começa com (simulador): é uma limitação dele, não um erro do Arch. Já um comando que realmente não existe responde como o Bash real: bash: xyz: comando não encontrado.

Diferenças que você pode notar

  • Relógio parado: date sempre mostra 16/10/2026, 14:30, para os exemplos ficarem iguais aos do guia; o sleep termina na hora.
  • Números fictícios: os PIDs dos processos e alguns números do df, free e ps não são os da VM.
  • Repositório parcial: pacman -Ss procura só nos pacotes que as aulas usam (e nas dependências deles), não nos 15 mil do repositório real.
  • Pacotes sem arquivos: depois de um sudo pacman -S simulado, o pacote aparece no pacman -Q, mas o programa não fica disponível para rodar.

Trilha de missões

Cada caixa abaixo é uma máquina nova. Se travar, abra a solução.

Missão 1: ir até Downloads

Missão: descubra onde você está com pwd, veja o que existe com ls e entre na pasta Downloads com cd. Repare que o prompt muda para [ana@notebook Downloads]$.

Missão 2: ler as notas

Missão: mostre o conteúdo do arquivo notas.txt, que está dentro de Documentos. Use Tab para completar os nomes.

Missão 3: qual é o kernel?

Missão: pergunte ao pacman a versão do pacote linux (o kernel). Depois compare com uname -r.

Missão 4: remover um pacote com sudo

Missão: a Ana não usa mais o tree. Remova-o com sudo pacman -Rs tree: digite a senha ana quando o sudo pedir e confirme a remoção. Depois confira com pacman -Q tree (a resposta deve ser um erro).

Missão 5: ligar um serviço

Missão: o servidor web nginx está desligado. Confira com systemctl is-active nginx e ligue-o com sudo systemctl start nginx. Veja o resultado com systemctl status nginx. (A aula systemctl e Serviços explica cada parte.)

Missão 6: um script que consulta o pacman

O script percorre uma lista de pacotes e pergunta a versão de cada um ao pacman:

LinhaO que faz
for p in bash linux; doRepete o bloco para cada nome da lista, guardando o nome na variável p.
pacman -Q "$p"Mostra o nome e a versão do pacote da vez.
doneFim do bloco.

Missão: acrescente o pacman à lista, para o script mostrar também a versão do próprio gerenciador de pacotes, e clique em Rodar.

#!/usr/bin/env bash
for p in bash linux; do
  pacman -Q "$p"
done

Quando não funciona

Digito e nada aparece

O que aconteceu: o terminal não está selecionado; ou ele está pedindo uma senha (o sudo não mostra o que você digita).

Como resolver: clique dentro da janela escura. Se a última linha for [sudo] senha para ana:, digite ana e aperte Enter, mesmo sem ver nada.

"Sinto muito, tente novamente."

O que aconteceu: a senha do sudo estava errada. No simulador, a senha é ana; num Arch de verdade, é a senha da sua conta.

Como resolver: digite de novo. Depois de três erros, o sudo desiste (sudo: 3 tentativas de senha incorreta); é só rodar o comando de novo.

Instalei um programa e ele "não existe"

O que aconteceu: no simulador, a instalação muda a lista de pacotes, mas não traz o programa de verdade.

Como resolver: é uma limitação do simulador. Para usar o programa, instale num Arch de verdade (uma VM serve).

Apaguei tudo e agora os exemplos não funcionam

O que aconteceu: os exemplos esperam a máquina no estado inicial.

Como resolver: clique em Reiniciar naquela caixa.

Resumo

  • O simulador roda na página: nada afeta o seu computador; Reiniciar volta ao começo.
  • No terminal: ↑ ↓, Tab, Ctrl+L, Ctrl+C, Ctrl+R.
  • sudo pede a senha ana (sem mostrar nada); o pacman pergunta [S/n] antes de mudar algo.
  • A máquina é a VM do guia: [ana@notebook ~]$, grupo wheel, kernel 7.2.10, 408 pacotes, sem desktop.
  • Funciona: Bash, arquivos, pacman, sudo, systemctl, journalctl. Não funciona: rede, AUR, editores, discos, reboot.

Na Arch Wiki: para montar o seu próprio laboratório, veja VirtualBox/Install Arch Linux as a guest e QEMU; o Bash está em Bash e os comandos básicos, em Core utilities (em português).
