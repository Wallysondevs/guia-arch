pacman: o Básico

No Arch, quase tudo o que você instala passa pelo pacman (de package manager, "gerenciador de pacotes", e um trocadilho com o Pac-Man do videogame). É um programa só, rápido e direto, que procura programas nos servidores do Arch, instala junto tudo de que eles precisam, remove e mostra informações sobre o que já está no seu sistema.

Você vai aprender
  • O que são pacote, repositório e dependência, e os repositórios core, extra e multilib.
  • Como o pacman é organizado: operações em letra maiúscula (-S, -R, -Q) e opções em minúscula.
  • Procurar (-Ss), ver detalhes (-Si), instalar (-S) e remover (-R, -Rs, -Rns).
  • Consultar o que está instalado (-Q, -Qi, -Ql).
  • Ler a saída real do pacman linha por linha e resolver os erros mais comuns.

Pacote, repositório e dependência

Pense numa loja de aplicativos de celular, só que pelo terminal. Três ideias explicam tudo:

  • Um pacote é um arquivo compactado com o programa pronto, mais uma ficha (nome, versão, do que depende). No Arch, ele termina em .pkg.tar.zst, como htop-3.5.3-1-x86_64.pkg.tar.zst: nome htop, versão 3.5.3, lançamento 1 (a 1ª compilação dessa versão pelo Arch), arquitetura x86_64.
  • Um repositório é uma "prateleira" de pacotes num servidor. Os servidores que copiam essas prateleiras pelo mundo se chamam espelhos (mirrors; veja Espelhos).
  • Uma dependência é outro pacote de que o programa precisa para funcionar. O fastfetch, por exemplo, precisa da biblioteca yyjson. O pacman instala as dependências sozinho.

Os repositórios oficiais

RepositórioO que temAtivado de fábrica?
coreO essencial para o sistema iniciar e funcionar: kernel, glibc, bash, systemd, o próprio pacman.Sim
extraTodo o resto: ambientes gráficos, navegadores, htop, nginx, vlc…Sim
multilibBibliotecas de 32 bits para rodar programas antigos de 32 bits (Steam e Wine são os casos clássicos).Não
core-testing, extra-testing…Versões em teste, antes de chegarem aos repositórios normais. Não são para o dia a dia.Não

Quem diz quais repositórios estão ligados é o arquivo /etc/pacman.conf. Este é o trecho real da VM do guia (os comentários em inglês vêm do próprio Arch):

#[core-testing]
#Include = /etc/pacman.d/mirrorlist

[core]
Include = /etc/pacman.d/mirrorlist

#[extra-testing]
#Include = /etc/pacman.d/mirrorlist

[extra]
Include = /etc/pacman.d/mirrorlist

# If you want to run 32 bit applications on your x86_64 system,
# enable the multilib repositories as required here.

#[multilib-testing]
#Include = /etc/pacman.d/mirrorlist

#[multilib]
#Include = /etc/pacman.d/mirrorlist

Cada repositório é um bloco com o nome entre colchetes. O # no começo da linha desliga (comenta) a linha. Por isso [core] e [extra] estão ligados e [multilib] não. Para ligar o multilib, você apaga o # das duas linhas dele e depois roda sudo pacman -Syu (veja Atualizar o Sistema). A linha Include diz "a lista de servidores está no arquivo /etc/pacman.d/mirrorlist".

E o AUR?

Programas que não estão em nenhum repositório oficial costumam estar no AUR (Arch User Repository), mantido pelos usuários. O pacman não instala do AUR sozinho: isso é assunto de O que é o AUR.

Como o pacman é organizado

O pacman não usa palavras como install ou remove. Ele usa uma letra maiúscula para a operação (o que fazer) e letras minúsculas para as opções (como fazer). As letras vêm do inglês:

OperaçãoVem dePara quê
-Ssync (sincronizar)Tudo o que envolve os repositórios: procurar, instalar, atualizar.
-RremoveRemover pacotes.
-Qquery (consultar)Perguntar sobre os pacotes instalados.
-FfilesDescobrir qual pacote tem um arquivo (pacman Avançado).
-UupgradeInstalar um arquivo .pkg.tar.zst que você já tem (do makepkg, por exemplo).
-DdatabaseMexer no banco de dados (marcar como dependência…).

A mesma letra minúscula muda de sentido conforme a operação. Juntas, viram "palavras" curtas:

-S s
sync + search: procurar nos repositórios.
-S i
sync + info: ficha de um pacote do repositório.
-Q i
query + info: ficha de um pacote instalado.
-Q l
query + list: arquivos de um pacote instalado.
-R s
remove + recursive: remover junto as dependências que ficarem sem uso.
-S yu
sync + refresh (o y, atualizar o catálogo) + sysupgrade (o u, atualizar tudo).

A ajuda do próprio pacman mostra as operações (em português, na VM):

$ pacman -h
uso:  pacman <operação> [...]
operações:
    pacman {-h --help}
    pacman {-V --version}
    pacman {-D --database} <opções> <pacote(s)>
    pacman {-F --files}    [opções] [arquivo(s)]
    pacman {-Q --query}    [opções] [pacote(s)]
    pacman {-R --remove}   [opções] <pacote(s)>
    pacman {-S --sync}     [opções] [pacote(s)]
    pacman {-T --deptest}  [opções] [pacote(s)]
    pacman {-U --upgrade}  [opções] <arquivo(s)>

use "pacman {-h --help}" com uma operação para ver as opções disponíveis

Para ver as opções de uma operação, junte o -h a ela: pacman -Q -h, pacman -S -h. Cada opção tem também um nome longo (-Ss = --sync --search), útil em scripts para ficar legível.

Quem pode usar o pacman

Consultar (-Ss, -Si, -Q…) qualquer usuário pode. Mudar o sistema (instalar, remover, atualizar) só o root. Se a ana tentar instalar sem permissão:

$ pacman -S fastfetch
erro: você não pode realizar esta operação a menos que seja root.
$ echo $?
1

A solução é colocar sudo na frente: ele roda aquele único comando como root, depois de pedir a senha da própria ana (veja sudo, root e Usuários). Por isso, nesta aula, os comandos que mudam o sistema aparecem como sudo pacman ….

Procurar um pacote: -Ss

pacman
O gerenciador.
-Ss
sync search: procura no catálogo dos repositórios.
fastfetch
O que procurar. É uma expressão regular: casa com qualquer parte do nome ou da descrição.
$ pacman -Ss fastfetch
extra/fastfetch 2.70.0-1                                     « repositório/nome versão
    A feature-rich and performance oriented neofetch like system information tool    « descrição
$ echo $?
0

Cada resultado ocupa duas linhas: repositório/nome versão e, recuada, a descrição (em inglês, como vem do Arch). Quando o pacote já está no seu sistema, aparece [instalado] no fim:

$ pacman -Ss htop
extra/bashtop 0.9.25-2
    Linux resource monitor
extra/evisum 0.6.4-1
    GUI top/htop-like process viewer using EFL
extra/htop 3.5.3-1 [instalado]                « você já tem este
    Interactive process viewer

O bashtop apareceu porque a descrição de outros pacotes também cita "htop". Uma palavra comum devolve muita coisa: pacman -Ss fetch lista 22 pacotes (44 linhas), entre eles o perl, que tem "fetch" na descrição. Para achar só o nome exato, use os marcadores de regex ^ (começo) e $ (fim):

$ pacman -Ss '^htop$'
extra/htop 3.5.3-1 [instalado]
    Interactive process viewer

Quando não acha nada, o pacman não escreve nenhuma mensagem: só devolve o código de saída 1.

$ pacman -Ss xyzabc
$ echo $?
1

O que acontece depois do "S"

Na VM do guia não se instala nada de verdade durante as aulas, então o resto vem de execuções reais em separado: o download foi feito com pacman -Sw (só baixa) numa pasta temporária, e a instalação vem do registro da instalação dos pacotes das aulas (210 pacotes, em 16/10/2026). Juntando, a sequência que você vê depois de responder S é esta:

:: Continuar a instalação? [S/n] S
:: Obtendo pacotes...
 yyjson-0.13.0-1-...   165,3 KiB   389 KiB/s 00:00 [######################] 100%
 fastfetch-2.70.0...   664,8 KiB  1064 KiB/s 00:01 [######################] 100%
 Total (2/2)           830,0 KiB  1208 KiB/s 00:01 [######################] 100%
(2/2) verificando chaves no chaveiro               [######################] 100%
(2/2) verificando integridade do pacote            [######################] 100%
  1. Obtendo pacotes: uma barra por pacote, com tamanho baixado, velocidade e tempo restante, e uma linha Total. Vários pacotes descem ao mesmo tempo (a opção ParallelDownloads = 5 do pacman.conf). Pacotes que já estão no cache não são baixados de novo.
  2. verificando chaves no chaveiro: confere se quem assinou cada pacote é um empacotador conhecido do Arch.
  3. verificando integridade: confere a assinatura de cada arquivo. Um arquivo alterado ou corrompido para tudo aqui, antes de mexer no sistema (veja Chaves e Assinaturas).

Depois, a instalação propriamente dita. Trecho real da instalação de 210 pacotes na VM (no registro, que não é um terminal, as barras viram linhas de texto):

Os hooks (ganchos) são tarefas que pacotes pedem para rodar depois da transação: atualizar o cache de ícones, criar usuários de sistema, refazer o initramfs quando o kernel muda. As mensagens deles vêm em inglês. O número entre parênteses é a contagem (11/18 = 11º de 18). Para escrever os seus, veja Hooks do pacman.

Reinstalar serve para consertar arquivos apagados por engano. Se você quer o contrário, pular o que já está instalado, use --needed: sudo pacman -S --needed htop responde atenção: htop-3.5.3-1 está atualizado -- ignorando e nada para fazer, com código 0.

Instale sempre com o sistema atualizado

O pacman instala a versão que está no catálogo baixado. Se o catálogo é de semanas atrás e você nunca atualizou, o pacote novo pode esperar bibliotecas mais novas do que as suas. O hábito seguro é sudo pacman -Syu antes, ou instalar junto: sudo pacman -Syu fastfetch. Nunca use pacman -Sy pacote (atualizar o catálogo e instalar sem atualizar o resto); o porquê está em Atualizar o Sistema.

Remover: -R, -Rs e -Rns

-R
remove: remove só o pacote pedido.
s
recursive: remove também as dependências dele que nenhum outro pacote usa.
n
nosave: não guarda cópia .pacsave dos arquivos de configuração que você alterou.

Veja a diferença com o podman, que trouxe várias dependências só para ele:

$ sudo pacman -R podman
verificando dependências...

Pacotes (1) podman-6.1.4-1                       « só o podman

Tamanho total removido:  82,66 MiB

:: Deseja remover estes pacotes? [S/n] n
$ sudo pacman -Rs podman
verificando dependências...

Pacotes (16) aardvark-dns-2.1.0-3  abseil-cpp-20260817.0-2  catatonit-0.2.1-2      « 15 dependências
             conmon-1:2.2.1-1  containers-common-1:0.69.2-1  criu-4.2.1-1      « que só o podman usava
             crun-1.30.1-1  libbsd-0.12.2-2  libmd-1.3.0-1  libnet-2:1.3-2
             netavark-2.1.0-3  passt-2026_10_02.cba3570-1  protobuf-36.1-1
             protobuf-c-1.5.2-15  python-protobuf-36.1-1  podman-6.1.4-1

Tamanho total removido:  133,23 MiB

:: Deseja remover estes pacotes? [S/n] n

Com -R sozinho, as 15 dependências ficariam esquecidas no disco (são os órfãos, assunto de Cache e Órfãos). Com -Rs, saem juntas. Repare que o -Rs é cuidadoso: só leva o que nenhum outro pacote instalado precisa.

Já o htop não tem dependências exclusivas (a ncurses e a libnl servem a outros programas), então -R, -Rs e -Rns mostram o mesmo resumo:

$ sudo pacman -Rns htop
verificando dependências...

Pacotes (1) htop-3.5.3-1

Tamanho total removido:  0,41 MiB

:: Deseja remover estes pacotes? [S/n] n

E o n? Alguns pacotes declaram arquivos de configuração em /etc. Se você editou um deles e remove o pacote com -R ou -Rs, o pacman guarda a sua versão como arquivo.pacsave (por precaução). Com -Rns, não guarda. Detalhes em .pacnew e .pacsave.

ComandoRemoveQuando usar
pacman -R pkgSó o pacoteQuando você quer manter as dependências (outro programa seu vai usá-las).
pacman -Rs pkgPacote + dependências sem usoRemover sem deixar lixo, mas guardando as suas configurações alteradas como .pacsave.
pacman -Rns pkgPacote + dependências sem uso + sem .pacsaveO mais usado para "desinstalar de vez".
Leia a lista antes do "S"

Remover algo de que o sistema precisa é bloqueado pelo pacman: sudo pacman -R glibc responde erro: falha ao preparar a transação (não foi possível satisfazer as dependências) e lista os 289 pacotes que quebrariam (:: a remoção de glibc quebra a dependência "glibc" necessária por bash…). Nunca "force" isso com -Rdd (remover ignorando dependências): é o jeito mais rápido de deixar o sistema sem iniciar.

Os arquivos que você criou na sua pasta pessoal (por exemplo ~/.config/htop/) nunca são apagados pelo pacman: ele só remove o que o pacote instalou.

Consultar o que está instalado: -Q

As consultas -Q olham só o "inventário" local, sem internet. Sozinho, -Q lista tudo; com nomes, mostra a versão instalada:

$ pacman -Q bash pacman linux

Experimente

O terminal abaixo é o simulador do guia, com os pacotes da VM. A senha da ana para o sudo é ana.

Missão 1: veja a ficha do htop instalado e descubra o motivo da instalação e o tamanho que ele ocupa.

Missão 2: procure nos repositórios um programa chamado fastfetch. De qual repositório ele vem? Ele já está instalado?

Missão 3: instale o fastfetch. Tente primeiro sem sudo e leia o erro. Depois, com sudo, leia a lista de pacotes antes de responder S. Confira com pacman -Q fastfetch.

Missão 4: remova o htop do jeito "de vez" (com as dependências sem uso e sem guardar .pacsave). Depois confirme que pacman -Q htop dá erro.

Quando não funciona

"você não pode realizar esta operação a menos que seja root" 
$ pacman -S fastfetch
erro: você não pode realizar esta operação a menos que seja root.

O que aconteceu: instalar, remover e atualizar mudam o sistema inteiro.

Como resolver: repita com sudo na frente. Atalho do Bash: sudo !! repete o último comando com sudo.

"alvo não encontrado" 
$ sudo pacman -S xyz
erro: alvo não encontrado: xyz

O que aconteceu: não existe pacote com esse nome nos repositórios ligados. Causas comuns: erro de digitação, o nome do pacote é diferente do nome do comando, o pacote está no AUR, ou está no multilib desligado.

Como confirmar e resolver: procure por parte do nome (pacman -Ss xy), pelo comando (pacman -F xyz, em pacman Avançado) ou no site archlinux.org/packages. Se não estiver em lugar nenhum, veja o AUR.

"o pacote … não foi encontrado" (em -Q, -Qi, -Si) 
$ pacman -Q fastfetch
erro: o pacote "fastfetch" não foi encontrado

O que aconteceu: com -Q, o pacote não está instalado (pode existir no repositório). Com -Si, não existe no catálogo.

Como resolver: para saber se existe para instalar, use pacman -Ss.

"não foi possível travar a base de dados" 
$ sudo pacman -Syu
:: Sincronizando a base de dados de pacotes...
erro: falha ao sincronizar todas as bases de dados (não foi possível travar a base de dados)

Com -S, a mensagem completa traz a dica (saída real, reproduzida num banco de testes da VM; no seu sistema o caminho é /var/lib/pacman/db.lck):

erro: falha ao iniciar a transação (não foi possível travar a base de dados)
erro: não foi possível travar a base de dados: Arquivo existe
  se tiver certeza de que um gerenciador de pacotes não esteja
  em execução, você pode remover /tmp/a4/dby/db.lck

O que aconteceu: enquanto trabalha, o pacman cria a "trava" /var/lib/pacman/db.lck, para dois pacman não mexerem ao mesmo tempo. Ou outro pacman está rodando agora (outro terminal, uma atualização gráfica), ou um pacman anterior foi interrompido à força e a trava ficou para trás. Na VM do guia, foi exatamente isso: um desligamento forçado deixou o arquivo.

Como confirmar: veja se há um pacman rodando. Se pgrep -a pacman não mostrar nada, a trava é sobra:

$ pgrep -a pacman                                 « nada: nenhum pacman rodando
$ ls -l /var/lib/pacman/db.lck
---------- 1 root root 0 16 out 12:40 /var/lib/pacman/db.lck

Como resolver: só se nenhum pacman estiver rodando, apague a trava e repita: sudo rm /var/lib/pacman/db.lck. Se houver um pacman rodando, espere ele terminar; apagar a trava nessa hora deixa dois programas escrevendo no mesmo banco de dados.

"não foi possível satisfazer as dependências" ao remover 
$ sudo pacman -R jq
verificando dependências...
erro: falha ao preparar a transação (não foi possível satisfazer as dependências)
:: a remoção de jq quebra a dependência "jq" necessária por devtools

O que aconteceu: outro pacote instalado (devtools) precisa do jq.

Como resolver: decida se quer remover os dois (sudo pacman -Rs devtools leva o jq junto, se mais ninguém o usar) ou deixe o jq onde está. pacman -Qi jq mostra quem depende dele no campo Necessário para.

Mensagens como falha ao obter o arquivo, The requested URL returned error: 404 ou a assinatura de "…" é inválida têm aulas próprias: Espelhos, Chaves e Assinaturas e Erros de Atualização.

Resumo

  • Pacotes vêm dos repositórios core e extra (o multilib vem desligado no /etc/pacman.conf).
  • Maiúscula = operação: -S sync, -R remove, -Q query. Minúscula = opção (s search, i info, l list).
  • Consultar não precisa de root; instalar e remover precisam (sudo).
  • Leia a lista antes de responder ao [S/n]; Enter aceita a letra maiúscula.
  • -Rns é o "desinstalar de vez"; o pacman nunca apaga os arquivos da sua pasta pessoal.
  • Trava db.lck: primeiro confira se há outro pacman rodando.
