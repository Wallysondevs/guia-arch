Arch Configurar o Sistema

O pacstrap copiou o Arch para o disco, mas o sistema novo ainda não sabe nada sobre si mesmo: não sabe quais partições montar, em que fuso está, que idioma fala, como se chama nem quem pode entrar. Nesta aula você responde a cada uma dessas perguntas, uma por vez, quase sempre escrevendo uma linha num arquivo de texto. É a parte da instalação em que você mais aprende como o Arch funciona por dentro.

Você vai aprender
  • Gerar o /etc/fstab com genfstab e ler cada coluna dele.
  • Entrar no sistema novo com arch-chroot (e por que o prompt muda).
  • Configurar fuso horário, idioma, teclado e nome da máquina.
  • Refazer o initramfs com mkinitcpio -P e entender por que o aviso do pacstrap sumiu.
  • Definir a senha do root, criar a usuária ana, liberar o sudo e ativar a rede para o primeiro boot.

Onde você está e o que falta

Pense numa casa recém-construída: as paredes estão de pé (os pacotes estão no disco), mas ainda não tem endereço na porta, relógio na parede, nem chave para os moradores. Na aula anterior (Espelhos e pacstrap) você terminou com a raiz montada em /mnt e a partição EFI em /mnt/boot. Agora cada pergunta vira um arquivo:

Todas as saídas desta aula são da instalação real da VM do guia (o coordenador gravou cada comando com a saída; veja o projeto de instalação). O ambiente live fala inglês, então as mensagens aparecem em inglês até o primeiro boot.

1. O fstab: a lista de partições

O fstab (file systems table, tabela de sistemas de arquivos) é o arquivo /etc/fstab. A cada boot, o systemd lê essa lista e monta cada partição no lugar certo. Sem ele, o sistema até liga (o bootloader diz qual é a raiz), mas o /boot e a swap ficam de fora.

Você não precisa escrevê-lo à mão: o genfstab olha o que está montado agora embaixo de /mnt e escreve as linhas certas. Por isso a ordem importa: primeiro montar tudo (aula Formatar e Montar), depois gerar.

genfstab
Gera linhas de fstab a partir do que está montado. Vem no pacote arch-install-scripts, que já está no live.
-U
Identifica cada partição pelo UUID (um número único gravado na formatação), não pelo nome /dev/sda1.
/mnt
A pasta a examinar: tudo o que está montado nela e abaixo dela.
>>
Acrescenta a saída ao final do arquivo (sem apagar o que já existe).
/mnt/etc/fstab
O fstab do sistema novo (visto do live, ele mora em /mnt).
#> genfstab -U /mnt >> /mnt/etc/fstab
#> echo $?
0                              « nada na tela, código 0: deu certo
#> cat /mnt/etc/fstab
# Static information about the filesystems.
# See fstab(5) for details.

# <file system> <dir> <type> <options> <dump> <pass>
# /dev/sda3
UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9	/         	ext4      	rw,relatime	0 1

# /dev/sda1
UUID=C509-6CB1      	/boot     	vfat      	rw,relatime,fmask=0022,dmask=0022,codepage=437,iocharset=ascii,shortname=mixed,utf8,errors=remount-ro	0 2

# /dev/sda2
UUID=02576132-0458-4975-916f-94e08af9a31c	none      	swap      	defaults  	0 0

As quatro primeiras linhas já existiam: o pacote filesystem instala um fstab só com comentários. O genfstab acrescentou três blocos, um por partição. Cada bloco tem um comentário (# /dev/sda3, só para você saber de quem se trata) e uma linha de verdade com seis colunas:

ColunaNa linha da raizO que significa
1. o quêUUID=75d167c8-…Qual partição. Aqui, pelo UUID que o mkfs.ext4 criou (veja o lsblk -f em Formatar e Montar).
2. onde/O ponto de montagem. A swap não é montada numa pasta, por isso tem none.
3. tipoext4O sistema de arquivos: ext4, vfat (a partição EFI, FAT32), swap.
4. opçõesrw,relatimerw = leitura e escrita; relatime = atualiza a data de acesso dos arquivos só de vez em quando (economiza escrita). Na EFI aparecem opções do FAT: fmask/dmask (permissões), codepage, utf8, errors=remount-ro (se der erro, vira somente leitura). defaults = as opções padrão.
5. dump0Para o antigo programa de backup dump. Ninguém usa mais: sempre 0.
6. pass1Ordem do fsck (verificação de disco) no boot: 1 = a raiz, primeiro; 2 = as outras, depois; 0 = não verificar (a swap).

Por que UUID e não /dev/sda3?

O nome /dev/sda é dado na ordem em que o kernel encontra os discos. Ligue um pendrive ou um segundo SSD e o seu disco pode virar /dev/sdb no próximo boot: um fstab com /dev/sda3 montaria a partição errada (ou nenhuma). O UUID fica gravado dentro da partição e não muda enquanto você não formatá-la de novo. Repare que o UUID da EFI é curto (C509-6CB1): é o "número de série" do FAT32, que tem só 8 dígitos.

FormaExemploQuando usar
genfstab -U (UUID)UUID=75d167c8-…Sempre, é o que a Arch Wiki recomenda.
genfstab -L (rótulo)LABEL=raizSe você deu nomes às partições (mkfs.ext4 -L raiz) e quer um fstab legível.
genfstab sem opção/dev/sda3Evite: quebra se a ordem dos discos mudar.

>> × >, e o perigo de rodar duas vezes

O >> acrescenta. Isso é bom na primeira vez (preserva o cabeçalho), mas se você rodar o comando de novo, as linhas entram outra vez e cada partição aparece duas vezes. Veja numa cópia do fstab, na VM do guia (nunca faça isso no fstab de verdade):

#> cp /etc/fstab /tmp/a3/fstab
#> genfstab -U / >> /tmp/a3/fstab           « a "segunda vez"
#> grep -c "^UUID" /etc/fstab /tmp/a3/fstab
/etc/fstab:3
/tmp/a3/fstab:6                            « cada partição duas vezes
#> findmnt --verify --tab-file /tmp/a3/fstab

0 erro de análise, 0 erro, 3 avisos
/
   [W] alvo especificado mais de uma vez
/boot
   [W] alvo especificado mais de uma vez
none
   [W] alvo especificado mais de uma vez

O findmnt --verify lê um fstab e aponta problemas; --tab-file diz qual arquivo ler (sem ela, lê o /etc/fstab). Cada [W] (warning, aviso) diz que o mesmo ponto de montagem aparece em duas linhas. Num fstab correto, a resposta é esta:

#> findmnt --verify
Sucesso, nenhum erro ou aviso detectado
Rodou duas vezes? Conserte antes de reiniciar

Abra nano /mnt/etc/fstab e apague o bloco repetido, ou gere de novo com um > só: genfstab -U /mnt > /mnt/etc/fstab. O > substitui o arquivo inteiro: você perde as quatro linhas de comentário do cabeçalho, o que não faz mal nenhum. No live, confira com findmnt --verify --tab-file /mnt/etc/fstab.

O fstab tem uma aula própria no Nível 2: mount e fstab (opções, partições extras, nofail, como testar com mount -a).

2. Entrar no sistema novo: arch-chroot

Até aqui você mexeu no sistema novo "de fora", escrevendo /mnt na frente de tudo. Para os próximos passos é mais fácil (e às vezes obrigatório) estar dentro dele: programas como locale-gen, mkinitcpio e passwd precisam enxergar o /etc do sistema novo como se fosse o /etc de verdade.

É isso que faz um chroot (change root, trocar a raiz): a partir dele, para os comandos que você rodar, /mnt passa a ser /. O arch-chroot é um chroot com ajudas: antes de entrar, ele monta /proc, /sys, /dev e /run dentro de /mnt e copia a configuração de DNS, para que os programas funcionem lá dentro.

arch-chroot
Entra no sistema montado num diretório (pacote arch-install-scripts).
/mnt
Onde está a raiz do sistema novo.
#> arch-chroot /mnt

Não aparece nada, só o prompt muda. O ambiente live usa o zsh com o prompt root@archiso ~ #; dentro do chroot quem responde é o Bash do sistema novo, com o prompt padrão do Arch:

#> pwd
/
root
Você continua root.
@archiso
O nome ainda é archiso: o kernel que está rodando é o do pendrive, e o nome da máquina vem dele. O notebook só vale no primeiro boot.
/
A pasta atual é a raiz... do sistema novo (o antigo /mnt).
#
Prompt de root.
Como o coordenador rodou os comandos

Para gravar cada saída num arquivo, na VM do guia cada comando foi rodado de fora, com arch-chroot /mnt comando (por exemplo, arch-chroot /mnt locale-gen): o arch-chroot entra, roda só aquele comando e sai. A saída é a mesma. Nesta aula você vê o jeito normal: entrar uma vez com arch-chroot /mnt e digitar tudo lá dentro, até o exit (em Primeiro Boot).

Fique atento ao prompt

A partir daqui, todos os comandos são dentro do chroot ([root@archiso /]#). Se você ver root@archiso ~ #, você saiu (ou nunca entrou), e um passwd mudaria a senha do live, que some ao desligar. Saiu sem querer? Rode arch-chroot /mnt de novo; nada se perde.

3. Fuso horário e relógio

O Linux guarda a hora em UTC (o horário de Greenwich) e converte para a sua hora local na hora de mostrar. Para converter, precisa saber o seu fuso. O fuso é escolhido apontando o arquivo /etc/localtime para um dos arquivos de fuso que vêm no pacote tzdata, em /usr/share/zoneinfo/Região/Cidade:

#> ls /usr/share/zoneinfo/America | head -5
Adak
Anchorage
Anguilla
Antigua
Araguaina

O Brasil tem quatro fusos. Os nomes são de cidades: America/Sao_Paulo (Brasília, a maior parte do país), America/Manaus, America/Rio_Branco, America/Noronha; há também nomes para cidades que já mudaram de regra, como America/Recife e America/Bahia. Use a sua cidade (ou a mais próxima da lista).

ln
Cria um link (um atalho para outro arquivo).
-s
Link simbólico (o atalho guarda o caminho do alvo).
-f
force: se /etc/localtime já existir, substitui.
/usr/share/zoneinfo/America/Sao_Paulo
O alvo: o arquivo com as regras do fuso de Brasília.
/etc/localtime
O nome do atalho, que todos os programas consultam.
#> ln -sf /usr/share/zoneinfo/America/Sao_Paulo /etc/localtime
#> hwclock --systohc
#> echo $?
0

Os dois comandos não mostram nada quando dão certo. O hwclock mexe no relógio do hardware (o RTC, o relógio da placa-mãe que continua contando com o computador desligado): --systohc (system to hardware clock) copia a hora do sistema para ele e cria o arquivo /etc/adjtime. Depois do primeiro boot, o resultado fica assim (VM do guia):

#> ls -l /etc/localtime
lrwxrwxrwx 1 root root 37 16 out 12:09 /etc/localtime -> /usr/share/zoneinfo/America/Sao_Paulo
#> cat /etc/adjtime
0.000000 1792163398 0.000000
1792163398
UTC                       « o relógio da placa guarda UTC (o padrão do Linux)

O l no começo de lrwxrwxrwx e a seta -> mostram que é um link. A última linha do adjtime é a que importa: UTC.

Vai ter Windows no mesmo computador?

O Windows guarda a hora local no relógio da placa, o Linux guarda UTC. Em dual boot, um dos dois sempre mostra a hora errada (3 horas de diferença, no fuso de Brasília). A solução recomendada é configurar o Windows para usar UTC; veja System time: UTC in Microsoft Windows na Arch Wiki.

4. Idioma (locale)

Um locale é um pacote de regras de idioma e país: em que língua aparecem as mensagens, se o decimal é vírgula ou ponto, como se escreve a data, a ordem alfabética com acentos. O nome junta idioma, país e codificação: pt_BR.UTF-8 = português, do Brasil, em UTF-8 (a codificação que entende acentos e emojis).

Configurar o idioma tem duas etapas: gerar os locales que você quer ter e escolher qual o sistema usa.

Gerar: /etc/locale.gen e locale-gen

O arquivo /etc/locale.gen tem uma lista enorme com todos os locales possíveis, todos comentados (com # na frente). Você tira o # dos que quer. Use nano /etc/locale.gen, procure com Ctrl+W por pt_BR.UTF-8, apague o #, faça o mesmo com en_US.UTF-8 e salve (Ctrl+O, Enter, Ctrl+X). Na VM do guia, o coordenador fez a mesma coisa com um sed, sem abrir editor:

#> sed -i -e 's/^#pt_BR.UTF-8 UTF-8/pt_BR.UTF-8 UTF-8/' -e 's/^#en_US.UTF-8 UTF-8/en_US.UTF-8 UTF-8/' /etc/locale.gen
#> grep -v "^#" /etc/locale.gen
en_US.UTF-8 UTF-8
pt_BR.UTF-8 UTF-8
sed -i
Edita o arquivo no lugar (in place).
-e 's/^#pt_BR.UTF-8 UTF-8/pt_BR.UTF-8 UTF-8/'
Troca a linha que começa (^) com #pt_BR.UTF-8 UTF-8 pela mesma linha sem o #.
-e 's/^#en_US…/en_US…/'
O mesmo para o inglês dos EUA.
/etc/locale.gen
O arquivo editado.

O grep -v "^#" mostra só as linhas que não começam com #: exatamente as duas que você ativou. Por que gerar o en_US.UTF-8 também? Alguns programas e scripts esperam que ele exista, e ter o inglês à mão ajuda a pesquisar mensagens de erro (dá para rodar um comando em inglês com LANG=C comando).

Cuidado com o pt_BR sem UTF-8

Logo abaixo da linha certa existe #pt_BR ISO-8859-1, uma codificação antiga. Ative a linha pt_BR.UTF-8 UTF-8, não essa.

Agora o locale-gen compila os locales ativados:

#> locale-gen
Generating locales...
  en_US.UTF-8... done          « um por linha ativada no locale.gen
  pt_BR.UTF-8... done
Generation complete.

Compare com o pacstrap: lá, o gancho Generating the configured locale... mostrou só Generating locales... e Generation complete., sem nenhum idioma no meio, porque ainda nenhuma linha estava ativa.

Escolher: /etc/locale.conf

Gerar não basta: o sistema precisa saber qual usar. Isso fica na variável LANG, escrita em /etc/locale.conf:

#> echo 'LANG=pt_BR.UTF-8' > /etc/locale.conf
#> cat /etc/locale.conf
LANG=pt_BR.UTF-8

Aqui o > (um só) é o certo: o arquivo não existia, e se existisse você quer substituí-lo. As aspas simples protegem o texto (veja O Terminal no Arch). O efeito aparece no primeiro boot: mensagens, datas e números em português.

5. Teclado do console

No live você rodou loadkeys br-abnt2 (aula O Ambiente Live), mas isso vale só até desligar. Para o sistema instalado, o mapa de teclado do console (a tela preta de texto, antes de qualquer interface gráfica) fica em /etc/vconsole.conf:

#> echo 'KEYMAP=br-abnt2' > /etc/vconsole.conf
#> cat /etc/vconsole.conf
KEYMAP=br-abnt2

Qual mapa escolher? Os brasileiros disponíveis são estes (lista tirada da VM com localectl list-keymaps | grep "^br"):

MapaTeclado
br-abnt2O padrão brasileiro atual, com Ç e a tecla /? ao lado do Shift direito. O da maioria dos notebooks vendidos no Brasil.
br-abntA variante ABNT anterior. Na dúvida, fique com o br-abnt2.
br-latin1-abnt2, br-latin1-usVariações com a tabela latin1.
usTeclado americano (sem Ç). Se o seu teclado é "internacional", veja us-acentos.

Esse arquivo vale só para o console. O teclado da interface gráfica (KDE, GNOME) é configurado nela; veja Instalar um Desktop.

6. Nome da máquina (hostname)

O hostname é o nome do computador na rede e no prompt ([ana@notebook ~]$). É uma palavra só, sem espaços nem acentos (letras, números e hífen):

#> echo notebook > /etc/hostname
#> cat /etc/hostname
notebook

Na VM do guia, os três arquivos (idioma, teclado e nome) foram escritos de fora do chroot numa linha só, com /mnt na frente: echo 'LANG=pt_BR.UTF-8' > /mnt/etc/locale.conf; echo 'KEYMAP=br-abnt2' > /mnt/etc/vconsole.conf; echo notebook > /mnt/etc/hostname. O resultado é idêntico.

E o /etc/hosts?

Guias antigos mandam editar o /etc/hosts. Hoje não é necessário: no Arch, o pacote filesystem já o traz com localhost configurado, e o próprio systemd resolve o nome da máquina.

7. Refazer o initramfs: mkinitcpio -P

Para dar a partida, o kernel carrega primeiro um mini-sistema chamado initramfs (o arquivo /boot/initramfs-linux.img), com os drivers necessários para achar o disco e montar a raiz. Quem gera esse arquivo é o mkinitcpio. O pacstrap já o gerou uma vez (ao instalar o kernel), mas naquele momento o /etc/vconsole.conf ainda não existia. Repare no aviso do log do pacstrap:

#> pacstrap -K /mnt base linux …
…
(15/18) Updating linux initcpios...
…
  -> Running build hook: [sd-vconsole]
==> WARNING: sd-vconsole: "/etc/vconsole.conf" not found, will use default values
…

O gancho sd-vconsole copia o mapa de teclado para dentro do initramfs (é ele que deixa você digitar a senha de um disco criptografado em ABNT2). Agora que o arquivo existe, gere de novo:

mkinitcpio
Cria o initramfs (o nome vem de make initcpio: o initramfs é um arquivo no formato cpio).
-P
allpresets: gera para todos os kernels instalados (cada kernel tem um preset em /etc/mkinitcpio.d/).
#> mkinitcpio -P
==> Building image from preset: /etc/mkinitcpio.d/linux.preset: 'default'    « um preset por kernel
==> Using default configuration file: '/etc/mkinitcpio.conf'
  -> -k /boot/vmlinuz-linux -g /boot/initramfs-linux.img       « kernel lido → imagem gerada
==> Starting build: '7.2.10-arch1-1'
  -> Running build hook: [base]
  -> Running build hook: [systemd]
  -> Running build hook: [autodetect]       « só os módulos do seu hardware
  -> Running build hook: [microcode]        « embute o intel-ucode
  -> Running build hook: [modconf]
  -> Running build hook: [kms]
  -> Running build hook: [keyboard]
  -> Running build hook: [sd-vconsole]      « agora sem o WARNING
  -> Running build hook: [block]
  -> Running build hook: [filesystems]
  -> Running build hook: [fsck]
==> Generating module dependencies
==> Creating zstd-compressed initcpio image: '/boot/initramfs-linux.img'
  -> Early uncompressed CPIO image generation successful
==> Initcpio image generation successful      « deu certo

Cada build hook (gancho) acrescenta uma parte ao initramfs; a lista vem da linha HOOKS= de /etc/mkinitcpio.conf. A última linha é a que você procura: successful. A diferença para o pacstrap é só uma: a linha WARNING sumiu. Os ganchos, o arquivo de configuração e quando é preciso rodar de novo estão em mkinitcpio e initramfs.

8. Senha do root: passwd

O root é o administrador. Sem senha definida, ninguém consegue entrar como root no sistema novo. O passwd (de password) sem nome de usuário muda a senha de quem está rodando, ou seja, do root:

#> passwd
New password:                « digite (nada aparece na tela) e Enter
Retype new password:         « de novo, para conferir
passwd: password updated successfully

Enquanto você digita, nenhum caractere aparece, nem asteriscos: é normal, é para ninguém ver o tamanho da senha. Se as duas não baterem, nada muda e você tenta de novo (código de saída 10):

#> passwd
New password:
Retype new password:
Sorry, passwords do not match.
passwd: Failed preliminary check by password service
passwd: password unchanged

(As mensagens são as do passwd real em inglês, conferidas na VM do guia com uma usuária de teste.)

9. A sua usuária: useradd

Usar o computador como root o tempo todo é perigoso: um comando errado apaga o sistema. O normal é ter uma conta comum para o dia a dia e pedir poderes de administrador só quando precisar, com o sudo. Na VM do guia, a usuária é a ana:

useradd
Cria um usuário.
-m
create home: cria a pasta pessoal /home/ana (sem isso, ela não existe).
-G wheel
Põe a usuária no grupo extra wheel, o grupo dos administradores no Arch (o nome vem de big wheel, "figurão").
-s /bin/bash
O shell dela: o Bash.
ana
O nome de login: minúsculas, sem espaços nem acentos.
#> useradd -m -G wheel -s /bin/bash ana
#> id ana
uid=1000(ana) gid=1000(ana) groups=1000(ana),998(wheel)
#> passwd ana
New password:
Retype new password:
passwd: password updated successfully

O useradd não mostra nada quando dá certo. O id confere: uid=1000 (o primeiro usuário comum sempre recebe 1000), o grupo principal ana (criado junto, com o mesmo nome) e o grupo extra wheel (número 998). Depois, passwd ana define a senha dela: com um nome, o passwd muda a senha de outra pessoa (só o root pode).

O -m cria /home/ana com permissão 700 (só a dona entra) e copia de /etc/skel três arquivos de configuração do Bash: .bashrc, .bash_profile e .bash_logout. Usuários, grupos e permissões são assunto de sudo, root e Usuários e Usuários e Grupos.

10. Liberar o sudo para o grupo wheel: visudo

Estar no grupo wheel ainda não dá poder nenhum. Quem decide quem pode usar o sudo é o arquivo /etc/sudoers, e no Arch a linha do wheel vem comentada. No log da instalação:

#> grep -n "wheel" /etc/sudoers
124:## Uncomment to allow members of group wheel to execute any command
125:# %wheel ALL=(ALL:ALL) ALL                       « esta é a linha
128:# %wheel ALL=(ALL:ALL) NOPASSWD: ALL            « esta não (sudo sem senha)

Nunca edite o /etc/sudoers direto com o nano: um erro de digitação ali pode deixar o sudo inutilizável. Use o visudo, que abre uma cópia, confere a sintaxe ao salvar e só então substitui o original. Ele usa o editor da variável EDITOR; sem ela, tenta o vi, que não vem instalado:

#> visudo
visudo: no editor found (editor path = /usr/bin/vi)
#> EDITOR=nano visudo
EDITOR=nano
Define a variável EDITOR só para este comando.
visudo
Edita o /etc/sudoers com segurança.

No nano, desça até a linha 125 (Ctrl+_ e digite 125), apague o # e o espaço do começo de %wheel ALL=(ALL:ALL) ALL, salve e saia. O trecho fica assim (VM do guia):

## Uncomment to allow members of group wheel to execute any command
%wheel ALL=(ALL:ALL) ALL

## Same thing without a password
# %wheel ALL=(ALL:ALL) NOPASSWD: ALL
%wheel
Para quem vale a regra. O % indica um grupo (sem ele, seria um usuário).
ALL=
Em qualquer máquina (o mesmo sudoers pode servir a vários computadores).
(ALL:ALL)
Pode agir como qualquer usuário : qualquer grupo (normalmente, como root).
ALL
Pode rodar qualquer comando.

Para conferir sem abrir o editor, visudo -c (check) só verifica a sintaxe:

#> grep -n "^%wheel" /etc/sudoers
125:%wheel ALL=(ALL:ALL) ALL                « agora sem o #
#> visudo -c
/etc/sudoers: parsed OK
Por que não a linha NOPASSWD?

Com ela, qualquer programa rodando como ana vira root sem pedir nada. Pedir a senha é a última barreira contra um comando colado sem querer. Use a linha 125.

11. A rede no primeiro boot: systemctl enable

O live tem rede porque ele mesmo liga seus serviços. O sistema novo não: se nada for ativado, o primeiro boot acontece sem internet, e sem internet não dá para instalar o que falta. Por isso o pacstrap instalou o networkmanager, e agora você o ativa. Na VM do guia, ativou-se também o servidor SSH (pacote openssh), para acessar a máquina de outro computador:

systemctl
Controla os serviços do systemd.
enable
Ativar: o serviço passa a iniciar sozinho em todo boot.
NetworkManager
O serviço que conecta cabo e Wi-Fi (atenção às maiúsculas).
sshd
O servidor SSH (opcional; só se você quer entrar por SSH).
#> systemctl enable NetworkManager sshd
#> echo $?
0

No log da instalação, dentro do chroot, o comando não mostrou nada. No sistema já instalado, o mesmo tipo de comando avisa cada link que cria (exemplo real na VM, com o cronie):

#> systemctl enable cronie
Created symlink '/etc/systemd/system/multi-user.target.wants/cronie.service' → '/usr/lib/systemd/system/cronie.service'.

"Ativar", portanto, é só criar um link numa pasta que o systemd lê no boot. Os links que o enable criou na instalação estão lá:

#> ls /etc/systemd/system/multi-user.target.wants/
NetworkManager.service  remote-fs.target  sshd.service
enable, não start

Dentro do chroot o systemd do sistema novo não está rodando (quem roda é o do live), então systemctl start e enable --now não ligam nada ali. Só o enable faz sentido: ele prepara o próximo boot. Serviços a fundo: systemctl e Serviços; rede: NetworkManager e iwd.

Conferir tudo antes de sair

Antes de instalar o bootloader, vale um minuto para conferir os arquivos. No sistema da VM do guia, depois de pronto, eles estão assim:

#> cat /etc/locale.conf /etc/vconsole.conf /etc/hostname
LANG=pt_BR.UTF-8
KEYMAP=br-abnt2
notebook
#> id ana
uid=1000(ana) gid=1000(ana) grupos=1000(ana),998(wheel)
#> systemctl is-enabled NetworkManager sshd
enabled
enabled

(No sistema instalado as mensagens já saem em português: grupos= em vez de groups=.)

Missão: no terminal simulado (a máquina já instalada), mostre o conteúdo do arquivo que guarda o idioma do sistema.

Missão: leia o arquivo que guarda o nome da máquina.

Quando não funciona

"WARNING: sd-vconsole: "/etc/vconsole.conf" not found"

O que aconteceu: o mkinitcpio rodou antes de você criar o /etc/vconsole.conf. No pacstrap isso é esperado.

Como resolver: crie o arquivo (passo 5) e rode mkinitcpio -P de novo. Se o aviso continuar, confira o nome do arquivo com cat /etc/vconsole.conf.

"visudo: no editor found (editor path = /usr/bin/vi)"

O que aconteceu: o visudo procura o vi, que não está instalado (o pacote vim instala o comando vim, não vi).

Como resolver: diga qual editor usar: EDITOR=nano visudo (ou EDITOR=vim visudo).

"syntax error" ao salvar o sudoers 
#> visudo -c
/etc/sudoers:125:21: syntax error
%wheel ALL=(ALL:ALL ALL
                    ^~~

O que aconteceu: a linha 125, coluna 21, está errada: faltou o ). (Saída real da VM, com o erro feito de propósito numa cópia do arquivo.)

Como resolver: ao salvar com erro, o visudo não grava e pergunta What now?: digite e e Enter para voltar a editar e corrigir. A linha certa é %wheel ALL=(ALL:ALL) ALL.

"useradd: user 'ana' already exists"

O que aconteceu: você rodou o useradd duas vezes (código de saída 9). A usuária já foi criada na primeira.

Como resolver: nada a fazer. Se faltou algo (o grupo, por exemplo), corrija com usermod -aG wheel ana em vez de criar de novo.

Escrevi o arquivo, mas foi no lugar errado

O que aconteceu: dentro do chroot, você digitou /mnt/etc/hostname (isso seria /mnt/mnt/etc/hostname do lado de fora), ou fora do chroot digitou /etc/hostname (o do live, que some ao desligar).

Como confirmar: olhe o prompt. [root@archiso /]# = dentro, use caminhos sem /mnt; root@archiso ~ # = fora, use /mnt na frente.

Como resolver: escreva de novo no lugar certo.

Rodei o genfstab duas vezes

Como confirmar: findmnt --verify --tab-file /mnt/etc/fstab mostra [W] alvo especificado mais de uma vez (no live, em inglês).

Como resolver: veja o aviso na seção 1: apague as linhas repetidas ou gere de novo com >.

Resumo

  • genfstab -U /mnt >> /mnt/etc/fstab, uma vez só; confira com cat e findmnt --verify.
  • arch-chroot /mnt entra no sistema novo; o prompt vira [root@archiso /]#.
  • Fuso: link em /etc/localtime + hwclock --systohc. Idioma: locale.gen + locale-gen + locale.conf. Teclado: vconsole.conf. Nome: hostname.
  • mkinitcpio -P refaz o initramfs, agora com o teclado certo.
  • Senha do root, useradd -m -G wheel, passwd ana e EDITOR=nano visudo para liberar o sudo.
  • systemctl enable NetworkManager, senão o primeiro boot fica sem rede. Próximo passo: o bootloader.
