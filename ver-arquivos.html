Arch cat, less, head, tail

No Arch, quase tudo o que você configura ou investiga é um arquivo de texto: o /etc/pacman.conf, o /var/log/pacman.log, as suas anotações. Esta aula ensina a ler esses arquivos no terminal, sem risco de mudar nada: cat mostra tudo, less mostra página por página, head mostra o começo, tail o fim, e wc e file dizem o tamanho e o tipo. Para editar, a aula é outra: nano e vim.

Você vai aprender
  • Quando usar cada comando de leitura, e por que nenhum deles altera o arquivo.
  • Numerar linhas e enxergar caracteres invisíveis com o cat.
  • Navegar e buscar dentro do less, e de onde ele vem no Arch.
  • Pegar as primeiras ou as últimas linhas, e acompanhar um arquivo ao vivo.
  • Contar linhas e palavras com wc e descobrir o tipo de um arquivo com file.

Os exemplos foram feitos num Arch Linux real, com a usuária ana na pasta pessoal dela. O arquivo frutas.txt tem uma fruta por linha.

cat: mostrar tudo

cat vem de concatenate, "concatenar" (juntar em sequência): ele lê arquivos e despeja o conteúdo na tela, um depois do outro. Com um arquivo só, ele simplesmente mostra o conteúdo inteiro.

cat
O programa.
frutas.txt
O arquivo a mostrar.
$ cat frutas.txt
banana
maçã
laranja
banana
uva
maçã
banana
$ echo $?
0                                « leu sem problemas

Numerar as linhas: -n

O -n (de number) põe o número antes de cada linha. Útil quando uma mensagem de erro diz "linha 5" de um arquivo:

$ cat -n frutas.txt
     1	banana
     2	maçã
     3	laranja
     4	banana
     5	uva
     6	maçã
     7	banana

Vários arquivos: o "concatenar" do nome

Com vários nomes, o cat mostra um depois do outro, sem nenhuma separação. Com -n, a numeração continua de um para o outro:

$ cat -n frutas.txt Documentos/notas.txt
     1	banana
     2	maçã
     3	laranja
     4	banana
     5	uva
     6	maçã
     7	banana
     8	Comprar café                  « aqui começa o notas.txt
     9	Ligar para o João
    10	Estudar Bash
    11	Fazer backup das fotos

Um exemplo do sistema: o /etc/os-release diz qual é a distribuição. É um dos arquivos que programas leem para saber "estou num Arch":

Ver o invisível: -A

Espaços no fim da linha e tabulações não aparecem na tela, mas às vezes quebram um arquivo de configuração. O -A (de all, "tudo") mostra: $ marca o fim de cada linha e ^I é uma tabulação (Tab):

$ printf 'nome\tidade \nAna\t29\n' > tab.txt        « cria um arquivo com tabs e um espaço no fim
$ cat tab.txt
nome    idade
Ana     29
$ cat -A tab.txt
nome^Iidade $                      « ^I = Tab; o espaço antes do $ estava escondido
Ana^I29$

Letras acentuadas aparecem estranhas com -A, porque cada uma ocupa dois bytes em UTF-8 e o cat mostra os bytes: maçã vira maM-CM-'M-CM-#$. Não é defeito no arquivo.

Quando NÃO usar o cat

Num arquivo grande, o cat despeja centenas de linhas e você só vê as últimas. O /var/log/pacman.log da máquina de exemplo, por exemplo, já tem 661 linhas. Para esses, use o less.

less: ler com calma

O less abre o arquivo numa tela própria e deixa você rolar para cima e para baixo, procurar palavras e sair quando quiser. Ele só lê: não muda nada no arquivo. É também o programa que o man usa para mostrar os manuais, então tudo o que você aprender aqui vale lá (veja Obtendo Ajuda).

less
O leitor página por página. O nome é uma brincadeira com um leitor mais antigo, o more ("mais"): "less is more", menos é mais.
/etc/pacman.conf
O arquivo a ler: a configuração do pacman, com 100 linhas.
$ less /etc/pacman.conf

A tela vira isto (captura real, terminal de 80×24):

#
# /etc/pacman.conf
#
# See the pacman.conf(5) manpage for option and repository directives

#
# GENERAL OPTIONS
#
[options]
# The following paths are commented out with their default values listed.
# If you wish to use different paths, uncomment and update the paths.
#RootDir     = /
#DBPath      = /var/lib/pacman/
#CacheDir    = /var/cache/pacman/pkg/
#LogFile     = /var/log/pacman.log
#GPGDir      = /etc/pacman.d/gnupg/
#HookDir     = /etc/pacman.d/hooks/

#XferCommand = /usr/bin/curl -L -C - -f -o %o %u
#XferCommand = /usr/bin/wget --passive-ftp -c -O %o %u
#CleanMethod = KeepInstalled

/etc/pacman.conf
  • As linhas de cima: o começo do arquivo, uma tela de cada vez.
  • A última linha: a linha de comando do less. Logo ao abrir, ela mostra o nome do arquivo; depois que você rola, vira só um : esperando teclas.
  • No fim do arquivo, ela mostra (END) ("fim"). Apertar mais teclas não sai do less: para sair é sempre q.

As teclas do less

TeclaFaz
Espaço ou f ou PgDnDesce uma tela
b ou PgUpSobe uma tela (back)
↓ ↑ ou j k ou EnterDesce ou sobe uma linha
g / GVai para o começo / para o fim
/texto EnterProcura "texto" para baixo
?texto EnterProcura "texto" para cima

-N EnterLiga ou desliga os números de linha

Experimente procurar: dentro do less /etc/pacman.conf, digite /Color e Enter. A tela pula para a linha #Color (a opção que liga as cores do pacman, desligada por padrão) e destaca a palavra. Depois aperte G para ver o fim, com o (END), e q para sair.

Opções úteis ao abrir

ComandoFaz
less -N arqMostra os números das linhas
less -S arqNão quebra linhas longas (role para os lados com →)
less +G arqAbre já no fim (bom para logs)
comando | lessLê a saída de um comando com calma (veja Pipes)

De onde vem o less no Arch?

Em outras distribuições o less é tão básico que ninguém pergunta. No Arch vale perguntar, porque o pacote base é mínimo. O pacman diz a qual pacote pertence um arquivo (-Qo, owns) e por que ele foi instalado (-Qi, info):

$ pacman -Qo $(command -v less)
/usr/bin/less pertence a less 1:710-1
$ pacman -Qi less | grep -E '^(Nome|Versão|Necessário|Motivo)'
Nome                 : less
Versão               : 1:710-1
Necessário para      : man-db                                          « quem depende dele
Motivo da instalação : Instalado como dependência de outro pacote     « não foi pedido
$(command -v less)
O shell troca isso pelo caminho do programa (/usr/bin/less) antes de rodar o pacman.
1:710-1
A versão: 1: é a "época" (um contador que o Arch usa quando o esquema de versões muda), 710 a versão do less e -1 a revisão do pacote.
Necessário para: man-db
O less está aí porque o man-db (o pacote do comando man) depende dele.

Ou seja: o less não faz parte do base. Ele chegou junto com o man-db, que foi pedido no pacstrap. Num Arch instalado sem o man-db, o comando less não existe; instale com sudo pacman -S less.

O less não roda no terminal simulado

Ele ocupa a tela inteira, e o simulador só mostra o arquivo de uma vez. Pratique no seu Arch.

head: o começo

head ("cabeça") mostra as primeiras linhas. Sem opção, as 10 primeiras. Com -n, você escolhe quantas:

head
O programa.
-n 3
Quantas linhas mostrar (number).
frutas.txt
O arquivo.
$ head -n 3 frutas.txt
banana
maçã
laranja
$ head -n 5 Documentos/alunos.csv
nome,idade,cidade,nota             « o cabeçalho de uma planilha: ótimo para ver o formato
Ana,29,Recife,9.5
Bruno,34,Curitiba,7.0
Carla,22,Salvador,8.5
Diego,41,Manaus,6.0

A forma curta head -3 faz o mesmo que head -n 3. Com vários arquivos, o head põe um cabeçalho ==> nome <== antes de cada um:

$ head -n 2 frutas.txt Documentos/acesso.log
==> frutas.txt <==
banana
maçã

==> Documentos/acesso.log <==
192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200

Tudo menos o fim, e bytes

$ head -n -5 frutas.txt            « tudo, MENOS as 5 últimas linhas
banana
maçã
$ head -c 20 Documentos/alunos.csv
nome,idade,cidade,no$              « 20 bytes; sem quebra de linha, o prompt cola no fim

tail: o fim

tail ("cauda") mostra as últimas linhas (10, sem opção). É o comando dos logs, porque as novidades sempre entram no fim:

$ tail -n 2 frutas.txt
maçã
banana
$ tail -n 1 Documentos/acesso.log
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200
$ tail -n 5 /etc/pacman.conf
# An example of a custom package repository.  See the pacman manpage for
# tips on creating your own repositories.
#[custom]
#SigLevel = Optional TrustAll
#Server = file:///home/custompkgs

A partir de uma linha: -n +N

Com um + antes do número, o tail mostra a partir daquela linha até o fim:

$ tail -n +6 frutas.txt
maçã                « linha 6
banana              « linha 7

Acompanhar ao vivo: -f

O -f (de follow, "seguir") mostra o fim e fica esperando: cada linha nova que entra no arquivo aparece na hora. O terminal fica "preso" no tail; para sair, aperte Ctrl+C. Aqui, um script de backup escrevia no backup.log enquanto a ana olhava:

$ tail -f backup.log
iniciando backup
copiando Documentos         « apareceu 1 segundo depois
copiando Imagens            « e esta, mais 1 segundo depois
^C
E os logs do sistema? No Arch, journalctl -f

O Arch não tem /var/log/syslog nem /var/log/messages: os registros do sistema ficam no journal do systemd, num formato binário que o tail não lê. O equivalente do tail -f é o journalctl -f (veja Logs (journalctl)):

$ ls /var/log
audit  btmp  journal  lastlog  nginx  old  pacman.log  private  wtmp
$ journalctl -f
…
out 16 15:02:12 notebook systemd-logind[290]: New session '243' of user 'root' with class 'user' and type 'tty'.
out 16 15:02:12 notebook systemd[1]: Started Session 243 of User root.
^C

Já o log do pacman é texto comum: tail -n 20 /var/log/pacman.log mostra as últimas instalações e atualizações.

wc: contar linhas, palavras e bytes

wc vem de word count, "contagem de palavras". Sem opção, ele mostra três números e o nome:

$ wc frutas.txt
 7  7 47 frutas.txt
NúmeroO que éOpção para ver só ele
7Linhaswc -l (lines)
7Palavras (pedaços separados por espaço ou quebra de linha)wc -w (words)
47Byteswc -c
Caracteres (letras)wc -m
$ wc -l frutas.txt
7 frutas.txt
$ wc -c frutas.txt
47 frutas.txt
$ wc -m frutas.txt
43 frutas.txt                       « 4 a menos: ç e ã ocupam 2 bytes cada, e "maçã" aparece 2 vezes
$ wc -w Documentos/notas.txt
12 Documentos/notas.txt
$ wc -l Documentos/*.txt Documentos/*.csv frutas.txt
  4 Documentos/notas.txt
  6 Documentos/alunos.csv
  7 frutas.txt
 17 total                           « com vários arquivos, uma linha de total
$ wc -l < frutas.txt
7                                   « com <, só o número (sem o nome)

O wc brilha junto com outros comandos: pacman -Qq | wc -l conta quantos pacotes estão instalados (veja Pipes e sort, uniq, cut, wc, tr).

file: que tipo de arquivo é este?

No Linux, a extensão (.txt, .jpg) é só parte do nome; ela não manda em nada. O file olha o conteúdo e diz o que o arquivo realmente é. Use antes de abrir um arquivo desconhecido com cat:

$ file frutas.txt Documentos/projetos/backup.sh Documentos/projetos /etc/pacman.conf /bin
frutas.txt:                    Unicode text, UTF-8 text                  « texto com acentos
Documentos/projetos/backup.sh: Bourne-Again shell script, ASCII text executable   « um script Bash
Documentos/projetos:           directory                                 « uma pasta
/etc/pacman.conf:              ASCII text                                « texto sem acentos
/bin:                          symbolic link to usr/bin                  « um atalho (link)
$ file /usr/bin/ls
/usr/bin/ls: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=d6281af586ce362d9c1029002636397df0cf21f1, for GNU/Linux 4.4.0, stripped

A última é um programa (ELF é o formato dos executáveis do Linux): nada que valha a pena abrir com cat. E repare no /bin: no Arch ele é só um link para /usr/bin (veja Estrutura de Diretórios e Links).

O file está instalado em todo Arch: ele é uma das dependências do próprio base.

$ pacman -Qi file | grep -E '^(Versão|Necessário|Motivo)'
Versão               : 5.48-1
Necessário para      : base  base-devel  nano  subversion  util-linux
Motivo da instalação : Instalado como dependência de outro pacote

Quando não funciona

"Arquivo ou diretório inexistente" 
$ cat nada
cat: nada: Arquivo ou diretório inexistente
$ head nada
head: não foi possível abrir 'nada' para leitura: Arquivo ou diretório inexistente
$ less nada
nada: Arquivo ou diretório inexistente

O que aconteceu: o nome está errado ou o arquivo está em outra pasta. Cada programa escreve a mensagem de um jeito, mas a causa é a mesma.

Como resolver: ls para conferir, Tab para completar o nome, pwd para saber onde você está.

"É um diretório" / "is a directory" 
$ cat Documentos
cat: Documentos: É um diretório
$ less Documentos
Documentos is a directory

O que aconteceu: esses comandos leem arquivos, não pastas. (A mensagem do less 710 não é traduzida.)

Como resolver: para ver o que há numa pasta, use ls (veja ls).

"Permissão negada" 
$ cat /etc/shadow
cat: /etc/shadow: Permissão negada

O que aconteceu: o arquivo só pode ser lido pelo root. O /etc/shadow guarda as senhas criptografadas.

Como resolver: se for mesmo necessário, leia como root: sudo cat /etc/shadow (veja sudo, root e Usuários).

"tail: nenhum aquivo restante" 
$ tail -f nada
tail: não foi possível abrir 'nada' para leitura: Arquivo ou diretório inexistente
tail: nenhum aquivo restante

O que aconteceu: o arquivo não existe, e o tail -f desistiu por não ter o que acompanhar. O "aquivo", sem o "r", é um erro de digitação da própria tradução do coreutils, e aparece assim no Arch também.

Como resolver: confira o caminho. Se o arquivo ainda vai ser criado, use tail -F (maiúsculo), que espera ele aparecer.

"bash: less: comando não encontrado"

O que aconteceu: num Arch instalado sem o man-db, o less não vem (ele não é do base).

Como resolver: sudo pacman -S less. Enquanto isso, head e tail resolvem.

A tela ficou cheia de símbolos estranhos

O que aconteceu: você usou cat num arquivo que não é texto (uma imagem, um programa), e alguns bytes viraram comandos para o terminal.

Como resolver: digite reset e Enter, mesmo sem ver o que digita. Da próxima vez, use file antes.

Resumo

  • cat mostra tudo (arquivos pequenos); -n numera, -A mostra invisíveis.
  • less lê com calma: Espaço desce, / busca, q sai. No Arch ele vem como dependência do man-db, não do base.
  • head -n N mostra o começo; tail -n N, o fim; tail -n +N, da linha N em diante; tail -f, ao vivo.
  • Logs do sistema no Arch: journalctl -f; o log do pacman é texto: /var/log/pacman.log.
  • wc -l conta linhas; file diz o tipo real de um arquivo.

Os logs do sistema estão em systemd/Journal (em português: systemd/Journal (Português)), e as cores e opções do less usadas pelo man, em Man page.
