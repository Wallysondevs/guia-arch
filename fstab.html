mount e fstab

Montar é ligar um sistema de arquivos a uma pasta, para que o conteúdo do disco apareça ali. O comando mount faz isso na hora; o arquivo /etc/fstab (de file systems table, tabela de sistemas de arquivos) diz o que montar a cada boot. Um erro de digitação nesse arquivo pode impedir o sistema de iniciar, por isso esta aula ensina também a testar antes de reiniciar.

Você vai aprender
  • Ler o /etc/fstab que o genfstab -U criou na instalação, coluna por coluna.
  • A diferença entre UUID, LABEL, PARTUUID e /dev/sdX, e qual usar.
  • As opções defaults, noatime, nofail e x-systemd.automount.
  • Montar e desmontar com mount e umount, usando um disco de teste.
  • Acrescentar um disco ao fstab, testar com findmnt --verify e mount -a, e sair do emergency mode se algo der errado.

Quem lê o fstab

No boot, antes de tudo, o systemd lê o /etc/fstab e transforma cada linha numa unidade de montagem (.mount), o mesmo tipo de unidade que você conhece de systemctl e Serviços. Quem faz essa tradução é um programa chamado systemd-fstab-generator. Depois, a unidade local-fs.target ("sistemas de arquivos locais prontos") espera essas montagens. Guarde essa ideia: ela explica por que uma linha errada trava o boot (mais abaixo).

Na instalação, você não escreveu o fstab à mão: o genfstab -U /mnt >> /mnt/etc/fstab olhou o que estava montado em /mnt e gerou as linhas (veja Configurar o Sistema). O -U mandou usar UUIDs.

O fstab real da ana

# Static information about the filesystems.
# See fstab(5) for details.

# <file system> <dir> <type> <options> <dump> <pass>
# /dev/sda3
UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9	/         	ext4      	rw,relatime	0 1

# /dev/sda1
UUID=C509-6CB1      	/boot     	vfat      	rw,relatime,fmask=0022,dmask=0022,codepage=437,iocharset=ascii,shortname=mixed,utf8,errors=remount-ro	0 2

# /dev/sda2
UUID=02576132-0458-4975-916f-94e08af9a31c	none      	swap      	defaults  	0 0

Linhas que começam com # são comentários. Os comentários # /dev/sda3 foram postos pelo genfstab para você saber de onde veio cada UUID. Sobram três linhas de verdade, uma por partição. Os espaços entre as colunas podem ser tabulações ou espaços, em qualquer quantidade.

As 6 colunas

Tome a primeira linha: UUID=75d167c8-… / ext4 rw,relatime 0 1.

#ColunaNa linha da raizSignifica
1<file system> (o quê)UUID=75d167c8-…Qual sistema de arquivos montar
2<dir> (onde)/O ponto de montagem. Para swap, none
3<type> (tipo)ext4ext4, vfat, btrfs, swap, ntfs3…
4<options> (como)rw,relatimeOpções separadas por vírgula, sem espaço
5<dump>0Backup pelo antigo programa dump. Ninguém usa: deixe 0
6<pass>1Ordem do fsck (verificação) no boot: 1 = a raiz, primeiro; 2 = os outros depois; 0 = não verificar

As outras duas linhas, lidas do mesmo jeito:

  • /boot: a partição EFI (vfat = FAT32). As opções longas (fmask=0022,dmask=0022 = permissões dos arquivos e pastas, já que a FAT não tem dono nem permissões; codepage, iocharset, shortname, utf8 = como tratar os nomes; errors=remount-ro = se achar erro, passar a só leitura) foram copiadas pelo genfstab do que o kernel estava usando. Pass 2: verificada depois da raiz.
  • swap: ponto de montagem none (swap não aparece em pasta nenhuma), tipo swap, opções defaults, pass 0 (swap não tem o que verificar). Mais em Swap e zram.

Missão: mostre o /etc/fstab sem as linhas de comentário (as que começam com #). Dica: grep -v mostra as linhas que não casam.

UUID, LABEL, PARTUUID ou /dev/sdX?

A primeira coluna pode apontar o disco de quatro jeitos. Os valores da ana (de lsblk e blkid):

FormaExemploMuda quando…Qual usar?
UUID=UUID=75d167c8-1dad-4d0a-a0ae-b063058a18e9Você formata de novoO padrão (genfstab -U). Sempre único
LABEL=LABEL=dadosVocê troca o rótuloLegível, mas dois discos com o mesmo rótulo dão confusão
PARTUUID=PARTUUID=431c3f9d-d4b9-4e4d-b16a-d5399a4aee27Você recria a partiçãoQuando a partição ainda não tem sistema de arquivos, ou para o kernel (root=PARTUUID=…)
/dev/sdX/dev/sda3A ordem dos discos muda (pendrive, outro cabo)Evite. Funciona até o dia em que o disco troca de letra
Formatou? Atualize o fstab

Se você formatar uma partição que está no fstab (por exemplo, recriar o ext4 de um disco de dados), o UUID muda e a linha antiga passa a apontar para um disco que não existe. É o erro clássico da seção "Quando não funciona".

As opções mais usadas

OpçãoO que faz
defaultsO pacote padrão: rw,suid,dev,exec,auto,nouser,async (leitura e escrita, monta no boot, só o root monta). Use quando não precisa de nada especial
rw / roLeitura e escrita / somente leitura
relatimeGrava a data de último acesso só de vez em quando. É o padrão do kernel (por isso o genfstab o escreveu)
noatimeNunca grava a data de acesso: um pouco menos de escrita no disco. Popular em SSDs; quase nenhum programa precisa dessa data
noautoNão monta no boot (só quando você mandar)
nofailSe o disco não estiver lá, o boot continua. Essencial para discos externos e segundos discos
x-systemd.automountMonta no primeiro acesso à pasta, não no boot (boot mais rápido; ótimo para discos de dados e de rede)
x-systemd.device-timeout=10sQuanto tempo esperar o disco aparecer (o padrão é 90 segundos)
user / usersDeixa usuários comuns montarem aquela linha
discardTRIM contínuo em SSD (o semanal, com fstrim.timer, costuma ser melhor: veja lsblk, df, du)

Opções do tipo x-systemd.algo são lidas pelo systemd e ignoradas pelo mount. Opções que só um tipo entende (como fmask da FAT ou compress=zstd do Btrfs) vão na mesma coluna.

mount e umount na prática

Para treinar sem risco, vamos usar um disco de teste: um arquivo comum transformado em disco com o losetup (loop setup). Para o Linux, ele se comporta como um pendrive. Todos os comandos abaixo são como root (sudo -i).

Preparar o disco de teste

  1. Criar um arquivo de 512 MiB (o truncate só anota o tamanho; o espaço é gasto aos poucos): 
    #> mkdir -p /var/tmp/a7
#> truncate -s 512M /var/tmp/a7/disco.img
#> ls -lh /var/tmp/a7/disco.img
-rw-r--r-- 1 root root 512M 16 out 13:22 /var/tmp/a7/disco.img
  2. Ligar o arquivo a um dispositivo loop (-f = o primeiro livre; --show = mostra qual foi): 
    #> losetup -f --show /var/tmp/a7/disco.img
/dev/loop0
  3. Formatar em ext4 com o rótulo dados: 
    #> mkfs.ext4 -L dados /dev/loop0
mke2fs 1.47.4 (6-Mar-2025)
A descartar blocos de dispositivo:      0/131072             feito
A criar sistema de ficheiros com 131072 4k blocos e 32768 inodes
UUID do sistema de ficheiros: 6a25becf-3d26-4913-b036-c34a83bc387e     « anote: é o UUID novo
Seguranças de super-blocos armazenadas em blocos:
	32768, 98304

A alocar tabelas de grupo: 0/4   feito
A escrever tabelas de inodes: 0/4   feito
A criar diário (4096 blocos): feito
A escrever super-blocos e informação de contabilidade do sistema de ficheiros: 0/4   feito

    Sim, o mkfs.ext4 do Arch fala português de Portugal ("ficheiros", "A criar"): a tradução dele não tem versão brasileira, e o sistema usa a mais próxima. Na instalação, no ambiente live em inglês, a mesma saída veio em inglês.

  4. Conferir: 
    #> lsblk -f /dev/loop0
NAME  FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
loop0 ext4   1.0   dados 6a25becf-3d26-4913-b036-c34a83bc387e

mount: montar

mount
Monta.
/dev/loop0
O quê (o dispositivo).
/mnt/a7
Onde (o ponto de montagem: uma pasta que precisa existir).
#> mount /dev/loop0 /mnt/a7
mount: /mnt/a7: o ponto de montagem não existe.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.
#> echo $?
32
#> mkdir /mnt/a7
#> mount /dev/loop0 /mnt/a7
#> echo $?
0
#> findmnt /mnt/a7
TARGET  SOURCE     FSTYPE OPTIONS
/mnt/a7 /dev/loop0 ext4   rw,relatime
#> df -h /mnt/a7
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
/dev/loop0      488M  152K  452M   1% /mnt/a7
#> ls -l /mnt/a7
total 16
drwx------ 2 root root 16384 16 out 13:22 lost+found

O primeiro mount falhou porque a pasta não existia; o código 32 é o "falha de montagem" do mount. Depois do mkdir, nenhuma mensagem e código 0: deu certo. Ninguém precisou dizer que é ext4, porque o mount descobre o tipo sozinho (para forçar, existe -t tipo). A pasta lost+found é do ext4: é onde o fsck guarda pedaços de arquivos recuperados.

umount: desmontar

O comando é umount, sem o "n". Ele aceita a pasta ou o dispositivo.

#> echo "arquivo de teste" > /mnt/a7/teste.txt
#> cd /mnt/a7
#> umount /mnt/a7
umount: /mnt/a7: o alvo está ocupado.
#> echo $?
32
#> cd
#> umount /mnt/a7
#> echo $?
0
#> ls /mnt/a7
#>

O primeiro umount falhou porque o próprio shell estava dentro da pasta: um disco não pode ser desmontado enquanto algum programa usa algo nele (uma pasta aberta, um arquivo aberto). Depois de sair com cd, deu certo, e a pasta /mnt/a7 voltou a ser uma pasta vazia comum: o arquivo teste.txt continua dentro do disco de teste, não na pasta.

Montar pelo rótulo, com opções

#> mount LABEL=dados /mnt/a7
#> ls /mnt/a7
lost+found
teste.txt
#> umount /dev/loop0
#> mount -o ro,noatime /dev/loop0 /mnt/a7
#> findmnt /mnt/a7
TARGET  SOURCE     FSTYPE OPTIONS
/mnt/a7 /dev/loop0 ext4   ro,noatime
#> touch /mnt/a7/novo
touch: não foi possível tocar '/mnt/a7/novo': Sistema de arquivos somente para leitura
#> umount /mnt/a7

A primeira coluna do fstab funciona também no mount: LABEL=, UUID=. O -o (options) recebe as mesmas opções da quarta coluna do fstab; com ro, qualquer gravação é recusada.

Forma de montarQuando usar
sudo mount /dev/sdb1 /mnt/pastaUma vez, agora (some no próximo boot)
Linha no /etc/fstabTodo boot, sempre no mesmo lugar (segundo disco, partição de dados)
Gerenciador de arquivos (Dolphin, Nautilus)Pendrives e HDs externos no desktop: um clique monta em /run/media/ana/RÓTULO (via udisks2), sem root
udisksctl mount -b /dev/sdb1O mesmo que o gerenciador, pelo terminal, sem sudo

Acrescentar um disco ao fstab (e testar antes)

Agora vamos fazer o disco de teste montar "sozinho". Para não arriscar o boot da ana, a linha vai para uma cópia do fstab em /tmp/a7/fstab. No seu computador, o roteiro é o mesmo, só que no arquivo real (veja o passo a passo logo depois).

  1. Pegue o UUID: 
    #> blkid -s UUID -o value /dev/loop0
6a25becf-3d26-4913-b036-c34a83bc387e
  2. Acrescente a linha (com >>, que acrescenta; um > sozinho apagaria o arquivo inteiro): 
    #> cp /etc/fstab /tmp/a7/fstab
#> printf "\n# disco extra de dados\nUUID=6a25becf-3d26-4913-b036-c34a83bc387e\t/mnt/a7\text4\tdefaults,noatime,nofail\t0 2\n" >> /tmp/a7/fstab
#> tail -3 /tmp/a7/fstab

# disco extra de dados
UUID=6a25becf-3d26-4913-b036-c34a83bc387e	/mnt/a7	ext4	defaults,noatime,nofail	0 2

    No dia a dia você vai usar um editor (sudo nano /etc/fstab); o printf só deixa o exemplo exato.

  3. Verifique a sintaxe com o findmnt --verify (--tab-file aponta a cópia; sem ele, verifica o /etc/fstab): 
    #> findmnt --verify --tab-file /tmp/a7/fstab
Sucesso, nenhum erro ou aviso detectado
#> echo $?
0
  4. Monte tudo o que está no arquivo com mount -a (all; --fstab aponta a cópia; -v conta o que fez): 
    #> mount -av --fstab /tmp/a7/fstab
/                        : ignorado
/boot                    : já montada
none                     : ignorado
/mnt/a7                  : successfully mounted
#> findmnt /mnt/a7
TARGET  SOURCE     FSTYPE OPTIONS
/mnt/a7 /dev/loop0 ext4   rw,noatime

    O mount -a pula o que já está montado (/ e /boot), ignora a swap e monta o que falta. Se ele funcionou sem erro, o boot também vai funcionar. Com a linha no fstab, até o atalho mount /mnt/a7 funciona: o mount completa o resto pelo arquivo.

No seu computador, com o fstab real

  1. Faça uma cópia de segurança: sudo cp /etc/fstab /etc/fstab.bak.
  2. Crie o ponto de montagem (sudo mkdir -p /mnt/dados) e edite: sudo nano /etc/fstab.
  3. Verifique: sudo findmnt --verify.
  4. Avise o systemd que o fstab mudou: sudo systemctl daemon-reload (senão ele reclama que o fstab é mais novo que as unidades geradas).
  5. Teste: sudo mount -a. Sem mensagens = tudo certo. Só depois reinicie.
findmnt --verify não pega tudo

Ele confere se o disco existe, se a pasta existe e se o tipo bate, mas não conhece as opções de cada sistema de arquivos. Teste real com a opção noatime escrita errado:

#> cat /tmp/a7/fstab-opcao
UUID=6a25becf-3d26-4913-b036-c34a83bc387e /mnt/a7 ext4 defaults,noatme 0 2
#> findmnt --verify --tab-file /tmp/a7/fstab-opcao
Sucesso, nenhum erro ou aviso detectado
#> mount -a --fstab /tmp/a7/fstab-opcao
mount: /mnt/a7: fsconfig() falhou: ext4: Unknown parameter 'noatme'.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.
#> echo $?
32

Por isso, sempre os dois: findmnt --verify e mount -a.

A linha errada que trava o boot

Lembra do systemd-fstab-generator? Dá para rodá-lo à mão numa cópia e ver o que ele gera: a variável SYSTEMD_FSTAB aponta o arquivo a ler, SYSTEMD_PROC_CMDLINE="" finge uma linha de comando do kernel vazia, e as três pastas no fim são onde ele grava as unidades. Duas cópias, uma linha cada, a única diferença é o nofail:

#> cat /tmp/a7/fstab-sem /tmp/a7/fstab-com
UUID=6a25becf-3d26-4913-b036-c34a83bc387e /mnt/a7 ext4 defaults 0 2
UUID=6a25becf-3d26-4913-b036-c34a83bc387e /mnt/a7 ext4 defaults,nofail 0 2
#> SYSTEMD_FSTAB=/tmp/a7/fstab-sem SYSTEMD_PROC_CMDLINE="" /usr/lib/systemd/system-generators/systemd-fstab-generator /tmp/a7/gen1 /tmp/a7/gen1 /tmp/a7/gen1
#> SYSTEMD_FSTAB=/tmp/a7/fstab-com SYSTEMD_PROC_CMDLINE="" /usr/lib/systemd/system-generators/systemd-fstab-generator /tmp/a7/gen2 /tmp/a7/gen2 /tmp/a7/gen2
#> ls -R /tmp/a7/gen1 /tmp/a7/gen2
/tmp/a7/gen1:
local-fs.target.requires          « sem nofail: "requires" (exige)
local-fs.target.wants
mnt-a7.mount

/tmp/a7/gen1/local-fs.target.requires:
mnt-a7.mount

/tmp/a7/gen1/local-fs.target.wants:
systemd-remount-fs.service

/tmp/a7/gen2:
local-fs.target.wants             « com nofail: só "wants" (deseja)
mnt-a7.mount

/tmp/a7/gen2/local-fs.target.wants:
mnt-a7.mount
systemd-remount-fs.service

Sem nofail, a montagem vai para local-fs.target.requires: o alvo "sistemas de arquivos locais" exige esse disco. Se ele não montar (UUID errado, disco desligado, opção errada), o local-fs.target falha, e o systemd não tem como seguir: ele para no emergency mode. Com nofail, a montagem vai para wants: se falhar, fica registrado no log e o boot continua.

Como é o emergency mode (ilustrativo)

Não dá para quebrar o boot da máquina de laboratório, então a tela abaixo é ilustrativa. Depois de esperar até 90 segundos pelo disco, o systemd mostra algo assim:

[ TIME ] Timed out waiting for device /dev/disk/by-uuid/6a25becf-….
[DEPEND] Dependency failed for /mnt/dados.
[DEPEND] Dependency failed for Local File Systems.
You are in emergency mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, or "exit" to continue bootup.
Give root password for maintenance
(or press Control-D to continue):

Como sair dele

  1. Digite a senha do root (a que você definiu com passwd na instalação). Você cai num shell de root, com a raiz já montada.
  2. Veja o que falhou: journalctl -xb -p err ou systemctl --failed.
  3. Se a raiz estiver somente leitura, libere a escrita: mount -o remount,rw /.
  4. Corrija a linha (nano /etc/fstab): conserte o UUID, acrescente nofail ou comente a linha com #. Se fez cópia: cp /etc/fstab.bak /etc/fstab.
  5. systemctl daemon-reload, mount -a para conferir, e systemctl reboot.

Se não aparecer o pedido de senha (root sem senha, ou a raiz nem montou), o caminho é o pendrive de instalação e o arch-chroot: veja Resgate com chroot.

Regra de ouro

Todo disco que não é necessário para o sistema ligar (segundo HD, partição de dados, disco externo, compartilhamento de rede) leva nofail. Se quiser que o boot não espere 90 segundos por ele quando estiver desligado, acrescente x-systemd.device-timeout=10s.

x-systemd.automount: montar só quando usar

Com noauto,x-systemd.automount, o boot não monta o disco: o systemd deixa uma "armadilha" na pasta, e o disco é montado no primeiro acesso. O gerador cria uma unidade extra, .automount:

#> cat /tmp/a7/fstab-auto
UUID=6a25becf-3d26-4913-b036-c34a83bc387e /mnt/a7 ext4 defaults,nofail,noauto,x-systemd.automount 0 2
#> SYSTEMD_FSTAB=/tmp/a7/fstab-auto SYSTEMD_PROC_CMDLINE="" /usr/lib/systemd/system-generators/systemd-fstab-generator /tmp/a7/gen3 /tmp/a7/gen3 /tmp/a7/gen3
#> ls -R /tmp/a7/gen3
/tmp/a7/gen3:
local-fs.target.wants
mnt-a7.automount
mnt-a7.mount

/tmp/a7/gen3/local-fs.target.wants:
mnt-a7.automount                  « no boot, só a "armadilha" é ligada
systemd-remount-fs.service

Para ver o efeito sem mexer no fstab, o systemd-mount cria a mesma dupla de unidades na hora:

#> systemd-mount --automount=yes /dev/loop0 /mnt/a7

#> findmnt /mnt/a7
TARGET  SOURCE    FSTYPE OPTIONS
/mnt/a7 systemd-1 autofs rw,relatime,fd=73,pgrp=1,timeout=0,minproto=5,maxproto=5,direct,pipe_ino=40026

teste.txt
#> findmnt /mnt/a7

Antes do ls, a pasta tinha só a armadilha (autofs). O ls tocou na pasta, o systemd montou o disco de verdade (ext4) e entregou a lista, sem você perceber a diferença.

Desfazer o disco de teste

#> losetup -d /dev/loop0
#> rm /var/tmp/a7/disco.img
#> rmdir /mnt/a7 /var/tmp/a7

O disco já foi desmontado pelo systemd-umount (se não, comece com umount /mnt/a7). losetup -d (detach) solta o arquivo do /dev/loop0. Se o rmdir disser Dispositivo ou recurso está ocupado, ainda há algo montado ali: confira com findmnt /mnt/a7 e desmonte de novo.

Quando não funciona

"o ponto de montagem não existe" 
#> mount /dev/loop0 /mnt/a7
mount: /mnt/a7: o ponto de montagem não existe.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

Como resolver: crie a pasta antes: mkdir -p /mnt/a7 (ou use mount --mkdir, como na instalação). No fstab, o findmnt --verify acusa: [E] alvo não alcançável na inicialização: Arquivo ou diretório inexistente.

"o alvo está ocupado" 
#> umount /mnt/a7
umount: /mnt/a7: o alvo está ocupado.

O que aconteceu: algum programa está usando o disco: um terminal com cd lá dentro, um arquivo aberto num editor, o gerenciador de arquivos.

Como resolver: saia da pasta e feche os programas. Para descobrir quem é: fuser -vm /mnt/a7 (pacote psmisc). Evite umount -l ("preguiçoso"): ele esconde o problema.

"é necessário ser superusuário para montar" 
$ mount /dev/loop0 /mnt/a7
mount: /mnt/a7: é necessário ser superusuário para montar.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

Como resolver: sudo mount …, ou udisksctl mount -b /dev/sdb1 para discos removíveis.

"não montado" 
#> umount /mnt/a7
umount: /mnt/a7: não montado.
#> echo $?
32

O que aconteceu: não havia nada montado ali (já foi desmontado, ou o nome está errado). Confira com findmnt /mnt/a7.

"não foi possível localizar UUID=…" 
#> mount -a --fstab /tmp/a7/fstab-erro
mount: /mnt/a7: não foi possível localizar UUID=6a25becf-3d26-4913-b036-c34a83bc3999.
mount: /mnt/fotos: o ponto de montagem não existe.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.
#> findmnt --verify --tab-file /tmp/a7/fstab-erro

0 erro de análise, 2 erros, 0 aviso
/mnt/a7
   [E] fonte não alcançável na inicialização: UUID=6a25becf-3d26-4913-b036-c34a83bc3999
/mnt/fotos
   [E] alvo não alcançável na inicialização: Arquivo ou diretório inexistente

O que aconteceu: o UUID não bate com nenhum disco: erro de digitação, disco desligado ou partição formatada de novo (UUID novo). O findmnt --verify mostra cada problema com [E] e sai com código 1.

Como resolver: pegue o UUID atual com lsblk -f ou sudo blkid e copie-o (nunca redigite). Se o disco é opcional, acrescente nofail.

"Unknown parameter" ou "Can't open blockdev" 
#> mount -a --fstab /tmp/a7/fstab-opcao
mount: /mnt/a7: fsconfig() falhou: ext4: Unknown parameter 'noatme'.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.
#> mount -t vfat /dev/loop0 /mnt/a7
mount: /mnt/a7: fsconfig() falhou: /dev/loop0: Can't open blockdev.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

O que aconteceu: no primeiro, uma opção que o ext4 não conhece (erro de digitação). No segundo, o tipo está errado: o disco é ext4 e foi pedido vfat.

Como resolver: confira a grafia das opções e o tipo com lsblk -f. Em dúvida sobre o tipo, deixe o mount descobrir (sem -t) ou use auto na terceira coluna.

O boot parou em "You are in emergency mode"

O que aconteceu: uma linha do fstab sem nofail não montou.

Como resolver: senha do root → journalctl -xb -p err → corrija o fstab → systemctl daemon-reload → mount -a → systemctl reboot (detalhes acima).

Resumo

  • mount o-quê onde monta agora; o /etc/fstab monta a cada boot. umount (sem "n") desmonta.
  • Seis colunas: o quê, onde, tipo, opções, dump (0), pass (1 raiz, 2 outros, 0 nunca).
  • Use UUID= (como o genfstab -U); copie o valor do lsblk -f, não redigite.
  • Discos que não são essenciais levam nofail; sem ele, um disco ausente leva ao emergency mode.
  • Depois de editar: findmnt --verify, systemctl daemon-reload e mount -a. Só então reinicie.
