Tutorial Arch Linux

Aprenda Arch Linux do zero, como numa escola: da instalação feita à mão até consertar um sistema que não liga. Cada comando é explicado parte por parte, você vê exatamente o que ele devolve e pratica num terminal simulado aqui mesmo no navegador. Tudo foi conferido num Arch Linux de verdade, instalado seguindo a Arch Wiki.

O sistema não liga depois de uma atualização?

Respire: quase sempre dá para consertar sem reinstalar. Dê boot pelo pendrive do Arch, entre no sistema instalado com arch-chroot e refaça o que faltou. O passo a passo está em Resgate com chroot; os erros mais comuns do pacman (chaves, arquivos em conflito, atualização interrompida) estão em Erros de Atualização. Se o problema é o computador travado agora, vá para Quando o Sistema Trava.

Experimente agora

A caixa abaixo é um terminal simulado: uma máquina fictícia chamada notebook, com a usuária ana, rodando Arch Linux. Ela funciona dentro do seu navegador e nada do que você digitar afeta o seu computador. Clique dentro dela, digite pacman -Q bash e aperte Enter.

Missão: pergunte ao pacman qual versão do Bash está instalada com pacman -Q bash. Depois veja a "carteira de identidade" do sistema com cat /etc/os-release, e digite help para ver tudo o que funciona aqui.

Na VM do guia, as respostas foram estas:

$ pacman -Q bash
bash 5.3.20-1                  « nome do pacote, versão 5.3.20, lançamento 1
$ cat /etc/os-release
NAME="Arch Linux"
PRETTY_NAME="Arch Linux"
ID=arch
BUILD_ID=rolling               « não há "versão 12" ou "versão 40": o Arch é rolling release
ANSI_COLOR="38;2;23;147;209"
HOME_URL="https://archlinux.org/"
DOCUMENTATION_URL="https://wiki.archlinux.org/"   « a famosa Arch Wiki
SUPPORT_URL="https://bbs.archlinux.org/"
BUG_REPORT_URL="https://gitlab.archlinux.org/groups/archlinux/-/issues"
PRIVACY_POLICY_URL="https://terms.archlinux.org/docs/privacy-policy/"
LOGO=archlinux-logo

Repare em duas coisas que você só vê no Arch. Primeiro, o -1 no fim de 5.3.20-1: é o número do lançamento do pacote (se o Arch corrigir o empacotamento sem mudar o Bash, vira 5.3.20-2). Segundo, BUILD_ID=rolling: enquanto o Debian e o Ubuntu têm versões com nome e número, o Arch não tem versão nenhuma. Ele é atualizado continuamente, e a aula Rolling Release explica o que isso muda na sua vida.

Como as aulas funcionam

Nenhum comando aparece "seco". Toda aula segue o mesmo caminho:

  1. A ideia primeiro. Antes do comando, você entende o problema que ele resolve (o que é um pacote, um espelho, uma partição EFI…).
  2. Anatomia do comando. Cada pedaço é numerado e explicado: o programa, as opções e os argumentos, inclusive de onde vem o nome (-S = sync).
  3. Terminal com a resposta real. Você vê o que aparece na tela de um Arch Linux em português, com etiquetas apontando o que importa e o código de saída (echo $?).
  4. Várias formas de fazer. GRUB ou systemd-boot? yay ou paru? Uma tabela "Qual usar?" ajuda a escolher.
  5. Quando não funciona. A mensagem de erro real, a causa, como confirmar e como resolver.
  6. Experimente, exercícios e Arch Wiki. Missões no terminal simulado, exercícios com correção na hora e, no fim, as páginas da Wiki que aprofundam o tema.

Veja um exemplo de anatomia, com o comando que todo usuário de Arch digita toda semana:

sudo
Roda o comando seguinte como administrador (root). Mexer nos pacotes muda o sistema inteiro, por isso precisa de permissão. Veja sudo, root e Usuários.
pacman
O gerenciador de pacotes do Arch. O nome vem de package manager (e lembra o jogo, de propósito).
-S
Sync: a operação que conversa com os repositórios (instalar, procurar, atualizar).
y
Refresh: baixa a lista atualizada de pacotes dos espelhos (os arquivos core.db e extra.db).
u
Sysupgrade: atualiza todos os pacotes instalados que têm versão nova nessa lista.

Juntas, as letras formam -Syu: "sincronize, baixe a lista nova e atualize tudo". As opções de uma letra podem ser grudadas, por isso -Syu é o mesmo que -S -y -u. Na VM do guia, num dia em que estava tudo em dia, a resposta foi curta:

$ checkupdates                « mostra o que o -Syu atualizaria, sem mexer no sistema
$ echo $?
2                              « 2 = nenhuma atualização pendente (0 = há atualizações)
#> pacman -Su
:: Iniciando atualização completa do sistema...
nada para fazer                « tudo já está na versão mais nova

Quando há novidades, o pacman mostra a lista de pacotes, o tamanho do download e pergunta :: Continuar a instalação? [S/n]. A aula Atualizar o Sistema mostra uma atualização inteira, linha por linha, e explica por que nunca se deve rodar só o -Sy seguido de um -S pacote (a "atualização parcial").

A regra de ouro

Ler não basta: digite cada exemplo. Use o terminal simulado das aulas e, quando ele não for suficiente, instale o Arch numa máquina virtual (VirtualBox, GNOME Boxes ou virt-manager). Se algo quebrar, você recria a VM em minutos e aprendeu algo no caminho. Foi assim que este guia foi feito: a VM tem o mesmo nome (notebook) e a mesma usuária (ana) que você vê nos exemplos.

Como ler este guia

ElementoO que significa
[ana@notebook ~]$O prompt do Arch: usuária ana, na máquina notebook, na pasta pessoal (~). Entre colchetes aparece só o nome da pasta atual: em /home/ana/Documentos ele vira [ana@notebook Documentos]$. O que vem depois do $ é o comando digitado.
[root@notebook ~]#Comando rodado como administrador (root). O # no fim avisa que esse shell pode mexer em tudo. Na prática, a ana chega lá com sudo.
root@archiso ~ #O ambiente live do pendrive de instalação (outro shell, o zsh, com outro prompt). Aparece só nas aulas de instalação.
Linhas sem promptA resposta do computador, copiada da VM do guia.
← etiquetaUma explicação do guia sobre aquela linha. Não aparece no terminal real.
… numa saídaTrecho encurtado (a saída real era mais longa).
<texto>Troque pelo seu valor. Ex.: pacman -Q <pacote> vira pacman -Q bash.
"ilustrativo"Exemplo que não pôde ser rodado na VM (um disco de verdade, um reboot, um pacote que não foi instalado). O texto sempre avisa.
Versão de referência: Arch Linux de outubro de 2026

O Arch não tem versões, então o guia diz quando foi conferido. A VM foi instalada à mão com a ISO 2026.06.01 e atualizada em outubro de 2026: kernel 7.2.10-arch1-1 (mais o linux-lts 6.18.57), Bash 5.3.20, pacman 7.1 (libalpm 16.0.1), GRUB em modo UEFI, sistema em português do Brasil (pt_BR.UTF-8), teclado br-abnt2, fuso America/Sao_Paulo, sem interface gráfica. Os números de versão no seu Arch serão outros (mais novos); os comandos e as ideias continuam os mesmos.

Vem do Debian, do Ubuntu ou do Fedora?

Muita coisa é igual (Bash, systemd, as ferramentas GNU), mas o dia a dia muda: no lugar de apt install você usa pacman -S, não há "atualizar a versão" do sistema, o instalador é um roteiro de comandos e muito pacote que nesses sistemas vem pronto (sudo, um editor, o man) é instalado à parte. Veja a tabela pacman × apt × dnf e a comparação Arch × Debian × Fedora.

Na Arch Wiki: a porta de entrada oficial é a página Arch Linux (em português); a instalação está no Installation guide (em português), e o que fazer depois, em General recommendations (em português). O pacman tem página própria: pacman (em português). A aula A Arch Wiki ensina a tirar o máximo dela.
