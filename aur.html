O que é o AUR

O AUR (Arch User Repository, "repositório dos usuários do Arch") é um site onde qualquer pessoa pode publicar receitas para montar pacotes do Arch. Ele não guarda programas prontos: guarda as instruções (o arquivo PKGBUILD) que o seu computador segue para baixar, compilar e empacotar o programa. É o motivo de "tem no AUR" ser a resposta para quase tudo no Arch, e também o motivo de você precisar ter cuidado.

Você vai aprender
  • A diferença entre os repositórios oficiais (pacotes prontos) e o AUR (receitas).
  • Ler a página de um pacote em aur.archlinux.org: votos, popularidade, comentários, "Last Updated", mantenedor, "desatualizado".
  • O que significam os sufixos -bin e -git.
  • Quando usar repositório oficial, AUR ou Flatpak.
  • Os riscos reais do AUR e por que ele "não é suportado".

Receita, não bolo

Pense numa padaria. Os repositórios oficiais (core e extra, veja pacman: o Básico) são a vitrine: o bolo já vem pronto, feito por gente da equipe do Arch (os Package Maintainers, que até 2023 se chamavam Trusted Users), embalado e com um selo de garantia (a assinatura digital, veja Chaves e Assinaturas). O pacman só busca e instala.

O AUR é um caderno de receitas que os clientes escrevem e compartilham. Você pega a receita, confere os ingredientes e assa o bolo na sua cozinha. Ninguém da equipe do Arch provou aquela receita antes.

Os números mostram por que o AUR é tão usado. Na VM do guia, em outubro de 2026, os repositórios oficiais tinham pouco mais de 15 mil pacotes:

$ pacman -Sl | wc -l
15330                     « um pacote por linha: core + extra
$ pacman -Sl core | wc -l
299
$ pacman -Sl extra | wc -l
15031

No mesmo dia, a página inicial do AUR mostrava 114.756 pacotes (14.058 deles órfãos, isto é, sem mantenedor). É muita coisa, mas lembre: cada um desses é uma receita escrita por alguém que você não conhece.

O pacman não sabe que o AUR existe

O AUR não é um repositório no sentido do pacman: ele não está no /etc/pacman.conf e não tem um banco de dados que o pacman entenda. Por isso, pedir um pacote do AUR ao pacman dá erro:

$ sudo pacman -S yay
[sudo] senha para ana:
erro: alvo não encontrado: yay     « "alvo" = o pacote que você pediu
$ echo $?
1

Não é que o yay não exista: ele só não está em core nem em extra. Para instalar coisas do AUR, você usa o makepkg (o jeito manual) ou um ajudante como o yay.

Cada pacote do AUR é um pequeno repositório git. Clonar o do yay-bin mostra tudo o que ele tem:

Só 110 KiB, e quase tudo é histórico do git. O programa em si não está aqui:

ArquivoO que é
PKGBUILDA receita: um script Bash com o nome, a versão, as dependências, de onde baixar o programa e como instalá-lo. É o arquivo que você precisa ler.
.SRCINFOUm resumo do PKGBUILD em texto simples, gerado com makepkg --printsrcinfo. O site do AUR e os ajudantes leem este, para não precisar executar o PKGBUILD.
.gitignoreDiz ao git para ignorar o que o makepkg cria (src/, pkg/, os downloads).
.git/O histórico: cada versão da receita é um commit. Com ele você vê o que mudou entre uma atualização e outra.

O que a receita do yay-bin faz, linha por linha, está na aula Compilar do AUR (makepkg).

Os sufixos: fonte, -bin e -git

O mesmo programa costuma ter várias receitas no AUR. O sufixo do nome diz o que a receita faz:

NomeO que a receita baixaCompila na sua máquina?Versão
paru (sem sufixo)O código-fonte de uma versão lançadaSim (precisa das makedepends, aqui o cargo do Rust)A última versão estável
paru-binO programa já compilado pelo autor (o binário do GitHub)Não, só empacotaA última estável, se o mantenedor atualizar
paru-gitO código do último commit do repositório do autorSimA de hoje (pode estar quebrada)

Uma busca mostra os três tipos convivendo. Repare no extra/pfetch-rs: um parente que está no repositório oficial.

$ yay -Ss pfetch
…                            « (resultados menos parecidos, cortados)
aur/pfetch-git r340.e18a095-1 (+15 0.00) [2305d10h]
    A pretty system information tool written in POSIX sh.
extra/pfetch-rs 3.0.2-1 (657.9 KiB 2.0 MiB)
    A rewrite of the pfetch system information tool in Rust
aur/pfetch 1.11.0-1 (+48 0.09) [128d17h]
    A pretty system information tool written in POSIX sh.

O (+48 0.09) é "48 votos, popularidade 0,09"; o [128d17h] é há quanto tempo a receita foi atualizada (128 dias e 17 horas). A versão do -git, r340.e18a095, é "commit número 340, identificador e18a095": ela é calculada na hora de compilar.

Compare o paru-bin com o paru no mesmo dia: o -bin estava parado em 2.1.0-1 e quebrado; o de fonte tinha ganhado um 2.1.0-2 (recompilado para o pacman novo) em dezembro de 2025.

Qual escolher?
Fonte (sem sufixo)O padrão. Compila contra as bibliotecas do seu sistema, então se ajusta quando elas mudam. Custa tempo de CPU (minutos, às vezes horas).
-binInstala rápido, ótimo em máquinas fracas e para programas enormes (navegadores, IDEs) ou fechados (que nem têm fonte). Depende do mantenedor acompanhar as mudanças do Arch: foi o que falhou no paru-bin.
-gitSó se você precisa de uma correção que ainda não saiu numa versão. Atualizar exige recompilar (os ajudantes têm a opção --devel).

AUR, repositório oficial ou Flatpak?

A ordem de preferência que a comunidade do Arch costuma seguir:

  1. Repositório oficial (pacman -Ss nome). Sempre a primeira opção: testado, assinado, atualizado junto com o resto do sistema.
  2. Se não tem, veja se é um aplicativo gráfico com versão oficial no Flathub: o Flatpak roda isolado (em "caixa de areia") e é mantido muitas vezes pelo próprio autor.
  3. Para o resto (ferramentas de terminal, drivers, fontes, temas, programas que precisam se integrar ao sistema): AUR, lendo a receita antes.
SituaçãoUse
Existe em extrasudo pacman -S. Não instale a versão do AUR "porque é mais nova".
Aplicativo gráfico fechado (Spotify, Discord, Zoom…)Flatpak (isolado) ou o -bin do AUR (integrado). Os dois funcionam; o Flatpak dá menos acesso ao sistema.
Ferramenta de terminal pequenaAUR (fonte ou -bin)
Driver, módulo do kernel, fonte, tema do sistemaAUR (o Flatpak não alcança essas partes)
Um programa seuEscreva o seu próprio PKGBUILD: Escrever um PKGBUILD
Nunca use o AUR para "trocar" pacotes do sistema

Receitas como pacman-git, systemd-git ou linux-git substituem peças centrais do Arch por versões em desenvolvimento. Uma receita errada aí deixa o sistema sem iniciar. Se você não sabe exatamente por que precisa disso, não precisa.

Os riscos do AUR

Qualquer pessoa pode criar uma conta e publicar uma receita. Ninguém da equipe do Arch revisa os PKGBUILDs antes de eles aparecerem. Um PKGBUILD é um script Bash que roda no seu computador com o seu usuário, e o pacote que ele gera é instalado como root. Então uma receita maliciosa pode fazer qualquer coisa.

Isso já aconteceu, e é bom conhecer os casos (o que está abaixo foi anunciado publicamente na lista de e-mails aur-general do Arch):

  • Julho de 2018: o pacote acroread (Adobe Reader) ficou órfão; uma conta o "adotou" e mudou a receita para baixar e rodar um script que coletava informações da máquina e criava um serviço do systemd para repetir isso. Outros pacotes órfãos foram alterados do mesmo jeito. A equipe do AUR removeu as mudanças e a conta.
  • Julho de 2025: foram publicados pacotes com nomes de navegadores "corrigidos" (como firefox-patch-bin e librewolf-fix-bin) que instalavam um programa de acesso remoto (um RAT). Eles ficaram no ar cerca de dois dias antes de serem removidos.

Repare no padrão: pacotes novos, com nomes que imitam programas conhecidos, e pacotes órfãos adotados por alguém desconhecido. Votos, idade da página e comentários ajudam muito a perceber isso. O que procurar dentro da receita está em AUR com Segurança.

"O AUR não é suportado"

A frase aparece em toda a documentação. Quer dizer: o Arch oferece o site e as ferramentas, mas não garante nada sobre as receitas. Se um pacote do AUR quebra, você reclama na página dele (comentários) e não no fórum do Arch ou no rastreador de bugs. O fórum, aliás, não dá suporte a ajudantes como yay e paru: quando algo der errado, tente repetir com makepkg puro antes de pedir ajuda.

A vida de um pacote no AUR

  • Órfão: o mantenedor desistiu; qualquer um pode adotar (e esse "qualquer um" é o risco).
  • Desatualizado (out-of-date): alguém marcou que saiu versão nova. É só um aviso; a receita antiga continua lá.
  • Removido: pacotes duplicados, abandonados ou quebrados podem ser apagados depois de um pedido (deletion request).
  • Promovido: pacotes muito usados podem ser adotados por um Package Maintainer e ir para o extra. Aí ele sai do AUR.

Quais pacotes do AUR eu tenho?

O pacman não sabe de onde veio cada pacote, mas sabe quais não estão em nenhum repositório configurado. São os "estrangeiros" (foreign), a letra m:

$ pacman -Qm
downgrade 12.0.4-1
paru-bin 2.1.0-1
yay-bin 13.0.1-1
yay-bin-debug 13.0.1-1      « um pacote extra que o makepkg criou (veja a aula do makepkg)
-Q
query: consulta os pacotes instalados.
m
foreign: só os que não existem em nenhum repositório do pacman.conf. Na prática, os do AUR e os que você instalou com pacman -U.

Guarde essa lista: são os pacotes que o pacman -Syu não atualiza. Atualizá-los é tarefa sua (ou do ajudante).

Missão: descubra quais pacotes da ana vieram de fora dos repositórios oficiais. Depois, veja com pacman -Qi yay-bin a ficha de um deles.

Quando não funciona

"erro: alvo não encontrado: yay" 
$ sudo pacman -S yay
erro: alvo não encontrado: yay

O que aconteceu: você pediu ao pacman um pacote que só existe no AUR.

Como confirmar: pacman -Ss '^yay' não acha nada; a página aur.archlinux.org/packages/yay existe.

Como resolver: instale pelo makepkg (o primeiro ajudante sempre é instalado assim) ou, se você já tem um ajudante, com yay -S yay.

yay -Si diz que o pacote não existe, mas a busca mostra 
$ yay -Si pfetch
erro: o pacote "pfetch" não foi encontrado
 -> exit status 1
$ yay -Si aur/pfetch
Repositório                   : aur
Nome                          : pfetch
Versão                        : 1.11.0-1
…

O que aconteceu: o yay consulta primeiro os repositórios oficiais, e lá o pacote pfetch-rs declara que fornece pfetch (pacman -Si pfetch-rs mostra Provê : pfetch). O nome "pfetch" ficou ambíguo. Pelo mesmo motivo, yay -S pfetch instalaria o pfetch-rs do extra, e não o do AUR.

Como resolver: diga a origem antes do nome: aur/pfetch (ou extra/pfetch-rs, se for esse que você quer).

O programa do AUR parou de abrir depois de uma atualização 
$ paru --version
paru: error while loading shared libraries: libalpm.so.15: cannot open shared object file: No such file or directory

O que aconteceu: o programa foi compilado contra uma biblioteca (libalpm.so.15) que o sistema atualizado não tem mais (agora é a .16).

Como resolver: recompile o pacote (a versão de fonte, ou a mesma receita de novo) ou espere o mantenedor do -bin. O passo a passo está em AUR com Segurança.

O pacote sumiu do AUR

O que aconteceu: foi removido (duplicado, abandonado) ou promovido para o extra.

Como confirmar: pacman -Ss nome; se apareceu no extra, reinstale de lá com sudo pacman -S nome. Se sumiu de vez, o seu pacote instalado continua funcionando, mas não recebe mais atualizações: procure uma alternativa.

Resumo

  • O AUR guarda receitas (PKGBUILD), não programas prontos; você compila na sua máquina.
  • Qualquer pessoa publica; ninguém revisa antes. Leia a página, os comentários e a receita.
  • Votes = total histórico; Popularity = uso recente; out-of-date e Last Updated mostram abandono.
  • Sem sufixo = compila da fonte; -bin = binário pronto do autor; -git = último commit.
  • Repositório oficial primeiro; Flatpak para apps gráficos; AUR para o resto.
  • pacman -Qm lista o que veio de fora; o pacman -Syu não atualiza esses pacotes.

Na Arch Wiki: a página Arch User Repository (em português: Arch User Repository (Português)) explica o AUR do começo ao fim, inclusive como votar, marcar desatualizado e pedir remoção. As regras para quem publica estão em AUR submission guidelines, e a comparação dos ajudantes, em AUR helpers. A API usada pelo yay está documentada em Aurweb RPC interface.
