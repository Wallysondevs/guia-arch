Cache e Órfãos

Com o tempo, o Arch acumula duas sobras: os pacotes baixados, que o pacman guarda depois de instalar, e os órfãos, dependências que ficaram para trás quando o programa que as usava foi removido. Nesta aula você aprende a medir e limpar as duas, sem apagar o que ainda pode salvar o seu sistema.

Você vai aprender
  • O que é o cache /var/cache/pacman/pkg, para que serve e quanto ocupa.
  • Limpar com paccache (-d, -r, -rk1, -ruk0) e com pacman -Sc/-Scc.
  • Automatizar com o paccache.timer.
  • Achar e remover órfãos com pacman -Qdt, e por que não remover no automático.

O cache de pacotes

Todo pacote que o pacman baixa fica guardado em /var/cache/pacman/pkg/, junto com a assinatura (.sig). Ele não apaga sozinho, nem as versões antigas depois de uma atualização. Isso tem dois lados:

  • A favor: se uma atualização der problema, a versão anterior está ali, pronta para voltar sem internet (veja Voltar um Pacote). Reinstalar um pacote também não precisa baixar de novo.
  • Contra: semana após semana, o cache cresce. Em um ano, passa fácil de vários GiB.

Quanto ocupa na VM do guia, que acabou de ser instalada (com sudo, porque algumas pastas lá dentro são protegidas):

$ sudo du -sh /var/cache/pacman/pkg
1,3G	/var/cache/pacman/pkg
$ ls /var/cache/pacman/pkg | head -4
aardvark-dns-2.1.0-3-x86_64.pkg.tar.zst
aardvark-dns-2.1.0-3-x86_64.pkg.tar.zst.sig          « a assinatura de cada pacote
abseil-cpp-20260817.0-2-x86_64.pkg.tar.zst
abseil-cpp-20260817.0-2-x86_64.pkg.tar.zst.sig
$ ls -l /var/cache/pacman/pkg | grep htop
-rw-r--r-- 1 root root    184319 16 ago 13:16 htop-3.5.3-1-x86_64.pkg.tar.zst
-rw-r--r-- 1 root root       119 16 ago 13:16 htop-3.5.3-1-x86_64.pkg.tar.zst.sig

Sem sudo, o du reclama de algumas pastas e mostra o total mesmo assim:

$ du -sh /var/cache/pacman/pkg
du: não foi possível ler diretório '/var/cache/pacman/pkg/download-veVDmJ': Permissão negada
du: não foi possível ler diretório '/var/cache/pacman/pkg/download-TUFm9E': Permissão negada
du: não foi possível ler diretório '/var/cache/pacman/pkg/download-ySVMmN': Permissão negada
1,3G	/var/cache/pacman/pkg

Essas pastas download-XXXXXX são temporárias: o pacman baixa os arquivos nelas, como o usuário sem poderes alpm (a opção DownloadUser), e depois move o pacote para o cache. Quando uma transação é cancelada ou interrompida, a pasta vazia fica para trás. Não ocupam espaço e podem ser apagadas quando nenhum pacman estiver rodando.

paccache: limpar com critério

O paccache vem no pacote pacman-contrib. A ideia dele: manter as últimas versões de cada pacote e apagar as mais antigas. Por padrão, mantém 3.

-d
dryrun: só mostra o que apagaria. Comece sempre por aqui.
-r
remove: apaga de verdade.
-k N
keep: quantas versões manter de cada pacote (padrão 3).
-u
uninstalled: olhar só os pacotes que não estão mais instalados.
-v
verbose: listar os arquivos.
-c pasta
Usar outro cache (o padrão é o do pacman.conf).

Na VM, recém-instalada, cada pacote tem uma versão só. O paccache não acha nada para apagar:

$ paccache -d
==> no candidate packages found for pruning           « nada a podar (a saída é em inglês)
$ echo $?
0
$ paccache -dk1
==> no candidate packages found for pruning

Um cache com versões antigas (exemplo controlado)

Para ver o paccache trabalhando, montamos um cache de teste em /tmp/a4/cache com quatro versões reais do htop (as três antigas baixadas do Arch Linux Archive, o arquivo histórico de pacotes do Arch) e dois pacotes que não estão instalados (fastfetch e yyjson). A opção -c aponta para ele:

#> ls /tmp/a4/cache
fastfetch-2.70.0-1-x86_64.pkg.tar.zst
fastfetch-2.70.0-1-x86_64.pkg.tar.zst.sig
htop-3.5.0-1-x86_64.pkg.tar.zst
htop-3.5.1-1-x86_64.pkg.tar.zst
htop-3.5.2-1-x86_64.pkg.tar.zst
htop-3.5.3-1-x86_64.pkg.tar.zst                       « a versão instalada
yyjson-0.13.0-1-x86_64.pkg.tar.zst
yyjson-0.13.0-1-x86_64.pkg.tar.zst.sig
#> paccache -d -c /tmp/a4/cache

==> finished dry run: 1 candidates (disk space saved: 170.06 KiB)    « mantendo 3, sobra 1 (o 3.5.0)
#> paccache -dvk1 -c /tmp/a4/cache
==> Candidate packages:
htop-3.5.0-1-x86_64.pkg.tar.zst
htop-3.5.1-1-x86_64.pkg.tar.zst
htop-3.5.2-1-x86_64.pkg.tar.zst

==> finished dry run: 3 candidates (disk space saved: 517.75 KiB)    « mantendo 1, saem 3
#> paccache -duk0 -c /tmp/a4/cache

==> finished dry run: 2 candidates (disk space saved: 831.13 KiB)    « desinstalados: fastfetch e yyjson

Agora de verdade, com -r:

#> paccache -rk1 -c /tmp/a4/cache

==> finished: 3 packages removed (disk space saved: 517.75 KiB)
#> paccache -ruk0 -c /tmp/a4/cache

==> finished: 2 packages removed (disk space saved: 831.13 KiB)
#> ls /tmp/a4/cache
htop-3.5.3-1-x86_64.pkg.tar.zst                       « sobrou só a versão em uso
#> paccache -rk1 -c /tmp/a4/cache
==> no candidate packages found for pruning

Repare que o .sig de cada pacote vai embora junto com ele. No cache do sistema, sem -c, rode com sudo: sudo paccache -r.

ComandoO que apagaQuando usar
paccache -rVersões além das 3 últimas de cada pacoteA limpeza normal, de rotina. Ainda dá para voltar até duas versões.
paccache -rk1Tudo menos a última versãoDisco apertado; você perde a volta rápida para a versão anterior.
paccache -ruk0Todas as versões de pacotes que você desinstalouDepois de remover programas grandes.
paccache -d…Nada (só mostra)Antes de qualquer um dos de cima.

pacman -Sc e -Scc

O próprio pacman também limpa, com menos controle. As duas formas perguntam antes (respondemos "não"):

$ sudo pacman -Sc
Pacotes a serem mantidos:
      Todos os pacotes instalados localmente           « mantém a versão de cada pacote instalado

Diretório de cache: /var/cache/pacman/pkg/
:: Deseja remover todos os outros pacotes do cache? [S/n] n

Diretório da base de dados: /var/lib/pacman/
:: Deseja remover repositórios não utilizados? [S/n] n   « catálogos de repositórios que você desligou
$ sudo pacman -Scc

Diretório de cache: /var/cache/pacman/pkg/
:: Deseja remover TODOS os arquivos do cache? [s/N] n    « repare: o padrão aqui é NÃO (N maiúsculo)

Diretório da base de dados: /var/lib/pacman/
:: Deseja remover repositórios não utilizados? [S/n] n
ComandoRemove do cacheParecido com
pacman -ScPacotes desinstalados e versões que não são as instaladaspaccache -rk1 + paccache -ruk0
pacman -SccTudopaccache -rk0
Cuidado com o -Scc

Sem o cache, voltar um pacote que quebrou depende da internet e do Arch Linux Archive. Por isso o pacman pergunta com [s/N]: só um s digitado confirma. Prefira o paccache -r no dia a dia; o -Scc serve para casos de disco cheio de verdade (e depois de confirmar que o sistema está funcionando).

Limpeza automática: paccache.timer

O pacman-contrib traz um timer do systemd que roda paccache -r uma vez por semana. Ele vem desligado:

$ systemctl status paccache.timer --no-pager
○ paccache.timer - Discard unused packages weekly
     Loaded: loaded (/usr/lib/systemd/system/paccache.timer; disabled; preset: disabled)
     Active: inactive (dead)                               « desligado
    Trigger: n/a
   Triggers: ● paccache.service
$ systemctl cat paccache.timer --no-pager
# /usr/lib/systemd/system/paccache.timer
[Unit]
Description=Discard unused packages weekly

[Timer]
OnCalendar=weekly                                         « toda semana
AccuracySec=1h
Persistent=true                                           « se o PC estava desligado, roda no próximo boot

[Install]
WantedBy=timers.target

O serviço roda /usr/bin/paccache -r $PACCACHE_ARGS, e a variável vem do arquivo /etc/conf.d/pacman-contrib:

# Pacman-Contrib arguments
#
# The PACCACHE_ARGS environment variable is used to provide flags
# and extra arguments to `paccache` when running paccache.service.
# See `man 8 paccache` or `paccache --help` for further information.

PACCACHE_ARGS=

Para ligar (e, se quiser, manter só 1 versão em vez de 3):

$ sudo systemctl enable --now paccache.timer
$ sudoedit /etc/conf.d/pacman-contrib          « troque para PACCACHE_ARGS='-k1'

Esses dois comandos são ilustrativos aqui: na VM do guia o timer fica como veio, desligado.

Pacotes órfãos

Um órfão é um pacote instalado como dependência que nenhum pacote instalado usa mais. Acontece quando você remove um programa com -R (sem o s), ou quando uma atualização deixa de precisar de uma biblioteca.

-Q
Consultar os instalados.
d
Só os instalados como dependência.
t
Só os que nenhum pacote exige.
$ pacman -Qdt
$ echo $?
1                                            « nenhum órfão na VM

Como sempre no pacman, "nada encontrado" é silêncio + código 1. Para ver como fica com um órfão, usamos a cópia do banco de dados da VM (sem tocar no sistema) e marcamos o htop como dependência, como em pacman Avançado:

#> pacman -D --asdeps htop
htop: motivo da instalação foi definido como "instalado como dependência"
#> pacman -Qdt
htop 3.5.3-1                                 « um órfão: dependência sem ninguém que a use
#> pacman -Qdtq
htop                                         « -q: só o nome, para usar em outro comando

Remover todos os órfãos

A receita clássica junta tudo numa linha:

pacman -Qdtq
Lista os órfãos, um nome por linha.
$( … )
Substituição de comando: o Bash roda o que está dentro e troca pelo resultado, e a linha vira pacman -Rns htop.
sudo pacman -Rns
Remove, com as dependências que sobrarem e sem .pacsave.
#> pacman -Rns $(pacman -Qdtq)
verificando dependências...

Pacotes (1) htop-3.5.3-1

Tamanho total removido:  0,41 MiB

:: Deseja remover estes pacotes? [S/n] n

No sistema de verdade, sem órfãos, a lista vem vazia e o pacman reclama que não recebeu nada:

$ sudo pacman -Rns $(pacman -Qdtq)
erro: nenhum alvo definido (use -h para obter ajuda)
$ echo $?
1

Não é problema: só quer dizer que não havia órfãos. Uma forma equivalente, que lê os nomes da entrada: pacman -Qdtq | sudo pacman -Rns -.

Por que não sair removendo

  • "Órfão" é sobre o pacman, não sobre você. Um pacote pode ter vindo como dependência e você usá-lo direto. Exemplo da VM: o jq veio como dependência do devtools. Se um dia o devtools sair, o jq vira órfão, mesmo que os seus scripts usem jq. Antes de remover, marque o que você usa: sudo pacman -D --asexplicit jq.
  • Dependências opcionais não contam. Com um t, um pacote que é opcional de outro não aparece. Com -Qdtt, aparecem também esses, que podem estar ativando um recurso que você usa (por isso o -Qdtt é ainda mais perigoso de remover no automático).
  • Leia a lista antes do S, como em qualquer remoção. Remover em cadeia pode levar mais do que você esperava.
  • Pacotes do AUR instalados por um ajudante: as dependências de compilação (makedepends) podem ter ficado como órfãs. Essas costumam ser seguras de remover (veja yay e paru).

Experimente

Missão 1: procure pacotes órfãos no sistema da ana. Não apareceu nada? Confira o código de saída com echo $?.

Missão 2: peça ao pacman para limpar o cache de pacotes desinstalados (a senha é ana). Leia as duas perguntas antes de responder.

Quando não funciona

"nenhum alvo definido" 
$ sudo pacman -Rns $(pacman -Qdtq)
erro: nenhum alvo definido (use -h para obter ajuda)

O que aconteceu: não há órfãos; o $( ) ficou vazio e o pacman recebeu só -Rns.

Como resolver: nada a fazer. Confirme com pacman -Qdt; echo $? (código 1 = sem órfãos).

"no candidate packages found for pruning"

O que aconteceu: não há versões além das que você pediu para manter (com -r, 3 de cada).

Como resolver: nada a fazer; se quer liberar mais, paccache -dk1 mostra quanto sairia mantendo uma só.

du: "Permissão negada" em download-…

O que aconteceu: as pastas temporárias de download pertencem ao usuário alpm.

Como resolver: use sudo du -sh /var/cache/pacman/pkg. As pastas vazias que sobram podem ser apagadas (com nenhum pacman rodando): sudo rmdir /var/cache/pacman/pkg/download-*.

Limpei o cache e agora preciso da versão antiga

O que aconteceu: uma atualização quebrou algo e o -Scc apagou a versão anterior.

Como resolver: o Arch Linux Archive guarda todas as versões; a ferramenta downgrade busca lá. Veja Voltar um Pacote.

Resumo

  • O cache /var/cache/pacman/pkg guarda os pacotes baixados e nunca encolhe sozinho; ele é a sua rede de segurança para voltar versões.
  • paccache -d primeiro; paccache -r mantém 3 versões; -rk1 mantém 1; -ruk0 limpa os desinstalados.
  • pacman -Sc limpa o que não está instalado; -Scc limpa tudo (padrão "não").
  • paccache.timer automatiza a limpeza semanal (vem desligado).
  • Órfãos: pacman -Qdt; remover com sudo pacman -Rns $(pacman -Qdtq), depois de ler a lista.
