Solução de Problemas

Todas as mensagens desta página aconteceram de verdade, na VM do guia ou durante a instalação registrada em log. Para cada uma: o que ela quer dizer, como confirmar e como resolver, com o link para a aula que explica o assunto. Procure a sua mensagem com Ctrl+F: copie um pedaço do erro (sem os números que mudam, como PIDs e datas).

O método, para qualquer erro
  1. Leia a mensagem inteira, principalmente a primeira linha de erro (as seguintes costumam ser consequência).
  2. Veja o código de saída (echo $?) e o log: journalctl -b -p err, journalctl -u SERVIÇO, /var/log/pacman.log.
  3. Pergunte "o que mudou?": uma atualização, um arquivo editado, um pacote do AUR.
  4. Procure nesta página, nas notícias do Arch e na Arch Wiki.
  5. Mude uma coisa por vez e confira de novo.

Instalação e ambiente live

"loadkeys: Unable to open file" 
#> loadkeys br-abnt3
loadkeys: Unable to open file: br-abnt3: No such file or directory
#> echo $?
1

Causa: nome de mapa de teclado errado. Confirme: localectl list-keymaps | grep br. Resolva: loadkeys br-abnt2. Aula: O Ambiente Live.

reflector: "Download timed out after 5 second(s)" 
[2026-10-16 15:02:03] WARNING: failed to rate http(s) download (https://archlinux.c3sl.ufpr.br/extra/os/x86_64/extra.db): Download timed out after 5 second(s).
[2026-10-16 15:02:09] WARNING: failed to rate http(s) download (https://mirrors.ic.unicamp.br/archlinux/extra/os/x86_64/extra.db): Download timed out after 5 second(s).

Causa: avisos (não erros) do reflector ao medir espelhos lentos ou fora do ar; ele segue com os outros. Resolva: nada, se a lista final ficou boa; senão, --download-timeout 15. Aula: Espelhos, pacstrap.

pacstrap: "target not found" 
#> pacstrap -K /mnt base linux networkmanger
…
error: target not found: networkmanger
==> ERROR: Failed to install packages to new root

Causa: nome de pacote errado (aqui, faltou um "a"). Nada foi instalado. Resolva: corrija o nome (pacman -Ss network) e repita. Aula: pacstrap.

pacstrap: "not enough free disk space" 
checking available disk space...
error: Partition / too full: 357700 blocks needed, 61200 blocks free
error: not enough free disk space
error: failed to commit transaction (not enough free disk space)

Causa: a raiz não foi montada em /mnt (o pacstrap escreveu na RAM do live) ou a partição é pequena. Confirme: findmnt /mnt. Resolva: monte a raiz e repita. Aula: Formatar e Montar.

pacstrap: "signature … is unknown trust" / "is corrupted" 
error: openssh: signature from "Fulano de Tal <fulano@archlinux.org>" is unknown trust

Causa: chaveiro da ISO antigo (ISO de meses atrás). Resolva: pacman -Sy archlinux-keyring no live e repita o pacstrap; ou baixe uma ISO nova. Aula: Chaves e Assinaturas.

fdisk: "Value out of range." 
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-62914526, default 62912511): +40G
Value out of range.

Causa: o tamanho pedido não cabe no espaço livre. Resolva: um tamanho menor, ou Enter para usar o resto. Nada é gravado antes do w. Aula: Particionar.

mkfs: "is mounted; will not make a filesystem here!" 
#> mkfs.ext4 /dev/loop3p3
mke2fs 1.47.4 (6-Mar-2025)
/dev/loop3p3 is mounted; will not make a filesystem here!

Causa: a partição está montada (proteção contra apagar um sistema em uso). Resolva: umount e confira se é mesmo a partição certa (lsblk -f). Aula: Formatar e Montar.

"umount: … target is busy" / "o alvo está ocupado" 
#> cd /mnt
#> umount /mnt
umount: /mnt: target is busy.

Causa: algum processo (o próprio shell, com cd lá dentro) usa a pasta. Resolva: cd / e repita; fuser -vm /mnt mostra quem usa. Aula: mount e fstab, Primeiro Boot.

"visudo: nenhum editor encontrado" 
#> visudo
visudo: nenhum editor encontrado (caminho do editor = /usr/bin/vi)

Causa: a base não traz editor, e o visudo procura o vi. Resolva: EDITOR=nano visudo (com o nano instalado). Aula: sudo, root e Usuários.

"WARNING: sd-vconsole: "/etc/vconsole.conf" not found" 
==> WARNING: sd-vconsole: "/etc/vconsole.conf" not found, will use default values

Causa: o mkinitcpio rodou antes de você criar o /etc/vconsole.conf (com KEYMAP=br-abnt2). É um aviso. Resolva: crie o arquivo e rode mkinitcpio -P. Aula: Configurar o Sistema.

Boot

"grub-install: erro: … não parece ser uma partição EFI" 
#> grub-install --target=x86_64-efi --efi-directory=/var/tmp/a8 --bootloader-id=TESTE --no-nvram
Instalando para a plataforma x86_64-efi.
grub-install: erro: /var/tmp/a8 não parece ser uma partição EFI.

Causa: o --efi-directory não é a ESP montada (FAT32). Confirme: findmnt /boot (ou /efi). Resolva: monte a ESP e aponte para ela. Aula: Bootloader, Recuperar o Boot.

Depois de instalar outro kernel, o sistema iniciou com ele 
$ uname -r
6.18.57-1-lts

Causa: com dois kernels, o GRUB põe como padrão o primeiro da sua ordenação (o LTS). Resolva: GRUB_TOP_LEVEL="/boot/vmlinuz-linux" em /etc/default/grub e grub-mkconfig -o /boot/grub/grub.cfg (o pacman não roda o grub-mkconfig sozinho). Aula: Kernels, Bootloader.

mkinitcpio: "ERROR: Hook '…' cannot be found" 
==> ERROR: Hook 'filesytems' cannot be found
…
==> WARNING: errors were encountered during the build. The image may not be complete.

Causa: nome errado em HOOKS=() do /etc/mkinitcpio.conf (aqui, "filesytems"), ou o pacote que fornece o hook (ex.: lvm2) não está instalado. Resolva: corrija e mkinitcpio -P antes de reiniciar. Aula: mkinitcpio, LVM.

"WARNING: Possibly missing firmware for module"

Causa: o mkinitcpio avisa de firmware para hardware que você provavelmente nem tem. Resolva: ignore, a não ser que aquele dispositivo não funcione. Aula: mkinitcpio.

"You are in emergency mode" no boot

Causa comum: uma linha do /etc/fstab aponta para um disco ou UUID que não existe (ou opção com erro de digitação). Confirme: journalctl -xb e procure "Dependency failed" ou o UUID. Resolva: com a senha do root, corrija o fstab (ou acrescente nofail em discos externos) e teste com mount -a. Aula: mount e fstab.

"não foi possível localizar UUID=…" no mount -a 
#> mount -a --fstab /tmp/a7/fstab-erro
mount: /mnt/a7: não foi possível localizar UUID=6a25becf-3d26-4913-b036-c34a83bc3999.

Causa: UUID errado ou de um disco ausente. Resolva: copie o UUID certo de blkid/lsblk -f. Teste o fstab sempre com mount -a antes de reiniciar. Aula: mount e fstab.

fsck.fat: "There are differences between boot sector and its backup." 
#> umount /boot && fsck.fat -a -w /dev/sda1; mount /boot; echo montado
fsck.fat 4.2 (2021-01-31)
There are differences between boot sector and its backup.
This is mostly harmless. Differences: (offset:original/backup)
  65:01/00

Causa: a ESP foi desmontada sem cuidado (desligamento forçado). "Mostly harmless". Resolva: fsck.fat (pacote dosfstools, que não vem na base) com a partição desmontada. Aula: Manutenção Periódica.

pacman e atualizações

"você não pode realizar esta operação a menos que seja root" 
$ pacman -S fastfetch
erro: você não pode realizar esta operação a menos que seja root.

Resolva: sudo pacman -S fastfetch. Consultas (-Q, -Ss, -Si) não precisam de root. Aula: pacman.

"alvo não encontrado" 
$ sudo pacman -S yay
erro: alvo não encontrado: yay

Causa: nome errado, lista desatualizada, ou o pacote é do AUR (o pacman só vê os repositórios oficiais). Resolva: pacman -Ss parte-do-nome; se for do AUR, veja O que é o AUR.

"não foi possível travar a base de dados" 
#> pacman -Syu
:: Sincronizando a base de dados de pacotes...
erro: falha ao sincronizar todas as bases de dados (não foi possível travar a base de dados)
#> pgrep -a pacman; ls -l /var/lib/pacman/db.lck
---------- 1 root root 0 16 out 12:40 /var/lib/pacman/db.lck
#> rm /var/lib/pacman/db.lck

Causa: outro pacman rodando, ou uma trava que sobrou de um pacman interrompido (na VM, um desligamento forçado). Confirme: pgrep -a pacman sem nada = trava velha. Resolva: só então apague /var/lib/pacman/db.lck. Nunca apague com outro pacman rodando. Aula: Atualizar.

"não foi possível satisfazer as dependências" ao remover 
$ sudo pacman -R jq
verificando dependências...
erro: falha ao preparar a transação (não foi possível satisfazer as dependências)
:: a remoção de jq quebra a dependência "jq" necessária por devtools

Causa: outro pacote precisa dele. Resolva: deixe-o, ou remova os dois (pacman -Rs jq devtools). Não use -Rdd. Aula: pacman.

"quebra a dependência … necessária por …" num downgrade 
erro: falha ao preparar a transação (não foi possível satisfazer as dependências)
:: a instalação de systemd-libs (261.3-1) quebra a dependência "systemd-libs=262" necessária por systemd

Causa: pacotes que andam juntos (mesma versão) precisam voltar juntos. Resolva: volte o conjunto inteiro (systemd e systemd-libs). Aula: Voltar um Pacote.

"nenhum alvo definido" ao limpar órfãos 
$ sudo pacman -Rns $(pacman -Qdtq)
erro: nenhum alvo definido (use -h para obter ajuda)

Causa: não há órfãos: a lista veio vazia. Não é problema. Aula: Cache e Órfãos.

"grupo de pacotes … não foi encontrado" 
$ pacman -Sg base-devel
erro: grupo de pacotes "base-devel" não foi encontrado

Causa: base-devel virou meta-pacote. Resolva: sudo pacman -S --needed base-devel. Aula: pacman Avançado.

pacman -F: "database file … does not exist" 
$ pacman -F hostname
atenção: database file for 'core' does not exist (use '-Fy' to download)

Resolva: sudo pacman -Fy uma vez. Aula: pacman Avançado.

"conflitos de arquivos" / "existe no sistema de arquivos"

Causa: um arquivo do pacote já existe e não pertence a nenhum pacote (instalado à mão, por pip, make install…). Confirme: pacman -Qo /caminho ("nenhum pacote"). Resolva: leia as notícias do Arch; se o arquivo é lixo seu, mova-o; --overwrite só com o caminho exato e sabendo o porquê. Aula: Erros de Atualização.

"Operation too slow" / "falha ao obter o arquivo" 
error: failed retrieving file 'linux-firmware-broadcom-20260916-1-any.pkg.tar.zst' from mirror.ufscar.br : Operation too slow. Less than 1 bytes/sec transferred the last 10 seconds

Causa: espelho lento ou fora do ar (o pacman tenta o próximo da lista). Resolva: se falhar no fim, atualize a lista com o reflector. Aula: Espelhos.

reflector: "error: no mirrors found" 
$ reflector --country Brasil --latest 5
error: no mirrors found

Causa: o país vai em inglês (Brazil) ou código (BR). Aula: Espelhos.

"error while loading shared libraries" depois de atualizar 
$ paru --version
paru: error while loading shared libraries: libalpm.so.15: cannot open shared object file: No such file or directory

Causa: um programa do AUR foi compilado contra uma biblioteca que a atualização trocou (aqui, a libalpm do pacman 16). Resolva: recompile/reinstale o pacote do AUR (para -bin, espere a versão nova ou use o makepkg do pacote sem -bin). Aula: yay e paru, Rolling Release.

checkupdates não mostra nada 
$ checkupdates
$ echo $?
2

Causa: código 2 = não há atualizações (0 = há; 1 = erro). Aula: Rolling Release.

Chaves e assinaturas

"a assinatura de … tem confiança desconhecida" 
erro: htop: a assinatura de "Christian Hesse <eworm@archlinux.org>" tem confiança desconhecida

Causa: o archlinux-keyring está velho (sistema muito tempo sem atualizar). Resolva: sudo pacman -Sy archlinux-keyring && sudo pacman -Su. Aula: Chaves e Assinaturas.

"faltando chave necessária no chaveiro" num pacman -U 
#> pacman -U htop-3.5.3-1-x86_64.pkg.tar.zst
carregando pacotes...
:: Importar a chave PGP 6D42BDD116E0068F? [S/n] n
erro: faltando chave necessária no chaveiro

Causa: você recusou importar a chave. Resolva: confira de quem é a chave e responda S, ou use pacman-key --recv-keys. Aula: Chaves.

AUR e makepkg

"Dependências faltando: … Não foi possível resolver todas as dependências." 
$ makepkg -s --noconfirm
==> Dependências faltando:
  -> fzf
==> ERRO: Não foi possível resolver todas as dependências.

Causa: a dependência não está nos repositórios configurados, ou o makepkg foi rodado sem -s. Resolva: makepkg -s instala as dos repositórios; se a dependência é do AUR, construa-a antes (ou use um ajudante). Aula: makepkg.

"FALHOU" na validação das somas 
==> Validando source arquivos com sha256sums...
    ola.in ... FALHOU
==> ERRO: Um ou mais arquivos não passaram na verificação de validade!

Causa: o arquivo baixado não é o que o PKGBUILD espera (atualização do autor ou adulteração). Resolva: num pacote seu, updpkgsums; num do AUR, não force: verifique e avise o mantenedor. Aula: PKGBUILD, AUR com Segurança.

"Executar makepkg como root não é permitido"

Resolva: rode como usuário comum; o makepkg -si pede o sudo só na hora de instalar. Aula: makepkg.

yay: "Evite executar o yay como root/sudo."

Resolva: yay -S pacote sem sudo. Aula: yay e paru.

sudo, usuários e permissões

A senha certa é recusada: "Sinto muito, tente novamente." 
Info: The account is locked due to 3 failed logins.
Info: (3 minutes left to unlock)
Password:

Causa: o pam_faillock: 3 senhas erradas em 15 minutos travam a conta por 10 (no sudo, sem aviso; no polkit, com a mensagem acima). Confirme: faillock --user ana como root. Resolva: espere ou faillock --user ana --reset. Aula: Segurança, Usuários e Grupos.

"… não está no arquivo sudoers." 
$ sudo pacman -Q bash
[sudo] senha para bruno:
bruno não está no arquivo sudoers.

Resolva: como root, usermod -aG wheel bruno, confira a linha %wheel ALL=(ALL:ALL) ALL descomentada (EDITOR=nano visudo), e faça logout/login. Aula: sudo, root e Usuários.

"Permissão negada" mesmo com sudo 
$ sudo echo teste > /etc/a1-teste.conf
bash: /etc/a1-teste.conf: Permissão negada

Causa: o > é feito pelo seu shell (sem root), não pelo sudo. Resolva: echo teste | sudo tee /etc/arquivo. Aula: sudo, root e Usuários.

"visudo … syntax error" 
#> visudo -c
/etc/sudoers:125:21: syntax error
%wheel ALL=(ALL:ALL ALL
                    ^~~

Resolva: corrija a linha indicada (aqui, falta o )). Sempre edite com visudo, que não salva arquivo quebrado. Aula: Configurar o Sistema.

"usermod: grupo 'x' não existe" 
$ sudo usermod -aG grupoinexistente teste-a6
usermod: grupo 'grupoinexistente' não existe
$ echo $?
6

Causa: o grupo é criado pelo pacote que o usa (docker, libvirt); instale-o antes. Aula: Usuários e Grupos.

"chmod: modo inválido" 
$ chmod 999 notas.txt
chmod: modo inválido: “999”

Causa: cada dígito vai de 0 a 7. Aula: Permissões.

Serviços, timers e logs

"Unit … not found" 
$ sudo systemctl start nginx-teste
Failed to start nginx-teste.service: Unit nginx-teste.service not found.
$ echo $?
5

Causa: nome errado ou pacote não instalado. Confirme: systemctl list-unit-files | grep parte. Aula: systemctl e Serviços.

"Access denied as the requested operation requires interactive authentication" 
$ systemctl start nginx
Failed to start nginx.service: Access denied as the requested operation requires interactive authentication. However, interactive authentication has not been enabled by the calling program.

Resolva: faltou o sudo. Aula: systemctl.

"Liguei, mas depois do reboot estava desligado"

Causa: start liga só agora; no Arch, nenhum serviço liga sozinho no boot. Resolva: sudo systemctl enable --now SERVIÇO. Aula: systemctl.

"Failed to parse calendar specification" 
$ systemd-analyze calendar 'segunda 08:00'
Failed to parse calendar specification 'segunda 08:00': Argumento inválido

Causa: os dias vão em inglês: Mon 08:00. Teste sempre com systemd-analyze calendar. Aula: Timers.

O timer do usuário não rodou à noite

Causa: sem lingering, o systemd do usuário só existe com sessão aberta. Resolva: sudo loginctl enable-linger ana. Aula: Timers, Servidor Caseiro.

journalctl: "-- No entries --" / "No journal boot entry found" 
$ journalctl -u nada
-- No entries --
$ journalctl -b -10
No journal boot entry found for the specified boot (-10).

Causa: nome de unit errado, ou o journal não guarda tantos boots. Aula: Logs.

Discos, montagem, Btrfs, LUKS e LVM

"é necessário ser superusuário para montar" 
$ mount /dev/loop0 /mnt/a7
mount: /mnt/a7: é necessário ser superusuário para montar.

Resolva: sudo mount …. Aula: mount e fstab.

"Unknown parameter" numa opção do fstab 
#> mount -a --fstab /tmp/a7/fstab-opcao
mount: /mnt/a7: fsconfig() falhou: ext4: Unknown parameter 'noatme'.

Causa: opção com erro de digitação (noatime). Aula: mount e fstab.

"wrong fs type, bad option, bad superblock" 
#> mount /dev/loop1p3 /mnt
mount: /mnt: wrong fs type, bad option, bad superblock on /dev/loop1p3, missing codepage or helper program, or other error.

Causa: partição sem sistema de arquivos (esqueceu o mkfs), partição errada, ou opção inválida. Confirme: lsblk -f. Aula: Formatar e Montar.

fdisk: "Permissão negada" 
$ fdisk -l
fdisk: não foi possível abrir /dev/sda: Permissão negada

Resolva: sudo fdisk -l, ou use lsblk, que não precisa de root. Aula: lsblk, df, du.

Btrfs: "No space left on device" com espaço sobrando no df 
#> btrfs balance start -dusage=50 /var/tmp/a8/m
Done, had to relocate 1 out of 3 chunks

Causa: blocos de dados meio vazios ocupando o espaço de metadados (ou snapshots antigos). Resolva: btrfs filesystem usage, apague snapshots velhos, balance com filtro. Aula: Btrfs, Snapshots.

snapper: "Sem permissões." / "A configuração "root" não existe." 
$ snapper list
A configuração "root" não existe. Provavelmente, o snapper não está configurado.

Resolva: sudo snapper -c root create-config / (raiz em Btrfs) e use sudo. Aula: Snapshots (snapper).

LUKS: "Nenhuma chave disponível com esta senha." 
#> printf '%s' 'senha-errada' | cryptsetup open /dev/loop1 a8cripto -
Nenhuma chave disponível com esta senha.
#> echo $?
2

Causa: senha errada (no boot, confira o teclado: o initramfs precisa do hook sd-vconsole/keymap para o ABNT2). Aula: LUKS.

LVM: "Insufficient free space" 
#> lvextend -L +5G vg_a8/dados
  Insufficient free space: 1280 extents needed, but only 105 available

Resolva: vgs mostra o espaço livre do grupo; adicione um disco (vgextend) ou peça menos. Aula: LVM.

mkswap: "permissões inseguras" / swapon: "parece ter buracos" 
#> truncate -s 256M /var/tmp/a7/ruim
#> mkswap /var/tmp/a7/ruim
mkswap: /var/tmp/a7/ruim: permissões inseguras 0644, corrija com: chmod 0600 /var/tmp/a7/ruim

Causa: arquivo de swap criado com truncate (esparso) e permissão aberta. Resolva: crie com mkswap --file -s 4G /swapfile (ou dd) e chmod 600. Aula: Swap e zram.

Rede

"Temporary failure in name resolution" / "Nome ou serviço desconhecido" 
$ ping -c 1 nao-existe.invalid
ping: nao-existe.invalid: Nome ou serviço desconhecido

Causa: nome inexistente, ou sem DNS/sem rede. Confirme: ping -c 3 1.1.1.1 (se o IP responde e o nome não, é DNS). Aula: NetworkManager.

Depois da instalação, nada de rede

Causa: o NetworkManager (ou outro gerenciador) não foi instalado no pacstrap, ou não foi habilitado. Resolva: do live, arch-chroot, pacman -S networkmanager, systemctl enable NetworkManager. Aula: Primeiro Boot e Rede, Resgate com chroot.

"Address already in use" 
$ python -m http.server 8080
Traceback (most recent call last):
…
OSError: [Errno 98] Address already in use

Causa: outra coisa já escuta na porta. Confirme: sudo ss -tlnp | grep :8080. Aula: Seu Próprio Repositório, Servidor Web.

Servidores, containers e VMs

nginx: "bind() to 0.0.0.0:80 failed (98: Address already in use)"

Causa: outro servidor (ou um nginx rodado à mão) já usa a porta 80. Resolva: sudo ss -tlnp | grep ':80 ', pare o outro, use só systemctl. Aula: Servidor Web.

nginx -t: "[emerg] invalid parameter" 
$ sudo nginx -t
2026/10/16 13:21:48 [emerg] 2123#2123: invalid parameter "server_name" in /etc/nginx/sites-enabled/meusite.conf:3
nginx: configuration file /etc/nginx/nginx.conf test failed

Causa: faltou o ; na linha anterior à indicada. Aula: Servidor Web.

nginx 403 com "(13: Permission denied)" no journal

Causa: o usuário http não lê o arquivo ou não entra na pasta (sites em /home, que no Arch é 700). Resolva: use /srv/http, chmod 644/755. Aula: Servidor Web.

Podman: "short-name … did not resolve to an alias" 
$ podman pull meuapp
Error: short-name "meuapp" did not resolve to an alias and no containers-registries.conf(5) was found

Resolva: use o nome completo (docker.io/usuario/meuapp). Aula: Docker e Podman.

Podman: "Listen failed for HOST TCP port */80: Permission denied"

Causa: sem root, portas abaixo de 1024 são proibidas. Resolva: -p 8080:80. Aula: Docker e Podman.

Podman: "executable file `httpd` not found in $PATH" / container some do ps 
$ podman logs casa-web
httpd: applet not found

Causa: o comando não existe naquela imagem. Confirme: podman ps -a e podman logs NOME. Aula: Servidor Caseiro.

KVM: "could not insert 'kvm_intel': Operation not supported" 
#> modprobe kvm_intel
modprobe: ERROR: could not insert 'kvm_intel': Operation not supported
#> dmesg | grep kvm_intel
[ 1474.053519] kvm_intel: VMX not supported by CPU 1

Causa: virtualização desligada no firmware, ou o Arch é ele mesmo uma VM sem virtualização aninhada. Aula: Máquinas Virtuais.

Flatpak: "Nenhuma ref de remoto localizada para “flathub”" 
$ flatpak install --user flathub org.gnome.Calculator
Procurando por correspondências…
erro: Nenhuma ref de remoto localizada para “flathub”

Causa: o Flatpak do Arch vem sem o Flathub (e o --user tem a sua própria lista de remotos). Resolva: flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo (com --user, se for o caso). Aula: Flatpak.

Não achou o seu erro?

  • Procure a mensagem exata, entre aspas, na Arch Wiki e nos fóruns.
  • Veja as notícias do Arch: muitos "erros" de atualização são mudanças anunciadas.
  • Problemas de atualização: Erros de Atualização. Sistema que não liga: Recuperar o Boot e Resgate com chroot. Tela congelada: Quando o Sistema Trava.
