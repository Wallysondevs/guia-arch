Arch: particionar o disco

Antes de instalar, o disco precisa ser dividido em partições: uma para o carregador de boot, uma para a memória de troca (swap) e uma para o sistema. Nesta aula você entende para que serve cada uma e faz a divisão com o fdisk, exatamente como foi feito na VM do guia. É o passo mais perigoso da instalação: leia tudo antes de digitar.

Você vai aprender
  • O que são disco, partição e tabela de partições (GPT × MBR).
  • Para que servem a partição EFI, a swap e a raiz, e se vale separar a /home.
  • Identificar o disco certo com lsblk e fdisk -l.
  • Criar as três partições do guia no fdisk, com os comandos g n t p w e os tipos 1 (EFI) e 19 (swap).
  • Reconhecer e evitar os erros comuns (disco errado, MBR, tipo esquecido).
Particionar apaga o disco

Criar uma tabela de partições nova faz o sistema "esquecer" tudo o que havia no disco: documentos, fotos, Windows, outro Linux. Não há lixeira nem "desfazer" depois do w. Antes de continuar: backup feito (veja Baixar e Verificar a ISO), disco certo identificado (seção abaixo) e, se é a sua primeira vez, de preferência numa máquina virtual. Este guia instala num disco inteiro e vazio; dual boot com o Windows é outro procedimento.

Os conceitos

Disco e partição

Pense no disco como um terreno e nas partições como os lotes cercados dentro dele. Cada partição funciona como um "disco" separado: tem o seu tamanho, o seu sistema de arquivos e o seu uso. No Linux, cada disco e cada partição aparece como um arquivo em /dev:

Tipo de discoNome do discoPartições
SATA/SAS (HD, SSD SATA, pendrive, e o disco da VM do guia)/dev/sda, /dev/sdb…/dev/sda1, /dev/sda2…
SSD NVMe (os SSDs "M.2" rápidos)/dev/nvme0n1/dev/nvme0n1p1, /dev/nvme0n1p2… (com p)
Disco virtual de VM KVM/QEMU (virtio)/dev/vda/dev/vda1…
Cartão SD / eMMC/dev/mmcblk0/dev/mmcblk0p1…

Neste guia o disco é /dev/sda. No seu computador pode ser outro: troque o nome em todos os comandos.

Tabela de partições: GPT × MBR

A tabela de partições é o "mapa do terreno", gravado no começo do disco, que diz onde começa e termina cada partição. Há dois formatos:

As partições de que o Arch precisa

Partição EFI (ESP)
A EFI System Partition: uma partição pequena, formatada em FAT32, onde o firmware UEFI procura o carregador de boot. Neste guia ela será montada em /boot e guarda também o kernel e o initramfs (cada kernel instalado ocupa dezenas de MB ali). A Wiki recomenda 1 GiB, com folga para mais de um kernel.
Swap
A "memória de troca": espaço no disco para onde o sistema empurra dados quando a RAM enche, e onde guarda a memória ao hibernar. É opcional.
Raiz (/)
A partição do sistema: programas, configurações e, neste guia, também a pasta pessoal (/home). Fica com o resto do disco.

O guia criou uma swap de 4 GiB, o mesmo tamanho da RAM da VM, que dá para hibernar. Se você não pretende hibernar, pode pular a swap e usar zram depois (veja Swap e zram): é só não criar a partição 2.

Separar a /home?

Uma partição só para a /home (as pastas pessoais) permite reinstalar o sistema sem tocar nos seus arquivos. O preço é ter que adivinhar agora quanto espaço cada uma vai precisar: se a raiz encher, sobra espaço na /home e vice-versa. Para quem está começando, uma raiz só é mais simples (o guia fez assim) e o backup é o que protege os seus arquivos de verdade. Com Btrfs, dá para ter os dois: subvolumes separados dentro de uma partição só.

Liste os discos com o lsblk (list block devices). Esta é a saída real, no live da VM, antes de particionar:

Particionar com o fdisk

O fdisk é interativo: você o abre num disco e ele pergunta, uma coisa de cada vez, o que fazer. Cada comando é uma letra seguida de Enter. E o mais importante: nada é gravado até você digitar w. Até lá, tudo fica só na memória, e q sai sem mudar nada.

Passo a passo

  1. Abrir e criar a tabela GPT (g). Ao abrir um disco vazio, o fdisk avisa Device does not contain a recognized partition table ("o dispositivo não contém uma tabela de partições reconhecida") e, por costume antigo, já cria na memória uma tabela MBR (DOS disklabel). Não se assuste: o g troca por uma GPT (Created a new GPT disklabel). O GUID é um número de identificação único do disco, diferente a cada vez. Num disco usado, o g também é o primeiro passo: ele descarta (na memória) todas as partições antigas.
  2. Partição 1 (n). Três perguntas:
    • Partition number (1-128, default 1): o número. Enter aceita o 1.
    • First sector (2048-…, default 2048): onde começa. Enter. O padrão 2048 (1 MiB do início) deixa a partição "alinhada", o que é melhor para SSDs; o comecinho do disco guarda a própria tabela GPT.
    • Last sector, +/-sectors or +/-size{K,M,G,T,P}: onde termina. Em vez de calcular setores, digite o tamanho com um + na frente: +1G = 1 GiB a partir do começo.
    O fdisk responde que criou a partição 1, of type 'Linux filesystem' ("do tipo sistema de arquivos Linux"), de 1 GiB. Toda partição nasce com esse tipo; o próximo passo corrige.
  3. Tipo da partição 1 (t). Como só há uma partição, o fdisk já a escolhe (Selected partition 1). Na pergunta Partition type or alias ("tipo ou apelido da partição"), digite 1, o código de EFI System. Resposta: Changed type … to 'EFI System'.
  4. Partição 2 (n). Enter, Enter e +4G. Repare que o primeiro setor sugerido agora é 2099200: logo depois do fim da partição 1.
  5. Tipo da partição 2 (t). Agora há duas partições, então ele pergunta qual (Partition number (1,2, default 2)): 2 (ou Enter, que já é o 2). Depois o código 19, Linux swap.
  6. Partição 3 (n). Três Enter: número 3, começa logo depois da swap e, no último setor, o padrão é o fim do disco. Resultado: 25 GiB. O tipo padrão, Linux filesystem, já é o certo para a raiz.
  7. Conferir (p). Leia a tabela com calma (veja a seguir). É a última chance de mudar algo.
  8. Gravar (w). The partition table has been altered ("a tabela de partições foi alterada"); Calling ioctl() to re-read partition table (o fdisk pede ao kernel que releia a tabela); Syncing disks (garante que tudo foi gravado). O fdisk sai e o prompt volta.
Tela estreita? A pergunta do último setor "anda"

A pergunta Last sector, +/-sectors or +/-size{K,M,G,T,P} (…) é longa. Num terminal estreito, o fdisk rola a linha para a esquerda enquanto você digita e ela aparece cortada, começando com <size{K,M,G,T,P} ou parecido (vimos isso ao repetir a sessão na VM). É só aparência: digite o tamanho normalmente.

Sem digitar: as respostas num printf

Na VM, a sessão acima foi feita sem interação, mandando todas as respostas de uma vez para o fdisk. Fica registrado aqui para você entender o log, não como recomendação: digitando, você vê cada pergunta e pode corrigir.

#> printf 'g\nn\n\n\n+1G\nt\n1\nn\n\n\n+4G\nt\n2\n19\nn\n\n\n\np\nw\n' | fdisk /dev/sda

Cada \n é um Enter; dois \n seguidos são um Enter "vazio" (aceitar o padrão). O | (pipe) entrega esse texto ao fdisk como se fosse o teclado. Para scripts, a ferramenta própria é o sfdisk (veja a tabela abaixo).

Se o disco já foi usado

Ao criar uma partição por cima de uma antiga, o fdisk pode encontrar restos do sistema de arquivos anterior (a "assinatura") e perguntar se deve apagá-los. Saída real, repetindo o particionamento num disco-imagem da VM que já tinha sido formatado:

Created a new partition 1 of type 'Linux filesystem' and of size 1 GiB.
Partition #1 contains a vfat signature.

Do you want to remove the signature? [Y]es/[N]o: Y

The signature will be removed by a write command.

"A partição 1 contém uma assinatura vfat. Quer remover a assinatura?" Responda Y (yes): numa instalação limpa, você quer começar do zero. No p, o fdisk lembra: Filesystem/RAID signature on partition 1 will be wiped. ("a assinatura será apagada"), o que acontece no w.

Outras formas de particionar

cfdisk: o fdisk com menus

O cfdisk (do mesmo pacote util-linux) mostra o disco numa tela de texto com menus, navegada pelas setas. Para iniciantes, costuma ser mais fácil de visualizar. O roteiro abaixo é ilustrativo (a VM foi particionada com o fdisk):

  1. cfdisk /dev/sda. Num disco vazio, ele pergunta o tipo de tabela (Select label type): escolha gpt.
  2. Com Free space selecionado, escolha [ New ] embaixo, digite 1G e Enter.
  3. Com a nova partição selecionada, [ Type ] → EFI System.
  4. Desça para o Free space e repita: [ New ] 4G, [ Type ] → Linux swap.
  5. Free space de novo, [ New ] e Enter no tamanho sugerido (o resto). O tipo já é Linux filesystem.
  6. [ Write ], digite yes por extenso para confirmar e depois [ Quit ].

Quando não funciona

O erro que não tem conserto: o disco errado

Tudo o que existe abaixo tem solução, menos isso. Num computador com dois discos (um SSD com o Windows e um HD de arquivos, por exemplo), fdisk /dev/sdb em vez de /dev/sda apaga o disco errado inteiro no w. Antes de abrir o fdisk: confira o tamanho e o modelo no fdisk -l; se puder, desconecte fisicamente os discos que não serão usados (e os HDs externos). Dentro do fdisk, antes do w, leia a primeira linha do p: Disk /dev/… e o tamanho são os que você espera?

"Disklabel type: dos" no p (MBR em vez de GPT)

O que aconteceu: você esqueceu o g (ou usou o o). O fdisk criou uma tabela MBR, a que ele cria sozinho num disco vazio. Os sinais, conferidos na VM: Disklabel type: dos, a pergunta extra Partition type: p primary, e extended ao criar partição, uma coluna Id e o tipo 83 Linux em vez de Linux filesystem.

Como resolver: se ainda não gravou, q e comece de novo com g. Se já gravou, abra o fdisk de novo e faça tudo a partir do g (o disco ainda está vazio, então não se perde nada).

Esqueceu o tipo EFI (a partição 1 ficou "Linux filesystem")

O que aconteceu: faltou o t → 1. Muitos firmwares UEFI só procuram o carregador numa partição marcada como EFI System; o grub-install pode funcionar e o computador, mesmo assim, não iniciar.

Como confirmar: fdisk -l /dev/sda mostra Linux filesystem na linha do sda1.

Como resolver: não precisa refazer nada: fdisk /dev/sda, t, 1 (a partição), 1 (o tipo), w. Mudar o tipo não apaga dados.

"Value out of range." e perguntas que se repetem 
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-62914526, default 62912511): +40G
Value out of range.
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-62914526, default 62912511):

O que aconteceu: (saída real, num disco-imagem de 30 GiB na VM) a partição não cabe no espaço livre ("valor fora do intervalo"). Se você digitar algo que o fdisk não entende, como 1 G com espaço, ele simplesmente repete a pergunta, sem mensagem.

Como resolver: digite o tamanho junto, com + e a unidade em maiúscula: +1G, +512M. Sem o +, o número é lido como uma posição no disco, não como tamanho.

Partição EFI pequena demais

O que aconteceu: tutoriais antigos usam 100 ou 300 MiB para a partição EFI. Funciona no começo, mas, montada em /boot como neste guia, ela guarda os kernels e os initramfs; com um segundo kernel (por exemplo o linux-lts), o espaço acaba e a atualização falha.

Como resolver: use 1 GiB desde o começo. Aumentar depois é trabalhoso (a partição seguinte está colada nela).

Errou alguma coisa antes do w

Como resolver: q sai sem gravar nada; abra de novo. Ou, dentro do fdisk, d apaga uma partição (na memória) e você a cria de novo.

4. Você criou as partições no fdisk, mas percebeu que escolheu o disco errado. Ainda não digitou w. O que fazer?

5. Num notebook com SSD NVMe, como se chama a primeira partição do disco?

Resumo

  • UEFI → tabela GPT; o guia usa EFI 1 GiB + swap 4 GiB + raiz com o resto.
  • Identifique o disco pelo tamanho e modelo (lsblk, fdisk -l) antes de tudo.
  • No fdisk: g, depois n + t para cada partição (tipos 1 e 19), p para conferir e w para gravar.
  • Até o w, nada muda no disco; q desiste.
  • Disklabel type: gpt e EFI System na partição 1 são as duas coisas a conferir no p.

As partições existem, mas ainda estão vazias, sem sistema de arquivos. Próximo passo: Formatar e Montar.
