Arch LVM

Partições comuns têm tamanho fixo: se a raiz encher e a home sobrar, mudar isso é trabalhoso e arriscado. O LVM (Logical Volume Manager, gerenciador de volumes lógicos) junta discos num "reservatório" de espaço e tira dele "partições" virtuais que você cresce com um comando, com o sistema ligado. Ele também é a forma clássica de ter várias partições dentro de um único volume criptografado.

Você vai aprender
  • O que são PV, VG, LV e extents.
  • Criar tudo com pvcreate, vgcreate e lvcreate, e ler pvs, vgs e lvs.
  • Aumentar um volume e o sistema de arquivos juntos com lvextend -r.
  • Snapshots LVM e como voltar com lvconvert --merge.
  • LVM on LUKS e o hook lvm2 do mkinitcpio.

As três camadas

SiglaNomeO que éComparação
PVPhysical Volume (volume físico)Um disco ou partição preparado para o LVMCada conta bancária que você tem
VGVolume Group (grupo de volumes)O reservatório: a soma do espaço de um ou mais PVsTodo o dinheiro, somado
LVLogical Volume (volume lógico)Um pedaço do VG, usado como partição (formata e monta)Os envelopes: aluguel, mercado, viagem

O espaço do VG é dividido em blocos iguais, os extents (por padrão de 4 MiB). Um LV é só uma lista de extents, que podem estar em qualquer PV. Por isso dá para crescer um LV usando espaço de outro disco.

/dev/loop3 (PV, 1 GiB) ─┐
                        ├─ vg_a8 (VG, ~2 GiB) ─┬─ dados  (LV) → ext4 em /mnt/a8
/dev/loop4 (PV, 1 GiB) ─┘                       └─ backup (LV)

O laboratório: dois discos de mentira

Dois arquivos-imagem de 1 GiB, cada um num dispositivo de loop (veja Btrfs para o truncate e o losetup). Os comandos do LVM vêm no pacote lvm2.

#> truncate -s 1G /var/tmp/a8/lvm1.img /var/tmp/a8/lvm2.img
#> losetup -f --show /var/tmp/a8/lvm1.img
/dev/loop3
#> losetup -f --show /var/tmp/a8/lvm2.img
/dev/loop4

1. Volumes físicos: pvcreate

pvcreate
Grava no começo de cada dispositivo um rótulo LVM (physical volume create).
/dev/loop3 /dev/loop4
Um ou mais dispositivos. Num computador real, partições como /dev/sda3.
#> pvcreate /dev/loop3 /dev/loop4
  Physical volume "/dev/loop3" successfully created.
  Physical volume "/dev/loop4" successfully created.
#> echo $?
0
#> pvs
  PV         VG Fmt  Attr PSize PFree
  /dev/loop3    lvm2 ---  1,00g 1,00g        « ainda sem VG
  /dev/loop4    lvm2 ---  1,00g 1,00g

As mensagens do LVM ficam em inglês, recuadas com dois espaços. Os números usam a vírgula do pt_BR. pvs é o resumo dos PVs: Fmt lvm2 é o formato, PSize o tamanho e PFree o que está livre.

2. O grupo: vgcreate

vgcreate
Cria um grupo de volumes.
vg_a8
O nome do grupo (vira /dev/vg_a8/).
/dev/loop3 /dev/loop4
Os PVs que entram no grupo.
#> vgcreate vg_a8 /dev/loop3 /dev/loop4
  Volume group "vg_a8" successfully created
#> vgs
  VG    #PV #LV #SN Attr    VSize VFree
  vg_a8   2   0   0 wz--n-- 1,99g 1,99g

#PV discos, #LV volumes lógicos, #SN snapshots. VSize é 1,99 GiB e não 2: cada PV guarda metadados no começo. Em Attr, o w é gravável (writeable), o z é redimensionável (resizable) e o n é a política de alocação normal.

3. Os volumes lógicos: lvcreate

lvcreate
Cria um volume lógico.
-L 600M
Tamanho fixo (M, G…). Ou -l (L minúsculo) em extents ou porcentagem: -l 50%FREE, -l 100%FREE.
-n dados
O nome do LV.
vg_a8
De qual grupo tirar o espaço.
#> lvcreate -L 600M -n dados vg_a8
  Logical volume "dados" created.
#> lvcreate -l 50%FREE -n backup vg_a8
  Logical volume "backup" created.
#> lvs
  LV     VG    Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  backup vg_a8 -wi-a----- 720,00m
  dados  vg_a8 -wi-a----- 600,00m
#> ls -l /dev/vg_a8/
total 0
lrwxrwxrwx 1 root root 7 16 out 13:30 backup -> ../dm-1
lrwxrwxrwx 1 root root 7 16 out 13:30 dados -> ../dm-0
#> lsblk /dev/loop3 /dev/loop4
NAME           MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
loop3            7:3    0   1G  0 loop
└─vg_a8-dados  253:0    0 600M  0 lvm
loop4            7:4    0   1G  0 loop
└─vg_a8-backup 253:1    0 720M  0 lvm

O 50%FREE pegou metade do que sobrava (1,99 GiB − 600 MiB ≈ 1,4 GiB → 720 MiB). Cada LV tem dois nomes que apontam para o mesmo lugar: /dev/vg_a8/dados e /dev/mapper/vg_a8-dados. O lsblk mostra em qual PV cada LV ficou.

Posição do Attr (-wi-a-----)Significado
1ª: -Tipo: - normal, o origem de snapshot, s snapshot
2ª: wGravável (r = só leitura)
3ª: iAlocação "herdada" do VG (inherit)
5ª: aAtivo (pode ser usado)
6ª: oAberto (montado ou em uso)

Agora o LV é como qualquer partição:

#> mkfs.ext4 -q -L dados /dev/vg_a8/dados
#> mount --mkdir /dev/vg_a8/dados /mnt/a8
#> echo "planilha de gastos" > /mnt/a8/gastos.txt
#> df -h /mnt/a8
Sist. Arq.               Tam. Usado Disp. Uso% Montado em
/dev/mapper/vg_a8-dados  574M  176K  532M   1% /mnt/a8

Crescer com o sistema ligado: lvextend -r

O grande trunfo do LVM. Repare no espaço livre de cada PV antes:

#> pvs
  PV         VG    Fmt  Attr PSize    PFree
  /dev/loop3 vg_a8 lvm2 a--  1020,00m 420,00m
  /dev/loop4 vg_a8 lvm2 a--  1020,00m 300,00m
lvextend
Aumenta um LV.
-r
--resizefs: aumenta também o sistema de arquivos de dentro, na mesma hora. Sem isso, o LV cresce mas o ext4 continua do tamanho antigo.
-L +300M
Mais 300 MiB (com +). Sem o +, é o tamanho final. -l +100%FREE usa tudo o que sobrou.
vg_a8/dados
Qual LV (grupo/volume).
#> lvextend -r -L +300M vg_a8/dados
  File system ext4 found on vg_a8/dados mounted at /mnt/a8.
  Size of logical volume vg_a8/dados changed from 600,00 MiB (150 extents) to 900,00 MiB (225 extents).
  Extending file system ext4 to 900,00 MiB (943718400 bytes) on vg_a8/dados...
resize2fs /dev/vg_a8/dados
resize2fs 1.47.4 (6-Mar-2025)
Sistema de ficheiros em /dev/vg_a8/dados está montado em /mnt/a8; requerido redimensionamento em linha
old_desc_blocks = 1, new_desc_blocks = 1
O sistema de ficheiros em /dev/vg_a8/dados tem agora 230400 (4k) blocos.

resize2fs done
  Extended file system ext4 on vg_a8/dados.
  Logical volume vg_a8/dados successfully resized.
#> echo $?
0
#> df -h /mnt/a8
Sist. Arq.               Tam. Usado Disp. Uso% Montado em
/dev/mapper/vg_a8-dados  868M  176K  815M   1% /mnt/a8          « cresceu montado
#> pvs
  PV         VG    Fmt  Attr PSize    PFree
  /dev/loop3 vg_a8 lvm2 a--  1020,00m 120,00m      « os 300 MiB saíram daqui
  /dev/loop4 vg_a8 lvm2 a--  1020,00m 300,00m

O LVM primeiro aumentou o LV (de 150 para 225 extents de 4 MiB) e depois chamou o resize2fs, o programa do ext4. As mensagens do resize2fs saem em português de Portugal ("sistema de ficheiros", "em linha" = com o sistema montado), porque a tradução do e2fsprogs é essa. Crescer um ext4 ou Btrfs montado é seguro. Diminuir (lvreduce -r) é mais delicado: o ext4 só diminui desmontado (na raiz, só pelo pendrive), o XFS não diminui nunca, e um backup antes é obrigatório.

Snapshots LVM

O LVM também tira "fotos", mas de um jeito diferente do Btrfs: o snapshot é um LV à parte com um tamanho que você escolhe. Ele guarda a versão antiga de cada bloco que muda no original. Primeiro, liberamos espaço removendo o LV backup:

lvcreate -s
--snapshot: cria um snapshot.
-L 200M
Espaço para guardar as mudanças. Se encher, o snapshot fica inválido.
-n dados-antes
O nome do snapshot.
vg_a8/dados
A origem.
#> lvremove -y vg_a8/backup
  Logical volume "backup" successfully removed.
#> lvcreate -s -L 200M -n dados-antes vg_a8/dados
  Logical volume "dados-antes" created.
#> lvs vg_a8
  LV          VG    Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  dados       vg_a8 owi-aos--- 900,00m
  dados-antes vg_a8 swi-a-s--- 200,00m      dados  0,95

Agora o dados é o (origem) e o dados-antes é s (snapshot) da origem dados. Data% é quanto dos 200 MiB já foi usado com blocos antigos. Estrague o original e espie o snapshot (montado só para leitura):

#> rm /mnt/a8/gastos.txt
#> echo "tudo errado" > /mnt/a8/erro.txt
#> ls /mnt/a8
erro.txt
lost+found
#> mount --mkdir -o ro /dev/vg_a8/dados-antes /mnt/a8-snap
#> ls /mnt/a8-snap
gastos.txt
lost+found
#> cat /mnt/a8-snap/gastos.txt
planilha de gastos
#> umount /mnt/a8-snap

Voltar tudo: lvconvert --merge

Para devolver o LV inteiro ao estado do snapshot, faça o merge. Com o LV desmontado, ele acontece na hora; montado, fica agendado para a próxima ativação (no caso da raiz, o próximo boot).

#> umount /mnt/a8
#> lvconvert --merge vg_a8/dados-antes
  Merging of volume vg_a8/dados-antes started.
  vg_a8/dados: Merged: 99,01%
  vg_a8/dados: Merged: 100,00%
#> echo $?
0
#> lvs vg_a8
  LV    VG    Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  dados vg_a8 -wi-a----- 900,00m                         « o snapshot foi consumido
#> mount /dev/vg_a8/dados /mnt/a8
#> ls /mnt/a8
gastos.txt
lost+found                                                « o erro.txt sumiu
#> cat /mnt/a8/gastos.txt
planilha de gastos

Existe ainda o LVM thin (volumes "finos", lvcreate --thin), com snapshots que crescem sob demanda; o snapper também sabe usá-los.

Desmontando o laboratório

#> umount /mnt/a8

  Logical volume "dados" successfully removed.
  Volume group "vg_a8" successfully removed
#> pvremove /dev/loop3 /dev/loop4
  Labels on physical volume "/dev/loop3" successfully wiped.
  Labels on physical volume "/dev/loop4" successfully wiped.
#> losetup -d /dev/loop3 /dev/loop4
#> rm /var/tmp/a8/lvm1.img /var/tmp/a8/lvm2.img

A ordem é a inversa da criação: LVs (o vgremove leva junto), VG, PVs. Sem o -y, o vgremove pergunta Do you really want to remove volume group "vg_a8" containing 1 logical volumes? [y/n]:.

LVM on LUKS

Juntando com a aula de LUKS: a partição inteira é cifrada uma vez, e dentro dela fica um PV com os LVs da swap, da raiz e da home. Uma senha no boot abre tudo, e você ainda pode redimensionar os volumes depois. Montamos essa pilha de verdade numa imagem de 1 GiB já formatada com LUKS:

#> printf '%s' 'arch-teste-123' | cryptsetup open /dev/loop1 cryptlvm -
#> pvcreate -y /dev/mapper/cryptlvm
  Wiping ext4 signature on /dev/mapper/cryptlvm.
  Physical volume "/dev/mapper/cryptlvm" successfully created.
#> vgcreate vg_cripto_a8 /dev/mapper/cryptlvm
  Volume group "vg_cripto_a8" successfully created
#> lvcreate -L 200M -n swap vg_cripto_a8
  Logical volume "swap" created.
#> lvcreate -L 500M -n raiz vg_cripto_a8
  Logical volume "raiz" created.
#> lvcreate -l 100%FREE -n home vg_cripto_a8
  Logical volume "home" created.
#> lsblk /dev/loop1
NAME                  MAJ:MIN RM  SIZE RO TYPE  MOUNTPOINTS
loop1                   7:1    0    1G  0 loop
└─cryptlvm            253:0    0 1008M  0 crypt                « 1 senha
  ├─vg_cripto_a8-swap 253:1    0  200M  0 lvm
  ├─vg_cripto_a8-raiz 253:2    0  500M  0 lvm
  └─vg_cripto_a8-home 253:3    0  304M  0 lvm
#> lvs vg_cripto_a8
  LV   VG           Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  home vg_cripto_a8 -wi-a----- 304,00m
  raiz vg_cripto_a8 -wi-a----- 500,00m
  swap vg_cripto_a8 -wi-a----- 200,00m

O Wiping ext4 signature aparece porque essa imagem tinha sido usada antes com um ext4 dentro; o -y confirmou a limpeza (sem ele, o pvcreate pergunta). Para fechar a pilha, a ordem é: desativar os LVs, depois fechar o LUKS:

#> vgchange -an vg_cripto_a8
  0 logical volume(s) in volume group "vg_cripto_a8" now active
#> cryptsetup close cryptlvm

Qual usar?

EsquemaComo éQuando
LVM on LUKSPartição → LUKS → PV → LVsO mais comum: uma senha, swap cifrada junto, volumes flexíveis. Limitação: tudo fica num disco só.
LUKS on LVMDiscos → PVs → LVs → LUKS em cada LVQuando o VG espalha por vários discos, ou só alguns volumes precisam de cifra. Uma senha por LV (ou arquivos de chave).
LUKS sem LVMPartição → LUKS → ext4/BtrfsO mais simples. Com Btrfs, os subvolumes já fazem o papel dos LVs.
LVM sem LUKSPartições → PVs → LVsServidores e máquinas fixas onde a flexibilidade importa e a cifra não.

O hook lvm2 do mkinitcpio

Se a raiz está num LV, o initramfs precisa ativar o LVM antes de montá-la: é o hook lvm2, entre block e filesystems. Com LVM on LUKS, ele vem depois do sd-encrypt (primeiro abre o LUKS, depois enxerga o PV de dentro). Esta parte é ilustrativa (o /etc/mkinitcpio.conf da máquina não muda), mas a imagem de teste abaixo foi gerada de verdade, a partir de uma cópia em /tmp:

#> sed -i 's/block sd-encrypt filesystems/block sd-encrypt lvm2 filesystems/' /tmp/a8/mkinitcpio.conf
#> grep -n '^HOOKS' /tmp/a8/mkinitcpio.conf
55:HOOKS=(base systemd autodetect microcode modconf kms keyboard sd-vconsole block sd-encrypt lvm2 filesystems fsck)
#> mkinitcpio -c /tmp/a8/mkinitcpio.conf -g /tmp/a8/initramfs-teste.img
==> Starting build: '7.2.10-arch1-1'
  -> Running build hook: [base]
  -> Running build hook: [systemd]
  -> Running build hook: [autodetect]
  -> Running build hook: [microcode]
  -> Running build hook: [modconf]
  -> Running build hook: [kms]
  -> Running build hook: [keyboard]
  -> Running build hook: [sd-vconsole]
  -> Running build hook: [block]
  -> Running build hook: [sd-encrypt]
==> WARNING: Possibly missing firmware for module: 'qat_6xxx'
  -> Running build hook: [lvm2]                         « o LVM entra aqui
  -> Running build hook: [filesystems]
  -> Running build hook: [fsck]

#> lsinitcpio /tmp/a8/initramfs-teste.img | grep -E 'bin/lvm|dm-mod|lvm2'
usr/lib/modules/7.2.10-arch1-1/kernel/drivers/md/dm-mod.ko.zst

(A cópia /tmp/a8/mkinitcpio.conf já tinha o sd-encrypt, da aula de LUKS.) No sistema real: editar o /etc/mkinitcpio.conf, rodar mkinitcpio -P e, nos parâmetros do kernel, abrir o LUKS e apontar a raiz para o LV, por exemplo rd.luks.name=UUID-DO-LUKS=cryptlvm root=/dev/vg_cripto_a8/raiz (ilustrativo; veja Bootloader para o /etc/default/grub). A swap entra no fstab como /dev/vg_cripto_a8/swap none swap defaults 0 0. O hook lvm2 vem no próprio pacote mkinitcpio, mas usa os programas do pacote lvm2, que precisa estar instalado (inclua-o no pacstrap).

Experimente

Missão: descubra qual pacote instalou o comando /usr/bin/lvcreate.

Quando não funciona

"Insufficient free space" 
#> lvextend -L +5G vg_a8/dados
  Insufficient free space: 1280 extents needed, but only 105 available
#> echo $?
5

O que aconteceu: o VG não tem espaço livre para isso (5 GiB = 1280 extents de 4 MiB; só havia 105).

Como confirmar: vgs (coluna VFree).

Como resolver: peça menos (-l +100%FREE usa tudo o que há), diminua outro LV, ou acrescente um disco: pvcreate /dev/sdb1 e vgextend vg_a8 /dev/sdb1.

"WARNING: ext4 signature detected … Wipe it? [y/n]" 
#> pvcreate /dev/mapper/cryptlvm
WARNING: ext4 signature detected on /dev/mapper/cryptlvm at offset 1080. Wipe it? [y/n]:
…
  Aborted wiping of ext4.
  1 existing signature left on the device.

O que aconteceu: o dispositivo tinha um sistema de arquivos. O LVM pergunta antes de apagar. No laboratório, a pergunta recebeu as linhas seguintes do script como resposta (cada uma virou WARNING: Invalid input) e acabou em "não".

Como resolver: confira com lsblk -f que pode apagar e responda y, ou use pvcreate -y, ou limpe antes com wipefs -a /dev/X.

"Hook 'lvm' cannot be found" 
#> mkinitcpio -c /tmp/a8/mkinitcpio-errado.conf -g /tmp/a8/initramfs-errado.img
…
  -> Running build hook: [sd-encrypt]
==> WARNING: Possibly missing firmware for module: 'qat_6xxx'
==> ERROR: Hook 'lvm' cannot be found
  -> Running build hook: [filesystems]
  -> Running build hook: [fsck]
==> Generating module dependencies
==> Creating zstd-compressed initcpio image: '/tmp/a8/initramfs-errado.img'
==> WARNING: errors were encountered during the build. The image may not be complete.
#> echo $?
1

O que aconteceu: o nome do hook é lvm2, não lvm. O mkinitcpio gera a imagem mesmo assim, mas sem o LVM: com a raiz num LV, esse sistema não liga.

Como resolver: corrija o nome e rode de novo; nunca reinicie depois de um mkinitcpio que terminou com ERROR ou código diferente de 0. Os hooks disponíveis estão em ls /usr/lib/initcpio/install/.

Os LVs não aparecem (sem /dev/VG/…)

O que aconteceu: o VG não foi ativado: o disco foi conectado depois, o LUKS de baixo ainda está fechado, ou (no pendrive de resgate) ninguém rodou o LVM.

Como confirmar: lvs: sem o a na 5ª posição do Attr, o LV está inativo.

Como resolver: abra o LUKS antes, se houver, e ative com vgchange -ay. No resgate com chroot, esse é o passo entre o cryptsetup open e o mount.

Resumo

  • PV (disco) → VG (reservatório) → LV (partição virtual, que você formata e monta).
  • pvs, vgs, lvs para conferir; lvextend -r cresce LV e sistema de arquivos com tudo ligado.
  • Snapshot LVM: tamanho fixo, volta com lvconvert --merge.
  • LVM on LUKS: uma senha abre swap, raiz e home; hooks block sd-encrypt lvm2 filesystems.
  • Para desmontar: LVs → VG → PVs (e vgchange -an antes de fechar o LUKS).
