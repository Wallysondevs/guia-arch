Arch Links (ln)

Um link é um segundo nome para um arquivo ou pasta que já existe. Parece o atalho da área de trabalho do Windows, só que funciona para qualquer programa, inclusive no terminal. O comando que cria links é o ln (de link, "ligação"). O próprio Arch está cheio deles: o /bin, o fuso horário e o sh são links.

Você vai aprender
  • A diferença entre link simbólico (atalho) e link físico (outro nome para os mesmos dados).
  • Ler um link no ls -l (a seta ->) e o número do inode com ls -i.
  • Criar, atualizar e apagar links com segurança.
  • Por que um link "quebra", e como evitar com caminhos relativos e absolutos.
  • Onde o Arch usa links: /bin, /etc/localtime, /usr/bin/sh e o systemctl enable.

Antes do comando: nome, dados e inode

Para entender links, é preciso saber como o Linux guarda um arquivo. Pense numa biblioteca: o livro fica numa prateleira com um número (os dados, no disco), e o fichário tem uma ficha com o título apontando para esse número (o nome, na pasta). O número da prateleira se chama inode (de index node, "nó de índice"). O nome que você vê numa pasta é só a ficha.

Daí saem os dois tipos de link:

No dia a dia, você vai usar o simbólico em 95% dos casos. O ln vem no pacote coreutils, parte do base:

$ pacman -Qo /usr/bin/ln
/usr/bin/ln pertence a coreutils 9.12-2

Criar um link simbólico

ln
O programa que cria links.
-s
Link simbólico (de symbolic). Sem o -s, vira link físico.
Documentos/trabalho/2026/projeto-site
O alvo: para onde o link vai apontar. Vem primeiro.
projeto
O nome do link: o atalho que será criado. Vem por último.

A ordem é a mesma do cp: primeiro o que já existe, depois o nome novo. Uma forma de lembrar: "ln -s de onde vem como vai se chamar".

$ ln -s Documentos/trabalho/2026/projeto-site projeto
$ ls -l projeto
lrwxrwxrwx 1 ana ana 37 16 out 15:02 projeto -> Documentos/trabalho/2026/projeto-site

Quando dá certo, o ln não mostra nada (e devolve 0). Leia a linha do ls -l, coluna por coluna:

PedaçoO que significa num link simbólico
lO primeiro caractere é o tipo: l = link. (- seria arquivo, d pasta.)
rwxrwxrwxSempre assim em links simbólicos. Não quer dizer que todos podem tudo: o que vale são as permissões do alvo.
1Quantos nomes (links físicos) o próprio link tem.
ana anaDono e grupo do link.
37O tamanho do link: o número de caracteres do caminho guardado (Documentos/trabalho/2026/projeto-site tem 37).
16 out 15:02Quando o link foi criado (no Arch em pt_BR, o dia vem antes do mês).
projeto -> Documentos/…O nome do link, uma seta, e o caminho para onde ele aponta.

O link funciona como se fosse a pasta

Uma barra no fim faz toda a diferença: ls -l projeto mostra o link; ls -l projeto/ entra nele e mostra o conteúdo do alvo:

$ ls -l projeto/
total 0
-rw-r--r-- 1 ana ana 0 16 out 15:02 index.html
-rw-r--r-- 1 ana ana 0 16 out 15:02 style.css
$ cd projeto
$ pwd
/home/ana/projeto                                   « o caminho "pelo atalho"
$ pwd -P
/home/ana/Documentos/trabalho/2026/projeto-site     « o caminho real

O -P (de physical) mostra onde você está de verdade, sem atalhos. Repare que o prompt mostrou projeto: o Bash lembra o caminho por onde você entrou.

Os links do próprio Arch

O Arch usa links em pontos muito importantes do sistema. Vale a pena olhar cada um.

1. /bin, /sbin e /lib. Antigamente os programas ficavam espalhados entre /bin, /sbin, /usr/bin e /usr/sbin. O Arch juntou tudo em /usr/bin (em 2013) e deixou os nomes antigos como links, para os scripts velhos continuarem funcionando:

$ ls -ld /bin /sbin /lib /lib64
lrwxrwxrwx 1 root root 7 12 out  2025 /bin -> usr/bin
lrwxrwxrwx 1 root root 7 12 out  2025 /lib -> usr/lib
lrwxrwxrwx 1 root root 7 12 out  2025 /lib64 -> usr/lib
lrwxrwxrwx 1 root root 7 12 out  2025 /sbin -> usr/bin    « sbin também vai para bin!
$ readlink /bin
usr/bin

O -d é importante: sem ele, ls -l /bin entraria no link e listaria os milhares de programas de /usr/bin. Repare na diferença do Arch: o /sbin aponta para usr/bin, não para usr/sbin (que também é um link para bin). No Debian, por exemplo, o /sbin aponta para usr/sbin, que ainda é uma pasta separada. Veja Estrutura de Diretórios.

2. O fuso horário, /etc/localtime. Na instalação, você mesmo criou este link, dentro do arch-chroot (veja Configurar o Sistema):

#> arch-chroot /mnt ln -sf /usr/share/zoneinfo/America/Sao_Paulo /etc/localtime
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 37 16 out 12:09 /etc/localtime -> /usr/share/zoneinfo/America/Sao_Paulo
$ readlink /etc/localtime
/usr/share/zoneinfo/America/Sao_Paulo

Trocar de fuso é trocar o alvo do link (o timedatectl set-timezone faz exatamente isso por você).

3. O sh do Arch é o Bash. Scripts que começam com #!/bin/sh rodam no Bash, porque /usr/bin/sh é um link para bash. (No Debian e no Ubuntu, o sh aponta para outro shell, o dash.) Siga a cadeia toda com readlink -f:

$ ls -l /usr/bin/sh
lrwxrwxrwx 1 root root 4 15 set 16:47 /usr/bin/sh -> bash
$ readlink -f /bin/sh
/usr/bin/bash                « /bin → usr/bin, e sh → bash
$ readlink -f /sbin/init
/usr/lib/systemd/systemd     « o primeiro programa do boot é o systemd
$ file /bin /usr/bin/sh
/bin:        symbolic link to usr/bin
/usr/bin/sh: symbolic link to bash

4. Versões de programas. Quem digita python3 recebe a versão atual. Quando o Python for atualizado, o pacote só muda o link:

$ ls -l /usr/bin/python3 /etc/os-release
lrwxrwxrwx 1 root root 21 16 out 12:09 /etc/os-release -> ../usr/lib/os-release
lrwxrwxrwx 1 root root 10  2 out 07:23 /usr/bin/python3 -> python3.14

5. Ligar um serviço é criar um link. O systemctl enable (veja systemctl e Serviços) não edita nenhuma configuração: ele cria um link simbólico numa pasta .wants, e o disable apaga esse link:

$ sudo systemctl enable nginx
Created symlink '/etc/systemd/system/multi-user.target.wants/nginx.service' → '/usr/lib/systemd/system/nginx.service'.
$ ls -l /etc/systemd/system/multi-user.target.wants/nginx.service
lrwxrwxrwx 1 root root 37 16 out 15:01 /etc/systemd/system/multi-user.target.wants/nginx.service -> /usr/lib/systemd/system/nginx.service
$ sudo systemctl disable nginx
Removed '/etc/systemd/system/multi-user.target.wants/nginx.service'.

Missão 2: descubra qual programa responde de verdade quando um script chama /bin/sh. Olhe o /usr/bin/sh com ls -l e depois siga a cadeia toda com readlink -f.

Relativo ou absoluto: a causa nº 1 de links quebrados

O caminho que você escreve como alvo é gravado do jeito que foi digitado. Se for relativo, ele é lido a partir da pasta onde o link está, e não de onde você estava quando o criou.

$ ln -s frutas.txt Documentos/atalho-frutas
$ cat Documentos/atalho-frutas
cat: Documentos/atalho-frutas: Arquivo ou diretório inexistente
$ ls -l Documentos/atalho-frutas
lrwxrwxrwx 1 ana ana 10 16 out 15:02 Documentos/atalho-frutas -> frutas.txt     « procura Documentos/frutas.txt

O link mora em Documentos/ e aponta para frutas.txt. Então ele procura Documentos/frutas.txt, que não existe. O /etc/os-release que você viu acima faz do jeito certo: ../usr/lib/os-release sobe de /etc para / e desce em usr/lib. Três formas de acertar:

$ ln -sf ../frutas.txt Documentos/atalho-frutas      « relativo ao link
$ head -2 Documentos/atalho-frutas
banana
maçã
$ ln -sfr frutas.txt Documentos/atalho-frutas        « o -r faz a conta
$ ls -l Documentos/atalho-frutas
lrwxrwxrwx 1 ana ana 13 16 out 15:02 Documentos/atalho-frutas -> ../frutas.txt
$ ln -sf ~/frutas.txt Documentos/atalho-frutas       « absoluto
$ ls -l Documentos/atalho-frutas
lrwxrwxrwx 1 ana ana 20 16 out 15:02 Documentos/atalho-frutas -> /home/ana/frutas.txt
FormaComandoQuando usar
Caminho absolutoln -s ~/frutas.txt Documentos/atalhoO alvo nunca muda de lugar. É o mais simples (o /etc/localtime é assim).
Relativo ao linkln -s ../frutas.txt Documentos/atalhoVocê vai mover a pasta inteira junto (projetos, backups, pendrive). O /bin -> usr/bin é assim.
Deixar o ln calcularln -sr frutas.txt Documentos/atalhoQuer relativo sem fazer a conta. O -r (relative) calcula sozinho.

O ~ é trocado pelo shell por /home/ana antes de o ln rodar, por isso vira um caminho absoluto. O -f (de force) substituiu o link que já existia; ele é explicado logo abaixo.

Link físico

ln
Sem -s: link físico.
original.txt
O arquivo que já existe.
outro-nome.txt
O novo nome para os mesmos dados.
$ echo ideia > original.txt
$ ln original.txt outro-nome.txt
$ ls -li original.txt outro-nome.txt
1314927 -rw-r--r-- 2 ana ana 6 16 out 15:02 original.txt
1314927 -rw-r--r-- 2 ana ana 6 16 out 15:02 outro-nome.txt
 « mesmo inode (1314927) e contador de links = 2

O -i do ls (de inode) mostra o número do inode, na primeira coluna. Os dois nomes têm o mesmo número: são o mesmo arquivo, a mesma "prateleira". O 2 depois das permissões diz quantos nomes ele tem. Na sua máquina o número do inode será outro; o que importa é ser igual nos dois.

Compare com um link simbólico: ele ganha um inode próprio, porque é um arquivinho separado que só guarda um caminho:

$ ln -s frutas.txt simbolico.txt
$ ls -li frutas.txt simbolico.txt
1314249 -rw-rw-r-- 1 ana ana 47 14 out 16:05 frutas.txt
1314929 lrwxrwxrwx 1 ana ana 10 16 out 15:02 simbolico.txt -> frutas.txt

Agora o teste de verdade com o link físico: mexer por um nome e apagar o outro.

$ echo "mais uma" >> outro-nome.txt
$ cat original.txt
ideia
mais uma                              « a mudança aparece pelos dois nomes
$ rm original.txt
$ cat outro-nome.txt
ideia
mais uma                              « os dados continuam lá
$ ls -li outro-nome.txt
1314927 -rw-r--r-- 1 ana ana 15 16 out 15:02 outro-nome.txt     « contador voltou para 1

O rm, na verdade, só apaga uma ficha (por isso existe também o comando unlink, "desligar"). Os dados só são liberados quando o último nome é removido.

Link físico não é backup

Como é o mesmo arquivo, editar por um nome altera o outro. Para ter uma cópia independente, use cp.

Por que as pastas têm contador maior que 1?

Em drwxrwxr-x 3 ana ana 4096 15 out 09:07 Documentos, o 3 conta os nomes da pasta: Documentos (dentro da pasta pessoal), o . dentro dela mesma e o .. dentro da subpasta projetos. Esses são os únicos links físicos para pastas que existem, e só o sistema pode criá-los.

Atualizar e apagar links

O nome já existe: -f e -i

Se o nome do link já existe, o ln recusa e devolve 1. O -f (force) apaga o antigo e cria o novo; o -i (interactive) pergunta antes:

$ ln -s frutas.txt atalho.txt
$ ln -s frutas.txt atalho.txt
ln: falha ao criar link simbólico 'atalho.txt': Arquivo existe
$ echo $?
1
$ ln -sf frutas.txt atalho.txt
$ echo $?
0
$ ln -si frutas.txt atalho.txt
ln: substituir 'atalho.txt'?             « responda s ou n

Link para pasta: -n

Com links para pastas existe uma armadilha. Se o nome do link aponta para uma pasta, o ln entra nela e cria o link novo lá dentro, mesmo com -f, sem erro nenhum:

$ ln -s ~/Documentos/v1 atual
$ ln -sf ~/Documentos/v2 atual
$ ls -l atual
lrwxrwxrwx 1 ana ana 23 16 out 15:02 atual -> /home/ana/Documentos/v1     « não mudou!
$ ls -l Documentos/v1
total 0
lrwxrwxrwx 1 ana ana 23 16 out 15:02 v2 -> /home/ana/Documentos/v2     « um link perdido dentro da v1
$ ln -sfn ~/Documentos/v2 atual
$ ls -l atual
lrwxrwxrwx 1 ana ana 23 16 out 15:02 atual -> /home/ana/Documentos/v2     « agora sim

O -n (no-dereference, "não seguir") manda o ln tratar atual como um nome, sem entrar nele. Para trocar o destino de um link de pasta, decore: ln -sfn.

Apagar um link

Apagar o link não apaga o alvo. Use rm ou unlink no nome do link, sem barra no fim:

$ rm projeto/
rm: não foi possível remover 'projeto/': É um diretório
$ rm projeto
$ ls Documentos/trabalho/2026/
projeto-site                         « a pasta original continua lá
Nunca use rm -r num link com barra no fim

Com a barra, o rm -r entra na pasta apontada e apaga o conteúdo real. Depois ainda reclama, e o atalho continua lá, apontando para uma pasta agora vazia:

$ ls alvo
importante.txt
$ ln -s alvo atalho
$ rm -r atalho/
rm: não foi possível remover 'atalho/': Não é um diretório
$ ls alvo
$                                    « o importante.txt sumiu
$ ls -l atalho
lrwxrwxrwx 1 ana ana 4 16 out 15:02 atalho -> alvo

Para remover um atalho, é sempre rm atalho, sem -r e sem barra. Veja também rm e rmdir.

Quando não funciona

"Arquivo ou diretório inexistente" ao abrir um link que existe 
$ ls -l ideias.txt
lrwxrwxrwx 1 ana ana 22 16 out 15:02 ideias.txt -> /home/ana/rascunho.txt
$ cat ideias.txt
cat: ideias.txt: Arquivo ou diretório inexistente

O que aconteceu: o link está quebrado: o alvo (rascunho.txt) foi apagado, renomeado ou movido. No terminal colorido, links quebrados aparecem em vermelho.

Como confirmar: o -xtype l do find lista só os links quebrados:

$ find . -maxdepth 1 -xtype l
./ideias.txt

Como resolver: recrie apontando para o lugar certo: ln -sf ~/Documentos/rascunho.txt ideias.txt. Ou apague o link: rm ideias.txt.

"falha ao criar link simbólico … Arquivo existe" 
$ ln -s frutas.txt atalho.txt
ln: falha ao criar link simbólico 'atalho.txt': Arquivo existe

Como resolver: escolha outro nome, ou substitua de propósito com ln -sf (ln -sfn se for um link de pasta).

"não são permitidos links físicos para diretórios" 
$ ln Documentos docs
ln: Documentos: não são permitidos links físicos para diretórios

O que aconteceu: faltou o -s. Links físicos não podem apontar para pastas.

Como resolver: ln -s Documentos docs.

"Link entre dispositivos inválido" 
$ echo teste > /tmp/x.txt
$ ln /tmp/x.txt x.txt
ln: falha ao criar link físico 'x.txt' => '/tmp/x.txt': Link entre dispositivos inválido

O que aconteceu: um link físico é outra ficha para o mesmo inode, e inodes só valem dentro de uma partição. No Arch, o /tmp é um tmpfs (fica na memória RAM), um "dispositivo" diferente da sua pasta pessoal. O mesmo vale para um HD externo ou outra partição.

Como resolver: use um link simbólico (ln -s /tmp/x.txt x.txt), que funciona entre partições, ou copie o arquivo.

"alvo 'atalho': Arquivo ou diretório inexistente" 
$ ln -s Meus Documentos atalho3
ln: alvo 'atalho3': Arquivo ou diretório inexistente

O que aconteceu: o nome com espaço virou dois argumentos. Com três nomes, o ln entende que o último é uma pasta onde criar dois links, e essa pasta não existe.

Como resolver: aspas: ln -s "Meus Documentos" atalho3. O mesmo vale para a "Área de trabalho".

Missão 4: o link ideias.txt está quebrado: o rascunho foi movido para Documentos/rascunho.txt. Veja com ls -l para onde ele aponta e conserte-o com ln -sf. Confira com cat ideias.txt.

Resumo

  • ln -s alvo nome cria um atalho (link simbólico); a ordem é a mesma do cp.
  • No ls -l, links aparecem com l e ->; readlink -f mostra o destino final.
  • Alvos relativos são lidos a partir da pasta do link; na dúvida, use caminho absoluto ou ln -sr.
  • Link físico (ln sem -s) é outro nome para o mesmo inode (ls -i); não serve para pastas nem entre partições.
  • Para trocar o destino: ln -sf (arquivo) ou ln -sfn (pasta). Para apagar: rm nome, sem -r e sem barra.
  • No Arch, /bin e /sbin apontam para usr/bin, /etc/localtime aponta para o fuso, sh é o bash, e o systemctl enable cria links.
