Arch grep

O find procura arquivos; o grep procura texto dentro dos arquivos. Ele lê linha por linha e mostra só as linhas que contêm o que você pediu. É a ferramenta para achar um erro num log de milhares de linhas, uma opção no /etc/pacman.conf ou um nome numa lista.

Você vai aprender
  • Como o grep funciona: um filtro de linhas.
  • As opções do dia a dia: -i, -v, -n, -c, -w, -o, -A/-B/-C, -r, -l.
  • Expressões regulares básicas (^, $, ., [ ]) e a estendida com -E.
  • Os códigos de saída (0, 1 e 2) e o -q para scripts.
  • Usar o grep no pacman.conf, no pacman.log e no meio de um pipe; e conhecer o ripgrep.

O nome vem de um comando antigo do editor ed: g/re/p, ou global / regular expression / print, "em todo o arquivo, procure a expressão e mostre". O Arch traz o GNU grep no base:

$ pacman -Qo /usr/bin/grep
/usr/bin/grep pertence a grep 3.12-2
$ grep --version | head -1
grep (GNU grep) 3.12-modified

O arquivo de exemplo

Nesta aula vamos usar o log de um pequeno site, Documentos/acesso.log. Cada linha é uma visita: quem visitou (o IP), quando, qual página e o resultado (200 = deu certo, 403 = proibido, 404 = não encontrado).

$ cat Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
192.168.0.23 - - [15/Oct/2026:09:07:02] "GET / HTTP/1.1" 200

Também vamos usar o frutas.txt (banana, maçã, laranja, banana, uva, maçã, banana, uma por linha), que está na pasta pessoal.

A forma mais simples

grep
O programa: filtra linhas.
403
O padrão: o texto que a linha precisa conter.
Documentos/acesso.log
O arquivo onde procurar.
$ grep 403 Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403

De seis linhas, só uma contém 403, e é a única que aparece. O arquivo não muda: o grep só lê.

As cores já vêm ligadas no Arch

No seu terminal, o 403 aparece destacado em vermelho. Quem liga isso é o ~/.bashrc que o Arch cria para todo usuário novo. Ele é curtinho, e uma das quatro linhas úteis é justamente um apelido (alias) para o grep:

$ cat ~/.bashrc
#
# ~/.bashrc
#

# If not running interactively, don't do anything
[[ $- != *i* ]] && return

alias ls='ls --color=auto'
alias grep='grep --color=auto'          « aqui
PS1='[\u@\h \W]\$ '
$ type grep
grep está apelidada para `grep --color=auto'

Toda vez que você digita grep, o Bash roda grep --color=auto. O auto pinta só quando a saída é a tela; mandando para um arquivo ou um pipe, o texto sai limpo. (No Debian esse apelido vem comentado; no Arch, ativo. Veja .bashrc, alias, PATH.)

Padrão com espaço? Use aspas

Sem aspas, a segunda palavra vira o nome de um arquivo:

$ grep GET /admin Documentos/acesso.log
grep: /admin: Arquivo ou diretório inexistente
Documentos/acesso.log:192.168.0.10 - - [15/Oct/2026:09:01:12] "GET / HTTP/1.1" 200
Documentos/acesso.log:192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
…
$ grep "GET /admin" Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403

O primeiro procurou "GET" em dois arquivos: /admin (que não existe) e o log. Na dúvida, coloque o padrão sempre entre aspas.

Uma opção por vez

-i: ignorar maiúsculas

Por padrão, Banana e banana são diferentes. Com -i (de ignore case), não:

$ grep BANANA frutas.txt
$ grep -i BANANA frutas.txt
banana
banana
banana

-n: mostrar o número da linha

Útil para abrir o arquivo no editor direto na linha certa (no nano: nano +3 arquivo; veja nano e vim).

$ grep -n admin Documentos/acesso.log
3:192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403     « linha 3

-c: só contar

Em vez de mostrar as linhas, mostra quantas combinam (de count):

$ grep -c 192.168.0.10 Documentos/acesso.log
3

-v: inverter (o que NÃO contém)

Mostra as linhas que não combinam. Aqui, tudo o que não deu 200, ou seja, só os problemas:

grep
O programa.
-v
Inverte (de invert): mostra as linhas que não contêm o padrão.
" 200"
O padrão, com um espaço antes para não pegar "2000" por engano. Por causa do espaço, as aspas são obrigatórias.
Documentos/acesso.log
O arquivo.
$ grep -v " 200" Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404

-w e -x: palavra inteira, linha inteira

O grep acha o padrão em qualquer lugar da linha, até no meio de uma palavra. Procurando "ana" em frutas.txt:

$ grep ana frutas.txt
banana                               « "ana" está dentro de "banana"
banana
banana
$ grep -w ana frutas.txt
$ echo $?
1                                    « nenhuma linha tem a palavra "ana" sozinha
$ grep -x uva frutas.txt
uva                                  « a linha inteira é "uva"

Com -w (de word), o padrão precisa ser uma palavra inteira, separada por espaço ou pontuação. Com -x, a linha inteira precisa ser igual ao padrão.

-o: só o trecho encontrado

Em vez da linha inteira, mostra só o pedaço que combinou (de only matching). Ótimo para extrair dados:

$ grep -o "192.168.0.[0-9]*" Documentos/acesso.log
192.168.0.10
192.168.0.23
192.168.0.10
192.168.0.57
192.168.0.10
192.168.0.23

A lista tem repetições. Para contar quantas visitas cada IP fez, junte com sort | uniq -c (veja sort, uniq, cut, wc, tr).

-A, -B, -C: linhas ao redor

Num log, a linha do erro nem sempre basta: você quer ver o que veio antes e depois. -A 2 mostra 2 linhas depois (after), -B 2 mostra 2 antes (before) e -C 2 mostra 2 de cada lado (context).

$ grep -n -A1 laranja frutas.txt
3:laranja                            « ":" = linha que combinou
4-banana                             « "-" = linha de contexto
$ grep -B1 uva frutas.txt
banana
uva
$ grep -C1 -n admin Documentos/acesso.log
2-192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
3:192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
4-192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404

Procurar em vários arquivos

Vários arquivos de uma vez

Com mais de um arquivo, cada linha vem com o nome do arquivo na frente (para esconder, -h):

$ grep -c banana frutas.txt Documentos/notas.txt
frutas.txt:3
Documentos/notas.txt:0

-r: procurar dentro de uma pasta inteira

grep
O programa.
-r
Recursivo: entra em todas as subpastas (de recursive).
"café"
O texto a procurar.
Documentos
A pasta onde começar.
$ grep -r "café" Documentos
Documentos/notas.txt:Comprar café
$ grep -rn "echo" Documentos
Documentos/projetos/backup.sh:2:echo "Fazendo backup..."      « arquivo:linha:conteúdo
$ grep -r --include="*.csv" -n Recife Documentos
Documentos/alunos.csv:2:Ana,29,Recife,9.5

O --include limita a busca a certos nomes de arquivo (aqui, só os .csv).

grep -r só em pastas pequenas

grep -r texto / lê o conteúdo de todos os arquivos do sistema, gigabytes de programas, imagens e pendrives. É ainda mais pesado que um find /. Comece na menor pasta possível (~/projeto, /etc/ssh) e, quando souber o arquivo, procure só nele.

-l: só o nome dos arquivos

Quando você só quer saber quais arquivos contêm o texto (de list):

$ grep -rl "Olá" Documentos
Documentos/projetos/site/index.html

Expressões regulares básicas

O padrão do grep não é só texto: é uma expressão regular (regex), uma pequena linguagem para descrever textos. Alguns caracteres têm significado especial:

SímboloSignificaExemploCombina com
.Qualquer caractere (um só)b.nban, bin, b9n
*O anterior repetido 0 ou mais vezes10*1, 10, 1000
^Começo da linha^blinhas que começam com b
$Fim da linhaa$linhas que terminam com a
[abc]Um dos caracteres da lista[bm]b ou m
[0-9]Uma faixa[0-9][0-9]dois dígitos
[^0-9]Qualquer um, menos os da lista[^a-z]o que não é letra minúscula
\.Um ponto de verdade\.txt$termina em ".txt"
$ grep "^[bm]" frutas.txt
banana
maçã
banana
maçã
banana
$ grep "a$" frutas.txt
banana
laranja
banana
uva
banana
$ grep "ma.ã" frutas.txt
maçã                                 « o ponto pegou o "ç"
maçã

O primeiro pede linhas que começam com b ou m; o segundo, linhas que terminam com a. No terceiro, o ponto valeu por um caractere acentuado: com LANG=pt_BR.UTF-8, o grep entende "ç" como uma letra só.

O ponto é "qualquer caractere": cuidado

$ grep -o "1.1" Documentos/acesso.log | head -3
1:1                                  « veio de "09:01:12"!
1.1
1.1

Procurando "1.1" (de HTTP/1.1), o grep também achou "1:1" dentro da hora. Para o ponto valer só como ponto, escreva "1\.1" ou use -F (veja abaixo).

-E: regex estendida (com "ou")

Com -E (de extended), você ganha | ("ou"), + (1 ou mais), ? (opcional), {n} (repetir n vezes) e parênteses para agrupar, sem precisar de barras:

grep
O programa.
-E
Usa a regex estendida.
"40[34]$"
"40", depois 3 ou 4, no fim da linha: pega 403 e 404.
Documentos/acesso.log
O arquivo.
$ grep -E "40[34]$" Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404
$ grep -E "POST|admin" Documentos/acesso.log
192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
192.168.0.10 - - [15/Oct/2026:09:06:44] "POST /login HTTP/1.1" 200
$ grep "POST|admin" Documentos/acesso.log
$                                    « sem -E, o | é um caractere comum
$ grep -oE "[0-9]{3}$" Documentos/acesso.log
200
200
403
404
200
200
Quer procurar o texto exato, sem regex? -F

Use -F (de fixed, "fixo"): grep -F "1.1" arquivo procura "1.1" de verdade. Os antigos egrep e fgrep ainda existem no Arch, mas reclamam a cada uso:

$ egrep 404 Documentos/acesso.log
egrep: warning: egrep is obsolescent; using grep -E
192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404

Prefira grep -E e grep -F.

grep no dia a dia do Arch

Ler um arquivo de configuração sem os comentários

O /etc/pacman.conf tem 100 linhas, a maioria comentários (#) e linhas vazias. Dois grep -v em sequência mostram só o que está valendo:

$ grep -v "^#" /etc/pacman.conf | grep -v "^$"
[options]
HoldPkg     = pacman glibc
Architecture = auto
CheckSpace
ParallelDownloads = 5
DownloadUser = alpm
SigLevel    = Required DatabaseOptional
LocalFileSigLevel = Optional
[core]
Include = /etc/pacman.d/mirrorlist
[extra]
Include = /etc/pacman.d/mirrorlist
grep -v "^#"
Tira as linhas que começam com # (comentários).
|
Entrega o resultado para o próximo comando (veja Pipes e xargs).
grep -v "^$"
Tira as linhas vazias: ^$ é "começo e fim colados", sem nada no meio.

Repare: a opção Color está comentada, por isso o pacman sai sem cores (veja pacman Avançado). E só os repositórios [core] e [extra] estão ligados:

$ grep "^\[" /etc/pacman.conf
[options]
[core]
[extra]
$ grep -n "PasswordAuthentication\|^Include" /etc/ssh/sshd_config
2:Include /etc/ssh/sshd_config.d/*.conf
59:#PasswordAuthentication yes
80:# PasswordAuthentication.  Depending on your PAM configuration,
84:# PAM authentication, then enable this but set PasswordAuthentication

No primeiro, a barra em \[ diz que o colchete é um caractere comum, não o começo de uma lista. No segundo, \| é o "ou" da regex básica (sem -E). A opção do SSH está na linha 59, comentada, e a linha 2 avisa que os arquivos de sshd_config.d também contam (veja SSH).

A armadilha do ps aux | grep

Procurando um programa na lista de processos, o próprio grep pode aparecer no resultado:

$ ps aux | grep NetworkManager
root         289  0.0  0.7 422460 27884 ?        Ssl  14:51   0:00 /usr/bin/NetworkManager --no-daemon
ana        24563  0.0  0.1   6968  4412 pts/0    S+   15:10   0:00 grep --color=auto NetworkManager     « o próprio grep!

Isso acontece porque, no momento em que o ps tira a foto dos processos, o grep já está rodando, e a linha de comando dele contém "NetworkManager" (repare no --color=auto do apelido). Às vezes a linha não aparece, quando o ps é mais rápido. Duas saídas:

  • Use pgrep -a NetworkManager, feito exatamente para isso (veja ps, pgrep, top, htop).
  • Ou o truque ps aux | grep "[N]etworkManager": a regex [N]etworkManager combina com "NetworkManager", mas a linha do grep contém "[N]etworkManager", que não combina com ela mesma.
$ pgrep -a NetworkManager
289 /usr/bin/NetworkManager --no-daemon

Missão 5: rode ps aux | grep NetworkManager. Depois descubra o processo do NetworkManager sem a armadilha, com pgrep -a.

O que o grep devolve

O grep é um dos poucos comandos em que o código de saída diz se ele achou algo:

CódigoSignificado
0Achou pelo menos uma linha
1Não achou nada (não é erro!)
2Houve erro: arquivo inexistente, regex inválida…
$ grep uva frutas.txt
uva
$ echo $?
0
$ grep abacaxi frutas.txt
$ echo $?
1                                    « silêncio + 1 = não achou
$ grep uva frutas.text
grep: frutas.text: Arquivo ou diretório inexistente
$ echo $?
2

Em scripts, use -q (de quiet, "quieto"): não mostra nada, só devolve o código. Junto com o && ("se deu certo, faça"):

$ grep -q "Arch Linux" /etc/os-release && echo "É Arch!"
É Arch!

Formas diferentes de fazer

Contar linhas que combinam

$ grep -c banana frutas.txt
3
$ grep banana frutas.txt | wc -l
3

Os dois dão o mesmo resultado. O -c é mais curto; o | wc -l funciona com qualquer comando no lugar do grep.

ripgrep: um grep -r mais rápido (ilustrativo)

O ripgrep (comando rg) é um programa moderno, do repositório extra, feito para procurar em pastas inteiras: é recursivo por padrão, pula arquivos ocultos, binários e o que estiver no .gitignore, e é muito rápido. Não vem instalado:

$ sudo pacman -S ripgrep
…
Pacotes (1) ripgrep-15.2.0-1

Tamanho total download:   1,39 MiB
Tamanho total instalado:  4,29 MiB

:: Continuar a instalação? [S/n]

Na VM do guia nada foi instalado: a saída abaixo é do rg 15.2.0 real, rodado a partir do pacote baixado, dentro de Documentos. Ele agrupa os resultados por arquivo e já mostra o número da linha. No simulador, ele não existe.

$ rg 40
acesso.log
2:192.168.0.23 - - [15/Oct/2026:09:01:40] "GET /contato HTTP/1.1" 200
3:192.168.0.10 - - [15/Oct/2026:09:02:03] "GET /admin HTTP/1.1" 403
4:192.168.0.57 - - [15/Oct/2026:09:05:19] "GET /fotos HTTP/1.1" 404

Quando não funciona

Não apareceu nada 
$ grep Banana frutas.txt
$
$ grep -i "maca" frutas.txt
$

O que aconteceu: nenhuma linha tem "Banana" com B maiúsculo; e "maca" não acha "maçã", porque acento conta (o -i ignora maiúsculas, não acentos). Silêncio no grep não é erro: só quer dizer "não achei" (código 1).

Como confirmar: echo $? mostra 1. Se mostrar 2, é erro de verdade.

Como resolver: tente -i, confira a grafia (ou troque a letra duvidosa por um ponto: "ma.ã") e se o arquivo é o certo.

"É um diretório" 
$ grep café Documentos
grep: Documentos: É um diretório

Como resolver: para procurar dentro da pasta, use -r: grep -r café Documentos.

"Arquivo ou diretório inexistente" 
$ grep 403 acesso.log
grep: acesso.log: Arquivo ou diretório inexistente

O que aconteceu: o arquivo está em outra pasta (Documentos/acesso.log). Também acontece quando o padrão tem espaço e está sem aspas: a segunda palavra vira "arquivo". Para esconder esse tipo de erro quando você passa vários arquivos, use -s.

"( ou \( descasados" e "Expressão regular inválida" 
$ grep -E "(erro" Documentos/acesso.log
grep: ( ou \( descasados
$ grep "[" frutas.txt
grep: Expressão regular inválida

O que aconteceu: na regex, ( abre um grupo e [ abre uma lista, e nenhum dos dois foi fechado.

Como resolver: para procurar esses caracteres literalmente, use -F (grep -F "(erro" app.log) ou uma barra antes (grep "\[" arquivo).

"arquivo binário coincide com o padrão" 
$ grep ELF /usr/bin/bash
grep: /usr/bin/bash: arquivo binário coincide com o padrão

O que aconteceu: o arquivo não é texto (é um programa, imagem, PDF, pacote .zst…). O grep avisa que achou, mas não imprime a linha para não sujar o terminal.

Como resolver: normalmente não há o que resolver. Se precisar mesmo, grep -a trata o arquivo como texto. Para arquivos compactados, use zgrep (veja tar, zip, gzip).

Resumo

  • grep padrão arquivo mostra as linhas que contêm o padrão; use aspas sempre que houver espaço ou símbolos.
  • -i ignora maiúsculas, -v inverte, -n numera, -c conta, -w palavra inteira, -o só o trecho, -A/-B/-C contexto.
  • -r procura em pastas (só pastas pequenas!) e -l mostra só os nomes dos arquivos.
  • Regex: ^ começo, $ fim, . qualquer caractere, [ ] lista; -E libera |, +, {}; -F desliga tudo.
  • Código 0 = achou, 1 = não achou, 2 = erro. -q serve para scripts.
  • No Arch, as cores vêm do apelido no .bashrc; grep -v "^#" limpa arquivos de configuração e o /var/log/pacman.log guarda o histórico.

Na Arch Wiki: o grep e as alternativas modernas, como o ripgrep, aparecem em Core utilities; as cores do grep e de outros comandos, em Color output in console; e o histórico do pacman (/var/log/pacman.log), em pacman (em português).
