Arch Variáveis e Argumentos

Uma variável é um nome que guarda um valor: um texto, um número, o resultado de um comando. Com variáveis, um script deixa de fazer sempre a mesma coisa e passa a se adaptar: ao pacote que você pediu, à data de hoje, à quantidade de pacotes do AUR que a máquina tem agora.

Você vai aprender
  • Criar e ler variáveis, e a regra de ouro: sem espaços em volta do =.
  • A diferença entre aspas simples, duplas e nenhuma aspa.
  • Guardar a saída de um comando (pacman -Qm, uname -r) com $( ) e fazer contas com $(( )).
  • Ler o que o usuário digita (read) e os argumentos do script ($1, $#, $@).
  • Valores padrão, recortes de texto (tirar a versão do nome de um pacote) e listas (arrays).

Antes, leia Primeiro Script. Os exemplos rodam na máquina notebook, com a usuária ana; as saídas vêm de um Arch Linux real.

Criar e ler uma variável

Pense numa variável como uma caixa com etiqueta: a etiqueta é o nome, e dentro está o valor. Você guarda uma vez e usa o nome quantas vezes quiser.

pacote
O nome da variável. Use letras, números e _; não pode começar com número.
=
Atribui o valor. Sem espaços antes nem depois.
"firefox"
O valor. Aqui as aspas são opcionais (não há espaço), mas são um bom hábito.
$ pacote="firefox"
$ echo $pacote
firefox
$ echo "Vou instalar o $pacote"
Vou instalar o firefox

Para ler a variável, coloque $ antes do nome. O Bash troca $pacote pelo valor antes de rodar o comando: o echo nem fica sabendo que ali havia uma variável. Criar a variável não mostra nada: silêncio, como sempre, é sucesso.

Chaves: onde o nome termina

Quando o nome da variável fica colado em outro texto, o Bash não sabe onde ele termina. Veja com o nome do arquivo que o makepkg baixou para o yay-bin:

$ arquivo=yay
$ echo "$arquivo_13.0.1.tar.gz"
.0.1.tar.gz                                « procurou a variável "arquivo_13", que não existe
$ echo "${arquivo}_13.0.1.tar.gz"
yay_13.0.1.tar.gz

O _ e os números podem fazer parte de um nome de variável, então o Bash leu arquivo_13. Com ${arquivo}, as chaves marcam o fim do nome. Um - ou um . já encerram o nome sozinhos ("$arquivo-bin" funciona), mas usar chaves nunca atrapalha.

Convenção de nomes

Variáveis do sistema são MAIÚSCULAS (HOME, PATH, USER). Nos seus scripts, prefira minúsculas (pasta_destino, qtd_aur) para não sobrescrever uma variável do sistema sem querer.

Missão: crie uma variável pacote com o nome de um programa (por exemplo, htop) e mostre a frase Vou instalar o … usando echo e $pacote. Depois tente pacote = htop, com espaços, e leia o erro.

Aspas: simples, duplas ou nenhuma

As aspas mudam o que o Bash faz com o texto. Esta é a parte mais importante da aula:

$ echo "Pacote: $pacote"                   « duplas: troca as variáveis
Pacote: firefox
$ echo 'Pacote: $pacote'                   « simples: tudo literal
Pacote: $pacote
$ echo Pacote:     $pacote                 « sem aspas: espaços extras somem
Pacote: firefox
Forma$variável é trocada?Espaços preservados?Use para
"texto $var"SimSimQuase tudo. É o padrão seguro.
'texto $var'NãoSimTexto que deve sair exatamente como está (como a linha do PATH que você pôs no .bashrc na aula anterior).
texto $varSimNão: o valor é quebrado em palavrasEvite com variáveis.

Por que sempre usar aspas em volta de variáveis

Sem aspas, um valor com espaço vira vários argumentos. Veja o que acontece ao criar um arquivo:

$ arquivo="Meu Relatório.pdf"
$ touch $arquivo
$ ls
Meu  Relatório.pdf                         « dois arquivos: "Meu" e "Relatório.pdf"!
$ arquivo="Meu Relatório.pdf"
$ touch "$arquivo"
$ ls
'Meu Relatório.pdf'                        « um arquivo, como esperado

(O ls põe aspas simples em volta de nomes com espaço só para você enxergar onde o nome começa e termina; elas não fazem parte do nome.) Regra prática: escreva "$variável", com aspas duplas, sempre que usá-la como argumento.

Guardar a saída de um comando: $( )

A substituição de comando roda o comando de dentro e coloca a saída dele no lugar. Combinada com uma variável, guarda o resultado para usar depois. É o que mais se usa em scripts de administração do Arch.

total=
A variável que vai receber o resultado.
$(
Abre a substituição: "rode o que vem a seguir".
pacman -Qq | wc -l
O comando: lista os pacotes instalados só pelo nome (-q, quiet) e conta as linhas.
)
Fecha a substituição.
$ kernel=$(uname -r)
$ echo "Kernel: $kernel"
Kernel: 7.2.10-arch1-1
$ total=$(pacman -Qq | wc -l)
$ echo "Há $total pacotes instalados"
Há 408 pacotes instalados
$ hoje=$(date +%F)
$ echo "Backup de $hoje"
Backup de 2026-10-16

Saída com várias linhas: as aspas de novo

O pacman -Qqm devolve um pacote do AUR por linha. A variável guarda as quebras de linha, mas só as aspas as mostram:

$ aur=$(pacman -Qqm)
$ echo $aur                                « sem aspas: as linhas viram espaços
downgrade paru-bin yay-bin yay-bin-debug
$ echo "$aur"                              « com aspas: o valor exato
downgrade
paru-bin
yay-bin
yay-bin-debug

Em scripts antigos você vai ver a forma com crases: hoje=`date +%F`. Ela funciona, mas a forma $( ) é mais legível e pode ser aninhada (uma dentro da outra).

Missão: guarde a data de hoje numa variável chamada pasta, usando $(date +%F), e crie uma pasta com esse nome usando mkdir "$pasta". Confira com ls. (Experimente também aur=$(pacman -Qqm) e compare echo $aur com echo "$aur".)

Contas: $(( ))

Para o Bash, tudo é texto. Para fazer contas com números inteiros, use dois parênteses:

$ echo $((7 / 2)) $((7 % 2)) $((2 ** 10))
3 1 1024                                   « divisão inteira, resto, potência
$ n=5
$ ((n++))                                  « soma 1 em n
$ echo $n
6

Um exemplo de verdade: que porcentagem dos pacotes foi você quem pediu? O pacman -Qqe lista os explícitos (-e, os que você instalou de propósito; os outros vieram como dependência):

$ total=$(pacman -Qq | wc -l)
$ explicitos=$(pacman -Qqe | wc -l)
$ echo $explicitos
45
$ echo $(( explicitos * 100 / total ))
11                                         « 45 de 408 ≈ 11%
$ echo $(( 4 * 100 / total ))
0                                          « 4 do AUR: 0,98%… vira 0!

Dentro de $(( )) não precisa do $ antes das variáveis. E repare no último: a divisão corta as casas decimais. Multiplique antes de dividir (como acima) e, para números com vírgula, use outra ferramenta:

$ echo "scale=1; 45 * 100 / 408" | bc
bash: bc: comando não encontrado            « no Arch, o bc não vem instalado
$ awk 'BEGIN { printf "%.1f\n", 45 * 100 / 408 }'
11.0

O awk (no Arch, o gawk) já vem no base; o bc é o pacote extra/bc (sudo pacman -S bc). Repare que o awk escreve 11.0, com ponto (veja awk).

Formas de fazer contas

$(( )) é a forma moderna e não precisa de nenhum pacote. Você também pode ver let "n = n + 1" e expr 7 + 2, que são mais antigas e fazem o mesmo. Para decimais: awk (já instalado) ou bc (instale antes).

Missão: o script já conta os pacotes. Complete a última linha para mostrar 11% dos pacotes foram instalados por você, calculando a porcentagem com $(( )) (lembre: multiplique por 100 antes de dividir).

#!/usr/bin/env bash
total=$(pacman -Qq | wc -l)
explicitos=$(pacman -Qqe | wc -l)
echo "Instalados: $total; explícitos: $explicitos"
echo "?% dos pacotes foram instalados por você"

#!/usr/bin/env bash
total=$(pacman -Qq | wc -l)
explicitos=$(pacman -Qqe | wc -l)
echo "Instalados: $total; explícitos: $explicitos"
echo "$(( explicitos * 100 / total ))% dos pacotes foram instalados por você"

Ler o que o usuário digita: read

O read pausa o script, espera o usuário digitar e apertar Enter, e guarda o texto numa variável.

read
O comando que lê do teclado.
-r
(raw) Lê as barras invertidas \ literalmente. Use sempre.
-p "Qual pacote…? "
(prompt) Mostra uma pergunta antes. Repare no espaço no fim, para a resposta não grudar.
pacote
A variável que vai receber a resposta (sem $: aqui você está criando).
#!/usr/bin/env bash
read -rp "Qual pacote você quer conferir? " pacote
echo "Você digitou: $pacote"
pacman -Q "$pacote"
$ ./pergunta.sh
Qual pacote você quer conferir? htop       « você digita "htop" e Enter
Você digitou: htop
htop 3.5.3-1

Para senhas, acrescente -s (silent): o que você digita não aparece. Depois de um read -s, dê um echo vazio, porque o Enter também não aparece:

#!/usr/bin/env bash
read -rsp "Uma senha: " senha
echo                               # pula a linha depois da senha
echo "Sua senha tem ${#senha} caracteres."
$ ./senha.sh
Uma senha:                         « -s: o que você digita não aparece
Sua senha tem 8 caracteres.

O ${#senha} é o tamanho do valor, em caracteres (mais sobre isso em "Recortar texto").

Argumentos: o que vem depois do nome do script

Em vez de perguntar com read, o script pode receber informações na própria linha de comando, como o pacman -Q bash recebe bash. Cada palavra depois do nome é um argumento, guardado em variáveis numeradas:

#!/usr/bin/env bash
echo "Script: $0"
echo "Primeiro: $1"
echo "Segundo: $2"
echo "Quantidade: $#"
echo "Todos: $@"
./args.sh
O script: fica em $0.
bash
O 1º argumento: $1.
"Meu Relatório.pdf"
O 2º argumento: $2. Com aspas, é um argumento só.
$ ./args.sh bash "Meu Relatório.pdf"
Script: ./args.sh
Primeiro: bash
Segundo: Meu Relatório.pdf
Quantidade: 2
Todos: bash Meu Relatório.pdf
VariávelContém
$0O nome do script, como foi chamado
$1 … $9Os argumentos 1 a 9 (do 10 em diante: ${10})
$#Quantos argumentos foram passados
"$@"Todos os argumentos, cada um separado, mesmo com espaços. Use este.
$*Todos juntos num texto só. Raramente é o que você quer.
$?Código de saída do último comando
$$O PID (número do processo) do próprio script
$RANDOMUm número aleatório de 0 a 32767

O "$@" é perfeito para repassar tudo a outro comando. O pacman -Q aceita vários pacotes de uma vez:

Missão: este script só mostra o primeiro pacote. Mude-o para dizer Você pediu 3 pacote(s) usando $# e para mostrar a versão de todos os pacotes passados, usando pacman -Q "$@". Os argumentos estão no campo ao lado do botão: troque-os à vontade.

#!/usr/bin/env bash
# Mostra a versão instalada dos pacotes passados como argumento
echo "Primeiro pacote: $1"
pacman -Q "$1"

#!/usr/bin/env bash
# Mostra a versão instalada dos pacotes passados como argumento
echo "Você pediu $# pacote(s)"
pacman -Q "$@"

shift: andar pela lista de argumentos

O shift descarta o $1 e "puxa" os outros: o $2 vira $1, e assim por diante. É útil quando o primeiro argumento é especial e o resto é uma lista:

#!/usr/bin/env bash
titulo="$1"
shift                                  # tira o título; agora "$@" tem só os pacotes
echo "== $titulo =="
pacman -Q "$@"
$ ./grupo.sh "Editores de texto" nano vim
== Editores de texto ==
nano 9.2-1
vim 9.2.1178-1

Valores padrão e argumentos obrigatórios

E se o usuário não passar um argumento? O Bash tem atalhos para isso:

${1
O primeiro argumento…
:-
…mas, se ele estiver vazio ou não existir…
linux}
…use linux no lugar.
#!/usr/bin/env bash
pacote="${1:-linux}"
echo "Versão instalada de $pacote:"
pacman -Q "$pacote"
$ ./versao.sh
Versão instalada de linux:
linux 7.2.10.arch1-1                       « sem argumento: usou o padrão
$ ./versao.sh pacman
Versão instalada de pacman:
pacman 7.1.0.r9.g54d9411-3

(Repare que a versão do pacote linux é 7.2.10.arch1-1, com ponto, enquanto o uname -r mostra 7.2.10-arch1-1: o pacman não permite - dentro da versão.)

Quando o argumento é obrigatório, use :?. O script para com a mensagem que você escolher e código 1:

#!/usr/bin/env bash
pacote="${1:?informe o nome de um pacote}"
pacman -Qi "$pacote"
$ ./obrigatorio.sh
./obrigatorio.sh: linha 2: 1: informe o nome de um pacote
$ echo $?
1
FormaSignifica
${var:-padrão}Usa "padrão" se var estiver vazia (não altera var)
${var:=padrão}Igual, mas também guarda "padrão" em var
${var:?mensagem}Para o script com a mensagem se var estiver vazia

Recortar e transformar texto

O Bash consegue mexer no valor da variável sem chamar outros programas. Um bom treino são os nomes de pacotes, que seguem a forma nome-versão-lançamento-arquitetura.pkg.tar.zst:

$ arq="yay-bin-13.0.1-1-x86_64.pkg.tar.zst"
$ echo ${#arq}                              « tamanho do texto
35
$ echo ${arq%.pkg.tar.zst}                  « tira um final exato
yay-bin-13.0.1-1-x86_64
$ echo ${arq##*.}                           « só a última extensão
zst
$ echo ${arq%%.*}                           « tira tudo a partir do PRIMEIRO ponto
yay-bin-13                                  « cuidado: a versão também tem pontos
$ echo ${arq%-*-*-*}                        « tira os 3 últimos "-pedaços": versão, lançamento, arquitetura
yay-bin
$ echo ${arq/yay/paru}                      « troca um trecho
paru-bin-13.0.1-1-x86_64.pkg.tar.zst
$ echo ${arq^^}                             « tudo maiúsculo
YAY-BIN-13.0.1-1-X86_64.PKG.TAR.ZST
$ caminho=/var/cache/pacman/pkg/bash-5.3.20-1-x86_64.pkg.tar.zst
$ echo ${caminho##*/}                       « só o nome do arquivo
bash-5.3.20-1-x86_64.pkg.tar.zst
$ echo ${caminho%/*}                        « só a pasta
/var/cache/pacman/pkg
FormaLembrete
${#var}Quantos caracteres o valor tem
${var#padrão} / ${var##padrão}Tira do começo (# = o menor trecho que casa, ## = o maior)
${var%padrão} / ${var%%padrão}Tira do fim (% = o menor, %% = o maior)
${var/de/para}Troca a primeira ocorrência; ${var//de/para} troca todas
${var^^} / ${var,,}Tudo maiúsculo / tudo minúsculo

Essas formas também têm equivalentes com comandos externos: basename caminho (= ${caminho##*/}) e dirname caminho (= ${caminho%/*}). Os padrões são os mesmos curingas do terminal (*, ?).

Listas: arrays

Um array guarda vários valores numa variável só. As posições começam em 0. Uma lista de serviços para conferir:

$ servicos=(sshd NetworkManager nginx)
$ echo ${servicos[1]}                       « posição 1 = o segundo item
NetworkManager
$ echo ${#servicos[@]}                      « quantos itens
3
$ servicos+=(cronie)                        « acrescenta no fim
$ echo "${servicos[@]}"
sshd NetworkManager nginx cronie
$ systemctl is-active "${servicos[@]}"      « passa a lista inteira a um comando
active
active
inactive
inactive

Você também pode encher um array com a saída de um comando: aur=($(pacman -Qqm)) dá ${#aur[@]} = 4 e ${aur[0]} = downgrade. Isso funciona porque nomes de pacotes nunca têm espaço; com nomes de arquivos, não faça assim. Você vai percorrer arrays com for em Laços.

Um script completo: guardar a lista dos seus pacotes

Juntando tudo: um script muito útil no Arch. Ele salva, com a data no nome, a lista dos pacotes que você instalou. Se um dia precisar reinstalar o sistema, essa lista recria tudo de uma vez.

#!/usr/bin/env bash
# lista-pacotes — guarda a lista dos pacotes que você instalou, com a data
set -euo pipefail

destino="${1:-$HOME/backups}"
hoje=$(date +%F)
repo="$destino/pacotes-$hoje.txt"
aur="$destino/aur-$hoje.txt"

mkdir -p "$destino"
pacman -Qqen > "$repo"
pacman -Qqem > "$aur"

qtd_repo=$(wc -l < "$repo")
qtd_aur=$(wc -l < "$aur")
echo "Salvei $qtd_repo pacotes dos repositórios em $repo"
echo "Salvei $qtd_aur pacotes do AUR em $aur"
LinhaO que faz
destino="${1:-$HOME/backups}"A pasta vem do 1º argumento ou, se não houver, é ~/backups.
hoje=$(date +%F)A data no formato 2026-10-16, que fica em ordem certa quando o ls ordena.
pacman -Qqen-Q instalados, q só o nome, e explícitos, n nativos (dos repositórios). O > grava no arquivo.
pacman -QqemO mesmo, mas m: os de fora dos repositórios (AUR).
wc -l < "$repo"Conta as linhas. Com <, o wc mostra só o número, sem o nome do arquivo.
$ lista-pacotes

Salvei 4 pacotes do AUR em /home/ana/backups/aur-2026-10-16.txt
$ head -3 ~/backups/pacotes-2026-10-16.txt

base-devel
$ cat ~/backups/aur-2026-10-16.txt

paru-bin

yay-bin-debug

Para reinstalar a partir da lista, o pacman lê os nomes da entrada padrão com -: sudo pacman -S --needed - < pacotes-2026-10-16.txt (veja pacman Avançado). Os do AUR você reinstala com o seu ajudante (yay e paru).

Quando não funciona

"comando não encontrado" ao criar a variável 
$ pacote = htop
bash: pacote: comando não encontrado

O que aconteceu: com espaços, o Bash acha que pacote é um comando e que = e htop são argumentos dele.

Como resolver: pacote=htop, tudo junto.

A variável aparece vazia 
$ echo "Arquivo: $arqivo"
Arquivo:

O que aconteceu: o nome foi digitado errado (arqivo), ou a variável foi criada em outro terminal, ou dentro de um script que já terminou. Para o Bash, uma variável que não existe vale "vazio", sem erro.

Como resolver: confira o nome. Em scripts, set -u transforma isso em erro: linha 3: arqivo: variável não associada (veja Primeiro Script).

Arquivo com espaço virou dois

O que aconteceu: faltaram aspas: cp $arquivo ~/backups com arquivo="Meu Relatório.pdf" vira cp Meu Relatório.pdf ~/backups, e o cp procura dois arquivos.

Como resolver: cp "$arquivo" ~/backups.

"$variavel" aparece literalmente na tela 
$ echo 'Pacote: $pacote'
Pacote: $pacote

O que aconteceu: aspas simples desligam a troca de variáveis.

Como resolver: use aspas duplas: echo "Pacote: $pacote".

A conta deu 0 (ou perdeu as casas decimais) 
$ echo $(( 4 * 100 / 408 ))
0

O que aconteceu: $(( )) só trabalha com inteiros: 0,98 vira 0.

Como resolver: para decimais, awk 'BEGIN { printf "%.1f\n", 4 * 100 / 408 }' (mostra 1.0). O bc também serve, mas no Arch precisa ser instalado: bash: bc: comando não encontrado é só isso.

"a variável permite somente leitura" e "divisão por 0" 
$ readonly PI=3
$ PI=4
bash: PI: a variável permite somente leitura
$ echo $((10 / 0))
bash: 10 / 0: divisão por 0 (token de erro é "0")

O que aconteceu: readonly trava a variável, e divisão por zero é proibida. Os dois param o comando com erro. Num script de contagem, a divisão por zero aparece quando o total veio vazio ou 0 (um pacman -Qqm numa máquina sem AUR, por exemplo): teste antes com um if (próxima aula).

Resumo

  • nome=valor cria (sem espaços); $nome ou ${nome} lê.
  • Aspas duplas trocam variáveis e preservam espaços; simples deixam tudo literal. Use "$var" sempre.
  • $(comando) guarda a saída de um comando (total=$(pacman -Qq | wc -l)); $(( )) faz contas inteiras; decimais com awk.
  • read -rp pergunta ao usuário; $1, $# e "$@" trazem os argumentos; shift anda na lista.
  • ${1:-padrão} dá um valor padrão; ${1:?msg} torna obrigatório; ${arq%.pkg.tar.zst} corta o final; arrays guardam listas.
