Arch cp

O cp faz uma cópia de um arquivo ou de uma pasta. O original continua onde estava, e a cópia é um arquivo novo, independente: mudar um não muda o outro. É o comando que você usa antes de mexer num arquivo importante, para fazer backup de uma pasta ou para levar um arquivo para outro lugar sem tirá-lo de onde está.

Você vai aprender
  • A regra de ouro do cp: primeiro a origem, depois o destino.
  • Copiar na mesma pasta, para outra pasta, com outro nome, para a pasta atual (.) e vários arquivos de uma vez.
  • Copiar pastas inteiras com -r, e a pegadinha de quando o destino já existe.
  • Proteger o que já existe com -i, -n, -u e -b, porque o cp sobrescreve sem perguntar.
  • Preservar data, permissões e dono com -p e -a, vendo a diferença no ls -l.

Todos os exemplos foram feitos num Arch Linux real (coreutils 9.12), com a usuária ana na máquina notebook, a partir da pasta pessoal dela. Se você ainda não leu, as aulas Caminhos e ls ajudam muito aqui: o cp recebe caminhos, e o ls é como você confere o resultado.

Antes de começar: o cp não pergunta nada

Se o destino já existir, o cp troca o conteúdo dele pelo da origem, em silêncio. Não há lixeira nem "desfazer". Mais adiante você verá as opções que evitam esse acidente.

A ideia: origem e destino

Pense numa fotocopiadora. Você põe o original de um lado e escolhe onde a cópia sai. O cp (de copy, "copiar") funciona igual: você diz o que copiar e para onde. A forma geral é:

cp [opções] ORIGEM DESTINO

O cp olha para o destino e decide o que fazer:

O destino é…O que o cp fazExemplo
Um nome que não existeCria um arquivo novo com esse nomecp frutas.txt frutas-copia.txt
Uma pasta que existePõe a cópia dentro dela, com o mesmo nomecp frutas.txt Documentos/
Uma pasta + um nomePõe a cópia dentro da pasta, com o nome novocp frutas.txt Documentos/feira.txt
Um arquivo que já existeSobrescreve o conteúdo, sem perguntarcp frutas.txt notas.txt

1. Copiar um arquivo na mesma pasta

O caso mais simples: fazer uma cópia de segurança de um arquivo, ao lado dele, com outro nome.

cp
O programa que copia.
frutas.txt
A origem: o arquivo que já existe.
frutas-copia.txt
O destino: o nome da cópia. Como não existe, o cp cria.
$ ls
'Área de trabalho'   Documentos   frutas.txt   Modelos   Público
 aur                 Downloads    Imagens      Música    Vídeos
$ cp frutas.txt frutas-copia.txt
$ echo $?
0                                    « 0 = deu certo
$ ls
'Área de trabalho'   Documentos   frutas-copia.txt   Imagens   Música    Vídeos
 aur                 Downloads    frutas.txt         Modelos   Público

Repare: o cp não escreveu nada. No Linux, silêncio é sucesso. O echo $? mostra o código de saída do último comando: 0 quer dizer que deu certo; qualquer outro número, que houve erro. O segundo ls confirma: agora há frutas.txt e frutas-copia.txt.

O que mudou na cópia? Veja com ls -l

$ ls -l frutas.txt frutas-copia.txt
-rw-r--r-- 1 ana ana 47 16 out 14:55 frutas-copia.txt     « data e hora de AGORA
-rw-rw-r-- 1 ana ana 47 14 out 16:05 frutas.txt           « a data original
ColunaOriginalCópiaPor quê
Permissões-rw-rw-r---rw-r--r--Um arquivo novo nasce com as permissões da origem "filtradas" pela umask do Arch (022), que tira a escrita do grupo. Veja chown, chgrp, umask.
Dono e grupoana anaana anaA cópia sempre pertence a quem copiou.
Tamanho4747Mesmo conteúdo, mesmo tamanho em bytes.
Data14 out 16:0516 out 14:55Para o sistema, a cópia é um arquivo novo, criado agora.

Se você quiser que a cópia fique com a data e as permissões do original, use -p ou -a, explicados na seção 7.

2. Copiar para outra pasta

Quando o destino é uma pasta que existe, a cópia vai para dentro dela, com o mesmo nome:

cp
O programa.
frutas.txt
A origem.
Documentos/
O destino: uma pasta. A barra no fim deixa claro que é uma pasta.
$ cp frutas.txt Documentos/
$ ls Documentos
acesso.log  alunos.csv  frutas.txt  notas.txt  projetos  relatorio.odt

Para outra pasta, com outro nome

Escreva a pasta e, depois da barra, o nome que a cópia deve ter:

$ cp frutas.txt Documentos/feira.txt
$ ls Documentos
acesso.log  feira.txt   notas.txt  relatorio.odt
alunos.csv  frutas.txt  projetos
A barra no fim protege você

Com a barra (Documentos/), se a pasta não existir o cp dá erro. Sem a barra, um erro de digitação vira um arquivo com o nome errado: cp frutas.txt Doc cria um arquivo chamado Doc, sem reclamar. Veja os dois casos em Quando não funciona.

Ver o que foi feito: -v

O -v (de verbose, "detalhado") faz o cp contar cada cópia, no formato 'origem' -> 'destino':

$ cp -v frutas.txt Imagens/
'frutas.txt' -> 'Imagens/frutas.txt'          « de onde -> para onde

Use o -v sempre que estiver aprendendo: você vê exatamente onde a cópia foi parar.

Missão: copie frutas.txt para a pasta Documentos e também para a pasta Imagens (são dois comandos). Use -v para ver cada cópia e confira com ls Documentos.

3. Trazer um arquivo para a pasta atual: o ponto

E o contrário: trazer um arquivo de outra pasta para onde você está? O destino é a pasta atual, que no terminal tem um nome curtinho: . (um ponto).

cp
O programa.
-v
Mostra o que fez.
Documentos/notas.txt
A origem, em outra pasta.
.
O destino: "aqui", a pasta atual. Não esqueça o espaço antes do ponto.
$ cp -v Documentos/notas.txt .
'Documentos/notas.txt' -> './notas.txt'        « ./notas.txt = notas.txt aqui

Também funciona com caminhos absolutos. Este exemplo traz uma cópia do arquivo de configuração do pacman para a sua pasta, para você estudar sem risco de estragar o original:

$ cp /etc/pacman.conf .
$ ls -l /etc/pacman.conf pacman.conf
-rw-r--r-- 1 root root 2928 15 out 05:27 /etc/pacman.conf     « o original é do root
-rw-r--r-- 1 ana  ana  2928 16 out 14:56 pacman.conf          « a cópia é sua

Repare no dono: o original pertence ao root, mas a cópia pertence à ana, porque foi ela quem copiou. Você pode ler e editar a sua cópia à vontade.

4. Vários arquivos de uma vez

O cp aceita várias origens. A regra é: o último argumento é o destino e tem que ser uma pasta. Todos os outros são copiados para dentro dela.

cp -v
O programa, mostrando cada cópia.
Documentos/notas.txt Documentos/alunos.csv
As origens (quantas quiser).
Imagens/
O destino: sempre o último, sempre uma pasta.
$ cp -v Documentos/notas.txt Documentos/alunos.csv Imagens/
'Documentos/notas.txt' -> 'Imagens/notas.txt'
'Documentos/alunos.csv' -> 'Imagens/alunos.csv'

Com curingas

Quando os arquivos têm algo em comum no nome, um curinga escreve a lista para você. O *.txt quer dizer "todos os nomes que terminam em .txt" (veja Curingas):

$ cp -v Documentos/*.txt Downloads/
'Documentos/feira.txt' -> 'Downloads/feira.txt'
'Documentos/frutas.txt' -> 'Downloads/frutas.txt'
'Documentos/notas.txt' -> 'Downloads/notas.txt'

O destino primeiro: -t

O -t PASTA (de target, "alvo") deixa você escrever o destino antes das origens. É útil em comandos montados por outros programas, como o xargs (veja Pipes e xargs):

$ cp -v -t Modelos/ frutas.txt notas.txt
'frutas.txt' -> 'Modelos/frutas.txt'
'notas.txt' -> 'Modelos/notas.txt'

Quando o último não é uma pasta

$ cp frutas.txt notas.txt nao-existe
cp: alvo 'nao-existe': Arquivo ou diretório inexistente
$ echo $?
1
$ cp frutas.txt notas.txt frutas-copia.txt
cp: alvo 'frutas-copia.txt': Não é um diretório

Com várias origens, o cp exige uma pasta no fim. Na primeira linha a pasta não existe; na segunda, o último nome é um arquivo. Nada foi copiado nos dois casos.

Missão: com um único cp, copie Documentos/notas.txt e Documentos/alunos.csv para a pasta Modelos.

5. Copiar pastas: -r

Sem opção nenhuma, o cp se recusa a copiar uma pasta:

$ cp Documentos/projetos copia
cp: -r não especificado; omitindo o diretório 'Documentos/projetos'
$ echo $?
1

A mensagem quer dizer: "você não passou o -r, então pulei a pasta". O -r (de recursive, "recursivo") manda o cp entrar na pasta, e nas pastas dentro dela, e copiar tudo.

cp
O programa.
-r
Recursivo: a pasta e tudo o que há dentro dela. -R (maiúsculo) é igual.
Documentos/projetos
A pasta de origem.
copia
O destino. Como copia não existe, ela é criada como uma cópia de projetos.
$ cp -r Documentos/projetos copia
$ ls copia copia/site
copia:
backup.sh  site

copia/site:
index.html  style.css

A pegadinha: quando a pasta de destino já existe

Rode o mesmo comando de novo, agora com -v, e veja onde as coisas vão parar:

$ cp -rv Documentos/projetos copia
'Documentos/projetos' -> 'copia/projetos'                   « DENTRO de copia!
'Documentos/projetos/site' -> 'copia/projetos/site'
'Documentos/projetos/site/index.html' -> 'copia/projetos/site/index.html'
'Documentos/projetos/site/style.css' -> 'copia/projetos/site/style.css'
'Documentos/projetos/backup.sh' -> 'copia/projetos/backup.sh'
$ ls copia
backup.sh  projetos  site

Da primeira vez, copia não existia e virou a cópia. Da segunda, copia já era uma pasta, então o cp fez o que sempre faz com pastas que existem: pôs a cópia dentro dela. Por isso apareceu copia/projetos.

Comandocopia não existecopia já existe
cp -r projetos copiaCria copia/ com o conteúdo de projetosCria copia/projetos/

Se você escrever Documentos/projetos/ com barra no fim, o cp se comporta do mesmo jeito (diferente do rsync, em que a barra muda tudo; veja scp e rsync).

Missão: crie a pasta backup (com mkdir, veja touch e mkdir) e copie para dentro dela a pasta Documentos/projetos inteira. No fim deve existir backup/projetos/site/index.html.

6. Quando o destino já existe: o cp sobrescreve

Este é o ponto mais importante da aula. Veja o que acontece com a notas.txt (uma cópia das anotações da Ana) quando o frutas.txt é copiado em cima dela:

$ cat notas.txt
Comprar café
Ligar para o João
Estudar Bash
Fazer backup das fotos
$ cp frutas.txt notas.txt                  « nenhuma pergunta, nenhum aviso
$ cat notas.txt
banana
maçã
laranja
banana
uva
maçã
banana

As anotações sumiram. O notas.txt agora tem o conteúdo do frutas.txt, e não há como desfazer. Quatro opções evitam isso:

-i: perguntar antes

O -i (de interactive, "interativo") pergunta antes de sobrescrever. Responda s (sim) para sobrescrever ou n (não) para manter o que existe:

$ cp Documentos/notas.txt .                 « traz as anotações de volta
$ cp -i frutas.txt notas.txt
cp: sobrescrever 'notas.txt'? n             « você digitou n e Enter
$ echo $?
1                                          « nada foi copiado
$ head -1 notas.txt
Comprar café                               « o arquivo está intacto

Qualquer resposta que não comece com s ou S vale como "não". Repare que, quando você diz não, o código de saída é 1: para o cp, a cópia não aconteceu.

-n: nunca sobrescrever

O -n (de no-clobber, "não atropelar") simplesmente pula os destinos que existem, sem perguntar e sem avisar. É o ideal em scripts:

$ cp -n frutas.txt notas.txt
$ echo $?
0                                          « no coreutils 9.12: sucesso, mesmo pulando
$ head -1 notas.txt
Comprar café                               « não foi tocado

Nem com -v o -n avisa que pulou. Se o destino não existir, ele copia normalmente.

-u: só se a origem for mais nova

O -u (de update, "atualizar") copia só quando a origem é mais recente que o destino (ou quando o destino não existe). É como atualizar uma pasta de backup copiando só o que mudou:

$ mkdir backup
$ cp -uv Documentos/*.txt Documentos/*.csv backup/
'Documentos/notas.txt' -> 'backup/notas.txt'
'Documentos/alunos.csv' -> 'backup/alunos.csv'
$ echo "Pagar a internet" >> Documentos/notas.txt     « só a notas.txt muda
$ cp -uv Documentos/*.txt Documentos/*.csv backup/
'Documentos/notas.txt' -> 'backup/notas.txt'        « o alunos.csv nem aparece: não mudou

Na primeira vez, nada existia em backup/, então tudo foi copiado. Na segunda, só a notas.txt, a única que ficou mais nova que a cópia. (O >> acrescenta uma linha no fim do arquivo; veja Redirecionamento.)

-b: sobrescrever, mas guardar o antigo

O -b (de backup) sobrescreve, mas antes renomeia o destino antigo com um ~ no fim:

$ cp -bv frutas.txt notas.txt
'frutas.txt' -> 'notas.txt' (cópia de segurança: 'notas.txt~')
$ ls notas*
notas.txt  notas.txt~                      « notas.txt~ é a versão antiga

Com --backup=numbered, cada sobrescrita guarda uma versão numerada, sem apagar a anterior:

$ cp -v --backup=numbered frutas.txt notas.txt
'frutas.txt' -> 'notas.txt' (cópia de segurança: 'notas.txt.~1~')
$ cp -v --backup=numbered frutas.txt notas.txt
'frutas.txt' -> 'notas.txt' (cópia de segurança: 'notas.txt.~2~')
$ ls notas*
notas.txt  notas.txt~  notas.txt.~1~  notas.txt.~2~
OpçãoSe o destino existe…Quando usar
(nenhuma)Sobrescreve em silêncioQuando você tem certeza
-iPerguntaDigitando à mão, com arquivos importantes
-nPula, em silêncioScripts; "copie só o que falta"
-uSobrescreve só se a origem for mais novaAtualizar uma cópia de backup
-bSobrescreve e guarda o antigo como arquivo~Quando você quer as duas versões
Fazer o cp sempre perguntar

O Arch não cria apelidos para o cp (o ~/.bashrc dele só tem os de ls e grep). Se você quiser que o cp sempre pergunte, acrescente alias cp='cp -i' ao seu ~/.bashrc (veja .bashrc, alias, PATH).

Missão: você quer levar o frutas.txt para Documentos, mas sem nunca estragar o que já existe lá. Rode cp com a opção que nunca sobrescreve, primeiro por cima de Documentos/notas.txt (confira com head -1 que as anotações continuam lá) e depois para a pasta Documentos/ (aí a cópia acontece, porque ainda não existia).

7. Preservar data, permissões e dono: -p e -a

Você viu na seção 1 que a cópia nasce com a data de agora e com permissões filtradas pela umask. Às vezes você quer uma cópia idêntica, por exemplo num backup, para saber quando o arquivo foi realmente modificado.

-p
Preserve: mantém data de modificação, permissões e (se você puder) dono e grupo.
-a
Archive: é o -r + -p + manter links simbólicos como links. O mais indicado para copiar pastas como backup.

Arquivo: sem e com -p

$ cp Documentos/notas.txt n1.txt
$ cp -p Documentos/notas.txt n2.txt
$ ls -l Documentos/notas.txt n1.txt n2.txt
-rw-rw-r-- 1 ana ana 69 14 out 17:40 Documentos/notas.txt     « o original
-rw-r--r-- 1 ana ana 69 16 out 14:56 n1.txt                   « sem -p: data de agora, rw-r--r--
-rw-rw-r-- 1 ana ana 69 14 out 17:40 n2.txt                   « com -p: igual ao original

Pasta: -r × -a

$ cp -r Documentos/projetos p-r
$ cp -a Documentos/projetos p-a
$ ls -l Documentos/projetos p-r p-a
Documentos/projetos:
total 8
-rwxrwxr-x 1 ana ana   45 15 out 09:15 backup.sh
drwxrwxr-x 2 ana ana 4096 12 out 08:03 site

p-a:                                                   « -a: tudo igual ao original
total 8
-rwxrwxr-x 1 ana ana   45 15 out 09:15 backup.sh
drwxrwxr-x 2 ana ana 4096 12 out 08:03 site

p-r:                                                   « -r: datas de agora, permissões filtradas
total 8
-rwxr-xr-x 1 ana ana   45 16 out 14:56 backup.sh
drwxr-xr-x 2 ana ana 4096 16 out 14:56 site

E o dono?

Mudar o dono de um arquivo para outra pessoa é coisa do root. Quando a ana copia um arquivo do root com -p, a data é mantida, mas o dono vira ela, sem nenhum aviso:

$ cp -p /etc/pacman.conf pacman2.conf
$ ls -l /etc/pacman.conf pacman2.conf
-rw-r--r-- 1 root root 2928 15 out 05:27 /etc/pacman.conf
-rw-r--r-- 1 ana  ana  2928 15 out 05:27 pacman2.conf     « data mantida, dono não

Para preservar também o dono (por exemplo, ao copiar arquivos de sistema para um backup), o cp -a precisa ser feito como root: sudo cp -a /etc/pacman.conf /root/ (veja sudo, root e Usuários).

Missão: faça uma cópia de Documentos/notas.txt chamada notas-original.txt na pasta pessoal, mantendo a data original. Confira com ls -l que as duas datas são iguais.

Qual usar?

  • Um arquivo, uma vez: cp simples (com -v enquanto aprende).
  • Arquivo importante no destino: -i à mão, -n em script, -b se quiser guardar os dois.
  • Pasta: -r para trabalhar na cópia; -a para backup.
  • Backup que você vai atualizar sempre: aprenda o rsync.

Quando não funciona

"-r não especificado; omitindo o diretório" 
$ cp Documentos/projetos copia
cp: -r não especificado; omitindo o diretório 'Documentos/projetos'

O que aconteceu: a origem é uma pasta e você não pediu cópia recursiva.

Como resolver: cp -r Documentos/projetos copia (ou -a para preservar datas e permissões).

"não foi possível obter estado de" 
$ cp nada x
cp: não foi possível obter estado de 'nada': Arquivo ou diretório inexistente

O que aconteceu: a origem não existe. "Obter estado" (stat) é a primeira coisa que o cp faz: ler as informações do arquivo.

Como confirmar: ls nada dá o mesmo erro.

Como resolver: confira o nome e a pasta; use Tab para completar nomes e evitar erros de digitação.

"alvo …: Arquivo ou diretório inexistente" / "Não é um diretório" 
$ cp frutas.txt notas.txt nao-existe
cp: alvo 'nao-existe': Arquivo ou diretório inexistente

O que aconteceu: com mais de uma origem, o último argumento precisa ser uma pasta que existe.

Como resolver: crie a pasta antes (mkdir nao-existe) ou corrija o nome.

"não foi possível criar arquivo comum 'Doc/': Não é um diretório" 
$ cp frutas.txt Doc/
cp: não foi possível criar arquivo comum 'Doc/': Não é um diretório
$ cp frutas.txt Doc
$ ls -l Doc
-rw-r--r-- 1 ana ana 47 16 out 14:56 Doc          « virou um arquivo chamado Doc!

O que aconteceu: a pasta Doc não existe (você queria Documentos). Com a barra, o cp entendeu que devia ser uma pasta e parou. Sem a barra, ele criou um arquivo chamado Doc.

Como resolver: apague o arquivo errado (rm Doc, veja rm e rmdir) e copie de novo com o nome certo. Use sempre a barra no fim quando o destino for uma pasta.

"Permissão negada" 
$ cp frutas.txt /etc/
cp: não foi possível criar arquivo comum '/etc/frutas.txt': Permissão negada

O que aconteceu: para criar um arquivo numa pasta, você precisa de permissão de escrita nela, e o /etc é do root.

Como resolver: primeiro pense se o destino está certo. Se estiver, copie como root: sudo cp frutas.txt /etc/ (veja sudo, root e Usuários e Entendendo Permissões).

"são o mesmo arquivo" 
$ cp frutas.txt ./frutas.txt
cp: 'frutas.txt' e './frutas.txt' são o mesmo arquivo

O que aconteceu: origem e destino apontam para o mesmo lugar (o ./ é só "aqui").

Como resolver: dê outro nome ou outra pasta ao destino.

Copiar uma pasta para dentro dela mesma 
$ cp -r Documentos Documentos/sub
cp: não é possível copiar um diretório, 'Documentos', para si próprio, 'Documentos/sub'

O que aconteceu: o destino fica dentro da origem; a cópia nunca terminaria.

Como resolver: escolha um destino fora da pasta, como cp -r Documentos Documentos-copia.

"falta o operando" 
$ cp Documentos/projetos
cp: falta o operando arquivo de destino após 'Documentos/projetos'
Tente "cp --help" para mais informações.

O que aconteceu: o cp precisa de pelo menos dois nomes, origem e destino.

Como resolver: diga para onde copiar; para "aqui", use ..

Sobrescrevi um arquivo sem querer

O que aconteceu: o destino já existia e o cp trocou o conteúdo, sem perguntar.

Como resolver: pelo terminal não há como desfazer. Recupere de um backup ou de um snapshot, se você tiver (veja Snapshots (snapper)). Para a próxima vez, use -i, -n ou -b.

  • cp ORIGEM DESTINO: primeiro o que copiar, depois para onde.
  • Destino pasta → a cópia vai para dentro; destino nome novo → cria; destino arquivo existente → sobrescreve sem perguntar.
  • . é a pasta atual; com várias origens, o último argumento é uma pasta.
  • Pastas precisam de -r (ou -a); se o destino já existe, a cópia vai para dentro dele.
  • Proteção: -i pergunta, -n pula, -u só o mais novo, -b guarda o antigo.
  • A cópia é sua e tem a data de agora; -p/-a preservam data e permissões.
